# scene-prep — 촬영 전 준비

촬영은 **마지막에 한 세션으로 몰아서** 한다. 그 세션이 짧고 조용하려면, 그 전에 아홉 장면이 전부 준비돼 있어야 한다.
이 스킬은 그 준비를 맡는다. **여기서는 캡처하지 않는다** — `sckcap`도 `--calibrate`도 부르지 않는다.

산출물은 장면마다 넷이다.

| 파일 | 무엇 |
|---|---|
| `sNN-이름/features.md` | 그 장면이 보여줄 기능 흐름 · **최소 정보 표**(누가 채우나 · 근거) · 조건 · 코드에서 확인한 사실 |
| `_mocks/sNN-<action>.json` | 목 에이전트 대사와 prefill 값 (에이전트가 나오는 장면만) |
| `_scripts/sNN-<action>.mjs` | 사람 조작 스크립트 |
| `sNN-이름/notes.md` | 조작 순서 · 캡처 지점 · 노컷 후보 |

## 사이클

한 장면은 이 고리를 **통과할 때까지** 돈다. 고칠 게 나오면 3~4로 돌아간다.

```
0-1 상태판 → 0 되돌리기 → 1 장면·앞뒤 읽기 → 2 코드에서 확정 → 3 대사 → 4 조작 스크립트
                                       ↑                                    ↓
                                       └──── 5 리허설(헤드리스, 빠르게) ────┘
                                                                     ↓ 통과
                                                    6 시뮬레이션(눈으로) + DB 확인
                                                                     ↓ 통과
                                              8 되돌리기 → 9 상태판 갱신 → 다음 장면
```

### 0-1. 상태판부터 읽는다

`movies/26IRDEMO/STATUS.md` — 아홉 장면이 어디까지 왔는지, 환경을 어떻게 세우는지, 앞선 세션이 어디서 넘어졌는지.
**이 장면이 앞 장면의 데이터를 이어받는지도 여기 적혀 있다**(검사 축은 s01을 먼저 돌려야 s04가 선다).

### 0. 되돌리기 — 매 사이클은 같은 자리에서 출발한다

```bash
.claude/skills/scene-prep/scripts/reset-seed.sh --yes
```

DB를 시드 상태로 다시 만들고 로그인 상태 파일까지 새로 만든다(재시드하면 계정 id가 바뀌어 기존 토큰이 죽는다).
**저장이 있는 장면은 두 번 못 돌린다** — 같은 이름의 내담자가 이미 있으면 `POST /clients`가 409다.
같은 자리에서 출발해야 리허설 시각도 매번 같은 값으로 떨어져 편집이 타임코드를 미리 잡을 수 있다.

### 1. 장면이 약속한 것과 **앞뒤 장면**을 읽는다

`_lab/research/04-artifacts/scenes9.html`의 해당 장면이 정본이고, **`movies/26IRDEMO/CAST.md`가 배역의 정본이다.**

장면은 따로 찍지만 한 편으로 붙는다. 그래서 준비의 첫 일은 이 장면이 **어느 축**에 속하는지 확인하는 것이다.

- 이 장면의 인물이 같은 축의 앞 장면과 **같은 사람인가**. 다르면 CAST.md를 고치거나 이 장면을 고친다 — 둘 중 하나는 반드시 한다
- 앞 장면이 만든 데이터를 이 장면이 **이어받는가**. 이어받는다면 그 데이터가 어떻게 생기는지 앞 장면 features.md에서 확인한다
- 이 장면이 뒤 장면에 **넘기는 것**이 있는가. 있으면 뒤 장면이 요구하는 조건(나이·검사 종류·케이스 상태)을 지금 만족시켜야 한다

> 실제로 이것이 필요했던 이유: s04(바로링크)는 케이스에 **온라인 응시 가능한 검사**가 있어야 버튼이 뜨는데,
> 온라인 검사는 18종 중 2종뿐이고 둘 다 만 10세 이상이다. 그래서 s01이 접수하는 아이들의 **나이**와
> **고르는 검사 항목**이 s04에서 역산돼 정해진다. 장면 하나만 보고 준비하면 이 제약이 보이지 않는다.

### 1-1. 장면이 약속한 것

왼쪽(아날로그 문제)과 오른쪽(기능적 해결)이 그 장면의 계약이다.
`faceless.html` §02 배정표에서 그 장면의 **AFTER 기법**을 확인한다. 아홉 장면 전부 AFTER는 ③ Screenlife이고,
BEFORE(탑다운 손·물건·목소리)는 이 스킬의 범위가 아니다 — 실사 촬영이다.

### 2. 코드에서 흐름을 확정한다 (추측 금지)

제품 소스는 `movies/26IRDEMO/_tool/saas-center-platform`. 화면마다 최소한 이 넷을 실제로 읽는다.

- **라우트** — `apps/web/src/routes/(protected)/…`
- **제출 게이트** — 버튼이 살아나는 조건(`canSubmit` 계열). **이것이 "최소 정보"의 정의다.** 디스크립터의 `required`가 아니다
- **버튼 라벨** — 셀렉터가 여기서 갈린다 (실측: 검사 접수의 제출 버튼은 `접수`가 아니라 **`등록`**)
- **prefill 디스크립터** — `apps/web/src/lib/features/agent/page-tools/`. `set`이 없는 필드는 **에이전트가 채울 수 없다** → 사람 몫

찾은 것을 features.md에 표로 남긴다. 각 줄에 근거 파일·줄을 적는다. 나중에 제품이 바뀌면 그 줄부터 깨진다.

### 3. 목 대사를 쓴다

형식의 정본은 제품의 `mock-capture` 스킬(`_tool/saas-center-platform/.claude/skills/mock-capture/SKILL.md`).
이 스킬은 **대사와 값**의 정본이다.

- 되물음 턴에는 `tools`를 넣지 않는다 — 사용자 입력을 기다리는 자리다
- **시드에 없는 인물은 지어낸 이름으로만.** 실명 금지
- **id를 박지 않는다.** 시드를 다시 만들면 죽는다. 이름으로 얹히는 필드는 이름만 쓴다
- 채팅 재생에서 `tools[].delayMs`는 무의미하다 — page tool은 답변이 끝나고 **1초 뒤에 한꺼번에** 실행된다
  (`agent.svelte.ts`의 `pendingPageTools` → `flushPageToolsSoon`). 대사가 끝나고 한 박자 뒤 화면이 바뀌는 리듬이 여기서 나온다
- 쓰고 나면 `node movies/26IRDEMO/_scripts/check-mock.mjs`

### 4. 조작 스크립트를 쓴다

`_scripts/_template.mjs`를 복사하거나 `capture-service`의 `record.mjs`로 기록해서 다듬는다.
헬퍼는 `h.click · type · scroll · hover · key · beat · modal · hold · nocutStart/nocutEnd`.
셀렉터는 텍스트·role 기반을 쓴다. 뷰포트·타이밍은 건드리지 않는다(SPEC이 정본, `capture-service/scripts/spec.mjs`).

### 5. 리허설 — 테이크를 태우지 않고 깨뜨려 본다

```bash
node .claude/skills/scene-prep/scripts/rehearse.mjs \
  --scene s01-접수 --url http://localhost:3503/agent \
  --state _state/local-saas-counselor1.json \
  --script _scripts/s01-intake.mjs --mock _mocks/s01-intake.json --headless
```

여기서는 `--headless`로 돈다 — 화면을 안 뺏으니 고치고 다시 돌리기를 빠르게 반복할 수 있다.
촬영과 **같은 뷰포트·타이밍·목 대본**으로 돌리되 캡처는 하지 않는다. 보는 것은 셋이다.

| | |
|---|---|
| 조작이 끝까지 가는가 | 셀렉터가 틀리면 어느 단계에서 멈췄는지 |
| **서버 오류(4xx·5xx)** | 화면은 멀쩡해 보여도 저장이 안 된 경우를 잡는다 |
| 페이지·콘솔 오류 | |

종료 코드 — `0` 통과 · `2` 조작 실패 · `3` 서버 오류 · `4` 페이지 오류 · **`5` 로그인 상태가 죽음**(리허설을 시작하기 전에 `/api/auth/check`·`/api/proxy/auth/me`로 확인한다 — 죽은 토큰은 401이 아니라 셀렉터 타임아웃으로 위장한다).
`--fast`는 셀렉터만 훑을 때. **`--fast`로 통과한 것은 촬영 통과가 아니다** — 대기가 짧아 되던 것이 SPEC 타이밍에서 깨진다.
`--keep`은 멈춘 화면을 그대로 두고 확인하고 싶을 때(직접 닫아야 한다).

> 실제로 이 검사가 필요했던 이유: s01 첫 촬영은 조작이 끝까지 갔고 화면도 정상으로 보였지만
> `POST /assessment-cases/batch`가 **404**였다. 내담자 3명만 생기고 검사 케이스는 안 생긴 채로 테이크가 끝났다.
> 리허설을 먼저 돌렸으면 테이크도 시드도 안 태웠다.

### 6. 시뮬레이션 — 사람이 눈으로 본다

헤드리스 리허설이 통과하면, **브라우저를 띄워 한 번 끝까지 본다.** `--headless`만 뺀다.

```bash
node .claude/skills/scene-prep/scripts/rehearse.mjs \
  --scene s01-접수 --url http://localhost:3503/agent \
  --state _state/local-saas-counselor1.json \
  --script _scripts/s01-intake.mjs --mock _mocks/s01-intake.json
```

헤드리스가 잡지 못하는 것을 여기서 잡는다 — 대사와 화면 문구가 어긋나는지, 커서가 어디서 튀는지,
읽을 시간이 모자란 곳은 없는지, 화면에 나오면 안 되는 것이 떠 있는지.

**그리고 저장이 진짜로 들어갔는지 DB로 확인한다.** 4xx가 없다고 저장된 것은 아니다.

```bash
docker exec saas-postgres psql -U imomtae -d imomtae -c "…"   # 그 장면이 만들어야 할 것
```

s01에서 확인한 것: 기관 1 · 내담자 3(생년월일까지) · 검사 케이스 3.
대화 두 마디로 세 군데에 저장된다는 장면의 논지가 화면과 DB 양쪽에서 서야 한다.

### 7. 제품 버그가 나오면

이 스킬은 **고치지 않고 기록한다**. features.md의 "조건"에 남기고, 고쳐야 하면 별도 작업으로 넘긴다.
장면을 우회로 바꿔 덮지 않는다 — 영상이 약속하는 기능이 실제로 동작해야 한다.

### 8. 끝나면 되돌린다

시뮬레이션도 저장을 누르면 **진짜로 저장된다**. 장면 하나를 끝냈으면 다음 장면을 위해 되돌린다(0과 같은 명령).
촬영 세션 직전에는 스냅샷까지 새로 박는다.

```bash
.claude/skills/scene-prep/scripts/reset-seed.sh --yes --snapshot
```

### 9. 상태판을 갱신한다

`STATUS.md`의 그 장면 줄과 갱신 시각을 고친다. 제품에 손댔거나 촬영 도구를 바꿨으면 그 절도.
새로 밟은 함정이 있으면 "함정"에 한 줄 더한다 — **다음 세션이 같은 데서 넘어지지 않게 하는 것이 이 단계의 전부다.**
`_tool/`은 커밋되지 않으므로, 제품 변경은 STATUS.md에 적히지 않으면 존재하지 않는 것과 같다.

`reset-seed.sh`가 하는 일: `init_db`(drop_all + create_all) → `alembic stamp head` → `seed.develop` → 로그인 상태 재생성 → (선택) 스냅샷.
마이그레이션 체인은 빈 DB에서 돌지 않는다(최초 리비전이 기존 스키마를 전제) — `init_db → stamp head` 순서가 정본이다.
재시드하면 id가 바뀌므로 그 전 테이크와는 섞을 수 없다.

## 준비 완료의 정의

장면 하나가 촬영 대기 상태라는 것은 이 여섯이 전부 참이라는 뜻이다.

1. features.md에 최소 정보 표와 **근거(파일·줄)** 가 있다
1-1. **CAST.md의 축과 어긋나지 않는다** — 인물·데이터가 같은 축의 앞뒤 장면과 이어진다
2. 목 대본이 `check-mock.mjs`를 통과한다
3. 리허설이 **종료 코드 0**으로 끝난다 (되돌린 시드 위에서)
4. **시뮬레이션을 눈으로 봤고, 저장 결과를 DB로 확인했다**
5. notes.md에 캡처 지점과 **실측 노컷 타임코드**가 적혀 있다
6. 화면에 실명·실제 내담자 데이터가 없다
7. **`STATUS.md`에 그 장면이 준비 완료로 적혀 있다** — 실측 수치와 함께

## 하지 않는 것

- 캡처하지 않는다. `sckcap`·`--calibrate`·`page.screenshot`·화면 녹화 전부. 촬영은 `capture-service`다
- SPEC(뷰포트·타이밍·fps·테마)을 바꾸지 않는다
- 목 대본에 시드 id를 박지 않는다
- 제품 코드를 이 스킬 안에서 고치지 않는다
- 실명 데이터를 쓰지 않는다
- 이 장면만 보고 결정하지 않는다 — 배역·데이터는 CAST.md의 축을 따른다
