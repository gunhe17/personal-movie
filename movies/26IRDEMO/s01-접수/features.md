# s01 접수 — 통화하면서, 최소 정보만

전화를 받는 중이다. 화면을 옮겨 다니지 않고 에이전트에게 말한다.
**통화 중에 받아 적을 수 있는 것만** 넘기면 검사 접수가 끝난다.

장면이 약속한 것: `scenes9.html` §01 — "같은 내용을 네 번 옮겨 적는다" / "단체 유입이면 명단을 엑셀로 옮겨 한 명씩 등록한다"의 역상.
기법: `faceless.html` §02 — AFTER는 ③ Screenlife("접수 스테퍼 한 흐름"). BEFORE(탑다운 손·메모지)는 이 장면의 촬영 범위 밖이다.

## 흐름

1. **에이전트 요청** — "통화 중인데, 여러 명 검사 접수해줄 수 있어?"
2. **에이전트가 필수 정보만 알려준다** — 기관 이름 · 아이들 성함과 생년월일. 그 밖은 묻지 않는다.
3. **정보 입력** — 통화에서 들은 그대로 한 줄로 답한다.
4. **검사 접수 폼으로 이동 + prefill** — 단체 모드로 열리고 기관·명단이 얹힌다. 담당 검사자는 본인으로 이미 채워져 있다.
5. **검사 항목 하나 고르고 등록** — 버튼이 살아나고, 누르면 기관이 만들어지고 아이 셋이 내담자로 등록되며 검사 케이스가 생긴다.

## 최소 정보 — 코드가 말하는 하한

**정의는 제출 버튼이 살아나는 조건이지, 디스크립터의 `required`가 아니다.**

```
canSubmit = groupMembers.length > 0 && (검사항목 or 패키지) > 0 && selectedMember.length > 0
canSubmitFinal = canSubmit && (!visitCenter || 일정·장소 완비)
```
— `hooks.svelte.ts:173-182`(게이트) · `:213-217`(최종) · `:193`(`visitCenter` 기본 **false**)

| 항목 | 누가 채우나 | 근거 |
|---|---|---|
| 명단(이름 · 생년월일) | 에이전트 | `assessment-receive.ts:94-108` `group_members` — 등록 안 된 사람을 넣는 유일한 경로. 성별·연락처 없이도 생성된다(`query-builders.ts:50-64`가 전부 `\|\| undefined`) |
| 기관/단체 이름 | 에이전트 | `assessment-receive.ts:71-88` — 목록 매칭 없이 이름만으로 얹힌다. 제출 때 실제로 만들어진다(아래 참조) |
| 담당 검사자 | **자동** | `+page.svelte:249-260` — 상담사 계정이면 본인이 기본값. 게이트가 요구하는 셋 중 하나가 로그인만으로 채워진다 |
| 검사 항목 | **사람** | `assessment-receive.ts:123-127` — `get`만 있고 **`set`이 없다**. 에이전트가 채울 수 없는 유일한 필수 항목 |
| 장소 · 일정 | 아무도 | `visitCenter`가 꺼져 있으면 필수가 아니다. 넣는 순간 setter가 `visitCenter=true`로 켜서 장소·일정 단계가 되살아난다(`assessment-receive.ts:150-186`) — **그래서 대본에 날짜·시간을 넣지 않는다** |

결과: 우측 `접수 진행`이 **3단계**(검사 항목 · 수검자 · 담당자)로 뜨고, 에이전트가 답한 직후 **2/3**가 되어
사람에게 남는 것은 검사 항목 하나다.

## 리듬 (SPEC v4)

지연은 **흐름을 알아보는 최소 길이**로 잡는다. 제품을 기다리는 자리는 고정 `hold`가 아니라 `until(조건)`이다 —
목이 답할 때까지, 폼이 갈아끼워질 때까지만 기다리고 그 뒤 한 박자.

**폼은 스크롤로 보여준다.** prefill 직후 `reveal`로 `총 3명`과 기관을 뷰포트 가운데로 끌어올린다.
채워진 값이 화면 밖에 있으면 관객은 채워진 줄 모른다 — 이 장면의 논지가 "채워졌다"이므로 이건 필수다.

| | v3 | v4 |
|---|---|---|
| 전체 | 44.45초 | **22.7초** (조작은 16 → 19단계로 늘었다) |
| 클릭 하나 | 2.09초 | 1.1초 |
| 끝 빈 화면 | 4.2초 | 1.8초 |

## 화면에서 일어나는 일

- 답변이 다 흘러나온 뒤 **1초 쉬었다가** 화면이 갈아끼워지고 명단이 얹힌다 — 커서는 움직이지 않는다.
  (`agent.svelte.ts:36-68` — page tool은 큐에 쌓였다가 `conversation_done` 뒤 `PAGE_TOOL_DELAY_MS=1000`에 한꺼번에 실행)
- 이동하면 채팅은 화면에서 사라진다 — 플로팅 아이콘이 꺼져 있다(`routes/+layout.svelte:206` 주석 처리).
  "대화 → 폼"의 연결은 컷이 아니라 **연속 시간**이 만든다.
- 명단은 `총 3명`과 이름 · 생년월일만 보여준다(`+page.svelte:841-889`). 통화에서 들은 것이 그대로 화면이 된다.
- 등록을 누르면 **기관 → 내담자 3명 → 검사 케이스** 순으로 만들어지고 검사 현황(`/assessment/status`)으로 간다.

## 조건

- **계정은 상담사(정상담).** 담당 검사자 자동 채움이 여기 달려 있다. 데스크 계정으로 찍으면 에이전트가 담당자를 id로 넣어야 하는데, 이름만 넣으면 우측 미리보기가 `m.person?.name`을 읽어 이름이 빈 채 "(대표)"만 나온다(`+page.svelte:535-547`).
- **에이전트가 등록 버튼을 대신 누르지 않는다**(`page.submit` 미사용). 단체 모드에서도 `client`가 `required: true`로 걸려 있어 실패하고, 저장은 사람이 누르는 것이 원칙이다.
- 첫 전송은 대화 생성 API를 한 번 부른다(`agent-service.ts:58-70`) — API가 떠 있어야 목이 재생된다. 크레딧은 쓰지 않는다.
- **재실행하면 409다.** 같은 이름의 내담자가 이미 있으면 `POST /clients`가 409를 낸다. 리허설을 두 번 돌리려면 그 사이에 시드를 되돌리거나 그 이름들을 지워야 한다.
