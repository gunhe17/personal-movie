# s05 회기 일정 — 빈 시간을 맞추려면 한 명 한 명 연락한다

장면이 약속한 것: `scenes9.html` §05 — ① 앱에서 변경 요청 → ② 웹에 쌓인다 → **③ 상담사가 승인하면 캘린더에 바로 반영**.
기법: `faceless.html` §02(5번 줄) — AFTER는 ③ Screenlife, "변경 요청 목록 → 승인 클릭 → 캘린더 반영".

**배역: 회기 축.** 이하준(C00002 4회기) · 보호자 이수진 · 담당 정상담.

## 웹만 찍는다

내담자 앱은 촬영 대상이 아니다(`.claude/loops/26irdemo-prep.md`). ①은 화면으로 보여주지 않는다.
**대신 요청을 데이터로 진짜로 만들어 둔다** — 그래야 ②③이 연출이 아니라 실제 처리가 된다.

이 장면의 심장은 원래 ③이다. demo-proposal이 이 비트를 "v2의 심장 — 승인은 전문가가 누른다"라고 적었다.
보호자가 고르는 화면이 빠져도, **결정하는 사람이 누구인지**는 웹 화면이 말한다.

1. 변경 요청 — 대기 한 줄. `기존 9/17 10:00 → 변경 9/18 16:00`과 사유가 한 줄에 있다
2. `승인` → 확인 모달(`요청한 시간으로 일정을 변경할까요?`) → `확인`
3. `일정을 변경했어요` · 대기 목록이 빈다. **회기가 실제로 옮겨진다**

## 코드에서 확인한 것

| | 근거 |
|---|---|
| 승인·반려는 예약 화면과 대시보드가 **같은 서비스**를 쓴다 | `reservations-service.ts:26-50` — 확인 팝업·사유 입력·invalidate가 갈라지지 않는다 |
| 확인 모달 문구·버튼 | `reservations-service.ts:27-30`(제목 `변경 승인`) · `ConfirmModal.svelte:34`(확인 버튼 기본값 `확인`) |

| 대기 요청은 일정당 하나 | `models.py` `uq_schedule_change_request_pending` — 부분 유니크 인덱스 |

## 준비 단계 — `_scripts/s05-setup.sql`

시드에는 이 장면의 시작 상태가 없다. 셋을 만든다.

1. **보호자 앱 계정** — 이수진에게 `account` + `person`. 시드는 보호자 앱 연결을 만들지 않는다(`center_links` 0)
2. **미래 회기** — C00002 4회기(2026-09-17). 시드의 회기 셋은 전부 과거라 옮길 일정이 없다
3. **대기 중 변경 요청** — 9/17 10:00 → 9/18 16:00, 사유 포함

```bash
.claude/skills/scene-prep/scripts/reset-seed.sh --yes
docker exec -i saas-postgres psql -U imomtae -d imomtae < _scripts/s05-setup.sql
```

**시각은 UTC(naive)로 넣는다.** 저장 규약이 UTC이고 승인 핸들러가 KST로 변환해 슬롯을 본다
(`approve_schedule_change.py:118`). KST로 넣으면 9시간이 밀려 **항상 409**다 — 처음에 여기서 한 번 막혔다.
시드의 `10:00` 일정들이 실은 KST 19:00인 것도 같은 규약 때문이다.

찍을 수 있지만, 한 장면에 승인 비트와 함께 넣으면 논지가 둘로 갈린다. **B컷 후보로 남긴다.**
