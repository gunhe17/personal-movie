조사 2026-09-10. 용도는 `STORY.md`의 BEFORE 층 제작 — **극사실 배경 + 2D 애니메이트 캐릭터**.
X 실시간 담론(실무 팁 · 실패담)은 `03-research/midjourney-video-grok.md`에 따로 있다.

**자료 기준 — 2026년.** 이 문서의 판단은 **2026년 자료**로만 세웠다. 2025년이 원천인 항목은 지우지 않고
`2025-NN 원천 · 2026 갱신 없음`으로 표시했다 — 뒤집는 2026 발표가 없어 아직 유효하다고 보되,
**본 제작 직전에 재확인해야 하는 줄**이라는 뜻이다. 2026 자료로 대체된 내용은 아래로 내리거나 각주로 돌렸다.

**조사 방법과 한계를 먼저 적는다.** `docs.midjourney.com`은 자동 요청에 **403**을 돌려줘 직접 읽지 못했다.
그래서 1차 출처는 **`updates.midjourney.com`의 공식 발표문**(직접 읽음)이고, 나머지는 검색 결과의 2차 문서다.
**2차 출처만 있는 항목은 그렇게 표시했다.** 버전이 자주 바뀌므로 촬영 직전에 다시 확인할 것.

## 1. 버전 지도 — 무엇이 폐기됐는가

이게 가장 중요하다. **인터넷의 미드저니 강의 대부분이 V6·V7 기준이고, 그 문법은 지금 안 통한다.**

| 시점 | 버전 | 바뀐 것 |
|---|---|---|
| 2026-03-17 | **V8 알파** | `alpha.midjourney.com`에서 공개 테스트. 지시 따르기 · 텍스트 렌더링 개선, 생성 약 5배 빠름 (2차) |
| 2026-04-14 | **V8.1** | 표준 작업 4~5배 빠름, HD 2K, Raw 모드 (2차) |
| 2026-07-24 | **V8.2** | 기본 버전이 됨. 미학 · 이미지 품질 · 퍼스낼리제이션 중심 (2차) |
| **2026-08-27** | **Edit Model for V8** | **`--oref`(Omni Reference) · `--cref`(Character Reference) · Retexture를 하나로 대체** (1차 — 공식 발표문) |
| 2026-08-29 | Edit Image Quality Update | (1차 — 발표 목록) |

**폐기된 문법 — 쓰면 안 되는 것**

- `--cref` / `--cw` — V6 · niji 6 시절의 인물 일관성. **V7 이상에서 무시되거나 오류** (2차)
- `--oref` / `--ow` — V7의 인물 일관성. **V8.2의 Edit Model이 대체** (1차)

> ⚠️ **정정 — X 조사가 더 정확하다.** "대체"는 기능 대체이지 문법 이식이 아니다. 공식(2026-08-28)과 실사용자
> 확인에 따르면 **V8·V8.2에는 `--oref`가 아예 없고 V7으로 폴백**해야 한다("v8 still doesn't have oref").
> 즉 **숫자로 인물 유사도를 조절(`--ow`)하려면 V7을 써야 하고**, V8.2에서는 Edit Model의 참조 4장뿐이다.
> 출처 `03-research/midjourney-video-grok.md` §2.

> **함정.** 2026년에 쓰인 블로그도 상당수가 `--oref --ow 100`을 "최신"이라고 소개한다. V7 시절 글이 날짜만 새로 붙은 것이다. **참조 관련 문법은 반드시 `updates.midjourney.com`에서 확인한다.**

## 2. 참조 넷 — 무엇이 무엇을 옮기는가

이 구분이 흐려지면 "인물은 같은데 스타일이 매 컷 다른" 결과가 나온다. 네 가지는 **서로 다른 것을 옮긴다.**

| 도구 | 옮기는 것 | 호출 | 값 |
|---|---|---|---|
| **Edit Model** | **인물 · 사물의 정체성** + 지시 편집 + 인페인팅 · 아웃페인팅 | 웹: 프롬프트 바에 이미지를 끌어다 `attach to prompt` · 라이트박스의 `edit` · 좌측 `edit` 탭 / 디스코드: `--edit <url> ...` | **참조 이미지 최대 4장** |
| **Style Reference** | 색 · 구성 · 질감 · 배경 · 분위기 (의상 · 소품은 섞여 들어감) | `--sref <url|코드>` (여러 개는 공백 구분) | `--sw` **0–1000, 기본 100** |
| **Personalization** | 내 취향 자체 (이미지를 평가해 만든 프로필) | 웹 `midjourney.com/personalize` · Imagine 바 옆 버튼 | **40개 평가로 시작 · 200개면 안정** |
| **Moodboard** | 내가 고른 이미지로 만든 전용 스타일 | 퍼스낼리제이션의 한 종류. 이름을 주고 업로드 · URL · 갤러리에서 채운다 | 기본 무드보드로 지정하면 전 프롬프트에 자동 적용 |

**Edit Model의 명시된 한계 (공식 발표문 원문):** *"moodboards/srefs may work best with some extra prompt direction in this version"* — 편집 모델과 무드보드 · sref를 같이 쓰면 **프롬프트로 더 지시해 줘야 한다.** 그리고 *"There's gonna be a lot of edge cases here."*

**`--stylize`는 스타일 레퍼런스의 다이얼이 아니다.** `--stylize`는 **퍼스낼리제이션 · 무드보드가 얼마나 적용되는지**를 조절하고, 스타일 레퍼런스의 다이얼은 `--sw`다 (2차). 이 둘을 혼동하는 글이 많다.

**V8.2로 넘어가도 이 둘은 유지된다** (2차): `--sw`는 **0–1000 · 기본 100**으로 V7과 V8.1/V8.2에서 같고,
**V7에서 만든 퍼스낼리제이션 프로필이 V8.1 · V8.2에서 그대로 쓰인다.** 프로필을 다시 만들 필요는 없다.

> **각주 — V7으로 폴백할 때만.** `--ow`(2025-05-01 공식 · **2026 기준으로는 V7 전용 레거시**): 범위 0–1000 · 기본 100,
> 사진→애니메 변환은 `--ow 25`, 얼굴·의상 고정은 `--ow 400`, 400을 넘기면 오히려 나빠질 수 있음, 참조는 투명 PNG가 유리.
> **2026 경로에서는 쓰지 않는다** — V8.2에 `--oref`가 없고(2026-08-28), 인물 고정은 Edit Model 참조 4장(2026-08-27)이다.

**`--sv` (스타일 레퍼런스 버전).** V7에서 이미지 sref는 여섯 버전이 있고 `--sv`로 고른다. `--sv 6`이 기본이며, **sref 코드와 sref random은 `--sv 4` · `--sv 6`에서만** 동작한다 (2차 · V7 기준. V8에서의 변화 미확인).

## 3. 파라미터 — 값과 범위

2차 출처 기준이고 버전에 따라 달라진다. **범위보다 중요한 것은 아래 "우리 값"이다.**

| 파라미터 | 범위 · 기본 | 우리 쓰임 |
|---|---|---|
| `--ar` | 화면비 | **`--ar 16:9` 고정.** 영상 전체가 같은 애스펙트여야 한다 — 전환이 인식되면 감정이 끊긴다 |
| `--s` / `--stylize` | 0–1000 | 사진 성격이면 **50–150**, 일반은 200–400 (2차). 배경은 낮게 |
| `--c` / `--chaos` | 0–100 | **20 미만.** 예측 가능해야 한다. 방향 탐색 때만 60–80 |
| `--weird` | 0–3000 | **쓰지 않는다** |
| `--iw` | 0–3 | 이미지 프롬프트 가중치 |
| `--sw` | 0–1000, 기본 100 | 스타일 고정용 |
| `--raw` / `--style raw` | — | **배경에 쓴다.** 미드저니 특유의 미화를 줄여 프롬프트 영향을 키운다 |
| `--no` | — | 제외. `--no text, watermark, logo` |
| `--seed` | — | 같은 프롬프트의 재현 |
| `--draft` | — | **약 10배 빠르고 GPU 비용 약 절반** (2차). 구도 탐색 단계에서만 |
| `--hd` | — | V8 계열. Edit Model과 호환 (2차) |

## 5. 영상 — V1 Video Model (1차 출처)

**2026년 기준으로 확정된 것 먼저.** ① 2026-09-03까지의 공식 발표 목록에 **V1 이후의 새 영상 모델이 없다.**
② 2026-09 미드저니 공식이 **V9 이미지를 V2 비디오보다 먼저** 내겠다고 밝혔다 — V1을 완성품으로 보지 않는다.
③ 2026년 실무 파이프라인은 거의 전부 **미드저니 스틸 + 외부 영상 모델**이다(§7).

아래 사양표의 원천은 **2025-06-18 공식 발표문**이고, 2026 자료에 이를 뒤집는 발표가 없어 유효하다고 본다.

| | |
|---|---|
| 방식 | **Image-to-Video.** 이미지를 만들거나 올리고 `Animate`를 누른다 |
| 모션 프롬프트 | **자동**(시스템이 알아서 만든다) 또는 **수동**(어떻게 움직일지 직접 쓴다) |
| `--motion low` | *"ambient scenes where the camera stays mostly still"* — 카메라가 거의 고정된 잔잔한 장면 |
| `--motion high` | *"scenes where you want everything to move, both the subject and camera"* — 피사체와 카메라가 다 움직일 때 |
| 한 잡의 산출 | **5초짜리 4개** |
| 연장 | **약 4초씩, 총 4회** → 최대 **약 20초** |
| 비용 | **이미지 잡의 약 8배.** 발표문 표현으로 *"영상 1초당 이미지 한 장 값"* |
| Relax | 테스트 기간 **Pro 이상** |
| **해상도 · 프레임률** | **480p · 24fps** — `2025-06 실측 · 2026 갱신 없음`. **제작 전 재확인 필수** |
| **오디오** | **없다** — `2026-09 확인`(공식 피드백 스레드에 여전히 요청 중) |

**X 조사가 더한 실측 (`03-research/midjourney-video-grok.md` §1·§3)**

| 실측 | 시점 |
|---|---|
| **텍스트·문서를 못 그린다** — "롤백·후작업 없으면 글자가 안 된다" · "mangles text" | **2026-09** |
| **손이 무너져** 다른 도구로 고쳐야 한다 | **2026** |
| **카메라를 지시하면 포즈가 바뀐다** — 통제력 부족이 프로덕션 도입을 막는 이유로 반복 지적 | **2026** |
| **플라스틱 질감** | **2026-09** |
| `--motion low`가 안전하고 high는 **얼굴이 붕괴**한다 | `2025-06 원천 · 2026 갱신 없음` |
| Auto보다 **manual 모션 프롬프트 + low**가 통제된다 | `2025-06 원천` |
| **Extend할 때 원문 프롬프트를 지우지 말 것** — 남기고 지시를 덧붙인다 | `2025-06 원천` |

위 표의 **2026 항목 넷이 우리 규칙과 정확히 같은 결론에 닿는다** — 서식 · 화면 · 손은 미드저니에 맡기지 않는다.

**우리 계산** (위 사양이 2026에도 유효하다는 전제). BEFORE 77초 + 후크 6초 + 정점 5초 = **88초**를 영상으로 만들면 이론상 약 88장 값이고,
컷 하나가 5초를 넘으면(B2 12초 · B4 12초 · B5 12초 · B6 14초) **연장을 붙여야 한다.**
연장은 4회까지이므로 **한 소스에서 최대 약 20초** — 우리 컷 길이는 전부 그 안에 들어온다.

**소리는 미드저니가 만들지 않는다.** 5레이어 사운드 · 저역 글리산도 · 무음 1.2초는 전부 밖에서 붙인다.

**상업 이용 — IR 영상에 직결된다.**

- 유료 구독자는 산출물을 소유하고 상업적으로 쓸 수 있다 (ToS: *"You own all Assets You create with the Services to the fullest extent possible under applicable law."*)

- **저작권 등록은 별개 문제다.** 순수 AI 생성물은 인간 저작성 결여로 미국 저작권 보호를 못 받을 수 있다 (Thaler). 영상 자체의 권리를 주장할 일이 있으면 법무 확인

## 7. 우리 제작에 붙이면

`STORY.md`의 제작 규칙과 충돌하지 않게 **미드저니가 맡을 것과 맡지 않을 것**을 나눈다.

| 층 | 미드저니 | 왜 |
|---|---|---|
| **배경 · 공간** | ✅ 극사실 배경. `--raw`, `--s` 낮게, `--c` 낮게 | 실제 센터 레퍼런스 사진을 **Style Reference 또는 Edit Model 참조**로 넣어 그 공간처럼 만든다 |
| **인물(정상담)** | ✅ **실사.** 배경과 **한 프롬프트에서** 함께 생성. **Edit Model 참조 4장**으로 컷마다 동일 인물 유지 | 2026-09-10 **전면 실사로 결정**. 합성 접합부가 없으면 어색함이 생길 자리도 없다. 얼굴을 가진 것은 한 명뿐이라 참조 세트도 하나 |
| **손 · 동작** | △ 컷 단위로 검수, **안 되면 실사 촬영으로 내린다** | 실무자들이 가장 많이 지적하는 실패 지점. 2D 층에 두어 피하던 문제라 실사에서는 대체 촬영이 상시 대기해야 한다 |
| **아이의 얼굴** | ❌ | 뒷모습 · 실루엣 · 프레임 밖. 윤리와 법 양쪽 |
| **서식 · 문서 · 화면** | ❌ **생성하지 않는다** | 생성된 서식은 읽기 어려운 게 아니라 **읽을 것이 없다.** 노력 전이(Song & Schwarz)가 여기서 죽는다. 실물 스캔을 합성한다 |
| **UI** | ❌ | AFTER 층은 실제 촬영본(`raw/*.mov`)이다 |
| **소리** | ❌ (기능 없음) | 전부 밖에서 |

> **파이프라인을 고쳐 잡는다.** 앞서 "스틸 확정 뒤 Animate"라고 적었으나, X 조사에서 확인된 2026년 실무는
> 거의 전부 **미드저니는 스틸 · 첫 프레임 엔진이고 움직임은 다른 모델**이다 —
> `MJ 스틸 → Seedance / Kling / Veo → Topaz 업스케일 → 편집기`. **480p·24fps**라는 V1의 출력이 결정적이다.
> 우리 AFTER 층은 3200×1800 · 60fps이므로 BEFORE를 480p로 만들면 두 층의 질감이 어긋난다.
> 미드저니 V1 Animate는 **5초짜리 앰비언트 테스트**에 쓰고, 본편 움직임은 외부 모델에 맡기는 것을 권한다.
> 2026-09 미드저니 공식도 **V9 이미지가 V2 비디오보다 먼저**라고 밝혔다 — V1을 완성품으로 보지 않는다.

### ~~두 룩을 한 프롬프트에 요구하지 않는다~~ → 전면 실사로 결정(2026-09-10)

> **아래 절은 2D 캐릭터 안을 전제로 쓴 것이다.** 전면 실사로 가면 층 분리의 이유가 사라진다 —
> 둘 다 사진이면 광원을 맞춰야 해서 합성이 오히려 어렵고, **인물을 방 안에서 한 번에 생성하는 쪽**이 낫다.
> 현행 방침은 `STORY.md` §7. 아래는 기록으로만 남긴다.

<details><summary>접힌 기록 — 2D 안의 층 분리 논거</summary>


"극사실 배경 + 2D 캐릭터"를 **한 프롬프트로 뽑는 검증된 공식은 찾지 못했다.** 검색에 걸리는 것은
프롬프트 판매 사이트의 셀셰이딩 예시뿐이고, 그것들은 화면 전체가 2D다.

그래서 **층을 나눠 생성하고 합성하는 것을 권한다.** 우리 규칙과도 맞는다 — 어차피 서식과 UI는 실물·실촬을
합성해야 하므로 합성 공정은 이미 있다.

| 층 | 어떻게 |
|---|---|
| 배경 | 실제 센터 레퍼런스를 `--sref`(또는 Edit Model 참조)로 넣고 `--raw` · `--s` 낮게 · `--c` 낮게 |
| 캐릭터 | 별도로 2D 셀셰이딩. 배경 없이(또는 단색 배경) 뽑아 따낸다. Edit Model 참조 4장으로 동일 인물 유지 |
| 합성 | 밖에서. 캐릭터에 배경의 광원·색온도를 맞춘다 |

참고할 결이 있다면 **Arcane** — 3D 렌더 위에 2D 회화 처리를 얹어 두 질감을 한 화면에 세운 사례다(2차).
다만 그것은 제작 방식이지 프롬프트가 아니다.

</details>

**작업 순서 제안**

1. **퍼스낼리제이션 프로필**을 먼저 만든다(40개 → 200개). 이 영상 전체의 룩이 여기서 정해진다
2. **무드보드**를 둘 만든다 — `센터 극사실`(실제 센터 레퍼런스 사진) · `2D 캐릭터`
3. `--draft`로 컷별 구도를 싸게 탐색한다. 확정되면 draft를 끄고 다시 뽑는다
4. 캐릭터 확정 이미지 4장을 **Edit Model 참조 세트**로 고정한다. 이 세트를 바꾸지 않는다
5. **`--ar 16:9` · `--sw` · 퍼스낼리제이션을 전 컷 동일**하게 잠근다. 컷마다 바꾸면 그게 룩이 흔들리는 원인이다
6. 스틸이 확정된 뒤에만 `Animate` — 영상이 이미지의 8배 값이다
7. 5초를 넘는 컷은 연장으로 잇되 **한 소스 20초 상한**을 넘기지 않는다

## 확인하지 못한 것

- **`docs.midjourney.com`을 직접 읽지 못했다**(403). 파라미터 범위·기본값은 2차 출처다
- **V8.2에서 `--sv`와 sref 코드가 어떻게 바뀌었는지** — V7 기준 설명만 찾았다(`--sw`와 퍼스낼리제이션 호환은 확인)
- **극사실 배경 + 2D 캐릭터를 한 프롬프트로 만드는 검증된 표현** — 찾지 못했다. 층 분리 합성을 권한 이유
- **V8 계열의 인물 일관성 실측** — Edit Model 발표문은 "참조 4장"만 말하고 가중치 파라미터를 언급하지 않는다. `--ow`에 해당하는 다이얼이 있는지 미확인
- **V1 이후 영상 모델** — 공식 발표 목록(2026-09-03까지)에서 확인되지 않았다. 검색 결과 일부가 "2026년 영상 업데이트: `/transition` · `/duration` 모디파이어, 12컷 연결"을 주장하나 **1차 출처가 없어 채택하지 않았다.** 지어낸 스펙일 가능성이 높다
- **한국어 프롬프트 처리** — 미확인. 영어로 쓰는 것을 전제한다
- **V8.2의 참조 4장이 V7 `--ow 400`을 실제로 대체하는지** — 공식은 "모든 면에서 낫다"고만 하고 독립 실측이 없다

## 법무 — X 조사가 더한 것

- **유료 플랜은 미드저니와의 상업 이용 계약이지 제3자 IP 면책이 아니다.** Disney · Universal 제소(2025-06)는 2026년에도 진행 중이고 Warner Bros.가 합류했다
- **화가 · 스튜디오 이름을 프롬프트에 넣지 않는다**(지브리 · 에반게리온 등). 소송 이후 공기에서 위험이 커졌다
- **실존 인물의 얼굴을 참조로 쓰지 않는다.** 상담사 · 아동은 지어낸 얼굴이어야 한다
- **"AI slop"은 2026-09에도 모욕이다.** 2026 슈퍼볼 광고 반응은 "AI처럼 **보이기만 해도** 감점". 생존 전략은 셋 중 하나 — AI 룩을 숨기거나, **2D를 의도된 양식으로 선언**하거나, 실제 UI는 실제 화면으로 넣는 것. **우리 구성은 뒤의 둘을 이미 하고 있다**
