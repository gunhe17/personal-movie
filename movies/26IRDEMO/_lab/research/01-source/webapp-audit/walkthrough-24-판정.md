# 24항목 워크스루 판정 (07-20, livinglab 모드 · 새봄센터)

> 방법: 평가 가이드 시나리오 그대로 Playwright 실조작 + 스크린샷 판독. 환경 `PUBLIC_APP_ENV=livinglab`(에이전트·필드노트 노출 상태).

## A. 내담자 관리 (7종)

- **A1 스케줄 관리 ✅ 통과** — 월간→주간→일간 전환, 일간 장소별↔담당자별 타임라인, 담당자 필터, 빈 시간 클릭 → "어떤걸 새로 등록할까요?"(내담자/상담·프로그램/검사) 모달 전부 정상. API 에러 0. 통계는 고지대로 웹 준비 중(모바일 기준 평가).
- **A2 내담자 조회/관계 ✅ 통과** — 아동+보호자 2명(엄마·아빠) 동시 등록, 검색, 역할 탭(보호자 6/아동 7), 상세 보호자 표시·클릭 시 해당 인물 상세로 점프 전부 정상. app-link/status 404는 API 서버 구코드 문제(재시작 후 200) — 버그 아님.
- **A3 검사 현황 ✅ 통과(조건부)** — 상태 탭·담당자 필터·카드 진행률(완료 0/총 1)·접수일 정상. 전송 내역 화면은 발송 실적 생기는 실기기 리허설에서 재확인.
- **A4 바로링크 🔴→✅ 수정** — **워크스루가 결함 2건 발견·즉시 수정**:
  - **W-1 검사 현황 카드 성별 오표기** — `AssessmentCaseCard`가 `gender==='M'`만 남으로 매핑, API는 `male` → 전원 "여" 표기. 남/여/미상 정규화로 수정, "남" 표기 확인.
  - **W-2 카드 바로링크 버튼 소실(회귀)** — `getHasOnlineLink`가 검사 정의 목록 없이 항상 false(뷰모델 주석의 "서버 필드 추가되면 반영" 상태 + 캐시 주입 함수 미배선). 백엔드 `AssessmentSummary.supports_online` 추가 + 상태 페이지에 검사 정의 쿼리·어댑터(`uid`/`is_online_available` 매핑) 연결로 복구. 바로링크 모달("모바일 가능 검사 → 검사 링크 전송") 정상 확인.
  - **W-3 [low→수정 ✅ 07-21] 검사 접수 착지 비일관** — 성공 시 `history.back()`(캘린더 복귀) → 신규 접수는 `/assessment/status` 착지로 수정(상담 접수 07-16과 동일 패턴). 수정 모드(editCase)는 상세 복귀(back) 유지.
- **A6 청구 ✅ 통과** — 목록(전체/결제대기/결제완료 탭·총 2건)·일괄청구 미리보기 버튼 존재. 생성→납부→결제완료 풀사이클은 규모감사 P6에서 기검증.
  - **W-4 사이드바 "단가 관리" 404 → 수정** — price-list 서브페이지는 07-09 "청구 v3 정합"에서 의도 제거됐는데 사이드바 링크가 남아 404 착지. 서브메뉴 제거 + 세팅 체크리스트도 3단계(상담실→프로그램→구성원)로 정합(단가는 프로그램 금액+청구 모달 단가표 선택으로 대체된 모델).
- **A7 바우처 알림 ✅ 조건부(고지)** — 바우처 화면(전체/진행중/완료 탭·빈 상태 문구) 정상 로드. D4 확정대로 "상태 알림" 범위 — 임박/소진 알림은 바우처 보유 데이터 세팅(운영 세팅) 후 재확인. 페르소나 감사에서 대시보드 바우처 임박 신호는 기검증.

## B. 관리자/전문가 (워크스루 블록 9)

- **B3 케어보드 ✅ 통과** — 내담자 상세에 상담·검사·바우처·진행·기록 섹션 집적 확인(서지우: 상담 1/1·청구 완료 정합 유지).
- **B4 스마트 일괄 회기 ✅ 통과** — "회기를 추가할게요" 모달: 복수 담당자(대표 왕관 지정+보조 치료사)·장소·**달력 다중 날짜 선택**("선택된 날짜" 패널). 중복 일정 경고는 규모감사 P5에서 강행까지 E2E 기검증.
- **B5 AI 상담일지 🟡 조건부(고지)** — 웹 회기 상세: 일지 필드(목표/진행/다음)·출석 토글·필드노트 패널 진입 정상. AI 초안 생성은 모바일 녹음(필드노트) 기반이라 웹 단독 평가 불가 — 가이드 고지("리빙랩 환경 활성화 후 평가")대로 모바일 트랙+크레딧 세팅 후.
- **B6 검사 18종 🔴 시드 미비** — 검사 관리 화면 정상(총 2개)이나 등록 검사가 스마트폰중독검사·스마트 바디체커 2종뿐. **18종 시드가 운영 세팅 최우선 과제**(2번 작업). 자가보고식 채점→결과→보고서 흐름 자체는 A4 계열로 검증 가능.
- **B10 자격/뱃지 🟡 조건부** — 내 정보 자격·학력·경력 탭(각 0건·추가 버튼) 정상. 인증 뱃지 노출은 자격 등록+인증 처리 후 재확인(운영 세팅 시 대표 계정 1건 등록 권장).
- **B12·13 바우처 증빙·서류 ⏸ 연기 고지** — D2·D3 연기 확정, D4=상태 알림. 평가 안내문에 반영할 것.
- **B14 AI 에이전트 ✅ 통과(UI)** — livinglab 모드에서 /agent 완전 로드: 새 대화·대화 검색·제안 프롬프트("오늘 상담 몇 건이야?" 등)·입력창(마이크·첨부). 실질의는 크레딧 소모라 평가 시작 전 담당자 안내대로.
- **B17 다중센터 🟡 조건부** — 박서봄 단일 소속이라 전환 UI 미노출(정상 동작). 평가자 계정에 복수 센터 소속 세팅(운영 세팅) 후 재확인 — 다중센터 격리·전환 자체는 4차 감사(07-09)에서 기검증.

추가 발견 3건:

## 결과 전송(보호자 인증 열람) E2E — 완주 (07-20 저녁)

## 전송 내역 실검증 (07-21 — 발송 실적 확보 후 A3 조건부 해소)

W-6 검증 과정에서 실발송 데이터가 생겨 A3의 "전송 내역은 발송 실적 후 재확인"을 실행 — **추가 결함 2건 발견·즉시 수정**:

- **W-8 [치명→수정 ✅] 검사 링크 문자에 URL·인증코드 누락** — `assessment_send_link_template`가 파라미터를 전부 무시하고 레거시 문구("아맘때… 앱 접속 후 보고서 다운로드")를 하드코딩 반환 → **수신자가 문자로는 검사에 진입할 방법이 없었음**. W-5 검증이 행 생성까지만 보고 문자 본문은 미검증했던 사각. → 결과 전송 템플릿(검증됨) 형식으로 재작성(센터명·수신자·verify-link URL·인증번호), 템플릿 관리 기본값(constants)도 동기화. 재발송으로 본문 검증 완료. ⚠️ alarmtalk 채널은 카카오 템플릿 등록 필요 여부를 실기기 리허설에서 확인.
- **W-9 [high→수정 ✅] 전송 내역 화면 무인증 호출 + dev 프록시 사설 IP 하드코딩** — `externalGet`(`/external-api`)는 vite 직프록시라 Authorization을 붙일 주체가 없어 **401→로그인 리다이렉트**(타깃이 죽어 있으면 500→빈 화면 0건). 게다가 vite 타깃이 `192.168.1.66:8000`(특정 개발자 LAN IP) 하드코딩. → 전송 내역 액션을 메인 프록시(`get`, 쿠키→Authorization)로 교체 + vite 타깃 env화(`EXTERNAL_API_TARGET`). 화면 검증: 총 3건(문자 2·카카오톡 1) 정상 렌더.
  - 관찰(잔존): `externalGet`의 다른 소비처 2곳(session.action 구 `assessment_sessions` 경로, assessment.action `/v1/assessments` 이중 프리픽스)은 레거시 의심 — 별도 정리 대상.
- 참고: 로컬 API에 LGU 실발송 키가 있어 **테스트 문자가 실제 발송됨**(status=sent) — 로컬 리허설 시 수신번호 주의.
