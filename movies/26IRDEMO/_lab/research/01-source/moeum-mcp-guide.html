인증 방법

모든 API 요청에 X-API-Key 헤더를 포함하세요.

X-API-Key: imtk_your_key_here

Base URL

모든 리소스 API는 워크스페이스 경로 하위에 있습니다.

http://192.168.1.186:3033/api/workspaces/c052a8b4-25ad-4746-809c-0f1566a6641c

요청 예시

산출물 목록 조회
curl -H "X-API-Key: imtk_your_key_here" \ http://192.168.1.186:3033/api/workspaces/c052a8b4-25ad-4746-809c-0f1566a6641c/artifacts
산출물 생성
curl -X POST \ -H "X-API-Key: imtk_your_key_here" \ -H "Content-Type: application/json" \ -d '{"title":"새 메모","content":"내용","type":"MEMO"}' \ http://192.168.1.186:3033/api/workspaces/c052a8b4-25ad-4746-809c-0f1566a6641c/artifacts
통합 검색
curl -X POST \ -H "X-API-Key: imtk_your_key_here" \ -H "Content-Type: application/json" \ -d '{"search":"검색어"}' \ http://192.168.1.186:3033/api/workspaces/c052a8b4-25ad-4746-809c-0f1566a6641c/search/unified
페이지네이션 조회 (권장)
curl -X POST \ -H "X-API-Key: imtk_your_key_here" \ -H "Content-Type: application/json" \ -d '{"page":1,"page_size":20,"include":["issues","relations"]}' \ http://192.168.1.186:3033/api/workspaces/c052a8b4-25ad-4746-809c-0f1566a6641c/search/unified

응답의 meta.has_more가 true이면 다음 페이지가 있습니다. page를 증가시켜 요청하세요.

멤버 목록 조회
curl -H "X-API-Key: imtk_your_key_here" \ http://192.168.1.186:3033/api/workspaces/c052a8b4-25ad-4746-809c-0f1566a6641c/members

멤버 초대(POST), 역할 변경(PUT), 제거(DELETE)는 Admin 권한이 필요합니다.

통합 검색 응답 형식

POST /search/unified는 산출물, 이슈, 관계를 한 번에 반환합니다.

{ "artifacts": [...], "pinned_artifacts": [...], "issues": { "artifact_id": [...] }, "relations": [...], "meta": { "page": 1, "page_size": 20, "total_count": 423, "has_more": true, "pinned_count": 3 } }

page 파라미터 없이 요청하면 전체 결과를 반환합니다 (검색용). 대량 조회 시 반드시 page/page_size를 사용하세요.

산출물 타입 (12개)

산출물 생성 시 type 필드에 사용합니다.

MEMO메모 — 간단한 메모, 일시적인 아이디어
NOTE노트 — 구조화된 문서, 정보 정리
PLAN기획안 — 프로젝트 기획, 전략 문서
STORY스토리 — 사용자 스토리, 역할/목표/행동
APIAPI — API 엔드포인트 명세
SCREEN화면 — UI 화면 설계, 이미지 첨부
TODO할일 — 체크리스트, 작업 목록
TABLE테이블 — 표 형식 데이터
MILESTONE마일스톤 — 목표 일정, 진행률 추적
MEETING_MINUTES회의록 — 회의 녹취/요약, 음성 전사
RETROSPECTIVE회고 — 스프린트/프로젝트 회고 (KPT 형식)
DECISION의사결정 — ADR(Architecture Decision Record) 형식

보안 참고사항

  • API 키는 생성 시 1회만 표시됩니다. 안전한 곳에 보관하세요.
  • 키가 노출된 경우 즉시 폐기하고 새 키를 발급하세요.
  • API 키는 해당 워크스페이스의 리소스에만 접근할 수 있습니다.
  • API 키의 실제 권한은 키 역할과 발급자 역할 중 낮은 쪽이 적용됩니다.
