DEMO VIDEO v2 — 스텝 분류 · 기능 후보

전화로 하던 일이,
앱·플랫폼의 양방향 흐름이 된다

데모 영상 v2 방향 검토용 (9/7) · 스텝을 먼저 분류하고, 스텝마다 나올 만한 기능을 나열한 문서.
어떤 기능을 핵심으로 세울지 여기서 고르고 → 대본·영상 제작으로 넘어간다.
대표 예시로 주신 방향: 기존에는 전화로 예약·변경(모션그래픽) → 지금은 내담자가 앱으로 변경 요청 → 전문가가 확인·승인.
모든 스텝을 이 감각(기존: 전화·수기 → 지금: 플랫폼 양방향)으로 구성한다.

먼저, 뭐가 실제로 있는지 확인했다 9/7 코드베이스 조사

✅ 킬러 흐름은 이미 구현돼 있다

예약 변경 요청 → 승인이 실제 기능으로 존재:
내담자 앱(일정 탭)에서 변경·취소 요청 → 웹 예약 화면(schedule/reservations)에서 승인/거절 → 누가 언제 결정했는지까지 기록. 원하시는 흐름을 실화면 그대로 촬영 가능.

⚠️ 전화 접수 전사는 현재 없다

"전화 접수 → 전사된 내용으로 빠르게 메모·일정 등록"은 미구현. 단, 필드노트에 녹음→전사→화자분리→요약 파이프라인이 이미 있어 기술 토대는 있음. 처리 방안 3가지를 마지막 장에 정리 (논의 1번).

상태 표기 (이후 모든 표에 사용)

실재 실화면 촬영 가능   부분 일부 구현 · 동작 확인 필요   신규 미구현 — 모션그래픽 연출 또는 개발 필요

에이전트의 경계 (정직 연출)

AI 에이전트는 조회 50+ 도구와 폼 미리 채움(prefill)까지만 — 등록·변경을 실행하는 쓰기 도구는 없다. "에이전트가 대신 등록해준다" 연출은 하지 않는다.

스텝 분류 — 5스텝 + 관통축

스텝기존 방식 (모션그래픽 영역)지금 방식 (실화면 영역)
1 접수·등록전화 받아 수기 장부·엑셀에 적는다접수 한 흐름(내담자→담당→상담실→일정→메모) + 통합 내담자 DB
2 일정·예약 ⭐변경 전화가 오면 달력을 지우고 다시 쓴다내담자 앱 변경 요청 → 전문가 확인·승인 → 캘린더 반영
3 상담 진행·기록회기 끝나고 기억으로 일지를 쓴다회기 녹음 → AI 전사·화자분리·요약(필드노트)
4 검사내원 실시 → 수기 채점 → 보고서 수기 작성온라인 응시 링크 → AI 채점 → AI 종합보고서 → 소견 워크스페이스 확정
5 바우처·청구엑셀 수기 차감 · 월말 대조회기 진행 → 소진 반영 · 청구·미납 현황
관통축 — AI 에이전트: 스텝 사이사이 "물어보면 답하고 화면까지 이동"으로 흐름을 잇는 내레이터 역할 (조회 한정).
⭐ = 데모 방향성의 심장 스텝. 기존 방식 문장은 전부 초안 — 현장 표현으로 교체 필요.
3

1접수·등록 — "전화 받아 적던 것"

기존: 전화 문의 → 수기 장부/엑셀 → 같은 사람 정보가 파일마다 흩어짐 (모션그래픽)
핵심?기능 후보상태설명
⭐전화 접수 전사 → 메모·일정 빠른 등록신규말씀하신 예시. 통화가 텍스트가 되고, 그 내용으로 접수가 바로 채워지는 그림. 처리 방안은 논의 1번
상담 접수 스테퍼실재내담자 선택 → 담당 → 상담실 → 다중 일정 → 메모, 한 흐름
통합 내담자 DB실재1인 1레코드, 보호자 관계 포함 — 이후 모든 스텝이 이 레코드에 쌓임
에이전트 prefill (대화로 폼 미리 채움)부분전사 연출의 대체 후보 — "이 내용으로 접수 잡아줘" → 폼이 채워져 있고 사람이 저장
4

2일정·예약 — "전화로 예약·변경하던 것" ⭐ 데모 방향성의 심장

기존: 변경 전화 → 달력 지우고 다시 쓰기 → 착오·누락 (모션그래픽)
내담자 앱: 변경 요청▶웹: 요청 확인 → 승인/거절▶캘린더 자동 반영▶앱: 결과 확인
핵심?기능 후보상태설명
⭐예약 변경 요청 → 승인 (양방향)실재내담자 앱 일정 탭에서 변경·취소 요청 → 웹 예약 화면에서 승인/거절, 결정자·결정시각 기록
캘린더 일정 등록·변경실재센터 전체 일정 한눈에 — 접수(스텝 1)에서 잡은 일정이 여기 뜬다
승인 결과 내담자 알림부분notification 모듈은 있으나 변경 승인→앱 알림 연동은 확인 필요
내담자 앱에서 새 예약 생성신규현재는 변경·취소 요청만 — 신규 예약은 미구현 (데모 범위에서 제외 권장)
5

3상담 진행·기록 — "기억으로 일지 쓰던 것"

기존: 회기 종료 → 기억에 의존해 수기 일지 → 기록이 밀림 (모션그래픽)
핵심?기능 후보상태설명
⭐필드노트: 녹음 → 전사 → 화자분리 → AI 요약실재파이프라인 전 단계 구현. 열람·편집 화면 상태는 촬영 전 확인 필요
상담일지 · 진행 회기 자동 집계실재몇 회기째인지 세지 않아도 맞는다 — 스텝 5(바우처)의 근거가 됨
내담자 앱 기록 탭 (상담 노트 열람)실재기록이 보호자에게도 이어진다 — 양방향 감각을 여기서도 한 번

4검사 — "내원 실시·수기 채점하던 것"

기존: 내원 → 대면 실시 → 수기 채점 → 보고서 수기 작성, N주 (모션그래픽) · "검사를 받아야 할 사람은 많은데, 실시할 수 있는 사람이 부족하다"
핵심?기능 후보상태설명
온라인 응시 링크 발송 + 접속 추적실재quick-links 화면 — 보냈는지·접속했는지 추적
AI 채점 · HTP · 로샤 (마인드봄)실재v1 클립 확보분 — 재사용 가능
⭐AI 종합보고서 초안 → 소견 워크스페이스에서 임상가 확정실재클라이맥스. 소견 워크스페이스(3열, 8월 말 신기능)로 "임상가 확정" 컷이 실화면이 됨
결과 전송 → 내담자 앱 도착부분앱에 도착 스테퍼(실시→준비 중→도착)는 있으나 결과 열람 화면은 확인 필요

5바우처·청구 — "엑셀로 차감하던 것"

기존: 엑셀 잔여 회기 수기 차감 → 월말 일일이 대조 → 미납은 기억으로 추적 (모션그래픽)
핵심?기능 후보상태설명
⭐회기 진행 → 바우처 소진 자동 반영부분진행 회기=소진 규칙은 확정(참석+불참+노쇼) — 화면 동작은 촬영 전 확인 필요. 스텝 3의 회기가 여기로 이어지는 게 스텝별 구성의 힘
바우처 소진 현황 (내담자 기준 / 센터 관리)실재내담자별 잔여·소진 한눈에
청구 생성 (회기 선택 → 금액 계산) · 미납 탭실재청구·부분결제·완납·미납 상태 분류
8

관통축 — AI 에이전트 스텝 사이를 잇는 내레이터

할 수 있는 것 (실재)

조회 50+ 도구 — "김도윤 진행 상황", "내일 일정", "진행 중인 검사", "바우처 소진 현황", "미납 청구" 등을 물으면 답하고 해당 화면으로 이동. v1에서 검증된 연출(답변 → 화면 전환)을 스텝 전환부에 배치.

하지 않는 연출

등록·변경 실행(쓰기)은 도구가 없다 — "에이전트가 예약을 승인해준다" 같은 연출 금지. 승인은 전문가가 누른다(그게 방향성과도 맞다 — 전문가가 확인하고 결정하는 그림).

배치 가안

스텝마다 1비트씩 넣으면 총 5비트(v1 클립 재사용 가능). 대안: 도입부에 1번 + 마무리에 1번만 넣어 담백하게. 스텝별 vs 몰아서 — 논의 3번.

prefill (부분)

"이 내용으로 접수 잡아줘" → 폼이 미리 채워지고 사람이 저장. 전사 접수(스텝 1)가 신규인 상황에서 실재하는 대체 연출이 될 수 있음.

9

핵심 후보 5 + 논의 포인트

① 전사 접수 (신규)▶ ② 변경 요청→승인 (실재)▶ ③ 필드노트 AI (실재)▶ ④ AI 보고서+소견 확정 (실재)▶ ⑤ 소진 자동 반영 (부분)
5개 전부 "전화·수기 → 플랫폼 양방향" 한 문장 안에 들어간다. 이 5개를 세울지, 빼거나 바꿀 게 있는지가 첫 결정.
논의 1 — 전사 접수(①)를 어떻게 갈까 (가장 먼저 정할 것)
(a) 컨셉 연출 — 통화가 텍스트로 변하는 모션그래픽 → 실화면 접수 스테퍼로 연결 (추천: 개발 없이 방향성 전달)
(b) 필드노트 전사 파이프라인을 접수에 붙여 실제 개발 후 촬영 (개발 소요 발생)
(c) 이번 데모에서 제외 — 접수는 스테퍼+통합 DB만으로
논의 2 — 스텝 2 승인 알림: 승인 후 내담자 앱에 알림이 실제로 가는지 확인 필요 — 안 가면 "앱에서 결과 확인" 컷을 어떻게 처리할지
논의 3 — 에이전트 배치: 스텝마다 1비트(총 5) vs 도입·마무리 2비트만
논의 4 — 검사 비중: v1은 검사가 40%였다 — v2에서도 클라이맥스(④)로 유지할지, ②(예약 양방향)를 더 키울지
논의 5 — 기존 방식 문장: 각 스텝 회색 문장은 전부 초안 — 현장에서 실제 쓰는 표현으로 교체
