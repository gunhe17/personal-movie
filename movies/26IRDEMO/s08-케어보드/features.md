# s08 케어보드 — 한 아이의 기록이 네 곳에 흩어져 있다

장면이 약속한 것: `scenes9.html` §08 — 내담자 한 명의 화면에 **전부 모인다**: 프로필과 보호자·형제 관계,
케이스 이력(회기별 진행), 서류, 바우처, 앱 연결 상태.

**배역: 모임 축 = 이하준.** 회기 축과 같은 사람이다 — s05(일정 변경) · s06(필드노트) · s07(일지) · s09(노쇼·차감)에서
**우리가 방금 쌓은 기록**이 그대로 여기 모인다. 장면의 논지가 앞 장면들의 결과로 증명된다.

> 처음엔 김민준(보호자 둘 + 형제)이었으나 **주인공이 그를 못 연다.** COUNSELOR는 `access_level=own`이라
> 담당 내담자만 열람되고 URL 직접 접근도 같은 기준으로 막힌다(`get_client.py:14-19`). CAST.md에 이유를 남겼다.

## 흐름 (웹)

1. 케어보드 기본 화면 = **진행 현황** — 놀이치료 · 담당 정상담 · **진행률 4/8 회기**(s09-setup의 5회기가 들어와 3/8→4/8) · 다음 상담일
2. 아래로 — 회기별 이력이 날짜순으로(2026년 8월 19일 1회기 …) · 차트 · 메모
3. **문서** 탭 — 사전기록지 · 동의서
4. **바우처** 탭 — 잔여와 사용 이력
5. **내담자 정보** — 프로필 · **가족관계(보호자 이수진)** · 메모

|---|---|

## 제품에서 발견한 것 — 관계 목록이 이름 하나를 N+1 단건 조회로 받아왔다 (고쳤다)

케어보드가 보호자(이수진)의 **이름**을 채우려고 관계마다 담당 범위 가드가 걸린 단건 조회를 불렀고,
그 조회가 404가 나면서 `Promise.all`이 거부돼 **`가족관계` 행이 통째로 사라졌다**(빈 이름이 아니라 행 자체가 없다).
DOM으로 확인: 수정 전 `가족관계` 0건 · `이수진` 0건 · `pageerror: Request failed with status code 404`.

원인은 담당 범위 가드가 아니라 **이름을 받는 경로**다. 관계 API는 상대가 누구인지 이미 알고 있는데
응답에 이름을 안 실어서, 호출부가 이름 한 개를 위해 격리 가드가 걸린 단건 조회를 관계마다 부르는 구조였다.
게다가 이 저장소의 자체 규약(`.claude/rules/api/agent-query.md` — "참조 1개 = 키 정확히 2쌍:
`{ref}_id`에는 `{ref}_name`을 동반")이 이미 요구하던 형태다.

| 무엇 | 파일 | 변경 |
|---|---|---|
| 응답 스키마 | `apps/api/app/modules/client/relation/schemas.py` `RelationResponse` | **`related_client_name: str \| None = None`** 필드 추가 |
| 엔드포인트 | `GET /centers/{center_id}/clients/{client_id}/relations` (`list_relations_handler`) | 모아진 `related_client_id`를 `ListClientsByIdsService`로 **한 번에** 조회해 이름을 채운다(센터 일치분만) |
| 웹 | `apps/web/src/lib/features/clients/detail/detail-service.ts` `fetchRelations` | `getClientDetail()` 호출 제거 — `rel.related_client_name`을 읽는다. 미사용 import도 정리 |
| 웹 타입 | `apps/web/src/lib/hooks/actions/client.action.ts` `RelationResponse` | 같은 필드 추가 |

**이것은 우회가 아니라 근인 수정이다** — 격리 가드(`_resolve_assigned_client_ids` · `get_client.py`)는
**한 줄도 바꾸지 않았다.** 가드는 그대로 두고, 이름 하나 때문에 가드 걸린 경로를 타던 구조를 없앴다.
(다른 우회였던 "이수진을 케이스 참여자로 넣기"는 하지 않았다 — 회기 참여자·청구·s09 차감까지 파급된다.)

결과: 404가 사라지고 `내담자 정보` 패널에 **`보호자 이수진`**이 뜬다. scenes9 §08이 약속한
"프로필과 보호자 관계"가 실제로 화면에 선다 — 범위를 좁힐 필요가 없어졌다.

**남긴 것**: 전문가 앱(`apps/mobile/src/features/client/hooks.ts` `useClientRelations`)도 같은 N+1을 돌지만
이름 말고 **`phone`까지** 쓰므로 단건 조회가 필요하다. 이름 필드 하나로는 못 고쳐서 손대지 않았다(s08 범위 밖).
