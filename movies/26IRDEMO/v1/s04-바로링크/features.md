# s04 바로링크 — 검사받으러 한 번, 결과 들으러 한 번

장면이 약속한 것: `scenes9.html` §04 — 오가는 일이 두 번인 이유는 결과가 늦어서가 아니라 채점이 사람 손에 있어서다.
기법: `faceless.html` §02(3번 줄) — AFTER는 ③ Screenlife, "문자 → 인증 → 수행 → 보고서 → 열람"의 Parisian Love 구조.

**배역: 검사 축.** s01이 접수한 햇살지역아동센터 세 아이 중 하나(윤도현 · 만 12세)에게
같은 케이스의 **스마트폰중독검사**를 집으로 보낸다. **케이스에는 검사가 4건 있다**(로르샤흐 · HTP · SCT · 스마트폰중독검사) —
대면 셋은 s02·s03에서 센터로, 온라인 한 건이 s04에서 집으로. 한 접수가 두 갈래로 갈린 그 지점이다.

## 흐름 — 웹만 찍는다

폰 파트(응시·PDF 열람)는 이 장면에서 **뺀다**. 촬영은 링크를 만들어 보내는 데까지다.

1. 검사 현황 → 케이스 카드의 `바로링크 전송`
2. 모달 — 보낼 검사(모바일 가능 검사만 뜬다) → 수신자 이름 · 번호
3. `바로링크 전송` → 링크 생성 + 발송 → **전송 내역** 탭으로 넘어간다
4. 전송 내역에 수신인 · 방식 · 상태가 남는다

폰 화면 없이도 장면이 서는 이유: 아날로그의 고통은 "**다시 온다**"였고, 그 반대는 "보냈다"가 아니라
**보낸 것이 남는다**이다. 전송 내역이 그 증거다. 응시·열람은 폰 경로가 정해지면 별도 컷으로 붙인다.

## 발송 드라이런 (제품 변경)

`settings.MESSAGING_DRY_RUN`이 참이면 `factory.get_messaging_client()`가 LGU+ 어댑터를 만들지 않고
`DryRunMessagingClient`(`app/infrastructure/messaging/dryrun.py`)를 돌려준다. 반환 모양이 같아서
소비처(`SendMessageService`)는 차이를 모르고, 발송 로그가 `sent`로 남아 **화면·DB·전송 내역이 전부 일관된다**.

UI를 건드리지 않았다는 점이 중요하다 — 실패를 숨긴 것이 아니라, 자격증명이 없는 **환경**을 메운 것이다.
운영 기본값은 `False`이고, 촬영 환경만 켠다.

```bash
MESSAGING_DRY_RUN=true uv run uvicorn app.main:app --host 0.0.0.0 --port 3502
```

## 검사 4건이 카드에 어떻게 보이나 (2026-09-10 실측 · 1600×900)

카드는 **검사 목록을 나열하지 않는다.** `첫 검사명 + 외 N건` 한 줄이 전부고 높이는 337px 고정이다
(`AssessmentCaseCard.svelte:81-92` `assessmentLabel`·`assessmentExtra` · `:182` `h-[337px]`).
그래서 4건이 돼도 **줄바꿈도 스크롤도 카드 높이 변화도 없다.** 바뀐 것은 문구와 진행률뿐이다.

| | 검사 2건 (t01~t03을 찍은 데이터) | 검사 4건 (지금) |
|---|---|---|
| 검사 줄 | `햇살지역아동센터` `로르샤흐 검사` `외 1건` | `햇살지역아동센터` `집-나무-사람 그림검사` `외 3건` |
| 진행률 | `0/2` | **`0/4`** |

`assessment_summary`의 순서는 **클릭 순서가 아니다** — DB 실측으로 집-나무-사람 · 로르샤흐 · 문장완성 · 스마트폰중독이라
카드의 첫 이름이 `로르샤흐 검사`(84px)에서 `집-나무-사람 그림검사`(137px)로 **길어졌다.**

### 그 줄이 잘리던 문제 — 찾았고, 고쳤다

**증상**(2026-09-10 실측): 검사명 행(`:268`)은 `기관 배지 + 검사명 + 외 N건` 셋인데 배지와 `외 N건`은 `shrink-0`이고,
검사명 span은 `truncate-safe`(`app.css:1456` `overflow:clip`)인데도 **`min-width:auto`라 플렉스에서 줄어들지 못했다.**
쓸 수 있는 폭 233px(카드 275 − 패딩 40)에 103 + 137 + 37 + 갭 12 = **289px** → 56px 초과 →
카드의 `overflow-hidden`(`:182`)이 **말줄임표 없이** 검사명 끝을 12px 자르고, `외 3건`은 화면에서 통째로 사라졌다.
검사 2건일 때는 합이 234로 **1px 초과**라 아무도 못 봤다 — 첫 이름이 HTP로 바뀌면서 드러난 것이다.

**고침**(제품 변경 · 2026-09-10): `AssessmentCaseCard.svelte:282-289` — 검사명 `Typography`의 클래스를
`truncate-safe` → **`truncate-safe min-w-0`**. `min-width:auto`를 풀어 주니 `truncate-safe`의 말줄임이 제대로 발동한다.
왜 필요한지는 그 자리 주석(`:282-285`)에 남겼다. 실측 확인: 세 카드 전부 **넘침 0px · `외 3건` 보임 · 이름은 말줄임표(…) 처리**.

**그러므로 카드 검사줄은 이제 프레임에 그대로 써도 된다** — 촬영·편집 제약이 아니다.
다만 이 변경은 `_tool/`에 있어 커밋되지 않으므로 **STATUS.md의 제품 변경 표에 적힌 것이 존재의 증거다.**
그 표의 줄이 사라지면 다음 세션은 잘린 카드를 다시 만난다.

장면의 논지는 어차피 카드의 검사 목록이 아니라 **모달의 `모바일 가능 검사`**다 — 4건 중 온라인 1건만 뜨는 그 화면이 증거 컷이다.

## 기존 테이크 t03 판정 — **무효. 재촬영해야 한다**

흐름이 깨져서가 아니다. 조작·셀렉터·타이밍·DB 결과는 4건에서도 그대로 선다(위 리허설 실측).
문제는 **t03이 찍은 화면의 데이터가 지금과 다르다**는 것이다.

- t03은 `s01 t07이 만든 케이스` 위에서 찍혔고(`raw/s04_web_sendlink_t03.meta.json` `retake_reason`),
  그 **t07은 검사를 2건만 골랐다** — meta의 steps에 클릭이 `로르샤흐(투사·대면) → s02` · `스마트폰중독검사(온라인) → s04` 둘뿐이다
- 그래서 t03의 오프닝 카드는 `로르샤흐 검사 외 1건 · 0/2`다. 새 s01 테이크(4건 클릭)와 **같은 편에 붙을 수 없다**
- s03의 마인드봄 배터리(로샤·HTP·SCT)도 s01이 4건을 고른 데서 나오므로, `외 1건`은 그 논지와도 어긋난다
- t01·t02도 같은 이유로 못 쓴다(셋 다 2026-09-09 · 검사 2건 데이터). **앞 테이크는 지우지 않는다** — 컷에 넣지 않을 뿐이다

**s01을 다시 찍는 순간 s04도 같이 다시 찍는다.** 검사 축은 한 시드 위에서 이어져야 한다.

### 셀렉터 함정 둘 (실측)

- **`바로링크 전송`이라는 버튼이 둘이다** — 케이스 카드와 모달 제출. `.first()`는 모달 뒤의 카드를 눌러
  **아무 일도 일어나지 않고 오류도 안 난다**. 모달 제출은 `getByRole('button', {name:'바로링크 전송'}).last()`
  **4건 구성에서 재확인(2026-09-10)**: 버튼 수는 검사 건수가 아니라 **카드 수**를 따른다 — 모달 열기 전 3개(카드 셋),
  열면 4개. `.last()`는 모달 안(x=1112·y=791), `.first()`는 카드(x=381·y=592). **`.last()`가 여전히 정답이다**
- 첫 카드는 **윤도현(AC0002)**이다 — `h.click`이 `.first()`로 잡는데 DOM 첫 카드가 AC0002다(실측 · DB의 링크도 AC0002에 붙었다)
- **관계는 `<input>`이 아니라 `<Select>`** — `input[placeholder="관계"]`는 없다
