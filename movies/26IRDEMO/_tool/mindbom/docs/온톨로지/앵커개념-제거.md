# 앵커 개념 제거 — 일정 없는 검사에 날짜를 붙이지 않는다

> 작업일 2026-08-18 · 백엔드 1파일 + 프론트 2파일 (−61 / +55, 순감 6줄)

## 1. 한 줄 요약

**검사일을 정하지 않고 등록한 검사가, 타임라인에 "예정"으로 떠 있었다.**

등록한 날짜에. 아무도 그 날로 잡은 적이 없는데.

---

## 2. 무엇이 문제였나

### 2.1 코드

```python
# 서버 (repository.py) — 기간 필터
anchor = func.coalesce(Examination.scheduled_at, Examination.created_at)
```

```typescript
// 프론트 (transforms.ts) — 카드 위치
const anchor = exam.scheduled_at ?? exam.created_at
```

"예정일이 있으면 그것, 없으면 생성일." 양쪽이 같은 규칙을 복제하고 있었다.

### 2.2 이게 만들어낸 거짓말

| 실제 | 화면 |
|---|---|
| 검사일 미정 | 등록일에 **'예정'** 라벨로 표시 |

`created_at`은 서버가 항상 채우므로 **`anchor`는 절대 null이 되지 않았다.**
그래서 "일정 없음"이라는 상태가 화면에 존재할 수 없었고,
`anchorAt: null` 분기는 사실상 죽은 코드였다.

### 2.3 왜 이렇게 됐나 (연쇄)

```
scheduled_at nullable 허용
  → 검사일 없이 등록 가능
     → 타임라인에 놓을 기준이 없음
        → coalesce로 created_at을 대신 씀
           → 서버 필터도 같은 식을 써야 함
              (안 그러면 조회는 되는데 화면에서 사라짐)
                 → "앵커"라는 개념이 생김
                    → 양쪽에 복제되어 유지 부담
```

**"앵커"는 두 필드 중 뭘 고를지 정해야 해서 생긴 이름이었다.**
고를 게 하나면 이름 자체가 필요 없다.

## 3. 검토했다가 버린 선택지

### ❌ A. `scheduled_at`을 필수로

처음 제안했으나 **플랫폼 구조를 확인하고 철회**했다.

| 플랫폼 필드 | 의미 | nullable |
|---|---|---|
| `assessment_sessions.schedule_id` | 일정에 붙었나 | **예** |
| `schedules.start` | 언제 | 아니오 |

"일정에 붙었나"와 "언제"가 분리돼 있고, **일정 미정이 정상 상태로 모델링**돼 있다.
온라인 링크 발송처럼 대면 일정 없이 진행되는 검사가 있기 때문이다.

운영 플랫폼에서 검사를 등록해도 일정 없는 검사는 계속 들어온다.
필수화하면 그 경로가 422가 된다.

### ❌ B. 파생을 컬럼으로 승격 (`anchor_at`)

거짓 날짜를 **DB에 영속화**하는 셈이다. 문제를 더 굳힌다.

### ❌ C. 현행 유지 + 모델에 파생 선언

규약(`naming.md` 파생 생명주기 분류)은 지키지만, **거짓말 자체는 남는다.**
"선언했으니 괜찮다"가 되지 않는다.

### ✅ 채택: 일정이 없으면 없는 것으로 남긴다

억지로 날짜를 붙이지 않는다. 그러면 앵커 개념도 함께 사라진다.

## 4. 무엇을 고쳤나

| | 이전 | 이후 |
|---|---|---|
| 서버 필터 | `coalesce(scheduled_at, created_at)` | `scheduled_at` |
| 프론트 위치 | `scheduled_at ?? created_at` | `scheduled_at` |
| 예정 없는 검사 | 등록일에 '예정'으로 표시 | **타임라인에서 제외** |
| `AnchorResult` 구조체 | 있음 | **삭제** |
| `resolveAnchor()` | 있음 | **삭제** |

### 서버 — NULL은 비교에서 자연히 탈락한다

```python
if date_from is not None:
    stmt = stmt.where(Examination.scheduled_at >= _as_naive(date_from))
if date_to is not None:
    stmt = stmt.where(Examination.scheduled_at < _as_naive(date_to))
```

SQL 3값 논리로 `NULL >= '2026-08-01'`은 참이 아니므로 별도 처리가 필요 없다.

### 프론트 — 놓을 자리가 없으면 카드를 만들지 않는다

```typescript
// 예정일이 없으면 놓을 자리가 없다 — 타임라인에서 제외한다.
if (!exam.scheduled_at) return null
const anchorAt = parseServerDate(exam.scheduled_at)
const anchorLabel = resolveAnchorLabel(exam)
```

**양쪽이 같은 규칙이라 어긋나지 않는다** — 서버가 안 보내고, 프론트도 안 그린다.

### 실제 SQL 확인 (돌려서)

```
examinations.scheduled_at >= :scheduled_at_1 AND examinations.scheduled_at < :scheduled_at_2
```

`coalesce`가 사라졌다.

### NULL 탈락 동작 확인 (돌려서)

```
데이터:  예정있음-범위내 / 예정있음-범위밖 / 예정없음
기간 조회 결과: ['예정있음-범위내']
→ 예정없음이 빠지는가: True
```

### 테스트도 함께 고쳤다

`transforms.test.ts`가 옛 동작을 고정하고 있었다:

- `serverAnchor()` 헬퍼가 `?? created_at`으로 서버를 흉내내던 것 → `scheduled_at` 하나로
- `'예정 없음 — created_at으로 떨어진다'` 케이스 → `'예정일이 없으면 카드를 만들지 않는다'`로 교체

**테스트가 거짓말을 증언하고 있었으므로, 코드와 함께 고치는 것이 맞다.**

## 6. 부수 효과 — 규약 정합성 회복

파생 필터가 사라지면서 `date_from/to`가 규약이 말하는 **대표 시간축**으로 정상화됐다.

| 축 | 필터 | 정렬 |
|---|---|---|
| 대표 (`created_at`) | `date_from/to` (무표) | `latest` · `oldest` |
| `scheduled` | `scheduled_from/to` | `scheduled_earliest/_latest` |
| `started` | `started_from/to` | `started_earliest/_latest` |
| `completed` | `completed_from/to` | `completed_earliest/_latest` |

이전에는 `date_from/to`가 계산식을 걸러서 **어느 필드에서도 유도되지 않는 파라미터**였다.
규약의 커스텀 봉쇄(`custom_param_gaps`)에 걸리는 형태였다.

> 유도표 전수 판정은 [검사축-구현방안.md](검사축-구현방안.md) §3.3 참조.
> `Examination` 15필드 전부가 판정을 받았고, 그 과정에서 누락 3건
> (`id` · `institution_id` · `started_at`)을 발견해 보완했다.

## 7. 남은 것

| 항목 | 내용 |
|---|---|
| 기존 데이터 | `scheduled_at IS NULL`인 검사는 이제 타임라인에 안 보인다. **의도한 동작**이나, 운영 데이터가 있다면 사용자에게 "일정 미정" 목록을 따로 보여줄지 판단 필요 |
| 일정 미정 검사의 접근 경로 | 현재는 검사 목록(`/examinations`)에서만 보인다. 타임라인에 "일정 미정" 영역이 필요한지는 UX 결정 |

**타임라인 앵커 규약 자체가 소멸**했으므로, 관련 메모리·문서에서 "앵커" 개념을 참조하는 부분은
"서버와 프론트가 `scheduled_at` 하나를 본다"로 대체된다.
