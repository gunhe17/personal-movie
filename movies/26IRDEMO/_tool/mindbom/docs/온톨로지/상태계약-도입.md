# 상태 계약 도입 — 프론트·백엔드가 같은 표를 통과하게

> 작업일 2026-08-18 · 선행 작업: [상태술어-정리.md](상태술어-정리.md)
> 배경 문서: [검사축-구현방안.md](검사축-구현방안.md) §4.3 (3층 — 적합성 표)

---

## 1. 한 줄 요약

**백엔드가 상태 규칙을 JSON으로 내보내고, 프론트와 백엔드가 각자 그 파일을 검증한다.**

```
apps/api/.../state_machine.py          ← 정본
        ↓ export_state_contract.py
contracts/exam-state.json              ← 계약 (상태 7종 · 전이 49쌍 · 검사 3종)
        ↓                    ↓
백엔드 pytest            프론트 vitest
(TestStateContract)      (state-contract.spec.ts)
```

양쪽이 같은 표를 통과하면, **서로의 구현을 몰라도 동작이 같음**이 보장된다.
준동형 $f(a \cdot b) = f(a) * f(b)$를 전수로 확인하는 형태다.

---

## 2. 왜 필요했나

### 2.1 프론트와 백엔드가 같은 지식을 각자 적고 있었다

| 지식 | 백엔드 | 프론트 |
|---|---|---|
| 상태 7종 | `VALID_TRANSITIONS` 키 | `ExamStatus` 유니온 + `EXAM_STATUS_ORDER` + `gate.spec.ts` 배열 |
| 확정 이후 구간 | `CONFIRMED_STATUSES` | `isConfirmed()` 내부 |
| 검사 유형 3종 | `SUPPORTED_EXAM_TYPES` | `registry.ts`의 `MODULES` |

**타입 체크는 언어 경계를 넘지 못한다.** 백엔드에 상태를 추가해도 프론트는 모른다.

### 2.2 기존 대조 장치가 조용히 깨져 있었다

`test_exam_types.py`가 프론트 소스를 **정규식으로 읽어** 대조하고 있었다.

```python
m = re.search(r"export type ExamType\s*=\s*([^\n]+)", text)
assert m, "ExamType 유니온을 찾지 못했다"
```

그런데 그 사이 프론트가 리팩터링됐다:

```typescript
// registry.ts — 이제 MODULES에서 파생된다
export type ExamType = keyof typeof MODULES
export const EXAM_TYPES = Object.keys(MODULES) as ExamType[]
```

**비교할 리터럴 자체가 사라졌다.** 모달 목록도 `EXAM_TYPES.map(...)`으로 바뀌어
정규식은 `comingSoon` 항목만 잡았다. 테스트 2건이 **실패한 채 방치**돼 있었다.

> 이게 핵심 교훈이다 — **소스 파싱은 리팩터링에 취약하다.**
> 계약은 데이터라 그 문제가 없다.

## 3. 무엇을 만들었나

### 3.1 계약 생성기 — `apps/api/scripts/export_state_contract.py`

```bash
uv run python -m scripts.export_state_contract          # 파일 갱신
uv run python -m scripts.export_state_contract --check  # 최신인지 확인 (CI용)
```

### 3.2 계약 파일 — `contracts/exam-state.json`

```json
{
  "statuses": ["created", "in_progress", "ai_draft_ready", "under_review",
               "confirmed", "report_generated", "completed"],
  "labels": { "created": "생성됨", ... },
  "exam_types": ["htp", "rorschach", "sct"],
  "confirmed_statuses": ["completed", "confirmed", "report_generated"],
  "transitions": [
    { "from": "created", "to": "in_progress", "allowed": true },
    { "from": "created", "to": "completed",   "allowed": false },
    ...
  ],
  "next_statuses": { "created": ["in_progress"], ... }
}
```

**전이는 허용 목록이 아니라 전수(7×7=49쌍)로 적는다.**
허용만 적으면 "여기 없으면 거부"라는 규칙을 읽는 쪽이 다시 구현해야 한다.
전수면 소비자는 표를 조회만 하면 된다 — 재구현할 여지가 없다.

### 3.3 양쪽 검증 테스트

| 위치 | 검증 내용 |
|---|---|
| `tests/unit/test_state_machine.py::TestStateContract` (+7) | 계약이 `state_machine.py`와 일치 · 49칸이 `can_transition`과 한 칸도 안 어긋남 · 전수인지 |
| `core/state-contract.spec.ts` (신규 21) | 상태 목록·순서·표시설정·검사유형·술어가 계약과 일치 |

## 4. 이 테스트들이 실제로 어긋남을 잡는가 (검증)

통과만으로는 믿을 수 없어 **일부러 어긋뜨려** 확인했다.

### 실험 1 — 계약에 상태 추가 (`archived`)

```
백엔드: 3 failed  (test_contract_is_current · statuses_match · labels_match)
프론트: 6 failed  (전수 검증 · 상태 목록 · 순서 · 표시설정 · 잔재검출 · 구간분류)
```

### 실험 2 — 계약에 검사유형 추가 (`mmpi2`)

```
프론트: 2 failed  (레지스트리 불일치 · mmpi2 인식 실패)
```

두 실험 모두 **양쪽이 각자 독립적으로** 어긋남을 잡았다. 실험 후 원복 확인 완료.

## 5. 부수 성과 — 오래 깨져 있던 테스트 2건 해결

`test_exam_types.py`의 정규식 기반 대조 2건을 제거하고 계약 방식으로 옮겼다.

| | 이전 | 이후 |
|---|---|---|
| 백엔드 테스트 | 141 passed, **2 failed** | **148 passed, 0 failed** |
| 프론트 테스트 | 208 passed | **229 passed** |

**중요**: 그 2건은 실제 어긋남이 아니라 **테스트가 낡은 것**이었다.
모달과 백엔드는 실제로 일치하고 있었고, 정규식이 파생 코드를 못 읽었을 뿐이다.
(그래서 "깨진 테스트를 고쳤다"가 아니라 "대조 방식을 바꿨다"가 정확한 표현이다.)

---

## 6. 발견 — 전수 매트릭스는 이미 있었다

작업 전 예상은 "49쌍 테이블을 새로 만든다"였는데, 열어 보니
`TestTransitionMatrix`가 **이미 `ALLOWED` 집합 + 49쌍 parametrize**로 하고 있었다.

그래서 실제 작업은 **매트릭스 신설이 아니라 언어 경계를 넘게 만드는 것**이 됐다.
(클래스 docstring이 "8×8 / 64칸"이라 적혀 있었는데 `ai_analyzing` 제거 후
7종이 되었으므로 49칸으로 정정했다.)

## 7. 남은 것

| 항목 | 상태 |
|---|---|
| CI에 `--check` 연결 | **미완** — 지금은 사람이 갱신을 잊으면 테스트가 잡지만, CI 파이프라인 설정은 별도 |
| 종합보고서 상태 계약 | **미도입** — 검사와 별개 상태 머신(`draft`·`ai_generated` 있음). 필요해지면 같은 방식으로 |
| 플랫폼(마인드스코프)과의 계약 | **회의 대기** — 이 구조가 그대로 확장 가능하다. 상대 6종을 계약에 추가하고 양쪽이 대조 |

## 8. 새 상태를 추가할 때 (작업 절차)

1. `state_machine.py`의 `VALID_TRANSITIONS`·`STATUS_LABELS` 수정
2. `uv run python -m scripts.export_state_contract` 실행
3. 백엔드 테스트 → `TestTransitionMatrix.ALLOWED`도 함께 고쳐야 통과
4. 프론트 테스트 → `EXAM_STATUS_ORDER`·`EXAM_STATUS_VISUAL`도 고쳐야 통과
5. `contracts/exam-state.json` diff가 곧 **"무엇이 달라졌나"**의 기록

2번을 잊으면 `test_contract_is_current`가 잡는다.
