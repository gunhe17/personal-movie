> 작성 2026-08-20 · **v5 (화면 통합 + CDSS 구멍 봉합, 2026-08-24)**
> v1은 4개 관점 적대적 검증에서 치명 13건을 포함해 다수가 깨졌다(§9).
> v2를 임상가 두 분이 검토했고(§11), 그 답변을 근거로 다시 적대 검증했다(§13).
> **재검증의 첫 지적이 "확정 도장을 남발했다"였다** — §11 결론을 격하했다.
> **v5에서 스텝이 4개 → 3개가 됐다(§14).** 자유반응과 질문을 한 화면으로 합치고,
> 그 과정에서 발견한 **AI 초안이 임상가 확인 없이 확정되는 경로**를 막는다.

## 30초 요약

**절대 전제: 임상가가 빠르고 편해진다.** "받아적기를 빠르게"는 그 수단 중 하나였을 뿐이고,
검토 결과 **가장 안 아픈 곳**이었다(§2-1).

새 프로세스는 이렇다.

```
[      실시      ]  [채점]  [결과 🔒]
   22 · 미완 2      12/22
        ↑              ↑
   ─── 자유롭게 오감 ───    결과만 게이트
```

핵심 결정 넷:

1. **관계를 뒤집는다** — 반응(Response)이 주인, 영역(Region)은 0..N개로 딸린다
2. **스텝은 나누되 벽은 없앤다** — 아날로그에서 종이를 고치듯 언제든 되돌아간다
3. **검사실 화면을 새로 만든다** — 채점 UI가 보이지 않는 실시 전용 화면
4. **(v5) 반응은 채점지의 한 줄** — 칸을 아무 순서로나 채운다. 자유반응/질문
   화면을 합치고(§14-1), 그 벽마저 없앤다(§14-2)

⚠️ **v5에서 CDSS 원칙이 깨진 자리를 찾았다(§14-4).** AI 초안이 임상가 확인 없이
확정 코딩으로 승격되고 있다 — 프론트는 AI 값을 임상가 입력칸에 미리 채우고,
백엔드는 `final_coding_json = ai_coding_json`으로 자동 승격한다. 실데이터 4건 해당.

임상가 두 분이 절차(§1)를 확인했고, 집계 단위가 범주임을 확정했다(§2-2).
기기는 노트북·태블릿 둘 다 대응한다. **STT는 별도 트랙으로 뺐다** — 두 분 다
"실측하고 정하자"였다. 다만 **확정된 것은 절차 하나뿐**이고 나머지는 잠정이다(§11).

⚠️ R<14 타당성 판정이 없어 해석 불가 프로토콜에서도 지표가 나오고 있었다.
`d3ec7b6`으로 고쳤다(§13).

## 1. 아날로그 프로세스 (정본)

```
[자유반응 — Free Association]
  카드 I~X 순회. "이게 뭐로 보입니까?"
  → 내담자: "박쥐 같아요"
  → 임상가: 말만 받아적는다. 영역은 묻지 않는다.
  카드당 반응 N개 (카드 X는 8~12개도 흔하다)

[질문 — Inquiry]
  10장을 다 마친 뒤 처음부터 다시
  "아까 박쥐라고 하셨는데, 어디가 그렇게 보였나요?"
  → 내담자가 짚는다 → 임상가가 위치도에 그린다  ← 그리기는 여기서 처음
  "뭘 보고 박쥐라고 생각하셨나요?" → 결정인 단서

[채점] 반응별 Exner CS 코딩
[결과] 구조요약 + 해석
```

### ⚠️ 왜 질문을 10장 뒤로 미루는가 — 이건 UX 선택지가 아니다

카드 I 직후에 질문을 끼워 넣으면 **피검자가 방어적·조심스러워져 이후 반응 산출이 왜곡된다.**
편의 문제가 아니라 **검사 타당도 문제**다. Exner가 질문을 뒤로 미루는 이유가 이것이다.

v1은 "흐름을 끊으면 안 되므로"라고만 적었는데, 이유가 문서에 없으면 나중에
"카드마다 질문하면 UX가 낫지 않나"는 제안을 막을 근거가 없다. **규약으로 못 박는다.**

### 실무 편차 (명시)

아동·지적장애·심한 정신증 환자에서는 10장 뒤 질문 시 "아까 뭐라고 했는지 기억이 안 난다"가
실제로 발생해 카드별 질문으로 전환하는 임상가가 있다. 훈련 계보(Klopfer/Beck)에 따라
카드별 질문을 배운 경우도 있다.

→ **스텝을 자유롭게 오갈 수 있게 하면(§3) 두 경로가 같은 모델로 표현된다.**

## 2. 무엇이 진짜 아픈가 — 목적 재설정

### 2-1. 받아적기는 아프지 않다

임상심리사 검토의 가장 근본적인 지적이다. 아날로그 로샤 1회의 임상가 시간:

| 구간 | 아날로그 | 자동화 여지 |
|---|---|---|
| 자유반응 실시 | 20~30분 | 받아적기는 **실시와 병렬**이라 이득이 작다 |
| 질문 실시 | 25~40분 | 마찬가지 |
| **채점(코딩)** | **40~90분** | **텍스트가 디지털이면 크게 준다** |
| **구조요약 산출** | **20~40분** | **자동화 시 0. 이미 `scoring.py`에 있다** |
| 해석/보고서 | 60~120분 | 부분적 |

**받아적기 자동화는 잘해야 본전이고, 검사 중 조작 부담은 순증한다.**
아날로그에 없던 "반응 경계 탭", "STT 오류 참거나 고치기"가 새로 생기기 때문이다.

### 2-2. 그런데 구조요약이 지금 고장나 있다

가장 큰 가치(구조요약 자동 산출)가 **이미 구현돼 있는데 틀린 값을 낸다.**
실 DB 60건 기준:

```python
# scoring.py:147-150
return (loc if loc in ("W","D","Dd") else None, False)   # "D1" → None
```

| `location` 저장값 | 건수 | 채점 결과 |
|---|---|---|
| `W` `D` `Dd` | 13 | ✅ 집계됨 |
| `D1` `D2` `Dd21` `DdS26` `Dds30` … | **47** | ❌ **조용히 버려짐** |

`W:D:Dd` 분포가 60건 중 13건만 반영된다. Zf·DQ 분포·X+%가 전부 틀어진다.
**에러도 경고도 없다.** 2026-08-20에 고친 Exner 부호 누락(COP/AG/ISO)과 같은 병이다.

→ **§8 착수순서 0번.** 읽는 쪽만 고치면 기존 데이터가 즉시 살아난다.

## 3. 새 프로세스

### 3-1. 스텝 4개, 벽 없음, 결과만 게이트

```
[자유반응 25]  [질문 18/25]  [채점 12/25]  [결과 🔒]
```

- **스텝은 나누되 자유롭게 오간다.** 실제 검사는 순서대로 가지만 **기록은 순차적이지 않다.**
  임상가는 계속 되돌아간다 — 아날로그에선 그냥 종이를 고친다.
- **진행은 완성도(N/M)로 표시**한다. 순서를 강제하지 않는다.
- **게이트는 결과 하나뿐.**

#### 결과에만 게이트를 두는 이유

현재 `ConfirmSessionService`(`services.py:921-928`)는 region을 순회하며 채점 여부를 보므로
**영역이 0개인 반응은 검사를 그냥 통과한다.** 미완성 프로토콜이 완성된 것처럼 구조요약을
산출하고, R이 틀린다. R은 거의 모든 비율의 분모다 — SaMD 데이터 무결성 결함이다.

게이트 조건:
```
모든 카드가 responded 또는 rejected로 표시됨
  ∧ 모든 정식 반응(is_formal)이 채점됨
  ∧ R >= 14                        ← 미만이면 차단 + 재실시 권고 (Exner 표준)
  ∧ (경고) 모든 정식 반응에 inquiry_text 존재
```

**R>=14는 차단, inquiry 누락은 경고**다. 전자는 Exner의 명문 규칙이고
(§13, `d3ec7b6`으로 구현), 후자는 질문 없이 명백한 반응도 실무에 있어
편차가 있다. 다만 **결정인은 질문에서만 나오므로** 경고는 반드시 띄운다 —
실 DB가 증거다: `inquiry_text` 0건인데 confirmed 56건.

#### 되돌아가기 잠금은 폐기한다

현재 잠금의 근거가 소멸하기 때문이다:
```
module.ts:5-9
 * 되돌아가 수정할 수 없게 막는 이유: region을 추가·삭제하면 이미 채점된
 * transcript 매핑이 어긋난다.
```
시간 매칭을 폐기하면(§4-3) 어긋날 것이 없다. **근거 없는 잠금이 남으면 나중에 아무도
왜 있는지 모르는 제약이 된다.** `module.ts` 주석과 `gate.spec.ts:128-165`를 함께 고친다.

무결성은 **잠금이 아니라 이력**으로 확보한다(SaMD 요구는 "모든 데이터 변경 이력 기록"이지
변경 금지가 아니다). 검사 종료 후 수정은 확인 후 허용하고 표식을 남긴다:
```
③ 사람 둘이 마주보고  ✎ 종료 후 수정 (08-20 15:32)
```
잠금은 `confirmed` 한 곳에서만.

### 3-2. 검사실 화면 — 원트랙

**설계 원칙: 임상가의 눈이 화면에 있으면 실패다.**

아날로그의 최대 강점은 손이 자동으로 움직이고 **눈은 피검자와 카드에 있다**는 것이다.
카드를 돌리는지, 어디를 짚는지, 표정이 어떤지는 그 자체로 임상 데이터다.

```
┌────────────────────────────────────────────┐
│  카드 I                        ● 12:04     │  ← 큰 글씨, 경과시간
├────────────────────────────────────────────┤
│                                            │
│        [   카드 이미지 (크게)   ]          │
│                                            │
│         ∧  ∨  <  >   ← 회전 (탭)          │
├────────────────────────────────────────────┤
│  ① 박쥐 같아요                             │
│  ② 나비 같기도 하고                        │
│  ③ ▌                          ← 입력 중    │
├────────────────────────────────────────────┤
│   [ ← 이전 카드 ]  [ 다음 카드 → ]         │  ← 큰 버튼
│   [ 거부 ]  [ 촉구 ]                       │
└────────────────────────────────────────────┘
```

**여기서만 되는 것:** 반응 입력, 카드 넘기기/회전, 거부·촉구 표시
**여기서 안 보이는 것:** 채점 UI 일체, 구조요약

질문 스텝은 같은 골격에 **영역 지정과 질문 응답 칸이 붙는다.**

채점·결과는 **기존 화면을 활용**한다. 새 실시 화면이 반응을 만들고 기존 채점 화면이
그것을 읽는 구조 — 검사가 끊기지 않는다.

### 3-3. STT — 반응 단위 즉시 배치

**"실시간"이 아니라 "반응 단위 즉시"다.**

```
임상가가 Enter(반응 확정)를 누르는 순간
→ 직전 발화 구간을 배치로 전사
→ 2~5초 뒤 그 칸에 초안이 채워진다 (빈 칸일 때만)
```

이 하나로 v1의 실시간 STT가 안고 있던 문제가 **한꺼번에** 사라진다:

| v1의 문제 | 왜 사라지나 |
|---|---|
| CPU 스트리밍 RTF 6.7 (배치는 0.45) | **배치 RTF를 쓴다.** 15초 발화 = 3~5초 |
| VAD 경계 ≠ 반응 경계 | **경계를 임상가가 정한다** |
| STT와 임상가의 입력칸 충돌 | 칸 확정 후 **한 번만** 채운다 |
| 한국어 환각 | 구간에 음성이 없으면 **넣지 않는다** |
| WebSocket 인프라 0줄 | **필요 없다.** 기존 POST 구조 |
| 동시 검사 CPU 고갈 | 연속 추론이 아니라 검사당 20~30회 짧은 배치 |

**왜 스트리밍이 안 되는가:** whisper 인코더는 항상 30초 mel을 통째로 처리한다.
입력이 3초든 30초든 비용이 같으므로, 1초마다 갱신하면 30초 인코딩을 1초마다 도는 셈이다.
같은 하드웨어에서 배치 대비 15배 느리고 지연이 누적된다. 현 배포는 `python:3.11-slim` +
`--workers 2`로 **GPU가 없다.**

**환각 방어(필수):**
- `condition_on_previous_text=False`, VAD 게이팅, `temperature=0.0` + greedy(재현성)
- 환각 의심 구간은 텍스트를 넣지 말고 **빈 칸 + "음성 감지됨(인식 실패)"** 로 남긴다
- 한국어는 무음 구간에 "시청해주셔서 감사합니다"를 삽입하는 알려진 환각이 있다.
  로르샤하는 반응잠재시간이 임상 지표라 **침묵이 길다** — 정확히 그 발동 조건이다.

**STT 없이도 완전히 동작해야 한다.** 타이핑이 1급 경로이고 STT는 초안 생성기다.

### 3-4. 영역 — 현행 유지 + 낮은 일치도 경고

그리기 방식은 그대로 둔다. 다만 실 데이터 135건을 재현해보니:

- 저장 코드 == 최고 IoU 매칭: **126/135 (93%)** — 매칭 로직 자체는 동작한다
- **평균 최고 IoU 0.573** — 잘 맞으면 0.8+가 나와야 한다
- **IoU 0.00이 2건** — 표준 영역과 아예 겹치지 않는데 그 코드가 저장돼 있다

원인은 셋 중 하나이고 지금은 구분되지 않는다: (a) 임상가가 표준과 다르게 그렸다(정상일
수 있다 — 그래서 `Dd99`가 존재한다) (b) 좌표계 왜곡 (c) 자동 배정이 틀린 값을 넣었는데
임상가가 안 고쳤다.

**어긋나도 아무도 모르는 자리다.** 자동 배정은 최고점을 넣는데, 그 최고점이 0.02여도 넣는다.

→ 자동으로 바꾸지 않고 **묻기만** 한다:
```
⚠ 그린 영역이 Dd22와 거의 겹치지 않습니다 (일치도 0%)
   [Dd21로 변경]  [그대로 두기]  [표에 없음(Dd99)]
```
잘 맞으면(대부분) 아무것도 뜨지 않으므로 조작 부담이 늘지 않는다.

## 4. 데이터 모델

### 4-1. 관계 역전

현재는 반응이 영역에 매달려 있다(`models.py:91` `region_id: unique NOT NULL`).
그래서 자유반응 단계에서 영역을 억지로 그리게 만들었고, 텍스트는 시간 매칭으로
끌어와야 했다(`services.py:535-560` `_extract_examinee_text`).

```python
RorschachResponse                    # 주인 — 자유반응에서 생성
    card_no, response_no
    phase: "free_association" | "inquiry" | "limits_testing"
    is_formal: bool                  # limits_testing은 R 집계에서 제외

    free_association_stt_raw         # STT 원문, 불변
    free_association_text            # 임상가 확정본
    inquiry_stt_raw / inquiry_text
    stt_edited: bool                 # 감사용

    card_orientation: up|down|left|right   # ∧ ∨ < >
    first_utterance_at               # 반응시간 계산용

    ai_coding_json / final_coding_json
        └ location: 단일 부호

RorschachRegion                      # 질문에서 붙는다. 0..N개
    response_id: FK                  # ← 관계 역전
    ref: "D1"                        # 이 조각이 무슨 영역인지
    path_json, color, ...

CardAdministration                   # 신규 — 카드 레벨 사실
    card_no
    status: "responded" | "rejected"  # 미입력과 구분된다
    presented_at, completed_at

ExaminerIntervention                 # 신규 — 검사자 개입
    response_id (nullable), card_no
    phase, kind: prompt|pull|repeat|limits|other
    text
```

### 4-2. STT 원문과 확정본을 나누는 이유

현재 채점은 CDSS 분리를 엄격히 지킨다 — `ai_coding_json` / `final_coding_json` 2컬럼,
주석에 "절대 덮어쓰지 않음"(`models.py:72`). **같은 원칙을 쓰면서 노트만 1컬럼이면
일관성 파괴다.**

세 가지가 걸린다:
1. **CDSS 검토가 승인으로 전락한다.** 검토자가 원본과 대조할 수 없으면 검토가 아니다.
2. **AI 초안 수용률을 측정할 수 없다.** V&V가 반드시 요구할 지표다.
3. **STT가 의료기기 구성요소가 된다.** 분리하면 "임상가가 확정한 텍스트만 의료기기
   데이터"로 격리할 수 있어 V&V 부담이 크게 준다.

### 4-3. 시간 — 폐기하는 것과 남기는 것

v1의 D7("시간 매칭 폐기")은 과했다. 정확히는:

**폐기:** 시간으로 텍스트와 영역을 **잇는 것** (`transcript-match.ts` 전체,
`autoSelectIndices`, `MATCH_PADDING_SEC`)

**남긴다:**
- `CardAdministration.presented_at` — 카드를 건넨 시각
- `Response.first_utterance_at` — 반응 발화 시작

반응시간(R/T)은 **Exner 표준 필수 기록**이다. 카드별 R/T 지연은 그 카드의 자극 특성에
대한 반응이고, 전체적 지연은 심리운동 지연이나 강박적 검토를 시사한다.

그리고 **STT를 쓰면 `first_utterance_at`이 공짜로 나온다.** 아날로그에서 초시계 병행은
부담이라 많은 임상가가 생략하는데, 자동화하면 **아날로그보다 데이터 품질이 올라간다.**
v1은 STT의 이 부가가치를 쓰지 않았다.

PDF 리포트가 타임스탬프를 인쇄하고 있으므로(`report/service.py:252-256`,
`rorschach_report.html:732`) 시간 축을 완전히 없애면 리포트에 빈칸이 생긴다.

### 4-4. Location 부호(1개)와 영역 조각(N개)

Exner CS 채점 가이드:
> Multi-object responses: 각 객체의 Loc을 먼저 보고, **전체 반응에 단일 Loc 부호를 배정한다**
> (1) 전체 블롯이면 W (2) 전부 D면 D, 전부 Dd면 Dd (3) D+Dd → Dd

실제 프로토콜(Hilsenroth 훈련 매뉴얼)에는 `(Dd99=D1+D7+D15)`처럼 적힌다 —
**부호는 `Dd99` 하나, `=D1+D7+D15`는 부기다.** 수백 개 반응 중 location 부호가
2개 붙은 반응은 0건이었다.

| | 개수 | 성격 |
|---|---|---|
| `location` 부호 | **1개** | 채점 단위 |
| 영역 조각(region) | **N개** | 위치도에 그리는 실체 |

**조각을 남기는 이유는 위치도 표시와 임상 기록이다.** (v1은 "ZA/ZD 계산에 공간 배치가
필요해서"라고 썼는데 **현재 코드에서 거짓**이다. `scoring.py:214-222`는 임상가가 고른
`z_score` 라벨로 `Z_TABLE`을 조회할 뿐 공간을 보지 않는다.)

**DQ는 독립 축이다.** DQ+("둘 이상의 대상이 분리되어 있으나 관련됨")는 위치를 쪼개지 않는다.

#### ⚠️ 부호와 조각이 어긋나는 것을 감지해야 한다

새 설계는 두 벌 표를 만든다. 임상가가 조각을 5개 그려놓고 location을 `W`로 골라도,
반대로 W 하나 그리고 `Dd`로 골라도 **아무도 모른다.** 그리고 그 차이는 W:D:Dd, Zf,
DQ 분포를 전부 바꾼다.

**override는 어긋남을 허용하는 장치이지 감지하는 장치가 아니다.**
자동 판정을 안 하는 것은 맞고, 대조를 안 하는 것은 틀리다.

→ 파생 규칙을 **경고 생성기**로 구현한다. 자동으로 바꾸지 말고
"조각 3개인데 location이 W입니다. 확인하세요"를 띄우고, dismiss하면 그 사실을 기록.

**함정:** `D` 부호 자체가 이미 "Table A에 등재된 다중 D 영역"을 포함한다.
**"조각 ≥ 2 → Dd99"로 단순화하면 틀린다.**

**확인 필요:** `LOCATION_CODES`(`coding_codes.py:34`)에 `Dd99`가 없다.
저장은 되지만(location은 `SCORED_GROUPS`에 없어 검증 대상이 아님)
`_split_location("Dd99")`가 `None`을 반환해 **조용히 사라진다.**

### 4-5. `card_no`를 두 곳에 두지 않는다

`Response.card_no`가 생기므로 `Region.card_no`는 **삭제**하고 항상 `response.card_no`로
조회한다. 남겨두면 한 반응의 카드번호와 그 조각의 카드번호가 달라질 수 있다.
(앵커개념-제거.md의 "고를 게 하나면 이름 자체가 필요 없다"와 같은 논지)

### 5-1. 카드 회전 — 단순 누락이 아니다

표기는 `∧`(정위) `∨`(180°) `<` `>`(90°). **반응마다 붙는다** — 같은 카드에서도 다르다.

세 가지가 걸린다:

1. **영역 좌표가 회전에 의존한다.** 피검자가 카드를 뒤집어 본 반응의 영역을 임상가가
   **정위 이미지 위에** 그리면, 좌표는 정위 기준인데 반응은 역위 기준이다.
   **두 좌표계가 갈라지는데 그 사실이 어디에도 안 남는다.**
2. **표준 영역 매칭이 깨진다.** `area-data.ts`가 전부 정위 기준이므로 회전을 모르면
   location 제안이 **체계적으로 틀리고, 틀린 채 그럴듯해 보인다.**
3. **회전 자체가 임상 정보다.** 자주 돌리는 것이 해석 대상이다.

**조작 부담 없이 얻는 법:** UI에서 카드를 실제로 회전시킬 수 있게 하고, **그 회전 상태가
곧 기록이 된다.** 별도로 부호를 고르지 않는다.

**좌표는 항상 정위 기준으로 정규화해 저장한다.** 화면에서 회전 상태로 그렸어도 저장 시
역회전 변환한다. 그래야 좌표계가 하나로 유지된다.

### 5-2. 거부는 "영역 없는 반응"이 아니다

v1이 개념을 잘못 잡았다. **거부는 반응이 없는 것이고, 카드 레벨 사실이다.**

현재는 region이 0개면 거부인지 미입력인지 구분되지 않는다. R은 거의 모든 비율의
분모이므로, 미완성 프로토콜이 완성된 것처럼 구조요약을 낸다.

→ `CardAdministration.status`로 명시. **미설정 카드가 하나라도 있으면 결과 산출을 막는다**(§3-1 게이트).

거부 전에 촉구했는지(`ExaminerIntervention`)가 기록돼야 진짜 거부와 촉구 후 회복이 구분된다.

## 6. 화자 구분 — 제거가 아니라 축소

v1의 D5("화자분리 제거")는 **세 검토자가 모두 반대**했고 근거가 순환적이었다
("임상가가 보며 확인하니 불필요" ↔ 그런데 검사 중엔 화면을 안 봐야 한다).

실질적 문제:
- **질문 단계는 검사자 발화가 절반이다.** 그대로 `inquiry_text`에 들어가면 채점이 지저분해진다.
- **임상가가 마이크에 더 가까워 더 또렷하게 인식된다.** 노이즈가 신호보다 깨끗하다.
- 지울 텍스트가 받아적을 텍스트만큼 생기면 목적에 역행한다.

→ **클러스터링(누가 몇 명인지)은 제거. 검사자/내담자 이진 구분은 유지.**
가장 싼 방법은 **PTT(push-to-talk)** — 내담자가 말할 때만 스페이스바를 누른다.
한 손이라 검사 흐름을 안 끊고 화자 문제가 사라진다.

두 분께 [검토요청 문서](로르샤하-임상가-검토요청.html)를 보내 답을 받았다.

| 2 | 영역 표기 | 가/나 | 나 | ◐ **집계는 범주로 확정 / 입력 UI는 미결** |
| 3 | 검사 중 조작 | 가 | 가 | ⏳ **잠정** — "지금 단계에서는" |

> **⚠️ 확정 도장을 조심할 것.** 재검증(§13)이 가장 위험한 지점으로 지목한 것이
> 틀린 설계가 아니라 **"더 이상 안 물어봐도 된다"고 표시된 항목들**이었다.
> 6항목 중 정말 확정된 것은 1번뿐이고, 2번은 절반, 3·4번은 유보, 5번은 보류다.

### 확정된 것

**1번 — 절차 이해가 맞았다.**
> 카드를 보여주며 "이게 무엇으로 보입니까?" 반응을 받아 적습니다. **10장 완료 후**
> 다시 보여주며 어떤 점 때문에 그렇게 보였는지를 묻습니다. 실제로 자유 연상
> 단계에서는 **영역 위치를 묻지 않습니다.** (임상가1)

§1과 §3-1의 전제가 그대로 유효하다.

**2번 — 번호가 아니라 범주가 채점 단위다.**
> 채점 시 영역과 숫자까지 적는 경우도 있고, `D/Dd/W/DS/DdS/WS`만 적기도 합니다.
> **중요한 것은 뒤의 숫자가 아니라 그 영역을 작성하고 집계하는 것**입니다. (임상가1)

임상가2는 아예 "범주만 적는다"(나)를 골랐다. 두 분 모두 **범주가 집계 단위**라는
데 일치한다 → §2-2의 파싱 수정(`6f15def`)이 맞는 방향이었음이 확인됐다.
번호는 받아주되(임상가1처럼 적는 경우) 집계는 범주로 한다.

한 가지 더 확인됐다: 임상가1이 나열한 여섯은 `D/Dd/W/DS/DdS/WS`로
**소문자 `Dds`가 없다.** 표준 영역 파일에 10건 있는 `Dds`는 별개 범주가 아니라
**데이터 표기 흔들림**이다. 파서가 소문자를 받는 것은 저장된 값을 읽기 위한
처리이지 별개 범주를 인정하는 것이 아니다.

**6번 — 태블릿 전제를 버린다.**
> 임상심리 검사를 하는 전문가 중에는 **정해진 사무실 없이 프리랜서로 근무**하시는
> 분들도 많다는 점을 생각하면 노트북 또는 태블릿 둘 다에 대응할 수 있으면
> 좋지 않을까 생각합니다. (임상가1)

프론트엔드 검토가 우려한 "마우스로 폐곡선 그리기"가 실제 시나리오가 된다.
다만 **영역 지정 방식은 현행(그리기) 유지**로 결정했다 — 표준 영역 선택 방식은
도입하지 않는다.

### 보류된 것

**5번 STT — 두 분 모두 "재보고 판단"**
> 질문단계에서 **실제로 타이핑을 해가며 검사를 진행하기도** 하기 때문에 유용할
> 것이라 생각됩니다. 다만 없는 말을 지나치게 지어낸다면 결국 녹음된 음성과
> 대조해가며 이를 수정해야 해 번거로운 일이 생길 수도 있을 것 같네요.
> **어느 정도로 문제가 일어나는지 확인해보면 좋겠습니다.** (임상가1)

임상가2는 "다"(써보고 판단)만 골랐다.

두 가지가 확인됐다:
1. **질문 단계에서도 타이핑을 한다** — 기록 부담이 자유반응에만 있는 게 아니다
2. 환각 문제를 정확히 이해하고 **실측을 요구**했다 — §10의 0.5단계와 같은 요구

→ STT는 착수순서에서 뒤로 뺀다. **실측이 선행 조건**이다.

### 3·4번은 승인이 아니라 판단 유보다

> **지금 단계에서는** 이 정도로 충분할 것 같습니다. **실 사용하며 더 좋은 의견이
> 나오지 않을까** 싶어요. (임상가1, 3번)
> 마찬가지로 **지금 단계에서는** 충분할 것 같습니다. (4번)

처음에는 이것을 "현 설계로 충분"으로 읽었다. 틀린 해석이다. **임상가는 화면을
아직 안 써봤다.** 종이 기록지를 오래 쓴 사람에게 ASCII 목업 하나를 보여주고
"빠진 게 있냐"고 물으면 "써봐야 알겠다"가 정직한 답이고, 그것을 받은 것이다.

**3번(UI)과 4번(스키마)을 한 문장으로 묶은 것이 더 큰 실수다.** 성격이 다르다:

| | 나중에 고치면 |
|---|---|
| 3번 UI 조작 | 고쳐도 과거 검사가 안 망가진다 → "쓰면서 다듬자"가 맞다 |
| 4번 기록 항목 | **그 전에 실시한 검사에 영구히 빈칸이 남는다** |

4번은 우리가 질문지에 직접 "되돌릴 수 없다"고 써놓은 항목이다.
되돌릴 수 없는 결정을 시한부 승인 위에 세웠다.

#### 4번 재질문 — 목록을 보여주면 안 된다

질문지 4번은 6항목 표를 먼저 보여주고 "빠진 것이 있습니까?"라고 물었다.
이것은 **재인(recognition) 과제**이고, 필요한 것은 **회상(recall) 과제**였다.
목록을 본 사람은 목록 안에서 사고한다.

실제로 그 표에 없는데 빠진 것이 최소 일곱이다(§13 A-2):

| 빠진 것 | 왜 |
|---|---|
| **Popular 판정 근거** | P는 Exner 표의 함수인데 체크박스로 받고 기본값 False → 안 누르면 P=0이 유의미한 값처럼 SCZI/PTI에 들어간다 |
| **연령별 규준** | DEPI/CDI/PTI 컷오프가 아동·성인이 다른데 단일 컷오프다. 아동에 성인 기준을 쓰면 위양성이 쏟아진다 |
| **실시 방식** | §1이 카드별 질문 편차를 짚어놓고 기록할 자리를 안 만들었다 |
| 총 소요시간 / 카드별 체류시간 | 반응잠재시간과 다른 지표다 |
| 검사 조건 메타 | 회차, 협조도, 안경, 보호자 배석, 약물 |
| 통역 개입 | verbatim 채점의 성격이 달라진다 |
| 재검사 링크 | 2회차는 1회차와 비교해 해석한다 |

→ 재질문은 목록 없이 한다: **"쓰시는 기록지 양식을 한 장 보내주십시오"**
(내담자 정보는 지우고). 두 분 것을 받아 합집합을 뜬다.

### 2번은 절반만 확정됐다

집계 단위가 범주라는 데는 두 분이 일치한다. 갈린 것은 **번호를 채점표에
적느냐**다 — 임상가2는 "번호는 위치도에만"이므로 채점표에 번호가 없다.

이것이 UI 결정을 가른다: 임상가2 방식이면 location 칸이 **6개 드롭다운**이어야
하고, 임상가1 방식이면 자유 텍스트여야 한다. 현재는 자유 텍스트다.

→ **번호를 옵셔널 부기로 받는 구조**(범주 선택 + 번호 입력 옵션)면 둘 다 만족한다.
입력 UI는 미결로 남긴다.

**실 데이터가 두 방식을 다 보여준다:** 번호 포함 43건, 범주만 13건.
그리고 **같은 날짜에 두 표기가 섞여 있다** — 한 사람이 그때그때 다르게 적는다는
뜻이다(임상가1의 "적는 경우도 있고"와 일치).

`Dds` 소문자 논거는 **표준 영역표(371개 파일)로 바꿔 쓴다.** 임상가1의 자유서술에
없다는 것은 n=1의 부재이지 근거가 아니다. 결론(별개 범주가 아님)은 맞다.

## 14. 화면 통합 (v5, 2026-08-24)

피드백에서 출발했다. 발단은 세 가지였다 — **화면이 너무 비슷하다**,
**우측 패널이 굳이 필요한가**, **AI 제안과 임상가 선택이 구분되지 않는다**.
파고들자 마지막 항목이 UI가 아니라 **CDSS 원칙이 깨진 자리**로 드러났다(§14-4).

### 14-1. 스텝 4개 → 3개

```
v4:  [자유반응]  [질문]  [채점]  [결과 🔒]
v5:  [   실시   ]        [채점]  [결과 🔒]
```

자유반응과 질문을 **한 화면**으로 합친다. 채점은 그대로 둔다.

**"두 바퀴"는 유지된다.** 화면이 순서를 강제하지 않고 임상가가 표준대로
1바퀴(카드 I~X 자유반응) → 2바퀴(다시 카드 I부터 질문)를 돈다. 이미 벽이
없으므로(§3-1) 구조상 지원된다.

⚠️ **타당도 메모:** 카드별로 자유반응+질문을 섞으면(카드 I 반응 → 즉시 카드 I 질문)
피검자가 방어적이 되어 R이 줄고, R은 거의 모든 Exner 지표의 분모다. §3-2가
"UX 선택지가 아니다"라고 못 박은 지점이다. **다만 CTO가 "타당도는 그렇게 고려하지
않아도 된다"고 명시**했다 — 화면 통합은 진행하되 위험은 여기 남긴다.

### 14-2. 반응 = 채점지의 한 줄

v5의 중심 개념이다.

> **반응은 채점지 한 줄이고, 그 줄의 칸(자유반응 텍스트 / 질문 답변 / 위치 /
> 방향 / 채점 코드)은 언제든 아무 순서로나 채울 수 있다.**

이 때문에 **"자유반응 모드 / 질문 모드"라는 축은 폐기한다.** 모드가 둘이라는 건
"지금은 이 칸만 채울 수 있다"는 뜻이고, 위 정의와 모순이다.
**§3-1의 "벽 없음"이 스텝 사이에서 반응 내부로 내려온 것**이다.

남는 모드는 하나뿐 — **누가 화면을 보느냐**:

| 모드 | 화면 | 상황 |
|---|---|---|
| 내담자 | 카드만. 탭·페이저·번호·개수 전부 숨김 | 태블릿을 피검자 쪽으로 돌릴 때 |
| 임상가 | 전체 | 검사자가 기록할 때 |

이유: 피검자가 이전 반응("박쥐 같아요")을 보면 다음 반응이 오염된다.

**카드 넘기기 화살표는 내담자 모드에 남겨도 된다.** 오염 요인은 반응 내용이지
진행 UI가 아니고, 실물 검사에서도 검사자가 카드를 집는 동작은 다 보인다.
단 **번호(`3/10`)와 반응 수 배지는 금지** — 실물 카드 뭉치에 없는 정보이고,
피검자가 페이스를 계산하게 만든다.

### 14-3. 레이아웃 — 우측 패널을 버린다

**왜 세 화면이 같아 보였나:** 화면 면적의 80%가 세 번 다 같은 카드 그림이고,
바뀌는 건 우측 `w-100` 패널뿐이었다. **변화가 잘못된 곳에서 일어났다.**

패널의 정당성도 화면마다 다르다. 채점의 녹취록은 **대조하며 계속 봐야** 하므로
정당하다. 반응 목록은 **입력할 때만** 필요하다 — 내담자 모드에서 통째로 사라진다는
사실 자체가 "항상 필요한 게 아니다"를 이미 인정한 것이다.

```
┌─────────────────────────────────────────────────────┐
│ ← 나가기   실시                    [내담자 모드]     │  헤더: 화면 전체
├─────────────────────────────────────────────────────┤
│  I  II  III  IV  V  VI  VII  VIII  IX  X            │  카드 선택
│                                 [거부] [촉구]        │  + 이 카드에 대한 기록
├─────────────────────────────────────────────────────┤
│                                                     │
│                    카드 (전체)                       │
│              [팝오버 — 이 반응의 전부]                │
│                                                     │
│         ◀  ③/5  ▶        + 새 반응            🎤    │  반응 이동/추가
├─────────────────────────────────────────────────────┤
│  R 22 · 미완: 카드 III ②          [채점으로 →]       │  진척 + 단계 전환
└─────────────────────────────────────────────────────┘
```

**팝오버는 채점 화면에서 이미 검증됐다.** 영역 bbox 기준 좌/우 자동 배치 +
viewport 클램프 + 드래그 이동(`RegionPopover.svelte`). 하나만 뜨므로 반응이
8개든 20개든 크기가 변하지 않는다.

⚠️ **`pos`가 `region.path.length === 0`이면 `null`을 반환한다** — 영역이 없는
반응은 팝오버가 아예 안 뜬다. 실시 화면에서는 그게 정상 상태이므로 대체 앵커가 필요하다.

**목록 대신 페이저(`◀ ③/5 ▶`).** 8개든 20개든 크기가 안 변하고, 카드 위에
반투명으로 얹어 세로 공간을 뺏지 않는다. 대부분의 시간 동안 손잡이는 하나면
충분하다 — 1바퀴는 방금 만든 반응만, 2바퀴는 ①→②→③ 순서대로다.
`③/5`를 누를 때만 전체 목록이 드롭업으로 펼쳐진다.

**골격이 갈라진다:** 실시는 상하(카드/페이저), 채점은 좌우(카드|녹취록),
결과는 표 중심. "또 이 화면"이 구조적으로 해소된다.

### 14-4. ⚠️ AI 초안이 임상가 확인 없이 확정된다 — CDSS 위반

"AI 제안과 임상가 선택이 구분되어 보여야 한다"는 피드백을 따라가자 **같은 문제의
앞뒷면 두 개**가 나왔다.

**프론트** (`CodingPanel.svelte:59-63`):
```js
if (finalCoding)      local = structuredClone(finalCoding)
else if (aiCoding)    local = structuredClone(aiCoding)   // ← AI 값이 임상가 칸에 미리 앉는다
```
화면상 "임상가가 W를 골랐다"와 "AI가 W라 했고 임상가는 아직 안 봤다"가 **똑같이 보인다.**

**백엔드** (`services.py:1372-1374`):
```python
if response.final_coding_json is None:
    response.final_coding_json = response.ai_coding_json   # ← 자동 승격
```
임상가가 한 번도 안 본 AI 초안이 확정 코딩이 된다. 확정 후에는 **누가 채웠는지
구분할 수도 없다** — 감사추적 구멍이기도 하다.

실데이터: 정식 반응 114건 중 `final_coding` 56건, **AI 초안만 있고 미확인 4건.**

**규칙을 이렇게 고친다:**

| | 규칙 |
|---|---|
| 반응 완료 | `final_coding_json IS NOT NULL` — 임상가가 저장을 눌러야 채워진다 |
| 확정 가능 | **모든 정식 반응**이 완료 (영역이 아니라 반응을 순회) |
| 결과 보기 | 확정 완료 (현행 유지) |

AI 자동 승격은 **제거**한다. 미확인 반응이 있으면 카드·반응 번호를 대며 거부한다.

**프론트 `canConfirm`도 축이 틀렸다** (`Review.svelte:314-323`) — region을 순회해서
**영역 0개인 반응(실데이터 7건)이 아예 안 세어진다.** `GetStructuralSummary`가
`continue`로 조용히 skip하던 것과 같은 계열의, 반응 축으로 안 옮긴 잔재다.
서버(`ConfirmSession`)는 이미 §7에 따라 반응을 순회한다 — 프론트만 뒤처져 있다.

### 14-5. 정보 군집 — 성질이 자리를 정한다

같은 성질의 것끼리 뭉쳐야 한다. 지금은 푸터 한 줄에 네 종류가 섞여 있다:

| 버튼 | 성질 | v4 위치 | v5 위치 |
|---|---|---|---|
| 거부·촉구 | 지금 이 카드에 대한 **기록** | 푸터 | **카드 탭 줄** |
| 이전/다음 카드 | 이동 | 푸터 | **삭제** (탭이 이미 한다) |
| 완료 | **단계 전환**, 되돌리기 어려움 | 푸터 | 푸터 (혼자) |

**"촉구"(기록) 옆에 "완료"(단계 전환)가 붙어 있는 게 가장 나쁘다** — 실수 비용이
전혀 다른 두 버튼이 같은 크기, 같은 줄, 인접한 자리에 있다.

거부·촉구는 **"지금 이 카드"에 대한 행위**이므로 카드를 고르는 줄에 있어야 한다.
지금은 카드를 위에서 고르고 그 카드에 대한 행동은 맨 아래에서 해서, 눈과 손이
화면 세로 전체를 왕복한다.

**한 반응의 정보가 세 곳에 흩어져 있다** — 그리기 버튼은 카드 좌상단,
부호 메뉴는 영역 위, 나머지 채점은 팝오버 안. 팝오버 하나로 모은다:

```
┌──────────────────────────────┐
│ ③ 반응                    ✕  │
│ 자유반응  [박쥐 같아요      ] │  ← 무엇을 봤나
│ 질문답변  [날개가 펴져…     ] │
│ ─────────────────────────── │
│ 위치   (•)D ( )W ( )Dd  [6]  │  ← 어디를 봤나
│        [x] 공백(S)     = DS6 │
│        [영역 그리기]          │
│ ─────────────────────────── │
│         AI (72%)    임상가    │  ← 어떻게 채점하나
│ DQ       o          [  ]     │
│ 결정인   F,FC       [  ]     │
└──────────────────────────────┘
```

`[영역 그리기]`를 팝오버에 두면 손이 카드로 한 번 더 이동하지만,
**정보 군집이 이긴다** — 그리기 모드에 들어가면 카드 전체가 판이 되므로
손 이동은 어차피 한 번이다. 그리기 중에는 팝오버를 반투명하게 한다.

### 14-6. Q8 해소 — location 입력 UI

**W/D/Dd 라디오 + 번호 + 공백(S) 체크박스.** 저장은 `DS6` 문자열 한 덩어리.

`parse_location`(`coding_codes.py:152`)이 이미 `DS5 → ('D', True)`로 쪼개주고,
구조요약은 범주만 세며, 번호는 `area_code`가 정본으로 보관한다.
**저장은 한 덩어리, 해석은 쪼갬** — 구조가 이미 맞다.

체크박스가 자유입력보다 나은 이유: `SD6`·`D6S`·`S` 단독 같은 잘못된 형태가 애초에
만들어지지 않는다. 지금 정규식이 막긴 하지만, 막히고 나서 임상가가 **왜 안 되는지
알 방법이 없다.** 그리고 S가 **붙는 것**이라는 개념이 UI에 그대로 드러난다.

### 14-7. `area_code`를 조각에서 반응으로 올린다

§4-4가 "부호는 반응당 1개"로 정해놨는데 스키마는 조각마다 `area_code`를 갖는다.
백엔드는 그 모순을 **임시방편으로 봉합**하고 있었다 (`services.py:1039`):

```python
# 부호는 반응당 1개다(§4-4). 조각 중 area_code가 있는 첫 값을 쓴다.
area_code = next((g.area_code for g in regions if g.area_code), None)
```

조각 2개에 서로 다른 부호를 넣어도 **아무도 막지 않고, 조용히 하나만 채점에 쓰인다.**
나머지는 화면엔 보이는데 채점엔 안 들어간다 — §4-4가 경고한 "어긋나도 모른다"가
실제로 구현돼 있는 자리다.

| | v4 | v5 |
|---|---|---|
| `regions.area_code` | 조각마다 (충돌 가능) | **삭제** |
| `responses.area_code` | 없음 | **신설** — 이 반응의 위치 부호, 1개 |
| 반응당 조각 수 | 0..N | **0 또는 1** (서버가 강제) |

**임상적 근거:** Exner에서 위치 부호는 언제나 1개이고, **그 부호가 가리키는 영역도
하나다.** 표준 영역(Table A)의 `D1`처럼 떨어진 두 덩어리를 포함하는 영역이 이미
있으므로 그런 경우도 조각 하나다.

한 반응 안에서 "여기는 날개, 여기는 몸통"처럼 부분을 나눠 보는 것은 **위치를
쪼개는 것이 아니라 DQ(발달질)와 내용의 문제다** — `DQ+`가 "둘 이상의 대상이 분리되어
있으나 관련됨"이고, §4-4가 이미 "DQ는 독립 축이다"라고 못 박았다.

> ⚠️ 초안에서 "한 위치를 여러 획으로 그린다"며 조각 N개를 유지하려 했는데
> **틀렸다.** 프리핸드로 못 그리는 것은 도구의 제약이지 임상 개념이 아니다.
> 도구 제약을 데이터 모델에 새기면 안 된다.

**다시 그리면 기존 것을 대체한다.** 거부하지 않는 이유는 "고쳐 그리기"가 정상
동작이기 때문이다. 조각이 쌓이면 어느 것이 이 반응의 위치인지 알 수 없게 된다.

실데이터: 반응당 영역 0개 7건 / 1개 107건 / 2개 이상 0건. `area_code` 105건 이관.

**이관이 드러낸 것:** 확정 코딩이 있는 56건 중 **3건이 조각과 부호가 어긋나 있었다**
(`Dd23`을 그려놓고 코딩은 `W`). §4-4가 경고한 "아무도 모른다"의 실제 사례다.
값이 한 자리에 모였으므로 앞으로는 생길 수 없다. 기존 확정본은 건드리지 않는다.

⚠️ 그리기 버튼(`CardCanvas.svelte:341`)의 `selectedRegionId === null` 조건은
**그대로 두면 된다.** 두 번째 조각을 그릴 일이 없다.

### 14-8. 채점 패널 — 접기·복원 제거, 근거는 조건부

**코딩 접기 폐기.** 접기가 하는 일이 팝오버 닫기의 부분집합이고, 드래그 이동이
있으므로 "가려서 접는다"는 이유도 사라졌다.

**"AI 채점 복원" 폐기.** 세 가지 이유:
1. AI 열이 항상 옆에 보이면 되돌릴 것이 없다 — 그 값을 다시 고르면 된다
2. 파괴적인데 되돌릴 수 없다 (임상가가 5개 고쳐도 확인창·undo 없이 전부 날아간다)
3. **방향이 거꾸로다** — CDSS는 AI 초안 → 임상가 수정인데, 이 버튼은 임상가 판단 → AI 회귀다

**AI 근거는 조건부로 되살린다.** 지금 `CodingPanel.svelte:358-364`에 **주석 처리**돼
있는데, 이유는 Mock이 쓸모없는 문자열을 내놓기 때문이다:
```
발화: 나비 | 핵심: 나비                              ← 임상가가 이미 보는 텍스트 반복
[Mock] 카드 1, 응답 3 — AI 채점 API 미연동 상태에서…  ← 내부 사정 안내
```
판단은 옳았지만 **주석은 나쁜 보관 방법이다** — 왜 꺼졌는지, 언제 켜야 하는지
아무도 모른다. `isPlaceholderReasoning()`으로 걸러 **AI팀 서버가 붙는 날 저절로
켜지게** 한다. 그때까지는 **confidence만 항목 옆에 표시**한다.

### 14-9. 한계검증 — 이번 범위에서 제외

표준 절차가 다 끝난 뒤 평범반응이 안 나온 카드를 다시 제시해 직접 묻는 선택적
절차다. **채점에 들어가지 않는다**(`is_formal=false`) — 유도된 반응이라 규준
비교가 깨지기 때문이다. 스키마·백엔드 필터는 이미 있고 화면 진입점만 없다.

**복잡도만 늘어나므로 이번엔 만들지 않는다.** `is_formal` 컬럼과 R 계산 필터는
그대로 둔다. 나중에 필요해지면 자리만 만들면 된다.
⚠️ 만들 때 **거부·촉구와 같은 줄에 두면 안 된다** — 시점이 다르다(검사 중 vs 검사 후).
같은 줄에 두면 검사 도중 한계검증을 하도록 유도하는 셈이고, 그건 절차 오염이다.

### 14-11. `collect_done` — 의미를 넓힌다

`rorschach_collect_done`(`progress.py:41`)은 `ended_at is not None` 하나만 본다.
그런데 `CompleteSessionService`는 **아무것도 검사하지 않고** `ended_at`을 찍는다 —
버튼을 눌렀다는 뜻이지 내용이 채워졌다는 뜻이 아니다.

스텝이 합쳐지면 이 플래그는 **"실시 전체 완료"**를 뜻해야 한다:
> 10장 전부 `responded` 또는 `rejected` **AND** 모든 정식 반응이 영역 ≥1개 + `inquiry_text` 보유

**이름은 그대로 둔다** — `collect`는 progress·URL·`StepKey`가 이미 쓰는 어휘이고,
뜻이 넓어질 뿐이다. 판정은 1번의 `completion.py`가 한다.

**미입력(pending)을 통과시키면 안 된다.** "안 물어본 카드"와 "물었지만 반응이 없던
카드"가 같아지는데, 그 둘은 R 판정에서 다르게 취급돼야 한다.

### 14-12. 누락 없는 기록 — 무엇이 안전장치인가

화면을 합치면 **자유반응 완료 게이트가 사라진다.** v4에서는 "10장 전부 실시"를
통과해야 질문으로 넘어갔다. 합치면 카드 III을 통째로 빠뜨린 채 채점으로 갈 수 있고,
R이 줄면 Exner 지표 전부가 틀어진다.

칸을 아무 때나 채울 수 있게 한 이상(§14-2), **안 채운 칸을 보여주는 것이 유일한
안전장치**다. 셋 다 있어야 한다:

1. **반응 줄마다 미완 칸 표시** — 영역/질문/텍스트 칩 (`Inquiry.svelte:494-518`이 이미 함)
2. **카드 탭 3색** — 회색(미실시) / 파랑(반응 있음·미완) / 초록(완료).
   **탭만 보고 빠뜨린 카드를 찾을 수 있으면 게이트보다 강하다**
3. **푸터가 미완 카드 이름을 직접 댄다** — 반응 25개 중 하나가 빠졌을 때
   버튼만 비활성이면 찾을 방법이 없다. 게이트가 벽으로만 작동하면 안 된다

#### 색 — `responseColor(response_no)`가 단일 출처

카드 안 번호 기준 8색. 카드마다 1번=파랑으로 고정돼 눈이 한 번만 학습하면 된다.

⚠️ **`region.color`(DB 저장값)는 아무도 안 읽는다.** 그릴 당시 규칙이 박제된
값이라 팔레트를 바꾸면 옛 조각만 옛 색으로 남는다(실제로 기존 조각이 전부
`#3B82F6`이었다). 색은 번호에서 **파생**시켜야 두 곳이 어긋날 수 없다.

**칩만 완성도를 겸한다**(미완=회색, 완료=반응색). 폴리곤·팝오버는 항상 반응색이다.
비일관이 아니라 **색이 하는 일이 자리마다 달라서**다 — 폴리곤은 카드 위에 겹쳐
그려지므로 구분이 임무이고(팔레트의 원래 목적), 칩은 줄에 번호순으로 나열돼 겹치지
않는다. "미완이면 전부 회색"은 검토 후 기각(2026-08-25). 팝오버 테두리는 **폴리곤
색의 파생**이므로, 규칙을 바꾸려면 폴리곤만 바꾼다.

#### 받아쓰기 — 마이크는 질문 칸에만

팝오버의 **자유반응 칸에는 마이크가 없다.** 팝오버는 지난 반응을 고치려고 열 때가
많은데, 그 상태로 받아쓰기를 켜면 **지금 말하는 다른 반응의 말이 그 칸에 들어간다.**
자유반응은 R을 결정하는 원자료라 오염 비용이 크다. 질문 답변은 그 반응을 놓고 지금
대화하는 중이라 시점이 어긋나지 않는다.

자유반응을 음성으로 받는 정본 경로는 **내담자 화면의 탭 + 툴바 받아쓰기**다. 거기는
도착 순서가 아니라 **시각으로 주인을 찾는다**(`routeClip`) — 검사자 탭이 항상 전사보다
빠르므로 순서로 붙이면 모든 반응이 이전 반응의 말을 갖는다.

마이크를 하나로 줄이면서 버그 둘이 함께 사라졌다: 녹음 중 다른 칸 마이크를 누르면
`toggle()`이 그냥 껐던 것, `phase`가 두 칸에 똑같이 흘러 어느 칸에 받아쓰는지
화면이 구분하지 못했던 것. **마이크 2개 : dictation 1개**가 원인이었다.

#### 반응 번호 — 저장하지 않고 파생시킨다 (2026-08-25)

`response_no`는 저장 컬럼이었고 삭제가 재배열을 안 했다. **1번을 지우면 화면에
2,3만 남고**, 다음에 추가하면 `max+1`이라 1번은 영영 안 돌아온다.

근본 원인은 "카드 내 순번"이 **두 곳**에 있었던 것이다 — 그 컬럼과, 살아 있는
행들의 실제 순서. 삭제가 둘을 갈라놓는다. 실데이터에서 이미 벌어져 있었다
(카드 60개 중 5개에 결번, 그중 하나는 **중복** `[…,10,10,11]`).

**중복이 결번보다 나쁘다** — `ORDER BY response_no`가 비결정적이 되어 표시 번호가
새로고침마다 바뀔 수 있었다.

| | |
|---|---|
| DB `sort_seq` | **정렬 서열.** 뒤에 붙이기만 하고 삭제해도 안 고친다. 간이 벌어진다 |
| API `response_no` | **화면 번호.** 살아 있는 반응을 세어 매번 1..n으로 파생 |

파생은 `completion.display_numbers()` **한 곳**에서만 한다. API DTO도 오류
메시지도 AI 채점 입력도 전부 여기서 받는다 — 화면엔 "반응 2"인데 오류 메시지엔
"반응 3"이 뜨면 임상가가 어느 반응인지 못 찾는다. 정렬은 `sort_seq → created_at
→ id`로 완전히 고정했다.

이름을 바꾼 이유: `r.sort_seq`를 표시 번호로 착각할 수 없게 하려는 것이다.
마이그레이션 `s0rtseq01`이 이름 변경 + 기존 값 1..n 정리를 함께 한다
(백업 `.backup/rorschach-responses-pre-sortseq-20260825.sql`).

⚠️ 채점 결과는 안 바뀐다 — R은 `len(codings)`로 세지 `max(response_no)`를 안 쓴다.
⚠️ **중간 삽입은 여전히 안 된다.** 지금도 `max+1` 뒤에 붙기만 한다. 필요해지면
   순서 바꾸기 기능을 따로 만들 것.

#### 14-16. 임상 규칙에는 코드 밖 출처가 있어야 한다 (2026-08-25)

기술 규칙과 임상 규칙은 **틀렸을 때 알 방법**이 다르다. 이 차이를 뭉개면
"단일 출처"라는 말이 임상 층에서는 헛돈다.

| | 정본이 어디 있나 | 틀리면 무엇이 잡나 |
|---|---|---|
| 기술 규칙 | 코드 안 (`responseColor`, `display_numbers`, `completion.py`) | 테스트·검사 스크립트 |
| 임상 규칙 | **코드 밖** (Exner 워크북) | 원전 대조 — 이것 말고 없다 |

**그래서 규칙이다:**

> 임상 규칙을 구현할 때는 **출처를 코드 주석에 적는다**(책·장·표·쪽).
> 출처를 못 적으면 그 규칙은 잠정이고, 잠정 규칙은 임상가 검토 목록에
> 등재된 채로만 산다. **기억으로 구현하지 않는다.**

이 규칙은 대가를 치르고 얻었다. GHR/PHR(§13 E-3)을 원전 없이 기억으로
구현했고, 테스트 42건을 붙여 통과시켰다. 그런데 그 테스트는 "구현이 **내가
생각한** 규칙대로 도는가"만 고정할 뿐이었다.

원전(워크북 110~111쪽)을 대조하니 **7단계 판정 규칙은 전부 맞았지만 판정
대상 준거가 틀렸다** — 준거 3은 "COP나 AG를 포함하는 **FM반응**"인데 `m`
(무생물운동)까지 넣어, 사람이 개입하지 않은 움직임이 인간표상으로 잡혀
GHR:PHR의 분모가 부풀었다. 테스트 42건 중 어느 것도 이걸 못 잡았다.

**더 나쁜 점은 방향이었다.** `"?:?"`(눈에 보이는 모름)를 숫자(눈에 안 보이는
가정)로 바꾼 것이라, 임상가가 오히려 더 믿게 되는 값이 된다. R<14 봉인이
"해석 불가를 값으로 내보내지 않는다"는 원칙을 이미 세워놨는데, 그 원칙을
어긴 셈이다.

**대조로 얻은 것:**

- 워크북이 제시한 **예시 4개(111쪽)를 그대로 테스트로 박았다.** 우리 해석이
  아니라 책이 답을 적어둔 것이라, 깨지면 기대값이 아니라 구현이 틀린 것이다.
- 5단계 카드 목록(III·IV·VII·IX)이 **왜 그 넷인지** 알게 됐다 — 평범반응 표
  (〈표 5-2〉)에서 인간표상이 평범반응인 카드가 정확히 그 넷이다. 자의적인
  목록이 아니라 다른 표에서 따라 나오는 값이다.
- 평범반응 13개를 `coding_codes.py`에 **출처와 함께** 넣었다(E-2의 토대).

⚠️ 아직 잠정인 것: **내담자 화면 카드 번호 표시**(§14-14). "실물 도판 뒷면에
로마숫자가 있다"는 전제로 기존 금지 결정을 뒤집었는데, 그 전제는 원전으로
확인하지 않았다. 임상가 검토 목록에 올린다.

### 14-15. 부호 어휘가 새던 구멍 (Q11, 2026-08-25)

임상가 저장 경로에는 계약 검증이 있었는데(`CodingUpdateRequest._known_codes_only`)
**AI 초안 저장 경로에는 없었다.** `_scoring_to_coding_dict`가 AI 출력을 그대로
jsonb에 넣었다.

그 구멍으로 옛 목업이 만들던 `INC1`(INCOM1 오타)·`M`/`FM`/`ma`(능동·수동 접미사
누락)가 들어와 **확정 검사 4건에 굳었다.** 목업 자체는 이미 고쳐져 있었다
(`remote.py:200` 주석이 이력을 남겼다) — 남은 건 그때 새어 들어온 데이터였다.

**왜 심각한가.** 채점은 부호를 이름으로 읽으므로 철자가 다르면 **에러 없이 그
지표만 0이 된다.** `INC1`은 Sum6에서, `M`은 SumM·EB·Ma:Mp·GHR/PHR에서 통째로
빠진다. 영역 부호 43건이 집계에서 사라졌던 것과 같은 종류다.

| 조치 | |
|---|---|
| AI 초안 경로에 필터 (`_keep_known`) | 모르는 부호를 거르고 **무엇을 버렸는지 로그에 남긴다** |
| 확정 검사 4건 soft delete | 사용자 결정. 전부 R<14 폐기 데이터(같은 테스트 내담자) |
| `scripts/audit_coding_codes.py` | 저장된 코딩 전수 검사. 위반 시 종료코드 1 |

⚠️ **추측해서 고치지 않는다.** `INC1 → INCOM1`은 맞혀볼 수 있지만 `M`은
`Ma`/`Mp`/`Ma-p` 중 무엇인지 알 수 없다 — 능동·수동은 임상 판단이고, 잘못 찍으면
틀린 값이 **맞는 것처럼** 저장된다. 모르는 건 버린다.

⚠️ **거르는 것도 무해하지 않다.** `['M','F'] → ['F']`는 그 반응을 순수형태
반응으로 만들어 **Lambda가 바뀐다.** AI 초안에서 이걸 허용한 것은 그게 초안이고
§14-4에 따라 임상가가 직접 채택해야 하기 때문이다. 확정본에는 절대 적용하지 않는다.

#### 팝오버 위치

조각이 없는 반응(= 방금 만든 반응)은 **카드 왼쪽 위**에 띄운다. 한동안 카드 중앙에
띄웠는데 그게 정확히 최악의 자리였다 — `.card-box`는 16:9인데 잉크 bbox는 그보다
좁아(가운데 ~64%) 반점이 늘 한가운데 있다. 조각이 있으면 조각 **반대쪽**에 붙인다.

⚠️ 왼쪽 위도 반점 가로폭의 1/3쯤은 덮는다. `.card-box`가 `width:100%`라 팝오버를
놓을 바깥 여백이 구조적으로 없다. 실측 후 폭 축소(360→300)나 접힌 상태로 열기를
검토할 것.
