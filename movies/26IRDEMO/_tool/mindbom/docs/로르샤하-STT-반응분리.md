# 로르샤하 STT — 반응 경계를 무엇이 정하는가

> 2026-08-25 논의 기록. **결론 없음 — 선택지와 제약만 정리한다.**
> 상위 문서: `로르샤하-프로세스-재설계.md` (§3-3 STT · §12 Q1 · §10 S-1~S-3)

---

## 발단

> 애들같은 경우는 막 빠르게 동시에 보이는것들을 여러개 얘기한다

아동 프로토콜에서 `"박쥐! 나비! 꽃!"`이 1~2초 안에 쏟아진다. 지금 구조는
**검사자의 탭이 반응 경계**라 이 상황에서 셋 다 기록되지 않는다.

세 군데가 동시에 무너진다:

| 자리 | 무슨 일이 | 결과 |
|---|---|---|
| 400ms 쿨다운 | 세 번 눌러도 두 번만 통과 | **R이 준다** |
| VAD (1200ms 침묵) | 쉼 없는 발화는 한 조각 | 반응 3개가 한 줄에 |
| 화면 | 어느 쪽도 신호가 없다 | **조용히 틀린 R로 채점까지 간다** |

R은 거의 모든 Exner 지표의 분모다. 이건 UI 불편이 아니라 **데이터 무결성**이다.

---

## ⚠️ 폐기된 안 — "침묵으로 한 번 더 가른다"

전사 조각 **안에서** 침묵 간격(예: 1.5초)을 찾아 반응을 쪼개자는 안이 나왔다가
그 자리에서 폐기됐다. **성립하지 않는다:**

- VAD가 이미 **1200ms 침묵으로 조각을 끊는다**(`dictation.svelte.ts`의 `SILENCE_MS`).
  그러면 조각 안에 1.2초 넘는 침묵은 **존재할 수 없다** — 1.5초 기준은 영원히
  발동하지 않는다.
- 더 짧게(0.8초 등) 잡으면 이번엔 `"박쥐 같아요… 날개가 펴져서"`를 쪼갠다.
  주석이 경고한 바로 그 함정이고, **R 과다는 R 과소만큼 나쁘다.**

> **침묵 축은 VAD가 이미 다 썼다. 이중으로 쓸 수 없다.**

애초에 발단을 보면 더 분명하다 — 문제가 되는 것은 **침묵이 없는 발화**다.
침묵이 있었다면 VAD가 이미 나눠서 지금도 반응 3개가 됐을 것이다.

같은 이유로 whisper 세그먼트 타임스탬프도 큰 도움이 안 된다. 조각 내부 타이밍은
VAD가 한 번 거른 뒤라 경계 정보가 별로 남아 있지 않다.

**남는 신호는 의미뿐이다.**

---

## 그래서 SLM

`"박쥐 같아요, 날개가 펴져서"`(반응 1개)와 `"박쥐. 나비. 꽃"`(반응 3개)은
문장 수로 못 가른다. 의미로 가려야 한다.

### 지켜야 하는 선

**분리 결과는 초안이다.** 분리 = R을 정하는 행위이고, R은 분모다. AI가 R을
확정하면 §14-4에서 고친 CDSS 위반이 되돌아온다.

다만 **교정 경로는 이미 다 있다** — 반응 추가·삭제·텍스트 편집. 3개로 쪼갰는데
2개면 하나 지우고 합치면 되고, 뭉쳤으면 추가해서 나누면 된다. 전용 병합/분리
UI를 새로 만들 필요는 없다. (논의 중 그걸 필수 선행으로 오판했다가 정정했다.)

R을 바꾸는 편집이므로 §13 D-1의 확인·이력은 그대로 붙는다.

## 배치 위치 — 네 갈래

### 지금의 사실

- **오디오가 이미 OpenAI로 나간다.** `whisper-1`을 OpenAI Audio API로 호출한다
  (`app/infrastructure/openai/`). 의존성은 `openai>=2.32.0` 하나.
- **GPU가 없다.** "현 배포는 `python:3.11-slim` + `--workers 2`"(§3-3).
  CPU 배치 RTF 0.45 기준 15초 발화 ≈ 7초.

| 안 | 비용 | 품질 | 규제(오디오 유출) | 걸리는 점 |
|---|---|---|---|---|
| **A. OpenAI 추가 호출** | 전사비의 ~1% | 높음 | 이미 나감 (변화 없음) | 공짜는 아니다 |
| **B. 로컬 SLM만** | 0 | ? | **이득 없음** — 오디오는 이미 나갔다 | 텍스트만 로컬로 지키는 셈 |
| **C. AI팀 요청** | 우리 쪽 0 | AI팀 구현에 달림 | 조직 내부 | AI팀 서버 대기 |
| **D. 로컬 whisper + 로컬 SLM** | 0 | ? | **완전 차단** | GPU 없음 · 선행 실측 미완 |

**C가 원래 설계에 제일 가깝다** — `CLAUDE.md`의 AI API 표에 이미
`POST /api/rorschach/transcribe`가 AI팀 몫으로 잡혀 있다. 거기에 "반응 분리"를
얹어 달라고 요청하는 형태.

**D가 규제 축에서 제일 깨끗하다** — C-2(local-first 파기 정책)와 Q1이 한 번에
풀린다. 대신 아래 선행 조건이 남아 있다.

> **B는 실익이 거의 없다.** 원본 음성을 이미 외부로 보내면서 그것을 받아적은
> 텍스트만 로컬에서 쪼개는 것이기 때문이다. 로컬 SLM은 **D의 일부일 때만**
> 의미를 갖는다.

### 참고 — 로컬 모델을 의존성으로 넣는 경우

`llama-cpp-python`을 `pyproject.toml`에 넣을 수는 있지만 **모델 가중치는 의존성으로
따라오지 않는다.** GGUF 파일(1.5B 기준 1GB 안팎)은 별도 다운로드라 배포 이미지
크기와 첫 실행 지연을 따로 봐야 한다.

## 선행 실측 (§10 S-1~S-3 + 새 항목)

문서는 이미 못박고 있다: **"두 숫자가 긍정적일 때만 §3-3을 구현"**, 그리고
실검사 녹음은 임상가께 요청해야 한다.

이번 논의로 잴 것이 하나 늘었다:

| # | 측정 | 실녹음 필요? | 지금 가능 |
|---|---|---|---|
| S-1 | whisper 정확도(CER) · **환각 건수** | ✅ | ✗ |
| S-2 | 스톱워치 A/B (STT 보정 vs 타이핑) | ✅ | ✗ |
| **S-5** | **SLM 반응 분리 품질** | ✗ | ✅ |
| — | whisper 속도(RTF) — 현 서버 사양에서 | ✗ | ✅ |

**S-5는 오늘 할 수 있다.** 분리는 텍스트 입력이라 오디오가 필요 없다. 로르샤하
반응 형태로 예문을 만들어 후보 모델(Qwen2.5-1.5B, EXAONE-2.4B 등)에 돌리면
**"소형 모델이 이 작업을 하긴 하는가"**를 알 수 있다.

합성 예문이라는 한계는 명시한다 — **여기서 실패하면 실데이터로도 안 된다**는
방향의 판단에만 쓴다(통과했다고 실환경 성공은 아니다).

## 어느 쪽으로 가든 공통인 것

**분리 판정을 `TranscribeClipService` 안의 함수 하나로 격리한다.**

- 스키마: `TranscriptClipResponse`에 `segments: list[str]` 추가.
  **비어 있으면 기존 동작**(한 덩어리)이라 하위호환이 된다.
- 프론트: 받아쓰기 모드에서 `segments` 개수만큼 반응을 만든다.
- 구현체는 그 함수만 갈아끼운다 — OpenAI든 AI팀 API든 로컬 SLM이든.

이렇게 두면 T-1을 나중에 정해도 화면과 계약은 안 바뀐다.
