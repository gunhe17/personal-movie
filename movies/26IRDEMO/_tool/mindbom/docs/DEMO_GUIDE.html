한 문장 요약

투사적 심리검사의 해석 초안을 AI가 만들고, 임상가가 검토·수정·확정하는 CDSS.

핵심 기능 3가지

  • 검사 간 교차분석 — 서로 다른 검사를 임상 구성개념으로 묶어 대조
  • 구간별 AI 리뷰 — 문장을 드래그하면 표현·맞춤법 교정 제안
  • 종합 AI 리뷰 — 문서 전체의 섹션 누락·논리 모순·검사 반영률

차별점

  • AI가 지적만 하지 않고 수정안을 제안하고 실제로 반영
  • 구간별(문장) ↔ 종합(문서) 역할이 갈리고 서로 연결됨
  • 규준 없는 검사는 정량 비교에서 의도적으로 제외

시연에서 보여줄 한 컷

종합 리뷰가 지적 → 임상가가 승인 → 본문이 고쳐지고 점수가 오른다.

55점→초안 작성→ 77점→'중등도'로 통일→ 99점

정적인 화면이 아니라 "쓰면 나아진다"가 눈에 보이는 것이 이 데모의 핵심.

시연 전 반드시 할 것 "지금 동작하는 것"과 "연동 예정"을 먼저 밝히고 시작한다. 화면 완성도가 높을수록 "이거 다 진짜냐"는 질문이 날카로워진다. 나중에 드러나는 것보다 먼저 말하는 편이 항상 유리하다. → 진짜 / 목업 탭 참고

시연 동선

준비된 시나리오는 2개. 즉석에서 다른 문장을 고치면 반응이 없을 수 있으니 이 동선대로.

사전 점검

  • 브라우저 폭 1554px 이상 (좌 사이드바 360 + A4 794 + 패널 400)
  • 보고서 작성 페이지 진입 후 본문이 프리셋대로 로드됐는지 확인
  • Ⅲ. 행동 관찰이 비어 있어야 함 (의도된 결함)

시나리오 A — 구간별 리뷰 (문장 단위)

  1. 본문 "6) 공격성" 문단으로 스크롤 "임상가가 초안을 검토하는 상황입니다."
  2. 공격 충동이 매우 높다는 점을 부근을 드래그 → 뜨는 AI 버튼 클릭
  3. 카드에서 교정 3건 확인 — 주관적 강조어 / 용어(환자→내담자) / 이중피동 "맞춤법뿐 아니라 심리평가 보고서의 문체 규범을 봅니다. '환자'가 아니라 '내담자'로 쓰는 것 같은."
  4. 제안을 클릭해 본문이 실제로 바뀌는 것 보여주기

시나리오 B — 종합 리뷰 (문서 단위) · 메인

  1. 툴바 우측 [AI 종합 리뷰] 클릭 "이번엔 문장이 아니라 보고서 전체를 봅니다."
  2. 4단계 분석 진행 표시 (약 3.9초) "구조 파악 → 검사 결과 대조 → 서술 일관성 → 표현 점검. 단계마다 걸리는 시간이 다릅니다."
  3. 결과: 55점 · 지적 3건. 분석 경로에 실제 숫자가 남는 것 강조 "검사 6건 중 6건 반영 — 실제로 대조한 결과입니다."
  4. [위치로 이동] 눌러 본문이 스크롤되고 하이라이트되는 것 보여주기
  5. [초안 작성] 클릭 → 미리보기 모달에서 멈추기 (중요) "AI가 바로 고치지 않습니다. 반드시 임상가가 확인하고 승인해야 반영됩니다. 의료기기 규제상 AI는 초안까지입니다."
  6. 승인 → Ⅲ이 채워지고 77점으로 상승
  7. ['중등도'로 통일] 클릭 → before/after diff 확인 → 승인 → 99점 "양쪽 선택지를 줍니다. 어느 쪽이 맞는지는 임상가만 판단할 수 있으니까요."
여기서 멈출 것 즉석에서 다른 문단을 고쳐보라는 요청이 오면 — "지금은 규칙 기반이라 준비된 패턴에 반응합니다. LLM 연동 후에는 임의 문장도 처리합니다"라고 솔직히 답한다.

백엔드 인프라 — 이미 있는 것

  • AIService 추상 인터페이스 + RemoteAIService 구현체
  • OpenRouter 경유 Gemini 2.5 Flash 실호출 코드 보유
  • 3단 폴백 확립: AI 서버 URL → LLM 직접 호출 → 룰베이스 — 외부 장애 시에도 결과를 반환
  • summarize_report(), generate_comprehensive_draft() 구현됨
단서 현재 .env에 OPENROUTER_API_KEY가 비어 있어 룰베이스로만 동작. "인프라는 완성, 키 설정과 프롬프트 검증이 남았다"가 정확한 표현.

교차분석 — 가장 날카로운 질문에 대비

"서로 다른 검사를 하나로 묶는 근거가 뭐냐"는 질문은 반드시 온다. 임상 배경이 있는 청중이라면 더욱.

방어 가능한 것 — 문헌으로 확인됨

① 도메인별 통합은 표준 관행

검사별로 나열하지 않고 기능 영역별로 통합하는 것이 권장되는 보고서 작성법 ("integrated report format"). 검사 순서대로 쓰는 방식은 "그림을 파편화시켜 통합을 불가능하게 만든다"고 명시적으로 비판된다.

② 불일치 해석에 확립된 모델

자기보고식 ↔ 수행기반(투사) 검사의 불일치는 Finn(1996) 통합 모델로 해석한다. 두 검사는 경쟁하는 것이 아니라 서로 다른 층위(직접 측정 vs 간접 측정)를 본다.

③ 충동조절 축은 근거 있음

MMPI-2 PSY-5 Disconstraint ↔ TCI Novelty Seeking은 수렴타당도가 확인된 관계 (충동성·위험감수·자극추구 공유). 임의 조합이 아니다.

④ 규준 없는 검사는 정량 제외

투사검사(HTP·로르샤하·SCT)는 value: null로 두고 정성 소견만 표시. 차트에 점을 찍지 않고 그 이유를 UI에 명시한다. 한계를 드러내는 것이 오히려 신뢰를 높인다.

아직 근거가 없는 것 — 먼저 인정할 부분

7개 축의 개수와 분할은 미검증 확립된 것은 "도메인별로 묶는다"는 형식이지, 우리가 정한 특정 7개가 아니다. 문헌의 표준 도메인은 인지·학업·정서·행동·성격·대인관계 계열이고, 우리 축은 정서/성격을 더 잘게 쪼갠 변형이다.
  • 축 간 독립성 미검증 — 우울 ↔ 자기개념, 공격성 ↔ 충동조절이 상당히 겹친다. 실데이터 요인분석을 한 것이 아니라 "왜 7개냐"에 답할 수 없다
  • 인지기능 축 부재 — 현재 배터리에는 지능검사가 없어 문제되지 않으나, 추가 시 필요

권장 답변

"도메인별 통합은 확립된 보고서 작성 관행이고, 불일치 해석은 Finn(1996) 모델을 따릅니다. 다만 축 구성 자체는 임상 자문을 거쳐 확정할 예정이며, 현재는 실무에서 흔히 쓰이는 영역을 반영한 초안입니다."

왜 이렇게 말하나 축을 "우리가 만든 것"이라고 하면 근거를 요구받는다. "확립된 형식 + 검증 예정인 구성"으로 나누면, 방어 가능한 부분은 지키고 미검증 부분은 로드맵으로 넘길 수 있다. 한계를 먼저 말하는 것이 신뢰를 높인다는 원칙은 투사검사 정량 제외에서 이미 적용한 것과 같다.

참고문헌

인용 전 확인 필요 아래는 웹 검색으로 확인한 2차 출처다. "이런 프레임워크가 존재한다"까지는 확인했으나 Finn 모델의 구체적 내용과 국내 지침은 원문을 보지 못했다. 외부 자료에 인용하려면 원문 확인이 필요하다.
  1. Finn, S. E. (1996). Assessment feedback integrating MMPI-2 and Rorschach findings. Journal of Personality Assessment, 67(3), 543–557. 자기보고식 ↔ 수행기반 검사의 불일치를 해석하는 통합 모델. 두 검사가 경쟁하는 것이 아니라 서로 다른 층위를 측정한다는 관점의 근거. 적용 사례 연구 (ResearchGate)
  2. Harkness, A. R., McNulty, J. L., & Ben-Porath, Y. S. MMPI-2 PSY-5 척도 개발 및 타당화 연구 계열. PSY-5 Disconstraint가 충동성·위험감수·자극추구와 수렴타당도를 보이며, TCI-R Novelty Seeking과 유의한 관계를 갖는다는 근거. 충동조절 축의 직접 근거. Linking the PSY-5 scales (Wichita State, PDF)
  3. 통합 보고서 작성 관행 (integrated report format). 검사별 나열이 아니라 기능 영역별 통합이 권장되며, 검사 순서대로 쓰는 방식은 "그림을 파편화시켜 통합을 불가능하게 만든다"고 비판됨. 축으로 묶는 형식 자체의 근거. Beyond the WISC — Strength-based report writing (BCcampus)
  4. Campbell, D. T., & Fiske, D. W. (1959). Convergent and discriminant validation by the multitrait-multimethod matrix. Psychological Bulletin, 56(2), 81–105. 서로 다른 측정 방법으로 같은 구성개념을 재는 것의 고전적 근거이자, method variance(측정 방법 자체가 만드는 분산) 문제의 출발점. 축 간 수렴/변별 타당도를 검증하려면 이 틀을 따르게 된다. — 향후 축 검증 시 참조할 방법론
아직 확인하지 못한 것 한국임상심리학회·정신건강임상심리사 실무 지침에 통합 보고서 구조에 관한 기준이 있는지 확인하지 못했다. 국내 인허가 대응에는 이쪽이 더 직접적인 근거가 될 수 있으므로 임상 자문 시 함께 확인할 것.

규제 · CDSS 원칙

SaMD 2등급 인허가를 염두에 둔 설계 지점들.

핵심 원칙 — AI는 초안까지

AI 분석→초안 제시→ 임상가 검토→승인→반영

AI가 최종 결정을 내리지 않는다. 종합 리뷰의 수정 제안도 클릭 즉시 적용되지 않고 미리보기 모달을 거쳐 명시적 승인을 받는다. 이 단계는 UX 편의가 아니라 규제 요구사항이다.

구현된 안전장치

요구사항 구현
AI 최종 결정 금지 모든 수정안이 미리보기 → 승인 경유. 자동 적용 경로 없음
변경 전후 확인 가능 before/after diff를 색상으로 구분해 표시
되돌리기 에디터 표준 실행취소(Ctrl+Z)로 복구 가능
AI 판단의 근거 제시 지적마다 근거 표기 + "분석 경로"에 확인 항목 명시
보조 도구임을 고지 패널 하단 및 미리보기 모달에 고지 문구 상시 노출
선택지가 갈리는 판단은 위임 서술 모순 시 양방향 선택지 제시 (어느 쪽이 맞는지 AI가 정하지 않음)

아직 붙이지 않은 것

  • 감사추적(Audit Trail) — 어떤 AI 제안을 누가 언제 승인/거부했는지 기록. GMP 필수 항목이며 종합 리뷰 적용 이력도 남겨야 한다
  • AI 모델 버전 기록 — 어떤 모델이 만든 초안인지 추적
질문받으면 "감사추적은 검사 도메인에 이미 구현돼 있고, 보고서 편집 이력에도 동일 구조를 적용할 예정입니다"가 정확하다. 이미 있다고 말하지 말 것.

그래서 정량 비교에서 의도적으로 제외했습니다. 규준 점수가 존재하는 표준화 검사만 차트에 표시하고, 투사검사는 정성 소견으로만 둡니다. 서로 다른 검사의 원점수를 하나의 척도로 환산하는 것은 표준화된 근거가 없어 하지 않습니다. 한계를 명시하는 편이 오히려 신뢰를 높인다고 봤습니다.
AI가 임상 판단을 대신하는 것 아닙니까? 규제 문제는?
AI는 초안까지만 만듭니다. 수정 제안도 클릭 즉시 적용되지 않고 미리보기를 거쳐 임상가가 승인해야 반영됩니다. 판단이 갈리는 경우(예: 우울 수준이 중등도냐 경미냐)에는 AI가 정하지 않고 양쪽 선택지를 제시합니다. 이는 UX 편의가 아니라 CDSS 원칙에 따른 설계입니다.
분석이 3.9초 걸리던데 실제로도 이 속도입니까?
아닙니다. 현재는 규칙 기반이라 즉시 끝나고, 단계 표시는 진행 상황을 보여주기 위한 것입니다. LLM 연동 시에는 문서 길이에 따라 5~15초가 예상되며, 그래서 단계별 스트리밍(SSE)으로 진행 상황을 실시간 표시할 계획입니다.
다른 문장도 고쳐볼 수 있나요?
지금은 규칙 기반이라 준비된 패턴에 반응합니다. 이중피동, 주관적 강조어, 용어 오류 같은 임상 보고서의 전형적 오류들입니다. LLM 연동 후에는 임의 문장도 처리 가능합니다.
경쟁 제품과 뭐가 다릅니까?
첫째, 지적만 하지 않고 수정안을 제안해 실제로 반영합니다. 둘째, 문장 단위 리뷰와 문서 단위 리뷰가 역할이 갈리면서 서로 연결됩니다 (구간별 지적을 종합이 집계). 셋째, 규준 없는 검사를 정량 비교에서 제외하는 등 측정학적 한계를 설계에 반영했습니다.
임상가가 실제로 쓸까요? 검증은 했습니까?
아직 사용성 검증은 하지 않았습니다. 현재는 기능 구현 단계이고, 축 분류 타당성을 포함한 임상 자문이 다음 과제입니다. V&V 계획에 사용적합성 평가가 포함될 예정입니다. — 이 질문에는 솔직히 답하는 것이 낫다. 검증했다고 말하면 근거를 요구받는다.

시연 전 인지하고 있어야 할 것들. 우선순위 순.

1. 축 분류 임상 자문 미완 높음

7개 축의 구성이 검증되지 않았다. 개발로 해결할 수 없고 임상 자문이 필요하다. SaMD 인허가에서도 결국 이 부분이 핵심이 된다. → 교차분석 방어 탭의 권장 답변 사용

2. LLM 파트 미검증 높음

OPENROUTER_API_KEY가 없어 모순 탐지 프롬프트가 실제로 동작하는지 확인하지 못했다. 인프라는 있으나 "실제로 잡아내는가"는 미확인.

3. 데모 시나리오 고정 중간

준비된 2개 시나리오 외에는 반응이 없을 수 있다. 즉석 요청 시 규칙 기반임을 밝힐 것.

4. 화면 폭 제약 중간

1554px 미만에서는 종합 리뷰 패널이 본문 일부를 가린다 (좌 360 + A4 794 + 패널 400). 1440px 노트북에서 시연하면 114px가 겹친다. 외부 모니터 권장.

5. S-척도 결과지 이미지 부재 낮음

MMPI·TCI는 실제 결과지 크롭이 있는데 S-척도는 차트 썸네일뿐이라 나란히 놓으면 대비된다. 검사자료 탭을 오래 보여주지 않는 편이 낫다.

6. 감사추적 미적용 낮음

보고서 편집·AI 제안 승인 이력이 기록되지 않는다. 검사 도메인에는 구현돼 있으므로 동일 구조를 확장하면 된다. GMP 필수 항목.

총평 화면 완성도는 외부에 내놓을 수준이다. 지금 더 필요한 것은 UI 개선이 아니라 말할 준비 — 무엇이 진짜인지, 축 근거를 뭐라 답할지, 실제 속도는 얼마인지. 화면이 좋을수록 질문은 날카로워진다.
