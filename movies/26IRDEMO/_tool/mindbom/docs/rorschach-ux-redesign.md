# 로르샤하 UX 재설계 검토안

> 작성: 2026-08-13
> 상태: **검토 요청 — 임상심리사 확인 필요**
> 계기: "자유반응과 질문 단계가 합쳐진 것"에 대한 임상심리사 의문 제기

---

## 0. 이 문서의 목적

임상심리사가 지적한 것은 색이나 버튼이 아니라 **검사 절차가 아니다**라는 점이다.
이건 스타일 개선으로는 없어지지 않는 구조 문제이므로, 코드를 고치기 전에
방향을 먼저 확정하려 한다.

**결정이 필요한 것은 3장의 A/B/C안 중 하나다.** 나머지는 근거 자료다.

---

## 1. 실제 검사 절차 vs 현재 구현

### 1-1. Exner 종합체계의 표준 절차

```
1단계  자유반응 (Free Association)
       카드 I~X 순서대로 제시, "이게 무엇처럼 보입니까?"
       → 내담자 반응을 그대로 받아 적는다
       → 위치는 묻지 않는다

2단계  질문 (Inquiry)
       카드 I~X를 다시 처음부터 제시
       "어디서 그렇게 보였나요?" "무엇 때문에 그렇게 보였나요?"
       → 여기서 위치(영역)와 결정인이 확정된다

3단계  채점 (Coding)
       검사 종료 후, 반응별로 기호화
       위치·발달질·결정인·형태질·내용·평범반응·조직화점수·특수점수

4단계  구조요약 (Structural Summary)
       빈도 집계 → 비율·백분율 산출 → 군집별 해석
```

**핵심: 위치는 1단계가 아니라 2단계에서 확정된다.**
자유반응 중에는 내담자가 어디를 보고 말하는지 검사자도 모르는 것이 정상이다.

### 1-2. 현재 구현

`module.ts` 기준 3단계:

| 단계 | 화면 | 하는 일 |
|---|---|---|
| `collect` | 반응 영역 기록 | 녹음 + 카드별 영역 그리기 + 메모 |
| `review` | 채점하기 | 영역 클릭 → 채점, 녹취록 연동 |
| `results` | 결과 보기 | Exner 구조요약 |

### 1-3. 어긋나는 지점

**① 자유반응과 질문이 한 화면에 합쳐져 있다**

현재 `collect`는 녹음을 시작해야 영역을 그릴 수 있다.
(`Collect.svelte:392` — `canDraw={hasStartedRecording}`, 힌트 "녹음을 먼저 시작해주세요")

즉 **말하는 동안 위치도 함께 기록**하는 것을 전제한다.
표준 절차에서 위치는 질문 단계에서 나오므로, 임상가 입장에서는
"아직 어디인지 안 물어봤는데 지금 그리라고?"가 된다.

**② 되돌아가기가 막혀 있다**

`module.ts:5-12`:
> 되돌아가 수정할 수 없게 막는 이유: region을 추가·삭제하면
> 이미 채점된 transcript 매핑이 어긋난다.

그런데 표준 절차에서는 자유반응이 끝나면 **당연히 카드 I로 돌아가서**
질문 단계를 진행한다. 되돌아가기 차단은 실제 검사 흐름과 정면 충돌한다.

**③ 반응 단위가 명시적이지 않다**

표준 채점의 단위는 "반응(response)"이다. 카드 하나에 반응이 여러 개 나오고,
각 반응이 독립적으로 채점된다(R = 총 반응 수). 현재 구조에서 반응 단위는
"영역(region)"으로 표현되는데, 영역은 **위치를 그린 것**이지 반응 그 자체가 아니다.

자유반응 단계에서 반응은 이미 발생했지만 영역은 아직 없다.
지금 구조에서는 이 시점의 반응을 담을 그릇이 없다.

## 2. 재설계 시 반드시 지켜야 할 것 (불변 조건)

현재 코드에는 실사용으로 다듬은 판단이 박혀 있다.
**전면 재설계 시 이것들이 조용히 사라지는 것이 가장 큰 위험이다.**

### 2-1. 녹음 t=0은 MediaRecorder의 start 이벤트 시점

`hooks/recording.svelte.ts:71-78`

`start()` 호출 시점을 t=0으로 잡으면 실제 첫 샘플 캡처보다 수십 ms 빠르다.
영역 타임스탬프가 오디오 파일 내부 시각과 어긋나므로 매칭이 틀어진다.

### 2-2. 발화 매칭에 양쪽 1.0초 패딩

`utils/transcript-match.ts:9`

임상가가 영역을 표시하는 시점은 발화 종료와 정확히 일치하지 않는다.
패딩이 없으면 매칭이 자주 실패한다.

### 2-3. 자동 선택에서 검사자 발화 제외

`utils/transcript-match.ts:84-98`

"이게 뭐로 보이지?" 같은 검사자 질문이 내담자 응답으로 잘못 잡히면
AI 채점 입력이 오염된다. examinee 우선, 없을 때만 examiner를 컨텍스트로 폴백.

### 2-4. 녹음 보안 컨텍스트 안내

`hooks/recording.svelte.ts:40-55`

HTTP 접속 시 `navigator.mediaDevices`가 아예 숨겨진다.
"브라우저 미지원"이 아니라 "HTTPS 또는 localhost로 접속하라"고 안내해야 한다.

### 2-5. 영역 저장 실패 시 화면에서 지우지 않음

`Collect.svelte:181`

검사 중 네트워크 오류로 임상가의 작업이 사라지면 안 된다.
(다만 화면에는 있고 서버에는 없는 상태가 남는 문제는 별도 해결 필요 — 5장)

## 3. 재설계안 — 세 가지

**공통 전제**: 실사용 시나리오가 두 가지다.
- (가) 실시간: 내담자와 마주 앉아 노트북에 입력
- (나) 사후: 검사는 종이/녹음으로, 끝난 뒤 사무실에서 입력

같은 화면이 두 시나리오를 다 만족하기 어렵기 때문에, 각 안이 이 문제를
어떻게 다루는지가 핵심 비교점이다.

---

### A안 — 절차 그대로 4단계로 분리

```
1. 자유반응    녹음 + 반응 텍스트만 기록 (위치 없음)
2. 질문        카드 재순회 + 각 반응에 영역 그리기
3. 채점        반응별 코딩
4. 결과        구조요약
```

**반응 단위를 1급 객체로 승격한다.** 자유반응에서 반응이 생성되고,
질문 단계에서 그 반응에 영역이 붙는다.

```
Response {
  card_no, response_index,     ← 자유반응에서 생성
  audio_start_sec, audio_end_sec,
  free_association_text,
  region: Region | null,        ← 질문 단계에서 연결
  inquiry_text,
  coding: Coding | null         ← 채점 단계에서
}
```

| | |
|---|---|
| **장점** | 임상가의 멘탈 모델과 정확히 일치. 지적받은 문제가 근본적으로 해소.<br>되돌아가기가 자연스러움(질문 단계는 원래 카드 I부터 다시).<br>R(총 반응 수)이 구조적으로 명확해짐. |
| **단점** | **가장 큰 변경.** DB 스키마·API·프런트 전부 영향.<br>기존 데이터 마이그레이션 필요(region → response 승격).<br>단계가 4개로 늘어 사후 입력 시 이동이 많아짐. |
| **매칭 해법** | 자유반응 시각은 그대로 유지(반응이 시간을 가짐). 영역은 시간을 갖지 않고 반응에 붙기만 함. **2-1~2-3 불변 조건이 그대로 보존됨.** |
| **시나리오** | (가) 1단계만 사용 → 부담 최소. (나) 2~3단계를 녹취 들으며 진행. **두 시나리오가 단계로 자연 분리됨.** |

---

### B안 — 현재 2단계 유지, 화면 내부를 두 모드로

`collect` 안에 "자유반응 모드 / 질문 모드" 토글을 둔다.
자유반응 모드에서는 캔버스가 비활성이고 반응 텍스트만 입력.
질문 모드로 전환하면 카드 I부터 다시 순회하며 영역을 그린다.

| | |
|---|---|
| **장점** | DB 스키마 변경 최소. 프런트 작업 위주.<br>단계 수가 안 늘어 사후 입력 시 이동이 적음. |
| **단점** | 모드 전환을 임상가가 기억해야 함.<br>"단계가 합쳐져 있다"는 지적이 **완전히 해소되지 않을 수 있음** — 여전히 한 화면.<br>반응 단위가 여전히 암묵적. |
| **매칭 해법** | 자유반응 모드에서 반응에 시간 부여, 질문 모드에서 영역 연결.<br>실질적으로 A안과 같은 데이터 구조가 필요해짐 → **B의 이점이 줄어듦.** |
| **시나리오** | 모드 토글로 구분하지만 화면이 같아 (가)에서 오조작 위험. |

---

### C안 — 자유반응만 분리, 질문+채점 통합

```
1. 자유반응        녹음 + 반응 텍스트
2. 질문 및 채점    영역 그리기 + 코딩을 같은 화면에서
3. 결과            구조요약
```

질문 단계에서 위치를 확정하는 순간 결정인·형태질도 함께 판단되는 경우가
많다는 점을 반영. 임상가가 카드를 한 번만 더 순회하면 된다.

| | |
|---|---|
| **장점** | 지적받은 문제 해소(자유반응 분리됨).<br>단계 3개 유지 — A안보다 이동 적음.<br>질문과 채점을 한 화면에서 하므로 **사후 입력 시 가장 빠름**. |
| **단점** | 질문 화면의 정보 밀도가 높아짐(캔버스 + 녹취 + 코딩 패널).<br>실시간 시나리오에서는 2단계가 무거움. |
| **매칭 해법** | A안과 동일(반응이 시간을 가짐). |
| **시나리오** | (가) 1단계만. (나) 2단계에서 한 번에 처리. **A안과 유사하되 더 압축적.** |

---

### 비교 요약

| | A안 (4단계) | B안 (모드 토글) | C안 (3단계) |
|---|---|---|---|
| 지적 해소 | 완전 | **부분** | 완전 |
| 변경 규모 | 큼 | 중간 | 큼 |
| 스키마 변경 | 필요 | 사실상 필요 | 필요 |
| 사후 입력 속도 | 보통 | 빠름 | **가장 빠름** |
| 실시간 부담 | **가장 낮음** | 중간 | 낮음 |
| 절차 일치도 | **가장 높음** | 낮음 | 높음 |

**작성자 의견: C안을 우선 검토 권장.**
A안의 절차 일치를 확보하면서 단계 수를 3개로 유지한다.
다만 "질문과 채점을 같은 화면에서 하는 것"이 실제 임상 작업 방식과
맞는지는 **임상심리사 확인이 필요하다** — 이게 C안의 유일한 불확실성이다.

B안은 스키마 변경을 피하려는 동기에서 출발했지만, 결국 같은 데이터 구조가
필요해지므로 이점이 크지 않다.

## 4. 확인이 필요한 질문

**Q1. 질문(Inquiry) 단계에서 채점까지 같이 하는가?**
→ 예: C안 / 아니오: A안

**Q2. 자유반응 중 반응 텍스트를 실시간으로 타이핑하는가, 녹음에만 의존하는가?**
→ 타이핑한다면 자유반응 화면에 입력 UI가 커야 함
→ 녹음만이라면 자동 전사 결과를 질문 단계에서 확인하는 흐름

**Q3. 한 카드에서 반응이 여러 개일 때 현재 어떻게 구분해 적는가?**
→ 반응 번호 체계가 있다면 그대로 UI에 반영해야 함

**Q4. 질문 단계에서 카드를 다시 보여줄 때, 자유반응 때 한 말을 화면에 띄워주면 유용한가?**
→ 유용하다면 이게 "시간 단축"의 핵심 기능이 됨
   (오프라인에서는 종이를 뒤적여야 하는 부분)

**Q5. 되돌아가기를 어디까지 허용해야 하는가?**
→ 확정 전까지 전 단계 자유롭게 / 단계별 잠금 / 현재처럼 엄격

## 5. 재설계와 별개로 남아 있는 결함

UX 재설계와 무관하게 존재하는 문제들. 재설계 시 함께 해소되는지 확인 필요.

| 위치 | 내용 |
|---|---|
| `result-mapper.ts:94-102, 162` | 형태질 표에서 **MQual·W+D 열이 백엔드 미계산인데 0으로 표시**됨. MQual은 사고장애 판단 핵심 지표라 임상적 오독 위험. `null` + "미산출" 표기가 안전. |
| `result-mapper.ts:158-159` | `single` 섹션이 Determinants 값을 그대로 복사, `(2)` 쌍반응 0 고정. 주석에 "placeholder" 명시. |
| `result-mapper.ts:134-135` | GHR/PHR(인간표상 점수) `null` — 미산출. |
| `CodingPanel.svelte:359-364` | **AI 채점 근거 표시 블록이 통째로 주석 처리.** prop은 계속 전달됨. CDSS 원칙상 "AI가 왜 그렇게 판단했는지"는 임상가가 봐야 하는 정보 — 의도적 숨김인지 확인 필요. |
| `Review.svelte:64-69` | 발화 선택(토글) 상태가 **휘발성**. 리로드하면 임상가의 가감 작업이 사라짐. 저장되는 건 최종 텍스트뿐. |
| `WaveformDisplay.svelte:12` | 파형이 실제 오디오 분석이 아니라 **sin + 랜덤 생성 패턴**. 진행률·seek는 실동작. 사용자가 실제 파형으로 오인 가능. |
| `Collect.svelte:82` | 내용 없는 고아 주석 — "카드별 색상 인덱스(서버 영역 로드 시 색 재현용)" 로직 부재. |
| `Collect.svelte:181` | 영역 저장 실패 시 화면엔 남고 서버엔 없는 상태가 지속됨. 재시도 또는 미저장 표시 필요. |
| `Collect.svelte:57-80`, `Review.svelte:97-108` | `CARD_TO_NO`/`NO_TO_CARD` 매핑이 두 파일에 중복 정의. `constants.ts`로 통합 여지. |
