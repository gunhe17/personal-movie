## ✅ 처리한 것 — 되돌리기 전에 읽을 것

### 1. 더블탭으로 반응이 두 개 생기던 것

`isSaving` 가드는 **요청이 도는 동안만** 서 있어서, 서버가 200ms에 답하면 두 번째
탭이 그 뒤로 통과했다. `handleClientTap`에 **400ms 쿨다운**을 뒀다.

> ⚠️ **R이 1 늘어나는 문제다.** R은 거의 모든 Exner 지표의 분모라 조용히 전 지표가
> 틀어진다. 쿨다운을 지우려면 다른 방어를 먼저 세울 것.

삼킨 탭에는 진동·잔물결을 주지 않는다 — 신호가 없는 것이 곧 "기록되지 않았다"다.

### 2. 실시↔채점 이동

두 가지였다.

- `CodingFooter`가 `onPrev`를 받는데 Review가 안 넘기고 있었다 → "실시로" 버튼 추가
- 실시 쪽 버튼이 `canComplete`로 **잠겨** 있었다 → **완료 표시와 이동을 분리**

조건 미달이면 미완 카드 **이름을 대고** 완료 표시 없이 이동한다. §3-1 "벽 없음",
§14-12 "게이트가 벽으로만 작동하면 안 된다"가 근거다.

### 3. 채점에서 기록 수정 — **설계 결정을 뒤집었다**

`isAdmin` → `canEditRecord = !readonly`. **단계가 아니라 확정 여부**가 편집을 막는다.

§14-14는 "기록은 실시에서만 고친다"였고 근거는 *"채점하며 원자료를 고치면 무엇을
근거로 채점했는지가 흐려진다"*였다. 실사용이 뒤집었다 — **되돌아갈 길이 없으면
임상가는 틀린 채로 확정한다. 흐려지는 것보다 틀린 게 나쁘다.**

안전장치는 사라진 게 아니라 축이 옮겨졌다: 확정 후 잠금(서버 `_ensure_editable`),
STT 원문 분리 보관(§4-2), 감사추적. 설계 문서에도 반영했다.

방향(카드 회전)도 같은 축으로 맞췄다 — 채점에 직접 쓰이는 정보다(§5-1).

### 4·5. AI 블록

제안 상자를 `CodingPanel`에서 꺼내 **팝오버 최상단**으로 올렸다. 채점 버튼·신뢰도·
제안 값·전체 반영이 한 상자에 모인다. 헤더의 중복 신뢰도 뱃지는 제거.

> **채택·저장 동작은 `CodingPanel`에 남겼다.** 대상이 그쪽의 편집 중인 값(`local`)이라
> 로직까지 올리면 저장 전 편집을 밖에서 알아야 해서 상태가 둘이 된다. 팝오버는
> `bind:this`로 `adopt()`/`save()`를 부르고 `bind:adoptable`/`bind:dirty`로 받는다.

'전체 반영' 버튼은 **항상 그린다**(비활성 + "확인됨"). 텍스트로 갈아끼우면 높이가
달라 상자가 튀고, 하필 채택 직후에 튀어 아래 표가 밀려 보인다.

## 🐛 피드백 처리 중 발견해서 함께 고친 것

### a. 저장한 채점이 다시 열면 전부 비어 보임

`CodingPanel`이 `structuredClone(finalCoding)`을 썼는데, 부르는 쪽 `responses`가
`$state`라 Svelte 5가 깊게 프록시를 씌운다. **프록시는 `structuredClone`이 복제하지
못하고 `DataCloneError`를 던진다.** 터진 자리가 `$effect` 안이라 effect가 통째로
죽고 `local`이 빈 값에 머물렀다 — 에러는 콘솔에만 남고 화면은 "아직 안 채웠다"와
구분되지 않는다.

→ 칸을 하나씩 옮기는 `cloneCoding()`으로 교체. **이 코드베이스에서 두 번째로 밟은
함정이다**(`handleSave`가 이미 `$state.snapshot`으로 막고 있었다). `$state` 객체를
복제할 일이 생기면 `structuredClone`을 쓰지 말 것.

### b. `area_code`와 `coding.location`이 어긋남

위치가 두 곳에 있고(§14-7이 경고한 그것) 실제로 갈렸다. 채점은 `coding["location"]`을
읽으므로 null이면 그 반응이 **위치 집계에서 조용히 빠진다** — 영역 부호 43건이
사라졌던 것과 같은 종류.

경위: **'전체 반영'은 location을 안 채운다**(임상가가 고른 값이라 AI가 못 건드린다).
그 상태로 저장되면 null이 굳는다.

→ 서버가 클라이언트 값을 안 믿고 **반응에서 파생**시킨다
(`UpdateResponseCodingService`). 기존 데이터 1건도 정본으로 맞췄다. 현재 0건.

### c. 위치 컨트롤이 두 개

채점에서 기록 표를 열면서(3번) `CodingPanel`에 있던 `LocationPicker`와 겹쳤다.
→ 기록 표(상단)에만 남기고 코딩표에서 제거. 코딩표의 그 행은 **발달질(DQ)** 행이 됐다.

## ✅ 6번 — 채점 화면 레이아웃 (B안)

> 채점 화면에서는 코딩표를 보여주는건 어떨지? 1:1 비율로 카드 그림과 함께 배치
> 디자인 톤앤매너 준수하여 세련되게 채점표는 문서처럼 깔끔해보이게

**B안 채택** — 카드 탭은 전폭, 그 아래 좌 카드 / 우 계열 기록지 1:1.
§14-3("우측 패널을 버린다")을 **채점에서만** 되돌린다. 그 근거는 실시 중 눈이
카드를 떠나면 안 된다는 것이었는데, 채점은 조건이 다르다 — 반응 하나를 부호로
옮기는 일이라 **직전까지의 계열이 옆에 있어야** 한다(접근방식·연쇄된 특수점수·
P를 몇 개나 줬는지는 한 반응만 보면 안 보인다).

### A안의 걸림돌("정보가 두 곳에 산다")을 없앤 방법

표는 **읽기 전용 파생 뷰**다. 편집은 팝오버 한 곳에서만 일어나고 표는 저장된
값만 그린다 — 저장돼야 표에 나타나는 것이 곧 "저장됐다"의 신호가 된다.
(중간에 "표에서도 편집" 안이 나왔다가 철회했다. 행을 누르면 그 카드로 옮겨
팝오버가 열리므로 되돌아갈 길은 이미 있다.)

### 팝오버 자리 — 두 번 고쳤다

1. 조각의 반대쪽에 붙이던 규칙을 **왼쪽 고정**으로. 2단에서 오른쪽에 붙으면
   코딩표를 덮는다. 고정으로 띄운 표가 채점 중에 안 보이면 고정한 의미가 없다.
2. 다시 **무대(카드를 담은 회색 영역) 좌상단 고정**으로. `.card-box`가 16:9라
   컬럼이 좁아지면 박스가 세로 가운데로 내려앉는다 — 팝오버는 박스 상단에
   정확히 붙는데도 화면에서는 어중간하게 떠 보였다. 무대는 줌·팬(`transform`)에도
   안 흔들려 **줌해도 팝오버가 제자리**라는 부수효과가 있다.

조각 앵커를 버린 이유: 앵커를 따라다니면 반응을 바꿀 때마다 팝오버가 화면을
뛰어다니고, 조각이 가운데 있으면 결국 반점을 덮는다. **어느 조각의 것인지는
자리가 아니라 색이 잇는다.**

### 표에 담은 것

| 상태 | 표시 |
|---|---|
| 확정 (`final_coding`) | 본문색 + 우측에 옅은 '확정' |
| AI 초안만 | 값 전체 `gray-400` + 우측 **[확정]** 버튼 |
| 낡음 | amber 배경 + **[재검토]** 배지 (버튼 없음) |
| 미채점 | '미채점' |

- **Z는 부호와 수치를 함께** — 저장값은 `ZW`뿐인데 수치는 카드마다 다르다
  (카드 I의 ZW=1.0, 카드 IX의 ZW=5.5). 합산되는 것은 수치다.
- `location` ≠ `area_code`면 셀이 amber (피드백 b번 재발 감지)
- **낡은 행에 확정 버튼을 두지 않는다** — 한 번에 되살릴 수 있으면 바뀐 원자료를
  안 보고 확정하는 길이 생긴다. 낡음 표시를 세운 이유가 그것이다.

### 표를 만들며 밟은 것

- **`border-collapse` + `sticky thead` → 헤더 테두리가 아예 안 그려진다.**
  collapse에서 테두리 소유자가 표가 되는데 sticky로 떠오른 행은 그걸 못 들고
  간다. 색을 진하게 해도 안 보인다 → `border-separate` + 가로선도 셀에 건다.
- 등폭 서체를 버렸다. 문서 느낌은 나지만 앱 어디에도 없는 언어라 **표만 따로
  노는** 주된 원인이었다. 자릿수 정렬은 `tabular-nums`가 한다.

## ✅ 채점 근거가 바뀌면 — 낡음 표시 (`coding_stale_at`)

실시로 돌아가 반응 텍스트·질문·위치·회전을 고치면 저장된 채점은 **없어진 근거**
위에 선다. 그런데 칸은 차 있으므로 확정 게이트를 통과하던 자리다.

**지우지 않고 표시만 한다.** 오타 하나에 임상가가 한 채점이 날아가면 임상가가
오타를 안 고치게 된다 — 되돌아갈 길을 막는 것과 같은 실수다(3번에서 이미 겪었다).
값은 남기고 게이트에서 막아, 유지할지 다시 채점할지는 사람이 고른다.

| | |
|---|---|
| 표시 조건 | `free_association_text`·`inquiry_text`·`area_code`·`card_orientation`이 **실제로 달라졌을 때만** (같은 값 재저장은 무시 — 포커스아웃 저장 경로가 있다) |
| 제외 | 조각(region). 채점에 들어가는 건 `area_code`뿐이고 조각은 "한 위치를 이루는 획"이다 |
| 해제 | 임상가가 그 반응 코딩을 **다시 저장할 때만.** AI 재채점은 초안만 갱신하므로 안 풀린다 |

**축은 `completion.response_coded` 한 곳이다.** 거기가 확정 게이트와 진행률의
유일한 정의라, 낡으면 미완으로 치게 한 것만으로 서버 확정 거부·미완 목록·화면
진행률이 동시에 맞물린다. 프론트 `isCoded`도 같은 규칙.

## ✅ 일괄채점 · AI 채점 입력 검증

**서버 API를 그대로 쓴다**(`POST /score`, `ScoreSessionService`). 프론트에서
반응마다 돌리지 않는 이유는 로직이 두 벌이 되는 것보다 **표시번호 기준이 갈리는
것**이 무섭기 때문이다 — 서버는 한계검증까지 포함한 세션 전체로 번호를 세는데
프론트 목록은 정식 반응만이라, 프론트가 번호를 붙여 보내면 AI 근거가 엉뚱한
반응을 가리킨다.

- 타임아웃을 **인자로 받는다**. 반응 하나당 ~25초라 기본 130초로 두면 R이 조금만
  커져도 **서버는 끝냈는데 화면만 실패**로 보인다. 지금은 `반응수 × 40초`.
- 시작 전 확인 모달이 덮어쓰기·예상 시간·제외 건수를 알린다.

### 입력 검증 — 셋 다 필수

반응 내용 · 질문 답변 · 위치가 다 있어야 채점을 건다. 하나라도 비면 AI는
"모른다"가 아니라 **그럴듯한 값**을 내놓고, 그 값이 임상가의 검토 대상이 된다.
근거 없는 제안을 검토하게 만드는 것이 검토를 안 받는 것보다 나쁘다.

화면(`canAiScore`)과 서버(`missing_score_inputs`)가 **같은 규칙**이다 — 화면만
잠그면 API로 통과하고, 서버만 잠그면 눌리는 버튼이 실패한다. 일괄은 미달 반응을
건너뛴다(하나 때문에 22건을 잃지 않는다). 건너뛴 반응은 초안 없이 남아 화면에
'미채점'으로 보이므로 조용한 skip이 아니다.

### 코드 안정성 (시니어 프론트·백엔드 관점)

이번 세션에 나온 **실제 실패 유형**이 점검 항목의 힌트다 — 같은 종류가 더 있을 것:

|---|---|
| 같은 값이 두 곳에 산다 | `area_code`↔`coding.location`, `response_no`↔행 순서, 색 규칙, P 표 |
| 계약 없이 손으로 적은 목록 | 부호 어휘(`INC1`·`M`), 컨트롤 높이가 6곳에 복제 |
| 조용히 죽는 코드 | `$effect` 안의 예외(`structuredClone`), `continue`로 skip |
| 값이 아니라 **모름**을 값처럼 내보냄 | `"?:?"`, `popular=False` 기본값 |

- **현재 기준선**: 백엔드 **425건** / 프론트 **269건** 통과, `svelte-check` 0 errors,
  `audit_coding_codes.py` 위반 0건
- `scripts/audit_coding_codes.py`는 CI에 붙일 수 있다(위반 시 종료코드 1)

2차 세션에서 위 표의 유형이 **또 걸렸다** — 목록이 예언대로 작동한다:

| 유형 | 2차 세션에 걸린 예 |
|---|---|
| 계약 없이 손으로 적은 목록 | **`m'a` 결정인 표기**(아래) |
| 조용히 죽는 코드 | `startswith("m'")`로 세던 두 곳 — 어휘를 고치면 값이 0이 된다 |
| 같은 값이 두 곳에 산다 | 채점 자격 판정이 화면·서버로 갈릴 뻔한 것 → 같은 규칙으로 맞춤 |

### ✅ 원전으로 확정한 것 — 무생물운동 결정인 표기

**`m'a` → `ma`.** 워크북 〈표 3-1〉 결정인 기호와 기준(56쪽)의 "**m** 무생물운동반응"이
정본이고, 본문도 "M이나 m", "M과 m 기호"로 일관한다(58쪽). **아포스트로피는 무채색에만**
붙는다(`C'`·`C'F`·`FC'`, 같은 표).

> 계약 어휘·감사 스크립트·테스트 421건이 **전부 통과하고 있었다.** 그 검사들은
> "구현이 **내가 정한 어휘**를 지키는가"만 봤기 때문이다. §14-16이 말한 그대로다.

고치면서 **조용히 0이 될 자리 두 곳**이 드러났다 — 어휘를 집합이 아니라 접두사로
세던 코드다:

| 위치 | 옛 코드 | 증상 |
|---|---|---|
| `scoring.py` | `k.startswith("m'")` | 표기를 고치는 순간 `sum_m`이 0. es·EB가 조용히 틀린다 |
| `result-mapper.ts` | `k.startsWith("m'")` | 결과 화면의 m이 0 |

둘 다 어휘 목록을 나열하는 방식으로 바꿨다. **어휘는 한 곳에서 오고, 세는 쪽은
그 어휘를 적어둔다** — 그래야 어휘가 바뀔 때 세는 쪽도 같이 눈에 띈다.

DB 저장값도 마이그레이션했다(`m0vfix01`). 옛 값이 곧 SQL 구분자(`'`)라
이스케이프가 필요했던 자리다.

### ✅ 원전 대조 — 어휘 전수 (2026-08-25)

**PDF 페이지 = 책 페이지**(오프셋 0). 목차 9~10쪽에서 확인했다.

| 어휘 | 워크북 | 결과 |
|---|---|---|
| 결정인 24개 | 〈표 3-1〉 55~57쪽 | `m'` → `m` **1건 교정**, 나머지 일치 |
| 내용 27개 | 〈표 5-1〉 83~86쪽 | **전부 일치** (Hx·(A)·Ay·Cl·Ex·Fd·Ge·Hh·Ls·Na·Sc …) |
| 특수점수 15개 | 제7장 95·113쪽 | **6개 결정적 특수점수**(DV·DR·INCOM·FABCOM·ALOG·CONTAM) 일치. 수준 1/2 구분은 **DV·DR·INCOM·FABCOM 4개만** — 우리와 같다. `INCOM`·`FABCOM` 축약 안 함도 일치 |

> **남은 것 하나 — GHR/PHR이 계약 어휘에 없다.** 워크북은 15가지 특수점수에
> GHR·PHR을 포함시킨다(113쪽: "PSV, AB, AG, COP, MOR, GHR, PHR, …는 서로
> 독립적"). 우리는 7단계 규칙으로 **파생**시키고 선택 목록에 두지 않는다 —
> Exner에서 임상가 재량 판정이 아니므로 설계는 맞다. 다만 **계열 기록지
> 특수점수 칸에 GHR/PHR이 안 보인다.** 종이 기록지에는 적히는 값이라,
> 파생값을 표에 함께 그릴지 결정해야 한다.

### 임상가 관점 프로세스 리뷰

§11에서 임상가 2인 검토를 이미 받았고 §13에 적대적 재검증이 있다. **새로 쌓인 것**을
들고 다시 물어야 한다:

1. GHR/PHR 7단계 구현 (워크북 대조 완료, **실제 출력은 여전히 미검증**)
2. 평범반응 자동 제안 — "P 자리"만 알리고 판단은 사람이 하는 형태가 맞는지
3. 기록을 채점 단계에서도 고칠 수 있게 한 것(3번)이 임상적으로 괜찮은지
4. §12 "임상가에게 추가로 물을 것" 표 7·8·9·10번 (10번 = 도판 뒷면 카드 번호)
5. **AI 채점 자격을 "반응·질문·위치 셋 다"로 잡은 것**이 맞는지 — 질문을 생략하는
   반응이 실제로 있다면 그 반응은 영영 AI 채점을 못 받는다
6. **낡음 표시를 푸는 조건**이 "다시 저장"뿐인 것 — 오타 한 글자를 고쳐도 그
   반응을 다시 열어 저장해야 한다. 임상가가 번거로워할 수준인지
