# grok-stt-1.0은 한국어 실환경 회의 녹음에서 채택 문턱을 넘는 전사 품질·비용·지연을 낸다

벤더 벤치마크(WER 6.9%·엔티티 5.0%)는 영어 중심 — 한국어는 고자원 티어 밖 "long tail"이라
미보장([특성.md](../../knowledge/grok-stt-1.0/특성.md)). 이 가설은 행동 기전형이 아니라 **측정형**
— 판정 기준 v2는 준용: 페어드 = 같은 오디오에 모드만 변형, 그라운드트루스 전사 부재라 WER 불가
→ 판정은 모드 간 상호 CER + 반복 안정성 + 사람 검수(탐색 한계로 명시).

### 측정 설계 — 모드 4 × 판정 5

| 모드 | 경로 | 키 |
|---|---|---|
| batch-or | OpenRouter `/api/v1/audio/transcriptions` multipart | OPENROUTER_API_KEY ✓ 보유 |
| batch-xai | xAI 직결 `POST /v1/stt` (diarize·format 포함) | **XAI_API_KEY ✗ 미보유 — 차단** |
| stream-xai | xAI 직결 `wss /v1/stt` (pcm 16k, interim_results) | 〃 |

판정(report): ① 모드 간 상호 CER(공백 제거 문자 기준, difflib — jiwer 미설치·그라운드트루스 부재라
탐색용 근사) ② 같은 모드 K=3 반복 CER(안정성) ③ 지연 — batch wall-clock(**60s 업스트림 타임아웃
관측이 곧 체크리스트 3번 답**)·stream 첫 partial/final ④ 실비 usage.cost vs 예산 대조 ⑤ 앞부분
전사 사람 검수. 스트리밍 fast-pace(실시간 미준수) 시 지연 수치는 참고용으로 강등.

### 결과·판정 [탐색] — 2026-07-28 1라운드 (batch-or만, 지출 $0.035)

| 시행 | 오디오 | 결과 |
|---|---|---|
| 클립 K=3 | 300s | 286~289자 — **첫 ~60초 분량만 전사, 이후 유실**. 반복간 CER 0·0.012(절삭 지점 결정적) |
| probe 30s | 30s | 137자 = 완전 전사(~4.6자/s 요율) |
| probe 90s | 90s | 289자 — 300s 결과와 동일 텍스트(절삭 재현) |
| probe offset(120~180s) | 60s | 287자 = 완전 전사 — 300s 전문과 단어 겹침 2/33(뒷부분 유실 확증) |
| probe 무음60+발화60 | 120s | 178자 — 발화 구간 도중 정지 |

발견 4건:
- **F1 조용한 절삭** — 90초 이상 오디오에서 첫 ~60초 분량만 반환(경계는 60~90초 사이),
  HTTP 200·에러 무표시. 모르고 쓰면 조용한 데이터 유실.
- **F2 기전 불명** — 무음 프로브가 후보 기전 둘 다 기각: "60초 오디오 캡"(무음 뒤 발화가
  전사됨 = 60초 이후 커버)도, "~290자 출력 캡"(178자 정지)도 아님. 콘텐츠 의존 조기 종료 추정.
- **F3 과금은 입력 전체 길이** — 전사는 60초뿐인데 300초 청구. +단발 1건: 120.0초 파일에
  180초 청구(mp3 concat VBR 헤더 오파싱 가능성 — 재현 미시도).
- **F4 품질·안정성** — 완전 전사 구간의 한국어는 구어체·필러("어", "그러니까")·도메인 어휘(qa·UI)까지
  자연스러움(주관 검수). 반복 CER 0~0.012. 5분 클립 wall 1.7~2.8s.

**판정**: OpenRouter 경유 배치는 **60초 초과 녹음에 부적합** — 회의 녹음 용도는 xAI 직결(batch-xai)
검증 또는 60초 청킹 우회가 전제. 체크리스트 3번(길이 한계) 실측 완료, 1번(한국어 품질)은 상한 내
구간 양호. 실측 사실은 [계약.md](../../knowledge/grok-stt-1.0/계약.md)·[특성.md](../../knowledge/grok-stt-1.0/특성.md)에 승격.

### 2라운드 bench60 [탐색] — 60초 상한 안의 품질, 레퍼런스 삼각측량 (2026-07-28, 지출 ~$0.08)

그라운드트루스 부재 대체 설계: 회의 전역 60초 세그먼트 6개(0·5·10·20·30·38분) × 3모델
[grok vs whisper-1 vs gpt-4o-transcribe, 전부 `language=ko`] — 상호 CER로 이탈자 판정
(레퍼런스끼리의 CER이 "정상 불일치" 기준선).

| offset | grok↔whis | grok↔4o | whis↔4o | 판정 |
|---|---|---|---|---|
| 0 | 0.086 | 0.075 | 0.041 | 레퍼런스급 |
| 300 | 1.0 | 1.0 | 0.589 | **일본어 횡설수설 30자** (발화 희박 구간, 레퍼런스는 정상 한국어) |
| 600 | 1.0 | 0.984 | 0.148 | **영어 번역 출력** — 전사 아닌 통역(내용은 동일) |
| 1200 | 0.087 | 0.106 | 0.084 | 레퍼런스급 |
| 1800 | 0.162 | 0.158 | 0.076 | 기준선의 ~2배 열화 |
| 2280 | 0.390 | 0.320 | 0.187 | 난구간(전 모델 불일치) — grok 최하위 |

- **F5 언어 이탈** — `language=ko` 명시에도 6세그먼트 중 2곳(33%)에서 출력 언어가 이탈
  (일본어 환각·영어 번역). 벤더의 "mid-stream language switching" 자동 감지가 힌트를 누르는
  것으로 추정 — 단 OpenRouter가 `language`를 grok에 전달 안 하는 가능성(체크리스트 2번,
  passthrough 미보장)과 미분리. **판별은 직결 대조로만 가능(XAI 키)**.
- 품질 요약: 정상 4세그먼트에서 CER 0.08~0.39(기준선 0.04~0.19) — 깨끗한 오디오는 레퍼런스급,
  난구간일수록 열화 폭 큼. 실패 2세그먼트는 품질 이전의 모드 실패.
- 지연(60초 세그먼트): grok p50 1.22s(최속) · gpt-4o-transcribe 2.71s · whisper-1 3.25s.

### 3라운드 직결 대조 [탐색] — GROK_API_KEY 확보 (2026-07-28, 지출 ~$0.02)

`api.x.ai/v1/stt` 직결로 미분리 판별 전부 해소:

| 판별 | 결과 |
|---|---|
| 절삭이 OpenRouter 층인가 | **아니다 — 모델 자체.** 직결도 같은 5분 클립에서 동일 289자·동일 지점 절삭. `duration=300.1`(서버가 전체 수신 인지)인데 **words 마지막 timestamp = 62.56s** — 절삭 지점 실측(추정 63s 적중) |
| 언어 이탈이 passthrough 문제인가 | **아니다 — 모델 자체.** `language=ko` 직결에서도 재현: seg300 일본어(lang=ja, 40자)·seg600 한국어로 시작해 **출력 도중** 영어 번역으로 전환(mid-stream switch가 힌트를 누름) |
| diarize 실효 | 필드는 실존(words[].speaker)하나 다화자 대화 구간(120~180s)에서 **화자 1로 뭉갬** — 단발 관측, 분리 실패 여부는 명백한 다화자 프로브로 재확인 필요 |
| 부수 | `language` 응답 필드가 한국어 전사에 `en` 오표기 · 난구간 세그먼트는 60초 내에서도 조기 정지(25.5s·49.2s) |

**판정 갱신**: 두 핵심 결함(조용한 절삭 ~62.6s·언어 이탈)이 **경로 무관 모델 자체 성향** → "직결이면 해결"
가설 사망. 남은 우회는 60초 청킹뿐인데 언어 이탈 33%가 청크 단위로 재발할 것이므로 실익 의문.
