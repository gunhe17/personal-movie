# 바로링크 발송 양식

신규·재발송·일괄 발송은 `MessageTemplateFacade.get_rendered_send_link_template`를 사용한다.

## 본문 선택 순서

1. 해당 센터의 `assessment_send_link` 기본 양식
2. 시스템의 같은 유형 기본 양식
3. `message_template/constants.py`의 기본 본문

웹의 `/center/message-templates`에서 검사 링크 전송 기본 양식을 관리한다. 렌더링에는 `center_name`, `recipient_name`, `assessment_url`, `verification_code`를 전달한다. 실제 링크 또는 인증번호가 빠진 본문은 전송하지 않고 수신자별 실패로 반환한다.

바로링크 전송 모달에서 양식 선택·본문 미리보기·실제 전송 내역 확인이 가능하다. 신규 전송은 문자(SMS)가 기본이며 알림톡은 준비 중으로 비활성화한다. 내역의 재전송은 확인을 거쳐 기존 링크와 원래 채널을 유지하며 현재 선택한 양식을 적용한다.

신규·재발송·일괄 요청의 `template_id`가 있으면 해당 센터 또는 시스템의 검사 링크 전송 양식만 사용하며, 잘못된 ID나 다른 유형은 기본 양식으로 조용히 대체하지 않는다. ID를 생략하면 위 기본 순서를 따른다. 선택 ID는 이번 발송 요청에 적용되며 링크에 영구 저장되지는 않는다. 재발송에서도 특정 양식을 유지하려면 `template_id`를 명시해야 한다.

## 카카오 승인 코드와 관리 양식의 차이

관리 화면은 본문을 관리하며, 카카오 승인 템플릿을 등록하거나 승인 코드를 수정하는 기능은 아니다. 발송 코드는 `HARDCODED_TEMPLATE_CODES[TemplateType.ASSESSMENT_SEND_LINK]`에서 공통으로 가져온다. 기존 중복 발송 코드 `SEND_LINK_01`은 제거했다.

현재 공통 매핑의 `TPDuXP9p9H`가 현 발신 프로필에서 승인된 코드인지는 외부 발송 서비스에서 확인해야 한다. 본문·변수 형식 역시 승인 내용과 일치해야 하며, 이번 코드 변경이 외부 승인을 보장하지 않는다. 다른 승인 코드를 사용한다면 공통 매핑을 갱신한다. 센터별 별도 승인 코드 선택은 현재 지원하지 않는다.

알림톡 실패 시 SMS 자동 대체 발송은 이번 변경에 포함하지 않는다. 링크 생성 성공과 메시지 발송 성공은 별개다. 실패했다고 신규 링크를 반복 생성하면 이전 활성 링크가 폐기되므로 기존 링크의 재발송 API 사용을 우선 검토한다.

## 검증

`python -m pytest tests/test_send_link_templates.py -q`

센터/시스템/기본 양식 우선순위, 링크·인증번호 누락 차단, 신규·재발송·일괄 발송 연결을 모의 객체로 검사한다. 실제 메시지 발송·운영 DB 변경은 하지 않는다.
