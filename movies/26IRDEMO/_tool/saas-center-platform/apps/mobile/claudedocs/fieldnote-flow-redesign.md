# 필드노트 녹음→분석 근본 흐름 재설계

> 작성: 2026-06-02 · 상태: 탐색(랩 시안과 짝) · 대상: CTO 검토
> 짝 산출물: `app/(main)/lab/field-note-flow.tsx` (인터랙티브 워크스루 — 현재/A/B/C)

## 한눈에 (TL;DR)

- **문제(CTO):** ① 정지하면 곧바로 분석으로 점프 ② 뒤로가기 목적지가 부자연스러움.
- **근본 원인:** 한 화면이 7모드(`recording→processing→completed…`)로 변형되는 **"화면=상태머신"** → capture와 review 경계가 없고, 뒤로가기는 늘 전체 탈출.
- **핵심 해법 둘:**
  1. **처리를 "화면"에서 "상태"로 내린다.** 정지=저장 후 목록/장소로 복귀, 처리는 백그라운드+알림(이미 `ProcessingHost` 지원). 어떤 녹음·전사 앱도 사용자를 처리화면에 가두지 않음.
  2. **분석을 두 층위로 쪼갠다.** 전사·화자분리=가벼운 기반(자동), AI 요약·일지초안=무거운 선택(원할 때 호출). 분석을 강제하지 않는다.
- **권장:** 단기 **대안 A**(≈클로바노트, 최소 변경) → 중기 B → 장기 C.

## 1. 문제

CTO 피드백 — 필드노트의 **녹음 → 분석 → 검토** 흐름이 어색하다.

1. **정지하면 곧바로 분석으로 점프.** 회기를 막 끝낸 순간 곧장 처리 스피너로 빨려 들어감. 숨 고를 틈도, "저장됐다"는 확정 피드백도 없음.
2. **뒤로가기 목적지가 부자연스러움.** 어느 화면에서든 뒤로가기가 어디로 가는지 예측이 안 됨.

표면(색·간격)이 아니라 **흐름(내비게이션·전환·결정 시점)** 의 문제.

## 2. 상담사는 이걸 실제로 어떻게 쓰나 (페르소나)

- **회기 중(40~50분):** 폰은 책상에 내려놓고 내담자(특히 아동)에게 100% 집중. 화면을 보거나 버튼 누를 여유 없음.
- **회기 직후(쉬는 10분):** 정신적으로 소진된 채 방 정리 + 다음 내담자·보호자 맞이. 이 순간 "지금 분석할까요? 옵션 고르세요"는 부담.
- **나중(저녁/다음 회기 직전):** 차분히 앉아 **상담일지를 쓰거나** 그 내담자 맥락을 떠올림. **검토는 이때** 일어남.
- **녹음은 목적이 아니라 수단.** "기억에 의존해 일지를 안 써도 되게." 상담 녹음은 민감 → "분명히 저장됐다"는 신뢰가 중요.

**상담사가 불편하지 않으려면 필요한 5가지:**

| # | 필요 | 의미 | 현재 |
|---|------|------|------|
| 1 | 시작은 거의 0마찰 | 한 손 한 번, 이미 그 회기에 연결, 고를 것 없음 | △ |
| 2 | 회기 중엔 안 보이게 | 글랜스만, 조작 요구 안 함 | △ |
| 3 | 정지 = "끝났고 저장됐다, 가도 된다" | 결정·대기 강요 없음 | **✗** |
| 4 | 처리는 알아서, 끝나면 알림 | 스피너 옆에서 지키지 않음 · 강제 분석 없음 | **✗** |
| 5 | 검토는 따로, 내가 앉을 때 | 일지 쓰는 순간이 곧 검토 | **✗** |

현재 구현은 **3·4·5에서 어긋난다.** 정지하면 스피너에 갇히고(3·4), 녹음→분석→검토가 한 화면에 붙어 "따로 앉아 검토"라는 맥락이 없다(5).

## 3. 비슷한 앱들은 어떻게 흐르나 (업계 표준)

앱이 달라도 뼈대는 동일하다. 한 문장:

> **정지 = 그냥 목록에 저장됨 → 처리는 백그라운드 → 끝나면 알림 → 검토는 내가 열어볼 때.**
> **어떤 앱도 "처리 중" 전체화면에 사용자를 가두지 않는다.**

- **클로바노트(국내 표준):** 멈추면 노트가 **"변환중" 상태로 목록에 바로 생기고** 변환은 백그라운드(화면 꺼져도 계속). 1시간 분량 3~5분, **완료 알림**. → 우리 **대안 A**와 거의 동일.
- **Otter.ai:** 녹음 **중 전사가 실시간**으로 흐르고, 멈추면 최종 전사 1.5~3분·요약 2.5~6분 뒤 **"요약 탭"이 알아서 채워짐.** → 전사=중에, 요약=끝난 뒤 비동기.
- **Granola:** 회기 중 **녹음이 배경에서 조용히** 돌고, 끝난 **뒤** AI가 전사를 정리해 노트로 "보강(enhance)". 끝난 뒤 보강이 곧 별도 검토 비트. → **대안 B·C**의 발상.
- **Plaud:** 녹음은 하드웨어 버튼, 검토는 앱 — **포착과 검토를 물리적으로 분리.** → "포착≠검토"의 극단.

핵심: **누구도 "멈추자마자 처리 스피너에 가두기"를 하지 않는다.** 멈춤은 저장일 뿐, 처리는 "화면"이 아니라 목록 항목의 **상태 배지**다.

## 4. "분석"은 어떻게 도나 — 두 층위로 분리 (중요)

**분석은 한 덩어리가 아니다. 강제할 이유도 없다.** 상담사 피드백 — "꼭 분석을 강제할 필요 없다, 저장만 해도 된다." 이를 받아 **분석을 두 층위로 쪼갠다.**

| 층위 | 무엇 | 무게 | 기본값 |
|------|------|------|--------|
| **기반** | **전사 + 화자 분리** — 녹음을 '읽을 수 있게' | 가벼움 | **자동** (정지 후 백그라운드) |
| **AI 분석** | **요약 + 일지 초안** — LLM 해석/생성 | 무거움·비용↑ | **선택** (원할 때 호출, 강제 X) |

- **저장은 늘 1급 결과.** 정지 = 저장. 그 위에 전사·화자분리가 자동으로 얹혀 "들을 수 있는 녹음 → 읽을 수 있는 대화"가 된다.
- **AI 요약·일지 초안은 사용자가 부를 때만.** 그 진짜 효용은 "일지 쓸 때"이므로, 그 순간에 '만들기'를 누른다(P5: 결정은 의도의 순간에). 매 회기 자동으로 LLM을 태우지 않는다 — 비용·민감도·presumption 회피.
- **이건 회의 앱(클로바노트·Otter)과의 차이.** 거긴 전사가 목적이라 정지=자동 전사가 맞지만, 필드노트는 녹음 자체가 1급 가치이고 AI는 한 용도일 뿐.

**백엔드 매핑 — 이미 분리돼 있음 (새로 안 만들어도 됨)**
- 기반: `processing_step` 의 `transcribing`·`refining` (전사·화자 정리) — `ProcessingHost` 백그라운드 폴링 + 토스트.
- AI: `summarizing`·`generating_note` 는 `summary_status`·`note_status` 로 **별도 상태**, `generateSummary()`·`generateCounselingNote()` 로 **개별 호출**. 오케스트레이터의 `isPostCompletionSummaryRun`(전사 끝난 뒤 요약만 도는 케이스)도 이미 존재.
- (참고) 전사조차 원치 않는 순수 저장은 기존 `skipPipeline`(`processing_status:'skipped'`)로 가능 — 센터/개인 설정의 여지로 남김.

**산출물 위계:** 전사·화자분리(기반) → 요약(자연문, `summary`) → **상담일지 초안**(`상담일지 초안 생성`) ← 상담사에게 가장 가치 있는 최종 산출물. 뒤 둘은 opt-in.

## 5. 근본 원인 — "화면 = 상태머신"

`useFieldNoteOrchestrator.ts` + `FieldNoteDetailView.tsx` 가 **한 화면**을 7개 모드로 다시 그린다.

```
new · resume · recording · processing · pending_analysis · completed · failed
        └────────────── 모두 같은 한 화면이 변형 ──────────────┘
```

| 마찰 | 설명 |
|------|------|
| **장소 감각 부재** | 같은 화면이 발밑에서 변형 → "어디 있고 뒤로가기가 어디로 갈지" 모델이 안 섬. 뒤로가기는 늘 `router.back()`(전체 탈출). |
| **capture/review 융합** | "정지→처리→완료"로 끊김 없이 이어져 "회기가 끝났다"는 박자가 없음. |
| **최악의 순간에 결정 강요** | `StopConfirmModal`이 정지 직후 파이프라인 옵션을 물음(시스템 관심사 누출). |
| **비동기인데 화면을 가둠** | `ProcessingScreen`이 뒤로가기 비활성 풀스크린 점유. 백엔드·`ProcessingHost`는 이미 백그라운드 지원 — 가두는 건 사실과도 안 맞고 답답함. |

## 6. 재설계 인지 원칙

- **P1. capture와 review를 별개의 장소로 분리.**
- **P2. 정지 ≠ 분석 확정** — 정지는 "포착 끝" = **저장**. 전사·화자분리만 자동 백그라운드, AI 요약·일지초안은 강제하지 않음(원할 때 호출).
- **P3. 비동기 작업에 사용자를 가두지 않음** — 이해되는 장소(목록/일정)로 복귀, 처리는 비차단.
- **P4. 뒤로가기는 공간적 약속** — 온 곳으로. 저장 뒤엔 늘 안전.
- **P5. 결정은 의도의 순간에** — 회기 연결·AI 분석 호출은 검토 맥락으로(정지 순간으로 욱여넣지 않음).
- **P6. 회기의 물리적 현실에 맞춤** — 녹음을 "요구하는 화면"보다 "주변 상태"로.

## 7. 세 대안 (각각 실제 앱 패턴에 대응)

### 대안 A — 마무리 & 백그라운드 (≈ 클로바노트) · 권장·최소 변경
```
녹음 ──정지──▶ [마무리 시트]        목록 복귀          (전사 완료 토스트)
              "녹음 마칠까요?"   ┌──────────────┐      ┌──────────────┐
              · 녹음 마치기  ──▶ │ ○○ 전사 중…  │ ──▶ │ ○○ 전사됨    │──▶ 노트(AI는 버튼)
              · 이어서 녹음      │ (백그라운드) │      │   + 토스트   │
              · 삭제            └──────────────┘      └──────────────┘
```
- 정지 → 파이프라인 옵션이 아닌 **차분한 "마무리" 시트** → 저장 + **전사·화자분리 백그라운드**(AI는 노트에서 따로) + **목록 복귀**(상단 "전사중" 카드, `ProcessingHost` 재사용). **풀스크린 처리 제거.**
- 장점: 변경 면적 작음, 두 불만 직답. 단점: 녹음이 여전히 화면 점유, review는 기존 완료 화면 그대로.

### 대안 B — 검토 대기실 (≈ Granola enhance) · 상세

**핵심 발상:** "정리 화면"과 "완료 노트"는 **별개 화면이 아니라 같은 한 장소**가 시간이 지나며 자라나는 것. 화면 수를 늘리는 게 아니라 **장소 하나에 시간축을 부여**한다.

```
녹음 ─정지─▶ ┌──────────────────────── 녹음 정리 (한 장소) ────────────────────────┐
            │ raw(방금 담음) ─(전사·화자분리 자동/백그라운드)─▶ transcribed(대화+메모) │
            │                                          └─[AI 만들기 누를 때]─▶ ai(요약·일지초안) │
            └────────────┬──────────────────────────────────────▲──────────────────┘
                   뒤로=목록(안전)                          알림 오면 같은 곳으로
```

**장소의 생애주기 (한 화면, 세 상태 — §4 두 층위 반영)**

| 상태 | 보이는 것 | 뒤로가기 |
|------|-----------|----------|
| **raw — 방금 담음** | ① "담겼어요 · 12:47" 저장 안도 ② 회기 연결 칩(연결됨 / quick면 "회기 연결하기") ③ **전사·화자 정리 중** 백그라운드 배너(AI 아님) ④ **한마디 더**(회기 직후 휘발성 생각) ⑤ 내가 담은 것(메모·태그) | 목록 — 이미 저장, 안전 |
| **transcribed — 전사·화자분리 완료** | 같은 장소가 자라남: **화자 분리 대화 타임라인**(상담사/내담자) + 메모. **AI 분석은 비어 있고 '만들기' 버튼**([AI 요약 만들기] / [일지 초안 만들기]) — opt-in | 목록 — 예측 가능 |
| **ai — AI 호출 후** | 사용자가 버튼을 누르면(보통 일지 쓸 때) 요약 + 일지 초안이 채워짐 | 목록 |

> **핵심:** 전사·화자분리(기반)는 자동으로 차오르지만, **AI 요약·일지 초안은 강제하지 않고 '만들기' 버튼**으로 둔다. 정리 화면이 곧 "AI를 부를지 결정하는 곳"이 된다 — 담은 걸 보고 차분히 고름.

**구체화 포인트 (A와 다른 점)**
- **머무를 수 있는 장소** — A의 "마무리 시트(한 번 확인하고 닫힘)"를 **체류 가능한 장소**로 승격. 회기 직후 10분의 인지 박자("끝났다 → 내가 뭘 담았나")를 채운다.
- **결정은 여기서(P5)** — 회기 연결, **AI 요약·일지 초안을 부를지** 같은 결정을 정지 순간이 아니라 **차분한 정리 맥락**에서 한다. 전사·화자분리는 자동이라 결정 대상이 아님.
- **한마디 더** — 상담 직후의 휘발성 통찰("오늘은 전환점 같았다")을 그 자리에서 포착. 녹음 본문과 별개로 노트에 붙는다. (기존 `entry`/메모 모델 재사용)
- **나갔다 되돌아오기** — 기다릴 필요 없이 목록으로 나가도 되고(가둠 없음), 알림이 오면 **같은 장소로 복귀**해 검토. CTO 불만 ②(뒤로가기)를 정면 해소.
- **진입 모드 2가지** — 일정 연결(이미 회기에 붙음) / quick(미연결). quick일 때 정리 화면이 회기 연결을 권하는 자연스러운 지점.

**매핑(데이터·인프라 재사용 — §4 두 층위)**
- raw = `status:'completed'` + 기반(`transcribing`·`refining`) 백그라운드(`ProcessingHost`). (전사조차 원치 않으면 `skipPipeline`.)
- transcribed = 전사·화자분리 완료 → 화자 분리 대화 타임라인 + 메모. **AI 영역은 `summary_status:'none'`** → "만들기" 버튼.
- ai = 버튼 → `generateSummary()` / `generateCounselingNote()` 호출(opt-in). `isPostCompletionSummaryRun` 으로 전체화면 전환 없이 AI 탭 안에서 로딩.
- "한마디 더"·회기 연결 = 기존 `addEntry`·`linkSchedule` 그대로.

- 장점: 인지 일치 최강("끝났다→뭘 담았나→반추"), 회기 직후 결정을 자연 맥락에서, 뒤로가기 완전 해소. 단점: 정리 화면이 과속방지턱이 아니라 가치 있게 느껴지도록 ①②④ 같은 실제 효용을 채워야 함.

### 대안 C — 라이브 바 (≈ Granola/Plaud ambient)
```
[FAB/일정] ─▶ 녹음 = 상단 라이브 바 (앱 자유 이동)
   ┌────────────────────────────────┐
   │ ● 12:47  ▮▮▮▮  ⏸  ■           │
   └────────────────────────────────┘
   정지 ─▶ 바가 "○○ 전사 중…" pill 로 축소 ─▶ 토스트 + 목록 카드 (AI는 노트에서 따로)
   뒤로가기 = 늘 자연스러움 (녹음이 내비 스택 미점유)
```
- 녹음 = 통화/재생처럼 진행 중 활동. 정지 → 인라인 확정 + pill 축소.
- 장점: 물리 현실 최일치, **"녹음에서 뒤로가기" 문제를 설계로 소거.** 단점: 변경 가장 큼(단 `RecordingHost`가 이미 전역).

## 8. 뒤로가기 목적지 비교

| 단계 | 현재 | A | B | C |
|------|------|---|---|---|
| 녹음 중 | 확인 모달 → 전체 탈출 | 마무리 시트 | 확인 후 정리로 | 앱 화면 사이 — 점유 안 함 |
| 정지 직후 | 처리에 **갇힘** | 목록(백그라운드) | 녹음 정리 → 목록 안전 | pill 축소, 어디든 |
| 처리 중 | 〃 갇힘 | 목록 자유 | 정리/목록 자유 | 자유 — 가둘 화면 없음 |
| 검토 | `router.back()` 불명확 | 목록 | 정리/목록 예측 가능 | 목록 |

## 9. 7-모드 → 장소 매핑

| 현재 모드 | A | B | C |
|-----------|---|---|---|
| recording / resume | 녹음 화면 | 녹음(장소1) | 라이브 바 / 펼친 녹음 |
| processing · **전사·화자(자동)** | 목록 "전사중" 카드 | 정리 화면 백그라운드 배너 | 라이브 "전사중" pill |
| processing · **AI 요약·일지(선택)** | 노트의 "AI 만들기" 버튼 | 정리 화면 "AI 만들기" 버튼 | 노트의 "AI 만들기" 버튼 |
| pending_analysis (저장만) | 목록 카드(전사만) | 정리 화면 그대로 | 목록 카드 |
| completed | 완료 상세 | 정리 = 노트(같은 장소) | 완료 상세 |
| failed | 목록 카드 재시도 | 정리/노트 재시도 | pill 재시도 |

→ 공통 전환 둘: **① processing이 "화면"에서 "상태"로 내려감 ② 무거운 AI는 "자동 단계"에서 "노트의 버튼"으로 내려가며 강제 해제.**

## 10. 권장 (단계적)

1. **단기 — 대안 A.** 저위험·고효과. 클로바노트와 동일 모델. 풀스크린 점유 제거 + 정지 후 목록 복귀 + 마무리 시트 + (전사 자동 / AI는 노트 버튼)만으로 두 불만 직답. `ProcessingHost` 인프라 그대로 활용.
2. **중기 — 대안 B.** capture/review 인지 박자를 "녹음 정리" 장소로 명확히. Granola의 enhance 비트 + 두 층위(전사 자동 / AI opt-in)를 화면으로 구현.
3. **장기 — 대안 C.** 녹음을 ambient로 — "녹음에서 뒤로가기" 문제의 근원 제거.
