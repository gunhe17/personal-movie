# 리빙랩 대비 웹 점검 — 시나리오·질문 리스트 (v0 초안)

> 2026-08 중순 센터 대상 리빙랩 대비. 관리자·상담사 실사용 시나리오를 먼저 정의하고,
> 각 시나리오가 코드에서 실제로 어떻게 동작하는지 A-Z 추적해 의도-구현 갭을 찾는다.
> 상태: **v0 — 시나리오 뼈대 + 자체 질문 리스트.** 코드 조사 결과로 `01-시나리오별-동작정의.md`에 답을 채운다.

## 점검 원칙

- 일차원(화면 단위) 점검 금지 — 사용자의 목적 단위(시나리오)로 묶어서 흐름 전체를 본다.
- 두 주체 분리: **관리자(manager)** = 센터 운영·멤버·수납·구독, **상담사(counselor)** = 내 일정·내 내담자·상담 기록·검사.
- 각 시나리오마다 ① 실제 동작 정의 ② 의도 대비 갭 ③ 사용성 모호 지점 ④ 리빙랩 전 수정 필요 여부를 판정한다.

---

## A. 관리자(manager) 시나리오

### A1. 센터 개설과 초기 세팅
가입 → 센터 등록 → 센터 정보 입력 → 상담사 초대 → 첫 사용 준비 완료까지.
- Q1. signup → welcome/register 흐름에서 센터 생성 시 무엇을 입력하는가? 건너뛸 수 있는 항목은?
- Q2. 멤버 초대는 어떤 방식(이메일? 링크?)이고, 초대받은 상담사의 합류 경험(accept-invitation)은 어떤가?
- Q3. 초기 세팅이 끝났는지 사용자가 알 수 있는가(온보딩 가이드/체크리스트 존재 여부)?

### A2. 신규 문의 접수 → 배정 → 첫 일정
전화로 들어온 신규 문의를 접수하고 상담사를 배정해 첫 상담 일정을 잡는다.
- Q4. 접수 진입점이 몇 개인가? `operation/receive`와 `counseling/receive`의 차이는 무엇이고 사용자가 구분할 수 있는가?
- Q5. 접수 시 내담자가 아직 등록 전이면? (접수와 내담자 등록의 선후 관계)
- Q6. 상담사 배정은 어디서 하고, 배정 시 상담사 일정 충돌을 시스템이 막아주는가?
- Q7. 접수의 상태값(대기/확정/취소 등)은 무엇이고 상태 전환은 누가 어디서 하는가?

### A3. 하루 시작 — 센터 전체 현황 파악
아침에 로그인해서 오늘 센터에 무슨 일이 있는지 3분 안에 파악한다.
- Q8. 로그인 직후 첫 화면은 무엇이고, 관리자에게 필요한 정보(오늘 전체 일정, 미처리 접수, 미수납)가 보이는가?
- Q9. 대시보드 위젯은 실데이터인가 더미인가? 역할별로 다른가?

### A4. 수납·청구 처리
상담 완료 후 상담비를 수납하고, 바우처 내담자는 회기를 차감한다.
- Q10. billing 화면이 다루는 범위는? (청구 생성/수납 기록/미수금 관리 중 무엇이 되는가)
- Q11. 바우처 차감은 세션 완료와 자동 연동되는가, 수동인가?
- Q12. price-list(단가표)는 어디에 쓰이는가 — 접수·청구와 연결되는가?

### A5. 검사지 구매·검사 운영
- Q13. 검사 구매(purchase) 모델은? 크레딧인가 건별인가, 실결제가 붙어 있는가?
- Q14. 검사 접수/전송/결과의 관리자 관점 흐름과 상담사 관점 흐름이 어떻게 다른가?

### A6. 멤버·구독 관리
- Q15. 상담사 퇴사 처리(비활성화)가 가능한가? 그 상담사의 내담자·일정은 어떻게 되는가?
- Q16. subscription과 settings/subscription이 왜 둘 다 있는가? (중복 의심)

## B. 상담사(counselor) 시나리오

### B1. 하루 시작 — 내 일정 확인
- Q17. 상담사 로그인 첫 화면에서 "오늘 내 상담"이 바로 보이는가?
- Q18. 상담사는 자기 일정만 보는가, 센터 전체 일정도 보이는가? (의도가 무엇인지 포함)

### B2. 세션 수행 — 사전 확인 → 상담 → 기록
세션 직전 내담자 히스토리를 훑고, 상담 후 일지(필드노트)를 쓴다.
- Q19. 일정에서 세션 상세로, 세션에서 내담자 상세로 이동이 자연스러운가(클릭 몇 번)?
- Q20. 세션 기록 작성 흐름: 수기 일지와 AI 필드노트(agent/session)의 관계는? 어느 쪽이 기본 동선인가?
- Q21. 세션 완료 처리는 명시적인가? 완료 시 무엇이 연쇄되는가(수납 대기, 바우처 차감, 다음 일정)?

### B3. 내담자 등록·관리
- Q22. 상담사가 내담자를 직접 등록할 수 있는가, 관리자만인가?
- Q23. 보호자 연결(role="both" 포함) 입력 UX가 실제 시나리오(아동 내담자+모 보호자)를 커버하는가?
- Q24. 상담사는 자기 담당 내담자만 보는가? 담당 개념이 코드에 존재하는가?

### B4. 검사 의뢰 → 수행 → 결과 확인
- Q25. 검사 링크는 어떻게 내담자에게 전달되는가? 내담자 수행 경로(/assessment-flow)는 로그인이 필요한가?
- Q26. 결과가 도착하면 상담사는 어떻게 아는가(알림?) 결과는 어디서 보는가?
- Q27. assessment와 assessment-case의 관계는? 사용자에게 두 개념이 노출되는가?

### B5. 일정 변경·취소
- Q28. 내담자 노쇼/변경 시 처리 동선은? 취소 사유 기록, 반복 일정의 단건 변경이 되는가?

## C. 횡단 질문 (메뉴·정보구조)

- Q29. 사이드바 메뉴 트리 전체와 역할별 노출 차이는? 메뉴 순서가 사용 빈도와 맞는가?
- Q30. "접수"가 메뉴 어디에 몇 번 나오는가? (operation vs counseling vs assessment 접수의 중복/혼란)
- Q31. 라우트는 있으나 메뉴에 없는 화면(고아 화면), 메뉴는 있으나 비어있는 화면은?
- Q32. counselor가 manager 전용 URL에 직접 접근하면 어떻게 되는가(가드 존재 여부)?
- Q33. myInfo / settings / center 세 곳의 설정 경계가 사용자에게 예측 가능한가?
- Q34. 알림(notifications)은 어떤 이벤트에 실제로 발생하는가? 리빙랩에서 "알림이 안 와요"가 나올 지점은?
