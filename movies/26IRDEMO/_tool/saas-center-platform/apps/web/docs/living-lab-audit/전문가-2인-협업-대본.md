# 전문가 2인 협업 — 평가 대본 (팀 운영 축)

> 2026-07-23 설계. 목적: 상담사 1명 관점("상담사의 하루")에선 드러나지 않는 **팀 운영의 4축** — 데이터 격리·자원 경쟁·공동 작업·담당 이관 — 을 검증한다.
> 지금까지: 도입(관리자축)·한 달 운영(관리자축)·하루(상담사 1인축) 완주. 이 대본은 **상담사가 둘일 때만 나타나는 문제**를 본다.
> 평가 환경: 스테이징 온빛심리상담센터. 상담사 A=이봄결(기존, 아동 놀이치료), 상담사 B=정하윤(신규, 부모 상담), 관리자=김온빛.

## 왜 2명인가 — 1명 시나리오가 못 보는 것

| 축 | 1명이면 안 보이는 이유 | 판단 질문 |
|---|---|---|
| 데이터 격리 | 볼 것만 있으니 "안 보여야 할 것"이 검증 안 됨 | B가 A의 내담자·케이스·청구를 못 보는가 (개인정보·업무 경계) |
| 자원 경쟁 | 혼자면 방·시간이 겹칠 일이 없음 | 같은 상담실 같은 시간 예약 시 경고되는가 (이중배정=경고 후 강행 정책) |
| 공동 작업 | 협업 대상이 없음 | 주담당+보조가 한 회기를 볼 때 양쪽에서 일관된가 |
| 담당 이관 | 넘길 사람이 없음 | 케이스를 B로 넘기면 A에서 사라지고 B에 나타나는가 |

## 등장 데이터

| 구성원 | 역할 | 담당 |
|---|---|---|
| 김온빛 | 관리자 | 팀 조망 (담당자별 필터·센터 전체 신호) |
| 이봄결 (A) | 전문가 | 기존 케이스(서은우·이도윤·한지우·김하람) |
| 정하윤 (B) | 전문가 (신규) | 이번에 합류 → 신규 케이스 + A에게서 이관받은 1건 |

## 장면

### S1. B 합류 (관리자 — 웹)
대표가 정하윤 초대(onbit-c2@stg-test.com, 전문가) → 수락(초대 토큰 직접 진입, 신규 가입) → 구성원 3명 확인.
- 판단: 초대·수락이 07-21 P3 검증분과 동일하게 동작하는가 (회귀 없음).

### S2. 자원 경쟁 — 이중 배정 (관리자/B — 웹)
대표가 B(정하윤)에게 신규 내담자 접수: **A의 기존 회기와 같은 상담실·같은 시간대**(예: 이도윤이 쓰는 화 14:00 놀이치료실에 겹치게) → **충돌 경고 확인** → 강행 선택(정책: 경고 후 강행) → 캘린더 장소별 뷰에서 두 회기가 같은 칸에 어떻게 보이는가.
- 판단: 충돌이 경고되는가. 강행이 되는가. 겹친 일정이 시각적으로 구분되는가.

### S3. 데이터 격리 (B 시점 — 웹, 상담사 로그인)
정하윤으로 로그인 → ① 내담자 목록: **본인 담당만**(A의 서은우·이도윤 등 안 보임) → ② 상담 현황: 본인 케이스만 → ③ 청구: 본인 담당만(access_level=own) → ④ 대시보드: 본인 신호만(A의 미작성 일지·연장 신호 안 보임) → ⑤ 전체 내담자 탭이 있으면 라벨("센터 전체" vs "내 담당") 명확한가.
- 판단: 안 보여야 할 것이 안 보이는가. 경계가 사용자에게 명확한가.

### S4. 공동 케이스 — 주담당+보조 (관리자 → A·B 시점)
그룹/동반 회기 구성: 대표가 케이스에 **A 주담당 + B 보조 치료사** 지정(회기 추가 모달의 복수 담당자·왕관 지정 — 한 달 시뮬 B4에서 확인된 기능) → ① A 시점: 이 케이스가 보이는가 ② B 시점: 보조인 이 케이스가 보이는가(보조도 담당 스코프에 드는가) → 회기 완료·일지 작성 시 작성자 구분.
- 판단: 공동 케이스가 양쪽에서 보이는가. 보조 상담사의 접근 범위가 합리적인가.

### S5. 담당 이관 (관리자 → A·B 시점)
대표가 A의 케이스 1건(예: 한지우 부모 상담)을 **담당자 B로 변경** → ① A 상담 현황: 사라지는가 ② B 상담 현황: 나타나는가 ③ 과거 일지·기록의 작성자는 유지되는가(A가 쓴 일지가 B에게 넘어가도 작성자=A) ④ 관련 신호(미작성·연장)가 B로 이동하는가.
- 판단: 이관이 깔끔한가. 과거 기록의 귀속이 보존되는가.

### S6. 관리자 조망 (관리자 — 웹)
대표가 ① 캘린더 담당자별 뷰(A·B 2열) ② 상담 현황 담당자 필터 ③ 대시보드가 센터 전체 신호(두 상담사 합산) ④ 구성원별 업무량 파악 가능 여부.
- 판단: 관리자가 팀 전체를 한눈에 보는가. 개별 상담사로 좁혀 볼 수 있는가.

## 검증 지표

| 지표 | 통과 기준 |
|---|---|
| 격리 | B가 A의 데이터에 도달하는 경로가 없다 (목록·상세·URL 직접 접근 모두) |
| 경쟁 | 충돌 경고가 뜨고, 강행 선택지가 있다 (차단 아님) |
| 협업 | 공동 케이스가 주담당·보조 양쪽에서 일관되게 보인다 |
| 이관 | 담당 변경 후 목록 귀속이 바뀌되 과거 기록 작성자는 보존된다 |
| 조망 | 관리자가 담당자별로 분리·합산 조회 가능하다 |

## 리빙랩 운영 메모
