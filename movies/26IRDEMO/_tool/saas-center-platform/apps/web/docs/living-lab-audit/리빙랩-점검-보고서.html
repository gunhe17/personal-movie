0.전제 — 전체 구조 한 장 요약

  • 로그인 후 첫 화면은 대시보드가 아니라 캘린더 (/schedule/calendar). 대시보드 메뉴는 따로 있다.
  • 메뉴 노출은 역할 하드코딩 + 권한 2계층 — 상담사는 설정·구성원·청구가 코드로 완전 숨김, 관리자는 권한으로만 판단.
  • 상담사의 데이터 격리(내 담당만)는 백엔드가 조용히 처리 — 화면에는 아무 표시가 없다.
  • 환경별 숨김: AI 에이전트(프로덕션 숨김) · 필드노트(전 환경 숨김) · 문서양식(프로덕션 숨김) → 리빙랩에서 AI 동선은 없음.

A.관리자 시나리오 — 실제 동작

A1. 센터 개설과 초기 세팅

가입 → 센터 생성 → 멤버 초대 → 첫 사용 준비까지
가입(/signup) → 센터 목록(/welcome) → 센터 생성(/welcome/register: 이름·전화·주소·대표자) → 캘린더 진입
Q1센터 생성 때 뭘 입력하나?
기본 정보만. 운영시간·상담실·프로그램·단가는 생성 후 설정 메뉴에서 각자 찾아야 하고, 어떤 안내도 없다.
Q2멤버 초대는 어떻게 되나?
이메일 초대 → 대기 탭에서 만료일(D-3)·재전송 관리 → 수락하면 센터 자동 선택까지. 흐름 자체는 완결. 엑셀 일괄 초대 버튼은 비활성.
Q3세팅이 끝났는지 알 수 있나?
온보딩 가이드·체크리스트 없음. 생성 직후 빈 캘린더에 떨어진다.
⚠ 갭
리빙랩 첫 세션에서 "가입은 했는데 다음에 뭘 해야 하나"가 나올 확률이 매우 높다. 최소한 빈 캘린더에 세팅 순서(상담실 → 프로그램 → 단가 → 멤버) 가이드가 필요. P1-1

A2. 신규 문의 접수 → 상담사 배정 → 첫 일정

전화로 온 신규 문의를 접수하고 첫 상담을 잡는다
상담 현황 [상담 접수하기] → 접수 폼(유형→내담자→상담사→프로그램→일정→메모) → 케이스+회기 일괄 생성 → SMS 알림
Q4접수 진입점이 몇 개인가?
3개가 따로 논다 — 상담 접수 / 검사 접수 / 운영 일정 등록. 사이드바에 "접수" 메뉴는 없고 각 화면 버튼으로 진입. 캘린더에서 상담 예약을 바로 잡는 동선은 없다 (캘린더의 등록 버튼은 운영 일정용).
Q5내담자가 등록 전이면?
접수 폼 안에서 인라인 등록 가능. 문제 없음.
Q6배정 시 충돌을 막아주나?
장소 충돌만 검사한다. 같은 상담사를 같은 시각 두 방에 배정해도 경고가 전혀 없다. 충돌이 있어도 경고만 하고 제출은 막지 않는 정책(이 정책 자체는 합리적).
Q7접수 상태값은?
케이스: 진행중→종결(되돌리기 가능)/취소. 회기: 예정→완료/노쇼/취소(사유+보충회기 옵션). 회기 상태 바꾸면 참석자 출석도 일괄 동기화. 5분 내 동일 조건 중복 접수는 409로 차단(상담만).
⚠ 갭
  • 상담사 이중 배정 무검사 — 실운영에서 가장 먼저 터질 지점. P0-2
  • 검사 접수는 충돌을 검사해놓고 응답에 경고를 안 담아서 사용자가 모른다(상담 접수는 담음). P0-6
  • "아직 상담인지 검사인지 모르는" 신규 문의를 받는 통합 인입점이 없다. P1-4

A3. 하루 시작 — 센터 전체 현황 파악

아침 로그인 후 3분 안에 오늘 상황 파악
Q8첫 화면에서 필요한 게 보이나?
첫 화면은 캘린더 — 오늘 일정은 보이지만 "밀린 일" 신호는 없다. 미청구 세션은 청구 화면 배너에, 소진·만료 임박 바우처는 대시보드에, 미처리 회기·연장/종결 확인은 상담 현황에 — 4개 화면에 분산.
Q9대시보드는 실데이터인가?
대시보드 본체(다음 일정 히어로·바우처 신호·공지)는 실데이터. 단 역할 구분이 없어 관리자용 운영 신호가 없다. 하위 analytics 페이지는 전부 더미("-" 표시 + "차트 준비 중").
⚠ 갭
관리자의 아침 질문("오늘 누가 오고, 뭐가 밀렸나")에 답하는 화면이 없다. 대시보드에 관리자 분기(미청구·미처리·임박 신호 모음)를 넣는 것이 최소 수정. P1-2 / analytics 더미 노출 P0-4

A4. 수납·청구 처리

상담 완료 후 수납, 바우처 내담자는 회기 차감
Q10청구 화면이 커버하는 범위는?
청구 생성(상담/검사/패키지 연계, 지원금)·납부 기록·미수금 추적·상태 탭(대기→부분결제→완료)·미청구 세션 배너까지. 완성도가 가장 높은 도메인.
Q11바우처 차감은 자동인가?
청구 항목에 바우처를 연결하는 구조. 단 만료일 검증이 차감 시점에 없어 만료 바우처도 차감될 수 있다. 바우처 수정 UI도 없음(API만 존재).
Q12단가표는 어디에 쓰이나?
상담/검사/패키지 단가 정의 + 검사·프로그램 자동 동기화. 청구 생성 시 참조.
⚠ 갭
  • 만료 바우처 차감 검증 없음 — 바우처 센터 리빙랩이면 정산 사고로 직결. P0-7
  • "billing"이 3가지 의미(내담자 청구 / 서비스 단가 / SaaS 구독 결제)로 혼용. P2

A5. 검사지 구매·검사 운영

Q13검사 구매 모델은?
/assessment/purchase는 라우트만 있고 페이지가 없다. 크레딧/결제 모델이 코드에 존재하지 않음. P0-5
Q14관리자와 상담사 흐름 차이는?
접수 폼에서 관리자는 담당자 전체 지정+대표 지정, 상담사는 본인만. 담당자 필터도 관리자 전용. 나머지(접수→링크→수행→결과)는 동일하고 흐름은 실제로 닫혀 있다.

A6. 멤버·구독 관리

Q15상담사 퇴사 처리는?
비활성화 토글과 삭제는 있다. 퇴사자의 담당 케이스·예정 일정을 어떻게 할지는 미정의 — 이관 흐름 없음. P1-9
Q16구독 메뉴가 왜 두 개인가?
/subscription과 /settings/subscription이 같은 쿼리·같은 화면의 완전 중복. AI 사용량도 중복. 게다가 둘 다 권한 체크가 없어 상담사도 URL로 접근 가능. "AI/구독 프로덕션 미배포" 방침과 리빙랩 빌드의 정합도 확정 필요. P0-3

B.상담사 시나리오 — 실제 동작

B1. 하루 시작 — 내 일정 확인

Q17첫 화면에서 오늘 상담이 보이나?
첫 화면이 캘린더라 상담사에게는 오히려 맞는 진입. 대시보드의 "다음 일정, N분 후" 히어로도 상담사 친화적 — 두 화면 역할이 겹친다.
Q18자기 일정만 보나, 전체를 보나?
백엔드가 "내 담당만"으로 자동 필터. 화면에는 그 사실이 표시되지 않아 전체를 보고 있다고 오해할 수 있다. P1-3

B2. 세션 수행 — 사전 확인 → 상담 → 기록

Q19일정→세션→내담자 이동이 자연스러운가?
상담 현황 행 클릭 → 상담 상세(/counseling/status/[id]): 세션 목록+상세 패널+청구 연동까지 실데이터로 동작. 주의: /session/[sessionId]는 어디서도 링크 안 되는 고아 라우트로, mock 데이터를 쓴다 — 실제 동선 아님, 삭제 대상. P0-5
Q20수기 일지와 AI 필드노트의 관계는?
일지(목표/진행/다음계획/개인메모/소견)는 상담 상세에서 작성. 필드노트 메뉴는 전 환경 숨김, AI 에이전트는 프로덕션 숨김 → 리빙랩에서는 수기 일지가 유일한 기록 동선.
Q21세션 완료 시 뭐가 연쇄되나?
명시적 [완료] 버튼 + 미확정 참석자 일괄 처리 모달. 완료가 청구·차감으로 자동 연쇄되지는 않고 미청구는 관리자가 청구 화면 배너로 사후에 잡는다. 분업은 성립하지만 그 인계가 화면에 드러나지 않는다.

B3. 내담자 등록·관리

Q22상담사가 직접 등록 가능한가?
가능(권한 기준, 역할 제외 없음).
Q23보호자 연결이 실제 케이스를 커버하나?
보호자 다중 행+관계 선택, 배치 API로 동시 생성·관계 연결 — 아동+보호자는 커버. 단 "내담자이자 보호자"(role=both)는 백엔드만 지원, UI 선택 불가. 중복 체크 API가 있는데 프론트가 안 불러서 동명이인·재등록 방지 없음. P1-6
Q24담당 개념이 있나?
백엔드에 존재(owner_scope). 화면 표시는 없음 — B1과 같은 이슈.

B4. 검사 의뢰 → 수행 → 결과 확인

접수 → [링크 전송: SMS/카톡/이메일/QR] → 내담자 검사(검사 전용 계정 로그인) → 제출 알림 → 상담사 결과 확인 → [결과 링크] → 내담자 인증번호 4자리 → 다운로드(1시간 유효)
Q25내담자가 링크만으로 검사할 수 있나?
아니다 — 검사 전용 계정 로그인이 필요하다. 계정 생성 UX와 검사 중 토큰 만료 복구는 미정의. 리빙랩 전 실전 리허설 필수. P1-10
Q26결과 도착을 상담사가 어떻게 아나?
"검사 제출" 인앱 알림(30초 폴링). 결과는 검사 상세에서 태스크별 확인.
Q27용어가 구분되나?
수행 링크(SendLink)와 결과 링크(SendResult)가 UI에서 둘 다 "링크 전송"처럼 보임 → "검사 링크"/"결과 링크"로 라벨 분리 필요. P1-5

B5. 일정 변경·취소

Q28노쇼·변경 처리가 되나?
취소(사유 입력+보충 회기 추가 옵션)·노쇼 별도 상태·단건 수정 모두 가능. 반복 규칙도 케이스에 저장. 흐름 성립, 문제 없음.

C.메뉴·정보구조 횡단 점검

Q29메뉴 순서가 사용 빈도와 맞나?
상담사 동선(스케줄·상담·내담자 상단)은 무난. 단 "바우처"의 1뎁스 승격이 실체(내담자 목록) 대비 과함 + 설정>바우처 관리와 같은 단어가 두 메뉴에 존재. P1-8
Q30"접수"가 몇 곳인가?
메뉴엔 없고 3개 화면 버튼으로 분산. "접수하기"(상담·검사) vs "등록하기"(운영) 용어 혼용. P1-4
Q31고아·빈 화면은?
/session/[sessionId](mock·링크없음) · /assessment-case(중복) · /assessment/purchase(미구현) · /settings/profile("준비 중") · /dashboard/analytics(전부 더미) · /assessment/statistics(가짜 숫자+TODO) · /assessment/quick-links(centerId 하드코딩!) P0-1·4·5
Q32상담사가 관리자 URL 직접 접근하면?
페이지는 뜨고 API 403에 의존하는 구조(버튼만 권한으로 숨김). /subscription은 그 API 게이팅조차 미확인. P0-3
Q33설정이 몇 곳인가?
3곳 — 센터 운영(/center/*) / 개인·계정(/settings/*) / 센터별 내 프로필(/myInfo). 구독은 심지어 3곳(myInfo 탭·/subscription·/settings/subscription)에서 접근된다. P1-7
Q34알림은 실제로 오나?
이벤트 종류는 풍부(케이스/회기 생명주기 전체+시스템). 실시간은 아니고 30초 폴링. 기본값: 인앱 ON, 알림톡·푸시 OFF. 치명도 낮음.

D.이슈 우선순위

P0  리빙랩 전 반드시 — 깨짐·오작동·신뢰 훼손 (7건)

#이슈왜 P0인가조치
1바로링크 centerId 하드코딩
quick-links/+page.svelte:21		다른 센터에서 남의 센터 데이터 조회 시도/빈 화면$centerId 바인딩 — 한 줄 수정
2상담사 이중 배정 무검사
충돌 검사가 장소 기준만		같은 시각 두 상담 배정 — 실운영 첫날 터질 지점상담사 기준 충돌 검사 추가(경고만이라도)
3구독 화면 권한 가드 없음
/subscription 계열 전체		상담사가 URL로 플랜 변경 접근 가능 + 프로덕션 미배포 방침과 충돌정책 결정: 리빙랩 빌드 노출 여부 확정 + 가드
4더미 화면 노출
analytics("-") · 검사 통계(가짜 숫자)		가짜 숫자는 센터 신뢰를 깎음정책 결정: 진입 차단 or "준비 중" 명시
5고아·미구현 라우트
/session(mock) · /assessment-case · /purchase · /settings/profile		URL 진입 시 mock 데이터·빈 화면삭제 또는 리다이렉트
6검사 접수 충돌 경고 누락
상담 접수는 warnings 반환, 검사는 없음		검사 일정이 조용히 겹침응답에 warnings 필드 추가(백엔드)
7만료 바우처 차감 검증 없음바우처 센터 리빙랩이면 정산 사고 직결차감/청구 연결 시점에 valid_until 검증
1·5·6·7 = 바로 코드 수정 가능 · 2 = 백엔드 보강 · 3·4 = 비즈니스 정책 결정 선행 필요

P1  사용성 모호 — 리빙랩 피드백 왜곡 방지용 사전 정리 (10건)

#이슈내용
1온보딩 부재센터 생성 직후 빈 캘린더 — 세팅 순서 가이드 필요
2관리자 아침 화면 부재할 일 신호가 4개 화면에 분산 — 대시보드 관리자 분기가 최소 수정
3데이터 범위 미표시"내 담당만" / "센터 전체" 를 목록 헤더에 명시
4접수 진입점·용어 분산3곳 분산 + 접수/등록 혼용 + 캘린더에서 상담 예약 불가
5검사 링크 용어수행 링크 vs 결과 링크 라벨 분리
6중복 체크 미사용API는 있음 — 연결만 하면 동명이인·재등록 방지
7구독·설정 3중 진입/subscription 중복 제거, myInfo 구독 탭 정리
8바우처 메뉴 이원화1뎁스 바우처(현황) vs 설정>바우처 관리(마스터) + 수정 UI 부재
9퇴사 처리 흐름비활성화 시 담당 케이스·일정 처리 미정의
10내담자 검사 로그인 리허설검사 전용 계정 생성·토큰 만료 복구 — 실전 테스트 필수

P2  리빙랩 이후 구조 개선

billing 3의미 재편(단가표→센터 설정 이동) · role="both" UI 지원 · 다중 상담사 표시 · 시간대 변환 ISO 통일 · 탭 전환 시 불필요 쿼리 재실행 · SSE 실시간 알림 · 세션 완료→청구 연쇄 자동화

잘 되어 있는 것 — 리빙랩에서 그대로 검증할 강점

  • 접수→케이스→회기→일지→종결 상태 머신이 명확하고, 회기 상태 변경 시 참석자 일괄 동기화까지 구현
  • 청구 도메인 완성도 — 미청구 배너·부분결제·패키지·바우처 연결
  • 검사 end-to-end가 실제로 닫혀 있음 (접수→링크→수행→인증번호 결과 확인)
  • 보호자-자녀 배치 등록 / 충돌 "경고하되 차단 안 함" 정책 / 권한 확정 후 메뉴 렌더(깜빡임 방지)
