평가자는 우리 화면 구조가 아니라 공식 평가 항목 24종으로 채점한다. 그 기준으로 다시 세어보면 — ✅ 10 · 🟡 8 · 🔴 4 · ❓ 2.

🔴 4건 중 3건이 AI(검사 해석·바우처 서류 생성·에이전트 노출)이고, 2차 평가 문안의 "중복 일정 확인"은 현재 최대 결함(상담사 이중 배정 무검사)을 정조준하고 있다. 리빙랩의 성패 = "AI를 보여줄 수 있는 환경"의 확정 + 이중 배정 수정.

2.내담자 관리 프로그램 7종 — 준비도

#평가 항목 (문서 원문)준비도구현 위치 · 리스크 · 보완
1주간/월간 스케줄 관리 + 스케줄 통계🟡 부분웹 캘린더 3뷰·모바일 3뷰(통계 포함) 완성. 웹 통계(analytics)는 전부 더미 — 평가자가 웹에서 "통계"를 찾으면 "-"만 봄
2내담자 조회 / 관계 관리✅ 완성웹 목록·상세(관계 표시·이동) / 모바일 목록·상세·즐겨찾기. 관계 수정은 웹 등록 폼 경유 — 동선 안내
3검사 진행 현황 조회✅ 완성웹 현황+이력(벌크) / 모바일 목록·상세
4검사의 시작부터 결과까지 (바로링크)🟡 부분end-to-end 닫혀 있음. 단 quick-links centerId 하드코딩(P0-1) + 검사/결과 링크 라벨 혼동 + 내담자 2단 인증 리허설 필요
5푸시 알림🟡 부분모바일 FCM(뱃지·딥링크·설정) 완성. 웹은 30초 폴링 — 푸시 아님. 평가 기대치 조정 or 알림톡 활성화 결정
6청구 관리✅ 완성웹 3경로·납부·단가 / 모바일 본인 담당. 환불·납부 정정 없음(사전 고지)
7최신 바우처 정보 알림❓ 의도 확인보유 바우처 상태 신호(신규·소진≤2회·만료 14일)는 대시보드에 있음. "최신 바우처 제도/사업 정보"라면 해당 기능 없음 — 기획 의도 확인 필수

3.관리자/전문가 프로그램 17종 — 준비도

#평가 항목 (문서 원문)준비도구현 위치 · 리스크 · 보완
1일간/주간/월간 스케줄 관리✅ 완성일간=장소/담당자 타임라인. 캘린더 "취소" 핸들러만 미구현(삭제는 동작)
2내담자 조회/관계 관리✅ 완성위 A-2와 동일
3내담자의 모든 기록 (케어보드)🟡 부분내담자 상세 4탭(진행현황·사전기록지·문서·바우처)+상담 상세 일지로 존재. "케어보드"라는 단일 화면은 없음 — 항목명↔화면 매핑표 제공
4스마트 일괄 회기 추가✅ 완성멀티 날짜 피커(간격 패턴 자동 반복)+회기 추가
5AI 기반 상담일지 초안🟡 조건부필드노트→초안 prefill 완성(모바일 녹음·웹 열람). "AI 프로덕션 미배포" 방침과 충돌 — 리빙랩 환경 AI 활성화 결정이 선행돼야 평가 가능
6검사 결과 통합 관리 (18종)✅ 완성검사 관리(활성화)+현황·상세. 센터에 18종 시드 세팅 확인
7AI 기반 검사 해석 보조🔴 미노출프로덕션 UI가 없다. 백엔드 ai_lab(실험 인프라) 단계. 평가 항목인데 진입 화면 부재 — 1차 보완 최대 갭. 범위 재협의 or 긴급 구현 결정
8AI 기반 검사 보고서 작성🟡 부분자기보고식 자동 채점+PDF 생성 엔진(백엔드) + 보고서 수동 업로드 존재. LLM "작성"으로 평가받기엔 범위 확인 필요
9검사의 시작부터 결과까지 (바로링크)🟡 부분A-4와 동일 — P0-1 수정 필수
10전문가 학력/경력/자격, 인증 뱃지✅ 완성myInfo 인증 신청→승인/반려 알림→뱃지. 승인 주체(플랫폼 admin) 운영 리허설
11결제 / 청구 관리✅ 완성A-6와 동일
12바우처 납부 증빙❓ 의도 확인사용 내역·월별 usage 조회는 있음. "증빙 서류" 출력/제출 형식은 미확인 — 기대 산출물 정의 필요
13바우처 서류 자동 생성🔴 미연결백엔드 모듈(voucher_document·draft·extraction·form) 존재, 프론트 미연결. 진행 중 과제 — 1차 보완 내 노출 여부 결정
14운영 업무 자동화 (AI 에이전트)🔴 숨김기능 완성(채팅+페이지 도구 5종). 프로덕션 메뉴 숨김 — 평가자가 진입 불가. 노출+AI 방침 결정 필수
15AI 기반 현장 비서 (필드노트)🟡 조건부모바일 sub-app 완성(녹음→분석→초안). 실기기 리허설 + AI 방침 + 웹 열람 경로 확정

4.2차 평가 문안과의 직접 충돌 — 예고된 시나리오

2차 평가(8.3~) 문안이 정확히 어디를 볼지 명시하고 있다:

2차 평가 문안 (원문)판정현재 상태
"보호자에게 온라인으로 점수내용 보내고, 결과까지 확인"✅결과 링크(인증번호 4자리·1시간) 완성, 수신자 관계(보호자) 지정 가능. 링크 라벨 혼동만 정리 권장
"상담 일정 예약, 시간 변경"✅접수·회기 수정 완성
"중복 일정 확인 여부"🔴장소 충돌만 검사 — 상담사 이중 배정 무검사. 평가 문안이 현재 최대 결함을 정조준. 1차 보완에서 반드시 해결

5.1차 보완(7.6 ~ 7.31) 작업 목록 — 우선순위 재편

기존 P0/P1을 평가 프레임으로 재배열. 개발=코드 수정 결정=비즈니스 판단 선행 운영=세팅·리허설

🔥 즉시 — 평가 항목 자체가 깨지는 것

  1. 상담사 이중 배정(중복 일정) 검사 추가 — 2차 평가 문안 명시 항목 개발
  2. 바로링크 centerId 하드코딩 수정 — 평가 항목 4/9번, 한 줄 수정 개발
  3. AI 노출 정책 확정 — 상담일지 초안·검사 해석·검사 보고서·에이전트·필드노트 5개 평가 항목이 "AI 프로덕션 미배포" 방침과 충돌. 리빙랩 전용 환경에서 AI 활성화 여부 결정 결정
  4. AI 검사 해석 보조 — 진입 화면 부재. 평가 범위 재협의 or 최소 구현 결정개발
  5. 바우처 서류 자동 생성 — 백엔드 완료, 프론트 연결 여부 결정 결정개발

⚡ 1차 보완 기간 내 — 평가 경험 왜곡 방지

  1. 웹 통계 더미 처리(analytics·검사 통계) — 항목 A-1이 "스케줄 통계" 포함: 최소 구현 or "준비 중" 명시 or 차단 개발
  2. 만료 바우처 차감 검증 — 바우처 관련 평가 항목 3개 개발
  3. 검사 접수 충돌 경고 응답 + 검사/결과 링크 라벨 분리 개발
  4. 고아·더미 라우트 정리(/session mock·/settings 인덱스·예약 기능군·purchase) — 우연 진입 시 신뢰 하락 개발
  5. 모바일: 홈 확정(전환 중 해소)·워크스페이스 placeholder 숨김·녹음 실기기 리허설 결정운영
  6. "최신 바우처 정보 알림"·"바우처 납부 증빙" 기획 의도 확인 → 기대 산출물 정의 결정

📋 평가 운영 준비 (개발 외)

  1. 평가자 5명 계정·센터·검사 18종·복수 센터 세팅 + 검사 전용 내담자 계정 리허설 운영
  2. 평가 항목명 ↔ 화면명 매핑표 제공("케어보드"=내담자 상세 등) — 평가 양식에 첨부 운영
  3. 알려진 미구현(환불·예약 기능군 등) 사전 고지 — 평가 왜곡 방지 운영
