# 기획 도구 작업 이어받기

작성 기준: 2026-09-08. 이 문서는 새 Codex 대화에서 작업 맥락을 복원하기 위한 인계 자료다. 전체 대화 이력이나 로컬 데이터 백업은 아니다.

## 작업 대상과 목적

- 저장소: `insightercorperation/saas-center-platform`
- 작업 경로: `apps/web/tools/planning-pilot`
- 주요 사례: `plans/plan-42a3a371.json` — 상담센터 바로링크 기획
- 사용자 목표: 기획을 한눈에 이해하고 정상 흐름, 예외 처리, 상태 변화, 기존 동작 영향과 실제 구현의 차이를 빠짐없이 검토하는 도구.
- 참고 UI: Manyfast. 상단 작업 탭, 왼쪽 요청 패널, 중앙 문서/구조, 오른쪽 상세 패널로 영역을 명확하게 구분한다. 복잡한 관계선과 중복 제목을 피하고 점진적으로 상세를 펼친다.

## 반영된 화면과 동작

- 상단 작업 탭: 기획 / 시나리오 / 영향·누락 점검 / 구현 비교.
- 기획의 하위 보기: 기획서 / 구조도 / 기능·동작.
- 구조도: 기능 → 해당 기능이 참여하는 흐름 → 진행 순서, 예외 경로, 상세 점검 사례.
- 사례 검토 클릭은 본문 스크롤과 펼친 목록을 유지한다. 검토 큐 이동과 분리되어 있다.
- 선택한 항목을 표시하고 오른쪽 상세 제목 및 검토 버튼을 고정한다. 제목은 헤더 두 번째 줄의 전체 너비를 사용한다.
- 채택/수정 요청/판단 보류 후 다음 미검토 항목으로 이동한다. 내용 채택은 정책 확정이나 구현 검증과 다르다.
- 엣지케이스는 정상 단계, 실패·중복·동시 변경, 시간·권한, 복구, 기존 영향 등을 근거와 함께 추적한다. 미정은 임의로 확정하지 않는다.

## 가장 최근 변경: 실행 명령과 AI 선택

```sh
pnpm dev:planning
pnpm dev:planning --ai=codex
pnpm dev:planning --ai=claude
pnpm dev:planning --ai=off
```

- Node 20.19 이상, 설치된 프로젝트 의존성 필요. 주소는 `http://127.0.0.1:4318`.
- 일반 웹 앱 API/DB/로그인은 필요 없다.
- 각 컴퓨터에서 사용할 CLI를 설치하고 로그인한다: `codex login` 또는 `claude auth login`.
- 자동 선택: `CODEX_THREAD_ID`가 있는 현재 Codex 대화 → 로그인된 Codex CLI → 로그인된 Claude Code CLI → 미연결.
- 명시적 `--ai`가 우선한다. 개인 기본값은 기획 도구 폴더의 `.env.local`에서 `PLANNING_AI_PROVIDER`로 지정한다. 파일은 Git 제외 대상이다.
- 모델은 CLI 기본 설정 또는 `--model=<ID>`로 선택한다. 기존 대화 연결에는 해당 대화의 모델을 사용한다.
- CLI 독립 실행은 요청마다 저장된 기획/선택/결정과 코드를 읽고 JSON을 반환한다. 서버가 스키마 검증 후 기획 결과만 저장한다. 두 CLI의 대화 이력 자체는 공유하지 않는다.
- 요청은 완료까지 대기하며 제한 시간은 10분이다. 작업 중인 기획의 외부 변경, 잘못된 응답 형식은 오류로 처리한다.
- 기록에는 AI 정보와 완료/실패 상태를 남긴다.

핵심 파일: `server.mjs`, `ai-config.mjs`, `src/lib/server/ai-runner.ts`, `src/lib/server/store.ts`, `src/lib/components/PlanningEditor.svelte`, 루트 `package.json`.

## 검증과 남은 확인

- 60개 테스트 통과, Svelte 타입·접근성 진단 0 오류/0 경고, 프로덕션 빌드 통과.
- `pnpm dev:planning --ai=off` 서버 실행 및 기획 페이지 HTTP 200 확인. 검증용 4319 서버는 종료했다.
- Codex·Claude 어댑터는 모의 CLI 응답으로 테스트했다. 실제 인증된 모델의 전체 기획 생성은 아직 검증하지 않았다. 다음에는 새 테스트 기획으로 각 공급자의 실제 생성·저장·실패 표시를 확인한다.
- 브라우저 자동화 연결이 없어 최근 화면 변경은 사용자 스크린샷과 코드 검사로 확인했다. 집 환경에서 패널 배치와 사례 클릭 시 스크롤 유지도 직접 확인한다.
- 상위 tsconfig의 `expo/tsconfig.base` 경고는 별도로 남아 있다.

## 다른 컴퓨터로 가져갈 때

1. 현재 코드 변경과 이 인계 문서가 원격 저장소에 반영됐는지 확인한다. 인계 문서 작성 시 최신 AI 연결 변경은 미커밋 상태였다. 다른 작업자의 변경은 섞어서 커밋하지 않는다.
2. `plans/`는 기획 원본이고, `records/`는 선택·검토 기록, 결과 문서, 첨부 이미지다. **`records/`는 Git에서 제외**되어 있으므로 필요한 경우 별도로 복사한다. Git 상태 전달만으로 이 폴더가 옮겨졌다고 가정하지 않는다.
3. 아직 브라우저에만 있는 초안은 회사 화면에서 먼저 임시 저장해야 `records/`에 남는다. 브라우저 localStorage는 컴퓨터 간 자동 이전되지 않는다.
4. `.env.local`과 CLI 로그인은 새 컴퓨터에서 직접 설정한다. 전체 사용자 인증 폴더를 저장소에 넣지 않는다.
5. 이 문서 외의 제품 코드 변경이 작업 폴더에 공존할 수 있다. `git status`를 확인하고 기획 도구 작업에 한정한다.
