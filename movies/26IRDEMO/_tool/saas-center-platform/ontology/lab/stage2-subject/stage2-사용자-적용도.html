Lab — 2단계(정의 → 생성)를 사람 축에 적용하면

harness가 ontology/를 입력으로 대상자(subject → clients) 도메인의 표준 코드를 생성한다고 가정한 구조 시뮬레이션. 실측 코드(create_client.py 등)가 실제로 하는 일을 전수 분류해서 "무엇이 생성되고, 무엇이 사람 몫으로 남는가"를 그렸다. 실물 lab: ontology/lab/stage2-subject/ · 정렬 회의 안건 3(handler layer 범위)의 입력.

1

전체 그림 — 정의가 흐르고, 코드가 남는다

ontology/ (정본)

attributes#subject — 필드·3분류·nullable
catalog#subject — 고유함 규칙 (D1)
states — active→inactive→archived
+ input/subject.actions.yaml (액션 선언 — 온톨로지를 참조만)

→

harness (생성기)

같은 정의 → 같은 출력 (멱등)
수제 파일이 있으면 그 use-case 스킵
생성물에 source-hash 각인

→

generated/ — 눈에 보이는 코드

git에 커밋 · 재생성 diff가 리뷰 대상
런타임 엔진이 아니라 보통의 파이썬 파일 — 콜스택이 그대로 보이는 것이 3단계와의 결정적 차이(탈출구)

🤖 온톨로지가 아는 것 → 생성

  • 파라미터 목록 (코어+역할기록 — 3분류에서 유도)
  • 필수 검증 (D2: 이름 필수)
  • 중복 차단 (D1: person_id 기연동 / 이름+생년 휴리스틱)
  • 상태 전이 가드 (states: "archive는 inactive에서만")

✋ 온톨로지가 모르는 것 → 커스텀 3경로

  • 훅 — 전후 처리 (아바타 배정)
  • SPI — 알고리즘 (code 발번기)
  • 오버라이드/수제 — 복합 use-case (가구 배치 등록)
2

현행 대상자 도메인 전수 분류 — 실측 기준

현재 clients 도메인이 실제로 가진 로직 하나하나를 "2단계라면 어디 속하나"로 판정. 생성 비중이 높은 이유는 그 로직들이 이미 온톨로지에 정의로 존재하기 때문이다 — 정의가 없으면 생성도 없다.

현행 로직 (실측)판정근거
create/update 뼈대 (파라미터·repo 호출)🤖 생성attributes 3분류에서 파라미터 유도 — agent-query 필터 유도와 같은 원리
이름 필수 등 코어 검증🤖 생성D2 + nullable 실측이 이미 온톨로지에 있음
name+birth / person_id 중복 차단🤖 생성D1(기관 내 유일)이 온톨로지의 identity 규칙 — 규칙이 정의니 코드도 유도 가능
상태 전이 3종 (activate/deactivate/archive + 가드)🤖 생성states 정의("archived는 inactive에서만")에서 전이표 생성 — lab의 archive_client.py
role 재계산 (관계 변경 시 캐시 동기화)🤖 생성 후보(2차)D3(role=관계의 요약 캐시)가 규칙 — 단 관계 이벤트 배선이 필요해 2차
code 6자 발번 (secrets.choice·충돌 재시도)SPI온톨로지는 "내부 코드, 자체 발번"까지만 안다 — 알고리즘은 코드 소유
기본 아바타 자동 배정훅표준 흐름과 무관한 after_create 부수 처리
배치 가구 등록 (보호자+자녀+형제 관계 자동)오버라이드/수제복합 use-case — 생성 뼈대의 변형이 아님. 현행 코드 그대로 유지
엑셀 임포트 (검증·중복 리포트)오버라이드/수제파이프라인성 로직 — 수제
바우처 차감·검사 채점 (타 도메인 연쇄)불가침비즈니스 코어 — "안 뒤집음" 방어선. 생성 코드는 이들을 호출만
수치로: 대상자 도메인 use-case 10종 중 5종이 즉시 생성(＋1종 2차), 커스텀은 4종 — 그리고 그 4종이 정확히 "제품의 개성"이 있는 부분이다. 생성이 뻔한 것을 가져가고 사람이 다른 것에 집중하는 구도.

규칙 3개

경계는 파일 단위한 파일에 생성+수제 혼합 금지
생성물도 git 커밋diff 리뷰 + 최후의 손 수정 가능 = 탈출구
승격은 단방향generated → services/로 복사하면 생성기가 영구 스킵. 되돌리지 않음

생성물 헤더 — 계약이 파일 안에

무엇이 좋아지고, 무엇은 아니게 되나

이득 — 다음 확장에서 즉시

쉼터 도입 시대상자 가변 속성(입소일·연계 경로)이 프로필 선언 → create/update 파라미터·검증에 자동 반영. 코드 0줄
신규 모듈 (예: roster)온톨로지에 개념 정의 + actions 몇 줄 → CRUD·상태 전이 뼈대가 하루가 아니라 분 단위로. 사람은 반입 파이프라인(수제)만 작성
규칙 변경 시"archive 조건 변경" = states 정의 수정 → 재생성. 코드·문서·explorer가 동시에 갱신 — 드리프트 원천 차단
감사source-hash 불일치(생성물 손 편집)·커버리지 갭을 audit_stage2가 검출 — agent-query 감사 문화 그대로
