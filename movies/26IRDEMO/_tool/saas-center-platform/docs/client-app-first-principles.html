SECTION 01

제1원칙 적용

기존 기획의 무의식적 가정을 해체하고 근본 질문에서 출발

기존 가정 해체

기존 가정질문결론
앱이니까 하단 4탭이 필요하다탭은 왜 존재하는가?핵심 정보는 하나의 흐름이므로 4탭 불필요
홈/일정/기록/마이 구조가 표준이다사용자가 이 구분을 원하는가?"언제 가지 → 뭘 하지 → 뭐 했대 → 어디쯤이지"는 하나의 흐름
미소속 유저에게도 풍부한 화면이 필요하다왜?핵심 가치는 센터 연결 후 발생. 미소속은 최소한으로
다른 헬스케어 앱처럼 대시보드가 필요하다대시보드를 왜 보는가?사용자가 원하는 건 "다음에 뭘 하면 되지?"에 대한 답
"내담자가 이 앱을 여는 이유는 딱 하나, 뭔가?" 성인 내담자: "다음에 뭘 하면 되지?"
보호자: "우리 애 어디까지 했지?"

왜 제1원칙인가

핵심 통찰

상담 앱의 내담자는 주 1~2회 상담에 갈 뿐이다. 기능이 많으면 좋은 게 아니라, "다음 행동이 뭔지"를 0.5초 안에 알 수 있으면 된다. 이 관점에서 역산하면 4탭 구조, 대시보드, 캘린더 그리드 등은 모두 불필요한 복잡성이다.

제1원칙 도출 과정

기존 접근 (Top-Down)

"다른 앱은 어떻게 하지?" → 4탭 + 캘린더 + 기록 탭 + 마이페이지

기능 나열 중심, 빈 화면 많음

제1원칙 (Bottom-Up)

"사용자가 왜 앱을 열지?" → 하나의 질문에 답하는 단일 흐름

질문 기반 설계, 빈 화면 없음

SECTION 02

핵심 결정 사항

사용자 경험, 정보 우선순위, 앱 구조의 근본적 결정

사용자 경험은 동일하다

  • 성인 내담자와 보호자의 앱 경험은 같다
  • 별도 역할 선택, 분기된 화면 구성 없음
  • 다중 자녀/다중 센터 모두 통합 표시 (전환 없음)

왜 역할을 구분하지 않는가

보호자와 내담자의 차이는 "누구의 일정을 보는가"뿐이다. 화면 구조, 기능, 접근 방식은 모두 동일하다. 역할 선택 화면을 추가하면 온보딩이 복잡해지고, 실제로 role="both"인 사용자(본인도 내담자이면서 자녀의 보호자)는 매번 전환해야 하는 문제가 생긴다.

정보 우선순위

순위정보사용자 질문이유
1캐릭터 멘트—감성적 첫인상, 상황별 안내
2다음 일정 (진행 바 포함)"언제 가지? 어디쯤이지?"0.5초 안에 답을 얻어야 하는 질문
3미션/성장 가이드"그때까지 뭘 하지?"Phase 2 (AI 성장 가이드)
4콘텐츠—매거진/카드뉴스, 태그 기반 맞춤 추천

앱 구조: 홈 + 마이 (2탭)

4탭이 아닌 2탭인 이유 일정, 미션, 진행현황은 하나의 흐름. 분리할 이유가 없다.
마이페이지(센터 정보, 설정)만 맥락이 다르므로 분리.

2탭 구조 상세

홈 탭

  • 오브 캐릭터 + 상황 멘트
  • 다음 일정 카드 (진행률 포함)
  • 콘텐츠 섹션
  • Phase 2: 미션/성장 가이드

마이 탭

  • 센터 카드 목록 (이용중/종결)
  • 각 센터 상세 (담당자, 검사결과 등)
  • 알림 설정
  • 계정 관리
SECTION 03 · MVP 필수

다중 센터 + 다중 자녀 통합

사용자는 센터 단위로 생각하지 않는다. "이번 주에 뭐가 있지?"로 생각한다.

영역별 통합 규칙

영역통합 방식구분자이유
일정전체 시간순 합산자녀 이름 + 센터명"언제 어디 가지"가 궁금
진행현황자녀별 분리자녀 이름 섹션치료 맥락이 달라 섞으면 의미 없음
콘텐츠통합태그 기반 매칭소속 여부 무관 공통 레이어

왜 센터 전환이 아닌 통합인가

자녀 2명이 각각 다른 센터를 다니는 보호자를 생각해보면, 매번 센터를 전환해서 일정을 확인하는 건 고역이다. "이번 주에 뭐가 있지?"라는 질문에 답하려면 모든 일정이 시간순으로 보여야 한다.

역할별 홈 일정 표시

순수 내담자 (client)

내 일정만 표시

순수 보호자 (guardian)

자녀 일정만 표시

둘 다 (both)

내 일정 + 자녀 일정 섹션 분리

데이터가 없는 섹션은 미노출. 조건부 렌더링으로 세 케이스 하나의 로직으로 처리.

데이터 모델 매핑

기존 모델 완전 활용 ClientRelation 모델이 다중 보호자(is_primary, relation_detail: mother/father)를 이미 지원한다. 양쪽 부모가 각자 계정으로 로그인하면, 센터에서 둘 다 보호자로 연결하면 된다. 스키마 변경 불필요.

공개 범위 (상담사 설정)

수준내담자에게 보이는 것사용 예시

AI 종합 보고서 흐름

풀배터리 검사 실시 (초기 1회) ↓ AI 종합 보고서 초안 생성 ↓ 상담사 검수/수정 ↓ 공개 범위 설정 후 발행 ↓ 내담자 앱에서 열람

풀배터리 검사 특성

종합 보고서는 풀배터리 검사(여러 검사 한번에)에서 주로 사용된다. 매 회기마다 검사하는 게 아니므로, 보고서는 한 케이스에 1~2건 정도. 따라서 보고서 화면은 복잡한 필터링 없이 단순 목록으로 충분하다.

SECTION 16

기존 기획서와의 관계

이 문서는 기존 기획서를 대체하지 않는다. 구조와 우선순위를 재정립한 것이다.

항목기존 기획서이 문서
기능 상세유효다루지 않음
화면 구조 (IA)4탭 → 2탭으로 변경이 문서 기준
다중 센터/자녀향후 → MVP 포함이 문서 기준
드릴다운 상세캘린더 뷰 → 타임라인이 문서 기준
진행현황별도 카드 → 일정 카드 통합이 문서 기준
충돌 시 이 문서가 우선 기존 기획서의 기능 상세(각 화면의 필드, 동작 스펙)는 그대로 유효하지만, IA(정보 구조)와 우선순위가 충돌하면 이 문서를 따른다.
