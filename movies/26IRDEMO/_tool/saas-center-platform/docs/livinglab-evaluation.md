# 상담센터 SaaS 리빙랩 평가 계획서

> 상담센터 운영 SaaS 플랫폼의 실사용 환경 기반 사용성 및 수용도 평가

---

## 1. 평가 개요

### 1.1 목적

- 실제 상담센터 환경에서 SaaS 플랫폼의 **사용성, 업무 적합성, 도입 가능성**을 검증
- 핵심 기능별 사용자 경험 데이터를 수집하여 **제품 개선 우선순위** 도출
- 기존 업무 방식(엑셀, 종이, 개별 SW) 대비 **효율성 향상 정도** 측정

### 1.2 대상 서비스 기능 범위

| 영역 | 주요 기능 |
|------|-----------|
| 내담자 관리 | 내담자 등록, 보호자 연결, 관계 관리, 내담자 검색/필터 |
| 심리검사 | 검사 도구 관리, 검사 접수/배정, 온라인 검사 수행, 결과 확인 |
| 상담 관리 | 상담 케이스 생성, 세션 기록, 필드노트 작성 |
| 일정 관리 | 캘린더 기반 일정, 예약 관리, 일정 충돌 감지 |
| 센터 운영 | 직원 관리, 역할/권한 설정, 공지사항 |
| 청구/결제 | 바우처 관리, 청구서 생성, 결제 처리 |

### 1.3 참여 규모 및 기간

| 항목 | 내용 |
|------|------|
| 참여 센터 | 5~8개 센터 (소규모 1~3인, 중규모 4~10인, 대규모 10인+ 각 포함) |
| 참여 인원 | 센터당 2~3명 (관리자 1명 + 상담사 1~2명), 총 15~24명 |
| 평가 기간 | 총 4주 (1주 교육/적응 + 3주 실사용) |
| 평가 시점 | 사전 설문 → 1주차 중간 체크 → 4주차 사후 평가 + 인터뷰 |

> **시점**: 리빙랩 시작 전 / **소요**: 10~15분 / **방식**: 온라인 설문

## 3. 과업 기반 사용성 평가

> **시점**: 리빙랩 2~3주차 / **소요**: 60~90분 / **방식**: 진행자 관찰 + 화면 녹화

### 3.1 평가 시나리오

각 과업은 실제 업무 상황을 시뮬레이션합니다. 참여자에게 시나리오를 제시하고, 스스로 수행하게 한 뒤 관찰합니다.

---

#### 과업 1: 내담자 등록 및 관계 설정

**시나리오**:
> "새로운 아동 내담자 '김민준'(10세)이 어머니 '이수진'과 함께 방문했습니다. 내담자와 보호자를 등록하고 관계를 연결해 주세요."

**수행 단계**:
1. 내담자(아동) 신규 등록
2. 보호자 신규 등록
3. 내담자-보호자 관계 연결 (어머니)
4. 등록된 내담자 정보 확인

**측정 항목**:

| 측정 | 방법 |
|------|------|
| 완료 시간 | 스톱워치 (시나리오 제시 ~ 최종 확인) |
| 성공 여부 | 완전 성공 / 부분 성공(힌트 후) / 실패 |
| 오류 횟수 | 잘못된 클릭, 되돌리기, 재입력 횟수 |
| 혼란 지점 | 관찰자 기록: 멈추거나 헤맨 화면/단계 |

**과업 후 질문** (7점 척도):
- "이 작업은 쉬웠다" (1=전혀 아니다 ~ 7=매우 그렇다)
- "입력해야 할 항목이 적절했다" (1~7)
- "보호자 연결 방식이 직관적이었다" (1~7)
- 자유 의견: "이 과정에서 불편하거나 개선이 필요한 점이 있다면?"

---

#### 과업 2: 심리검사 접수 및 결과 확인

**시나리오**:
> "내담자 '김민준'에게 CBCL(아동행동체크리스트)를 실시하려 합니다. 검사를 접수하고, 보호자에게 온라인으로 검사를 보낸 뒤, 결과를 확인해 주세요."

**수행 단계**:
1. 검사 접수 (내담자 선택 → 검사 도구 선택)
2. 온라인 검사 링크 발송 (또는 현장 실시 설정)
3. 검사 현황에서 진행 상태 확인
4. (사전 준비된 완료 데이터로) 검사 결과 확인

**측정 항목**:

| 측정 | 방법 |
|------|------|
| 완료 시간 | 단계별 소요 시간 분리 측정 |
| 이탈 지점 | 어디서 포기하거나 도움을 요청했는가 |
| 검사 도구 탐색 | 원하는 검사를 찾는 데 걸린 시간/클릭 수 |
| 결과 해석 가독성 | 결과 화면에서 핵심 정보를 즉시 파악했는가 |

**과업 후 질문** (7점 척도):
- "원하는 검사 도구를 쉽게 찾을 수 있었다" (1~7)
- "검사 접수 과정이 간단했다" (1~7)
- "검사 결과 화면이 이해하기 쉬웠다" (1~7)
- "기존 검사 실시 방식보다 편리하다" (1~7)
- 자유 의견: "검사 관련 기능에서 추가로 필요한 것이 있다면?"

---

#### 과업 3: 상담 일정 예약 및 변경

**시나리오**:
> "내담자 '김민준'의 첫 상담 일정을 다음 주 화요일 오후 2시에 잡아주세요. 이후, 보호자 요청으로 같은 주 목요일 오후 3시로 변경해 주세요."

**수행 단계**:
1. 캘린더에서 일정 생성 (내담자 연결, 시간 설정, 상담실 배정)
2. 생성된 일정 확인
3. 일정 변경 (날짜/시간 수정)
4. 변경된 일정 확인 + 충돌 여부 확인

**측정 항목**:

| 측정 | 방법 |
|------|------|
| 일정 생성 시간 | 캘린더 진입 ~ 저장 완료 |
| 일정 변경 시간 | 기존 일정 찾기 ~ 변경 저장 |
| 충돌 감지 인지 | 충돌 알림을 인지했는가 (Yes/No) |
| 캘린더 탐색성 | 원하는 날짜/시간으로 이동하는 데 걸린 시간 |

**과업 후 질문** (7점 척도):
- "캘린더에서 원하는 시간대를 쉽게 찾을 수 있었다" (1~7)
- "일정 생성 과정이 직관적이었다" (1~7)
- "일정 변경이 간편했다" (1~7)
- "일정 충돌 알림이 도움이 되었다" (1~7)
- 자유 의견: "일정 관리에서 빠진 기능이나 불편한 점이 있다면?"

---

#### 과업 4: 상담 기록 작성

**시나리오**:
> "오늘 진행한 '김민준' 상담 세션의 기록을 작성해 주세요. 상담 내용 요약, 주요 관찰 사항, 다음 세션 계획을 포함해 주세요."

**수행 단계**:
1. 상담 케이스에서 해당 세션 찾기
2. 세션 기록 작성 (상담 내용, 관찰, 계획)
3. 필드노트 작성 (선택)
4. 저장 및 확인

**측정 항목**:

| 측정 | 방법 |
|------|------|
| 기록 완료 시간 | 진입 ~ 저장 |
| 입력 필드 적절성 | 필요한 내용을 기록할 수 있었는가 |
| 기존 방식 비교 | 참여자 자가 평가 |

**과업 후 질문** (7점 척도):
- "상담 기록에 필요한 항목이 충분했다" (1~7)
- "기록 작성 화면이 사용하기 편했다" (1~7)
- "기존 기록 방식(종이/엑셀)보다 효율적이다" (1~7)
- 자유 의견: "상담 기록 시 추가로 필요한 항목이나 기능이 있다면?"

---

#### 과업 5: 내담자 검색 및 이력 조회

**시나리오**:
> "기존 내담자 '박서연'의 상담 이력과 검사 결과를 확인해 주세요. 최근 3개월간의 상담 내역을 찾아보세요."

**수행 단계**:
1. 내담자 검색 (이름으로 검색)
2. 내담자 상세 정보 확인
3. 상담 이력 조회
4. 검사 결과 이력 확인

**측정 항목**:

| 측정 | 방법 |
|------|------|
| 검색 소요 시간 | 검색 시작 ~ 대상자 클릭 |
| 정보 탐색 효율 | 원하는 이력에 도달하기까지 클릭 수 |
| 정보 가독성 | 필요한 정보를 한눈에 파악할 수 있었는가 |

**과업 후 질문** (7점 척도):
- "원하는 내담자를 쉽게 찾을 수 있었다" (1~7)
- "내담자의 전체 이력을 한눈에 파악할 수 있었다" (1~7)
- "정보가 체계적으로 정리되어 있다" (1~7)

---

#### 과업 6: 센터 운영 관리 (관리자 전용)

**시나리오**:
> "새로운 상담사 '정유진'을 센터에 초대하고, 상담사 역할을 부여해 주세요. 이후 이번 달 공지사항을 하나 작성해 주세요."

**수행 단계**:
1. 직원 초대 (이메일 발송)
2. 역할/권한 설정
3. 공지사항 작성 및 등록

**측정 항목**: 과업 1~5와 동일한 측정 프레임 적용

**과업 후 질문** (7점 척도):
- "직원 초대 과정이 간단했다" (1~7)
- "권한 설정이 이해하기 쉬웠다" (1~7)
- "센터 운영에 필요한 관리 기능이 충분하다" (1~7)

## 4. 사후 설문 (종합 평가)

> **시점**: 리빙랩 4주차 종료 후 / **소요**: 15~20분 / **방식**: 온라인 설문

### 4.1 SUS (System Usability Scale) — 표준 10문항

5점 척도 (1=전혀 아니다 ~ 5=매우 그렇다)

| # | 문항 |
|---|------|
| 1 | 이 시스템을 자주 사용하고 싶다 |
| 2 | 이 시스템이 불필요하게 복잡하다고 느꼈다 |
| 3 | 이 시스템이 사용하기 쉽다고 생각한다 |
| 4 | 이 시스템을 사용하려면 기술 지원이 필요할 것 같다 |
| 5 | 이 시스템의 다양한 기능이 잘 통합되어 있다 |
| 6 | 이 시스템에 일관성이 없는 부분이 많다고 느꼈다 |
| 7 | 대부분의 사람들이 이 시스템을 빨리 배울 수 있을 것이다 |
| 8 | 이 시스템을 사용하는 것이 매우 번거롭다고 느꼈다 |
| 9 | 이 시스템을 사용하면서 자신감을 느꼈다 |
| 10 | 이 시스템을 사용하기 전에 많은 것을 배워야 했다 |

> **SUS 점수 해석**: 0~100점 환산. 68점 이상 = 평균 이상, 80점 이상 = 우수

### 4.2 도메인 특화 만족도

7점 척도 (1=전혀 아니다 ~ 7=매우 그렇다)

#### 업무 적합성

| # | 문항 |
|---|------|
| 11 | 이 시스템은 상담센터 업무 흐름에 맞게 설계되어 있다 |
| 12 | 내담자 정보를 관리하는 데 기존 방식보다 효율적이다 |
| 13 | 심리검사 접수부터 결과 확인까지의 과정이 매끄럽다 |
| 14 | 일정 관리 기능이 실제 예약 업무에 도움이 된다 |
| 15 | 상담 기록 작성 및 관리가 기존보다 편리하다 |
| 16 | 여러 업무를 하나의 시스템에서 처리할 수 있어 편리하다 |

#### 신뢰성/안정성

| # | 문항 |
|---|------|

## 5. 심층 인터뷰 가이드 (FGI / 1:1)

> **시점**: 사후 설문 완료 후 / **소요**: 40~60분 / **방식**: 대면 또는 화상

### 5.1 인터뷰 구조

#### 도입 (5분)
- 참여 소감, 전반적 인상
- "한 마디로 표현한다면 이 서비스는 ___이다"

#### 업무 적합성 (15분)
- "실제 업무에 적용해 보니 기대와 달랐던 점은?"
- "기존 방식으로 돌아가고 싶은 순간이 있었나요? 언제?"
- "센터의 다른 직원이 사용한다면 어떤 반응일 것 같나요?"
- "우리 센터의 업무 흐름에서 맞지 않는 부분이 있었나요?"

#### 기능 심화 (15분)
- "가장 자주 사용한 기능은? 가장 안 쓴 기능은? 이유는?"
- "검사 관리 기능에서 기존 검사 도구(인싸이트, 마음사랑 등)와 비교하면?"
- "상담 기록 작성 시 빠진 필드나 불필요한 필드가 있었나요?"
- "일정 관리에서 실제로 충돌이 발생한 적이 있나요? 어떻게 해결했나요?"

#### 도입 장벽 (10분)
- "실제로 도입한다면 가장 큰 걸림돌은?"
- "기존 데이터(내담자 정보, 검사 결과)를 옮기는 것에 대한 부담은?"
- "보안/개인정보 측면에서 우려되는 점은?"
- "적정 가격은 얼마라고 생각하시나요? 그 이유는?"

#### 마무리 (5분)
- "이 서비스가 성공하려면 반드시 해결해야 할 한 가지는?"
- "추가로 하고 싶은 이야기가 있으시면 자유롭게 말씀해 주세요"

- "___________" (맥락: ___________)

## 6. 분석 프레임워크

### 6.1 정량 분석

| 분석 | 데이터 | 산출물 |
|------|--------|--------|
| SUS 점수 | 표준 10문항 | 전체 평균 + 역할별/경력별 비교 |
| NPS | 추천 의향 | 전체 NPS + 세그먼트별 |
| IPA (중요도-성과 분석) | 기능별 중요도/만족도 | 4사분면 매트릭스 → 개선 우선순위 |
| 과업 성공률 | 과업별 완전성공/부분성공/실패 | 기능별 사용성 등급 |
| 과업 소요 시간 | 시간 측정 데이터 | 기존 방식 대비 효율성 비교 |
| 전환 의향 분포 | 전환/가격 문항 | 시장 수용도 예측 |

### 6.2 정성 분석

| 분석 | 데이터 | 산출물 |
|------|--------|--------|
| 주제 분석 (Thematic) | 개방형 응답 + 인터뷰 | 핵심 테마 도출 (불편/요구/만족 요인) |
| 어피니티 다이어그램 | 모든 정성 데이터 | 이슈 그룹핑 + 우선순위 |
| 퍼소나 기반 분석 | 역할/규모별 응답 차이 | 관리자 vs 상담사 니즈 차이 |

### 6.3 최종 보고 구조

```
1. Executive Summary (1페이지)
   - SUS/NPS 핵심 수치
   - Top 3 강점 / Top 3 개선점
   - 전환 의향 요약

2. 사용성 평가 결과
   - 과업별 성공률/소요시간
   - 기능별 IPA 매트릭스
   - 주요 사용성 이슈 목록

3. 만족도 및 수용도
   - SUS 상세 (역할별/경력별)
   - NPS 분석
   - 전환 의향/가격 수용도

4. 정성 분석 결과
   - 핵심 테마 + 대표 인용
   - 도입 장벽 분석
   - 추가 기능 요구사항

5. 개선 권고사항
   - 즉시 개선 (Quick Win)
   - 단기 개선 (1~3개월)
   - 중장기 로드맵 반영
```
