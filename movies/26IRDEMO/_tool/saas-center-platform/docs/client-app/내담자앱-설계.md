## 0. 구현 스냅샷 (2026-07-15 최신 확정)

> **구현자용 요약.** 본문 §1~§17은 서사·결정 경위가 두껍다. 앱 구현은 **이 §0 + 인터랙티브 프로토타입([내담자앱-프로토타입-v1.0.html](내담자앱-프로토타입-v1.0.html) = UI 단일 소스)** 을 기준으로 한다. §0와 본문이 충돌하면 **§0가 우선**(본문은 왜 그렇게 됐는지의 기록). 07-15 개편이 본문 일부 서술(watching 3구분 · 초대 링크+전화인증 · "홈 골격 불변")을 대체했다.

### 0-1. 사용자 상태 — 홈은 '연동 여부' 2진으로 갈린다
- 상태 3층: **looking**(다니는 센터 없음·찾는 중) · **enrolled**(센터 다님·앱 미연동) · **linked**(연동). ※ 07-15: 기존 `watching`('지켜보는 중')은 제거하고 looking에 흡수.
- **홈 최상위 분기 = 미연동(looking+enrolled) / 연동(linked) 2진.** 원리 = **"손이 가야 하는 것을 전면에"**:
  - **미연동** — 센터 데이터가 없으니 유저가 직접 챙길 **바우처가 전면**. 내집다오식(맞춤 지원 히어로 "받을 수 있는 지원 N개" + 지원 카드 리스트[지원금·자격·D-day/상시 배지·자격확인 CTA] + 1분 자격 확인). 그 위에 상황별 today 카드: looking=전화 리마인더 / enrolled=오늘 수업·다녀왔어요·말씀 담기. 아래에 무료검사·주변 센터·육아 매거진.
  - **연동** — 센터 데이터가 자동 유입되어 **검사·상담·일정이 전면**. 통합 허브(다가오는 일정+결과지+사전설문/온라인검사) · 진행 중인 치료 · 바우처는 자동 관리라 보조 카드 · 기록은 "다음 상담 재료"로 축소.
- 온보딩 시작 질문 = **2선택지**: "아직 다니는 센터가 없어요"(→looking) / "다니는 센터가 있어요"(→초대 코드 유무 분기: 받음=코드 입력→연결 / 못 받음=센터 찾기·요청).

### 0-2. 계정·연결
- 계정 모델: **Account → Family(관리자/구성원 2등급) → Profile(아이 N 또는 본인) → CenterLink(N).** Profile은 가족 단위 공유 엔티티. 앱 유저 = Member 없는 Account(기존 SaaS 직원 계정과 토큰 권한 분리).
- **연결 = 초대 코드 방식**(07-15 확정, 전화 인증 단계 제거):
  - 센터가 **특정 보호자(`ClientRelation`) 단위로** 6자리 초대 코드 발급 → 앱에서 코드 입력 → 센터가 초대한 아이 확인 → **CenterLink** 수립.
  - **데이터 방향** — 앱→센터로 아이 기록/데이터 복사 **없음**. 연결로 수립되는 건 CenterLink(Profile↔`client_id` 매핑) + 입력 Account 식별자 + 승인 근거 스냅샷(코드·시점). 이후 센터의 예약·검사·바우처가 **앱 쪽으로** 조회 파생 유입(복사본 없음, §5).
  - **보호자 매핑** — 코드가 보호자(ClientRelation) 단위라, 코드 입력 = 센터 명부의 그 보호자 자리에 Account **부착** → 가족관계 자동 매핑. 앱이 센터에 **새 보호자 레코드를 만들지 않음**(기존 명부에 부착 — 중복·오연결 방지). 앱 Family의 다른 구성원(아빠 등)은 센터로 확산 안 함(각자 코드 받거나 앱 가족 초대로 앱 안에서만 공유).
  - **보호자(법정대리인) 확인 = (a)안**(07-15 대표 지시): 코드 발급 시점에 센터가 명부로 확인한 것으로 봄. 앱 내 별도 본인인증 없음(대안 (b) 코드+1회 인증은 미채택).
  - 폴백: 코드 오류→재발급 안내 / 코드 없음→역방향 연결 요청·데스크. 연결 완료 후 **후회 유예**(아이 다시 선택, 센터 표면 무노출 자동 정리).

### 0-3. 탭·화면 (탭 5개: 홈 · 일정 · 기록 · 센터 찾기 · 마이 — 07-15 일정 탭 신설)
- **일정** — 예약·바우처·결과지·**진행 현황**의 고정 주소. **두 축으로 나뉨**: ① **다가오는 일정**(미래 예약 — 비어도 됨: "다가오는 예약이 없어요") ② **진행 현황**(누적 — 예약이 0이어도 남아, 지난 상담·검사를 언제든 조회). 다음 예약은 **카드 탭 → 예약 상세 시트에서** 변경/취소(카드엔 변경 버튼 미노출). **예약 변경 = 보호자 요청(희망+메모) → 센터 수정권한 직원 승인 → 담당 선생님 푸시 + 보호자 알림**, 확정 전까지 기존 시간 유지.
- **진행 현황**(일정 탭 내 · 웹 케이스 이력의 앱 대응) — **상담**: `type · N/M 회기` → 지난 회기 목록 → **완료 회기 상세**(N회기차·날짜·출석 + **상담사가 공유한** homework/다음목표만; 없으면 "공유된 내용 없어요"). **검사**: 목록·상태(결과지 도착/완료/진행중/예정) → 결과지·실시. **노출 게이트(§2-3·2-4)**: 진행 N/M·출석·공유분만, **상담일지 임상 원문·private_notes·AI 분석은 G1 비노출**("상담 기록은 선생님의 영역"). 별도 탭 아님(탭 5개 유지 — 이력은 daily 아니라 상시 탭 불필요).
- **바우처**(중요도 상향) — 목록 페이지(보유 바우처 아이별 + 받을 수 있는 제도 카탈로그) · L3 상세(센터 기준 잔여 + 사용 내역["기록의 다녀온 날과 하나씩"] + "다음 달 N회로 갱신" + 재신청 리마인더). **회기 수만 노출, 금액 비노출.** **✅ 07-31 구현** 바우처 홈(시안 480:4615) — `GET /app/client-vouchers`(아이별 잔여·유효기간, 금액 비노출), 프로필 칩 전환 + 카드 스택(드래그·터치로 앞장 교체). 사용 내역·재신청 리마인더는 이월.
- **바우처 자격 매칭**(내집다오식 킬러 기능) — 소셜 로그인은 신원만 주므로, **자가진단 2문항**(소득 구간 · 진단서/검사 유무)으로 자격 정보를 받아 각 바우처의 **자격 룰**(`{maxAge, incomeMax, needEvidence}`)과 매칭 → "받을 수 있어 보이는 지원 N개" 추천(ok/조건부/해당 어려움 3상태). **판정 아닌 안내** — "받을 수 있어 보여요, 최종 확인은 주민센터·복지로에서"(§7-2 판정 금지 정합). 입력값(소득·진단)은 **비저장, 매칭만**(민감정보 최소). 자격 룰은 지자체·연도 변동 대비 **제도 팩(§17-5)에 담아 서버 갱신**, 화면에 기준일 표기.
- **센터 상세** — 실제 공공 API 스키마 필드 렌더: `category·distance·address·cures·voucher(콤마 문자열)·inspections·service·phonenumber·time·owner·link_url·thumbnail_url`. **`saasLinked`(우리 시스템 연동 여부)는 공공 스키마 밖 별도 매핑값**(link_url=센터 홈페이지지 우리 연동 아님). 후기·평점 없음.
- **청구·결제** — **조회만**(인앱 결제 없음). 바우처=회기 · 청구서=원, 지원금 라인에 적용 회기 병기("바우처 지원 · 4회 적용 -180,000원"). 상태 라벨 중립(연체·빨강 금지). **✅ 07-22 구현** `GET /app/billables`(draft 비노출·단가/메모 G2 제외), 마이 진입 행(active 링크 시).
- **가족** — 한 아이를 부모 둘이 함께 본다. Family 2등급(관리자/구성원). **✅ 07-22 구현** `/app/family/{invitations,join,members}` + 나가기·추방. 초대 코드=센터 코드 구조 복제(6자리·48h). 권한: 초대·추방·센터 연결·연결 해제·프로필 삭제 = 관리자만, 구성원=열람·프로필 수정. ⚠️ 관리자 이양 미구현(sole owner 고정).
- **알림** — 이벤트 소환 모델(§0-4). **✅ 07-22 구현** 수신자=`client_id→center_links→family_id→가족 전원`(합류 배우자 포함). 생산자 6곳(검사·상담 접수·일정 변경/삭제·회기 취소). 인앱/푸시 문구 분리(NTF-01 잠금화면 무해). 앱 알림함(단일 인박스)+설정(인앱/푸시 토글)+홈 종 배지. 인앱은 로그인 무관 상시 축적, 푸시는 토큰 등록(로그인+권한) 시에만. ⚠️ 실기기 푸시 미검증 · **초대 코드 문자 전달·앱 미설치 보호자 알림톡 폴백 미구현**(§10 07-22 이월).
- **결과지** — 원본 그대로 + 판정 무음 착지("결과지는 선생님과 함께 읽을 때 가장 정확해요"). 열람 시 원장에 마디(result_doc).
- **기록** — 자발적 텍스트 관찰은 주력·성공지표에서 **내림**(리텐션 훅 아님). 말씀 담기·첫 방문 정리는 유지 — 존재 이유를 **"선생님에게 건널 재료"** 로 좁힘.

### 0-4. 리텐션·시각 원칙
- **이벤트 소환(push) 모델** — daily/DAU 앱 아님. 치료 주기 + 이벤트(예약·결과지·바우처 임박·재신청) 발생 시 앱이 부른다. 스트릭·죄책감 장치·빨강 배지 금지(§7). 지표는 이벤트 도달률·연동 W4 리텐션(구 "주간 기록 작성률"은 종과 불일치).
- **시각** — 일러스트 히어로 + 파스텔 섹션 카드(홈), v2 컴포넌트 토큰(액센트 #4486FF). 미연동 홈에 **센터 추천·육아 매거진 허용**(§5 "홈 타 센터 노출 금지"·§7 "채우기 콘텐츠 금지" 원칙 07-15 일부 완화 — 발견 깔때기·리텐션 목적).

### 0-5. 백엔드 정합 (기존 SaaS Client와 붙일 때 — 07-15 코드 조사 기준)
- **앱 Profile ↔ 웹 Client 데이터 모델** (`apps/api client` 모델·`apps/web clients/register` 대조):
  - 웹 Client DB 진짜 필수(nullable=False) = `name·role·code·status·center_id`. **사용자 입력 필수는 `name`·`role`뿐**; `birth_date·gender·phone·email·address`는 DB상 선택. `code`(6자리)·`status`(active)·`role`은 서버가 관리(앱 미입력).
  - 단 웹 UX·배치 등록·중복판정은 **이름+생년월일(+성별)** 을 사실상 필수로 취급. **센터 내 중복 판정 키 = 이름+생년월일**(`find_by_name_birth_in_center`).
  - **앱 Profile 정합 원칙**: 정합 키 = **이름 + 생년월일**(연도만 X — 자격 매칭 나이 룰·센터 중복판정이 생년월일 필요). 단 게스트 진입은 최소(애칭+연도) 유지, **생년월일은 정식 순간(자격 매칭·연결)에 점진 수집**. 성별·주소는 앱에서 안 받고 연동 시 센터 Client가 정본. `phone`은 연결 매칭에 필요(아래).
- **연결 아키텍처 재정합 (⚠️ 앱 표현 ↔ 백엔드 현행 차이 — 구현 시 재설계 필요)**:
  - 백엔드 연동 = **Person ↔ Client 매핑**인데 **`role='client'`(아이) Client는 연동 금지 · `guardian`/`both`만 연동 가능.** 즉 실제 연동 대상은 **보호자 Client**. → 앱의 "아이를 연결"은 백엔드에서 **"보호자 Client에 Person 부착 + 그 보호자의 자녀(client)를 앱 Profile에 노출"** 로 매핑된다. 이는 07-15 "코드=보호자(ClientRelation) 단위 발급"과 정합(연동이 보호자에 붙으므로).
  - 현행 `ClientLinkRequest` 매칭 키 = **전화번호(Person.phone)** + **수동 승인**(상담사가 client_id 지정). **초대 코드 개념은 백엔드에 아직 없음.** → 07-15 초대 코드 방식은 `ClientLinkRequest` 확장(코드 필드 + 코드→client_id 자동 결정)으로 구현; 코드가 곧 "센터가 지정한 대상"이라 수동 승인을 대체 가능.
  - 1 Person = 센터당 1 Client(중복 연동 방지). `both` 승격(내담자였던 사람이 보호자 겸함) 존재. `relation_detail` enum(mother/father/grandmother… caregiver)로 관계 표기.
  - **정체성 2평면 구조 (멀티센터 통합·중복 방지의 근거)** — 임상 데이터는 센터별 격리, 통합은 전역 평면에서만. 아동이 여러 센터를 다녀도 앱에선 **프로필 1개**:

    ```
    [전역 평면]  center_id 없음 · 계정 소유            ← 아이가 하나로 통합되는 유일한 곳
       Account ─ Person ─ Family ─ Profile "지민"(아이=전역 1개) ─ center_links(N)   [Profile·center_links = 신설]
                     ▲                                    │
                     │                                    ├─▶ (center A, 아동 client_id_A)
         Client.person_id                                 └─▶ (center B, 아동 client_id_B)
         (테넌트 보호자행 → 전역 Person)                       center_links = Profile ↔ (center_id, 아동 client_id)
       ═══════════════╪═══════════════════════════════════════════════════ 테넌트 경계
       [테넌트 평면]   center_id NOT NULL · 센터 격리 · 아동은 센터마다 "별도 행"
                     │
         센터 A:  Client(보호자 · center=A · person_id=지민맘)
                    └ ClientRelation ▶ Client(아동 "지민" · center=A)   ◀ center_links_A
         센터 B:  Client(보호자 · center=B · person_id=지민맘)
                    └ ClientRelation ▶ Client(아동 "지민" · center=B)   ◀ center_links_B
    ```

    - **아동은 DB에 센터마다 별도 행**(`Client.center_id` NOT NULL) — 처음 등록한 센터 A 행은 A 테넌트 소유, 센터 B는 자기 행을 새로 만든다(B는 A를 모름). 중복이 아니라 멀티테넌트 격리(정상). **Client 테이블 자체가 테넌트 스코프** — 통합은 Client 층이 **아니라** 전역 평면에서 일어난다.
    - **두 평면을 잇는 다리는 참조 필드 2개뿐**: `Client.person_id`(테넌트 보호자행 → 전역 Person, 이미 존재) · `center_links`(전역 Profile → 아동 client_id, 신설). 임상 데이터는 전역화하지 않는다 — 프라이버시·테넌시 근거.
    - **통합 조회** = `clients WHERE person_id=P`(테넌트 가로지름 · 본인 데이터 한정) → ClientRelation → 아동행 → `center_links`가 Profile 하나로 묶음 = 통합 타임라인. 센터끼리는 서로 못 봄(상담사 콘솔은 `center_id=자기` 필터 유지).
    - **앱 전역 중복 방지 = "아이 확인" + `center_links` 유니크**: 둘째 센터 코드 청구 시 **이름+생년월일로 후보 제안 → 부모가 확정**(자동 매칭 금지 · 제안 오버라이드·새 프로필 폴백 가능), `center_links`는 센터당 Profile 1개 · 아동행→Profile 1개를 강제. 통합 뷰 = **시간축 병합+센터 라벨**이지 합산·임상 해석 아님(§7 판정 금지 · 인벤토리 G1).
- **구현 선행 과제**(인벤토리 §5와 정합): ① 내담자 인증층(Person·CenterLink) — ✅ 07-16 구현(JWT audience + `modules/family`·`modules/center_link`, 결정 로그 07-16 참조. 초대 코드는 `ClientLinkRequest` 확장이 아니라 §18 판정대로 **신설** `center_link_invitations`로) ② 웹 상담사측 코드 발급 UI — ✅ 07-16 구현(내담자 상세 앱 연결 카드) ③ 앱 프로필 생년월일 점진 수집 — ✅ (profiles.birth_date nullable, 연결 시 명부값 승계) ④ 바우처 자격 룰 = 제도 팩 서버 배포 — 이월.

### 0-6. 연결 화면 구현 지침 (웹 발급 ↔ 모바일 청구 — 디자이너 핸드오프)

> 초대코드 연결은 **두 앱에 걸친 한 흐름**: 웹(상담사)이 보호자에게 6자리 코드 발급 → 모바일(보호자)이 코드 입력·아이 확인·연결. **3원칙(양쪽 공통):** ① 코드는 **보호자(guardian/both) 단위** 발급 — 아이에게 발급하는 화면 없음(아이는 보호자 연결 시 자동 노출) ② 앱은 센터 명부의 아이를 **확인만**, 새로 만들지 않음 ③ 중복 방지 = **이름+생년월일 제안 → 부모 확정**(자동 합치기 아님).

- **웹 (상담사 콘솔 · 신규 — 현재 UI 없음. 위치 = 내담자 상세 `clients/[clientId]`):**
  - **① 코드 발급** — 보호자 내담자 상세의 `ProfileSection` 액션(또는 "앱 연결" 탭). 발급 전 = `[앱 초대 코드 발급]`; 발급 후 = **6자리 코드(크게) + 만료("48시간 유효") + `[문자 보내기]`(message-templates 재사용) + `[재발급]`**. **대상 확인 문구 필수**: "○○ 보호자에게 발급 — 연결되면 자녀 △△이 앱에 보입니다"(누구에게·어느 아이가 딸려오는지 명시). 상태 3종: 발급 전 / 발급됨·대기 / 연결됨. **✅ 07-22 구현**(복사 버튼까지 · `[문자 보내기]`는 미구현 §10). **발급은 보호자 상세 한 곳에서만**(07-22 UX 판정 — 발급 지점 단일화로 재발급·상태 혼란 방지). 아이 상세는 발급하지 않고 안내만: 보호자 있으면 `[보호자 화면으로 이동]`, 없으면 `[보호자 등록하기]`.
  - **② 연결 상태 배지** — 내담자·보호자 목록/상세에 `미연결 · 발급 대기 · 연결됨`. 관리자 요약 "연결된 보호자 N명"(영업 자산 프레임 — 미연결 폄하 톤 금지).

  - 컴포넌트는 디자인시스템 v2 토큰 준수([.claude/rules/frontend/web.md](../../.claude/rules/frontend/web.md)) — 새 언어 만들지 않는다.
- **모바일 (내담자앱 = 보호자 · 시안 단일 소스 = 프로토타입 v1.0 LNK 흐름):** 대부분 이미 있음 — LNK-01 코드 입력 · 코드 오류 폴백 · 코드 없음→역방향 요청 · LNK-05 완료+후회 유예를 그대로 실물화. ✅ 07-16 `apps/mobile-client` 스캐폴딩 완료(Expo SDK 54 · apps/mobile 패턴 · 탭 5 · 온보딩→가입→코드→아이 확인→완료 + 홈/일정/마이 MVP). 역방향 요청은 이월(데스크 안내 폴백).
  - **★ "아이 확인" 화면만 멀티센터 dedup 보강** — 현행 프로토는 "이 아이 ✓ / 새 프로필"만 있다. **둘째 센터 코드**일 때 이미 앱에 있는 아이를 표현해야 함: `● 지민(이미 있어요 · 해맑음센터 연결됨) ✓추천`(이름+생년월일 일치로 자동 선택) + 부모 탭 확정 + **오버라이드**(추천이 틀리면 목록에서 다른 프로필 직접 선택) + 새 프로필 폴백. §0-5 2평면 · "통합 기준 = 부모 확정"의 화면 표현.
- **디자이너 비관여(백엔드 몫):** `Client.person_id` 매핑 · `center_links` · 코드→대상 자동결정 · 내담자 인증층.

## 1. 정체성

**"아이(또는 나)의 센터 여정에서 지금 해야 할 일과 그동안의 기록을 한곳에 모아주는 앱."**

- 회사 본업은 센터용 운영 SaaS. 이 앱은 그 센터의 고객(보호자·내담자)에게 주는 앱 — **상황 ③(연동)이 회사 우선순위 최상위**, 단 ①·②도 혼자 설 수 있게 설계
- 북극성 = **여정 원장**(기록은 상황이 바뀌어도 전부 이어짐, 소유는 항상 유저)
- 페르소나 기준점 "지민맘": 38세 워킹맘, 5세 아이 "언어가 좀 느린 듯" 언질, 밤 맘카페, 전화 못 함, 육아 앱 3회 삭제(빈칸 죄책감)
- **센터 유형 중립**: 아동 발달은 비치헤드일 뿐 — 코어 구조는 성인 상담센터에도 성립해야 한다("본인" 프로필, 마음투자 바우처 명단으로 검증됨)
- 서비스명: **마인드스코프** (07-09 확정. 스토어 검색 노출은 이름이 아니라 서브타이틀·키워드 필드로 대응 — "센터 찾기"·"바우처" 등)
- **v1 범위 = 설계 전체(시안 24종 전부)** — 축소 없음 (07-09 감사 판정 1)
- **성공 지표 4개** (07-09 감사 판정 3): 연동 전환율(초대→연결 완료) · 연동 유저 W4 리텐션 · 센터당 연결 보호자 수(SaaS 영업 자산) · 주간 기록 작성률(말씀 담기·관찰기록). 목표치는 출시 후 베이스라인 측정 뒤 설정

## 2. 구조 — 사용자의 상황 3가지

같은 앱, 상황에 따라 홈의 공급원이 달라진다. 첫 실행 때 "지금 어느 쪽에 가까우세요?"로 시작점만 정한다.

| 상황 | 정의 | 홈의 공급원 |
|---|---|---|
| ① 센터가 처음 | 걱정 시작~알아보는 중, 다니는 센터 없음 | 유저 + 공공 정보 |
| ② 미연동 소속 | 센터 다니는 중, 그 센터가 SaaS 미사용 | + 유저의 세션 리듬 |
| ③ 연동 | 센터가 SaaS 사용 — **최우선 케이스** | + 센터 데이터(자동) |

- 흐름: ① → (센터 등록) → ② 또는 ③. ②의 센터가 SaaS 도입하면 ③으로
- 상황은 재질문 없이 **행동 기반 자동 승격**(찜·등록·연동)
- 한 가족 안에 ①②③ 공존이 기본 지원(다자녀 혼합 상태)

## 3. 상황 ① — 센터가 처음 ("다음 한 걸음을 알려주는 것")

정보(목록·콘텐츠)가 아니라 **행동 대본** — 막막함을 걸음으로 바꾼다. 여정은 센터 등록 전부터 시작되고 그 기록은 원장의 프리퀄이 된다.

**위상 (07-09 전수 감사 R2 확정):** ①은 성장 엔진이 아니라 **입소문 랜딩 + ③ 유저의 여정 앞부분**(둘째 아이 걱정 등). 획득 KPI 없음, v1 마케팅 투자 없음 — 유입은 자연 유입(맘카페 선배맘 추천 = ③→① 역방향 전파)만. 공유 산출물(첫 방문 한 장 PDF 등)에 앱 이름 워터마크 한 줄.

```
설치 → "지금 어느 쪽에 가까우세요?" (게스트)
 ├─ 지켜보고 있어요 → 관찰기록(한 줄+영상, 촬영 가이드) · 공공 선별 안내(3갈래) · 바우처 정보(안도 톤)
 ├─ 알아보고 있어요 → 행동 대본("이번 주 두 군데 전화 — 물어볼 것") · 센터 찾기 · 전화 후 리마인더
 │                     · 공백기 적응형 홈(임박 리마인더 > 기록) · 초진 확정 → D-day + 정렬 화면
 └─ 다니는 센터가 있어요 → ②/③으로
```

| 기능 | 확정 내용 |
|---|---|
| 시작 질문 | 진단 언어 금지, "가까우세요"로 선언의 무게 낮춤. 게스트로 진행 |
| 가입 시점 | 둘러보기는 게스트 끝까지. **첫 저장 행위(기록·찜·리마인더)에서 소셜 가입** → §6 동의 스택 |
| 관찰 기록 | "카톡 나에게 보내기" 기준 — 한 줄, 날짜 자동, 빈도 무요구. **날짜 축 탐색 허용**(07-28 개정 — 구 "달력 뷰 금지", §7-1·§15-4 참조). 사후 선택 칩(상황 태그 = 장소 축. 감정 `mood`는 선행·필수로 별도 — §15-1). **영상 1급** + 촬영 가이드("이럴 때 30초", 치료사 감수) — 검사실에서 안 나오는 평소 모습이 임상 가치. 주경로 앱 내 촬영, 보조 갤러리 가져오기=복사 |
| 무료 검사 안내 | 공공 무료 선별검사로 안내, **3갈래 분기**(검진 전 / 심화평가 권고 / 결과 정상인데 걱정). 앱은 판정 뉘앙스 절대 금지 |
| 바우처 정보 | 제도 설명 + 신청 기간 알림. 걱정 단계 홈에도 입구(안도 톤 "지원받을 수 있어요"). 미연동 유저에겐 제도 정보만 |
| 센터 찾기 | **리스트 우선 + 지도 토글**(07-09 확정). 바닥 데이터 = 공공 바우처 제공기관 명단(전국 2,843곳·시군구당 ~12곳·위경도 확보 가능). 카드 = 이름·거리·바우처 세 줄(공공 팩트가 얇음). 지방은 가까운 순+옆 지역 확장(빈 지도 금지). 검색바 최상단 크게(맘카페 이름 검색 동선). **후기·리뷰 절대 금지**. 성장층 = 전화 이력의 구조화 익명 집계(선택지 입력만·3개월 만료) — **수집만, 노출 보류** |
| 전화 도우미 | "전화하면 이걸 물어보세요" 스크립트 → 전화 끝 한 줄("언제 다시?") → 리마인더. 대기 순번 보드는 안 만듦(센터가 순번을 안 알려주는 게 현실) |
| 첫 방문 준비 | D-day + **기록 시간순 한 장 정렬 화면**(치료사에게 보여주는 용도, 판정 무음) |

## 4. 상황 ② — 미연동 소속 ("매주의 5분을 붙잡는 곳")

②는 독립 제품이 아니라 ③의 미연동 모드 — 연동 시 센터 데이터로 대체될 수기 표면은 만들지 않는다. 연동돼도 센터가 절대 대체 못 하는 것(부모 기록·선생님 말·홈워크)으로만 산다. 무대 = **대기실 프라임타임**(수업 40분).

| 기능 | 확정 내용 |
|---|---|
| 센터 등록 분기 | 센터 검색 → (a) 연동 센터 = "바로 연결" 배지 → ③ 절차 (b) 미연동 → ② 모드 (c) 미등재 → 직접 입력 + ② 모드. 배지는 기능 사실만 — 미연동 폄하 금지 |
| 수업 일정 | 반복 슬롯 1개만(리듬의 시계). **휴강·보강은 정직하게 포기** — 그 불편이 연동 전환의 동력 |
| 다녀왔어요 | 원탭 = **원장에 마디 찍기**(카운트 아님). 다녀온 횟수는 표시 OK, **잔여 회기 계산 절대 금지**(센터 장부의 영역 — "세 번째 숫자"는 신뢰 붕괴) |
| 선생님 말씀 담기 | 하원 5분 브리핑의 휘발 붙잡기. **녹음 기본, 직접 적기 폴백**(같은 슬롯). 양해 프레임 내장("잊어버릴까 봐 담아둘게요"라고 말씀드려 보세요). **은밀·백그라운드 녹음 절대 금지**(치료사 레드라인). STT·AI 요약은 AI 프로덕션 승인 후. **07-09 감사 개정**: ① **첫 선택 기억** — 시트 구조 고정, 히어로 자리 점유자만 교체(직접 적기파에겐 ✏️가 히어로), 설정 토글 없음 ② ② 리마인드는 서버 푸시 아닌 **로컬 노티**(슬롯 종료+15분·옵트인·유저 조정) ③ 녹음 스펙: 포그라운드 한정, 화면 잠금 시 자동 저장 종료, 최대 15분 |
| 홈워크 카드 | "집에서 이렇게" 일주일 홈 상주. 미실행 표시·경고 없음 |
| 종이 문서 보관 | 평가 보고서 등 사진으로 원장에 마디 |
| 연동 안내 (노이즈 마케팅) | 골격 = **"말하게 하지 말고 보이게 하라"** — 정당한 사용(초진 정렬·말씀 메모·대기실 어깨너머)이 노출이 되게. ③ 프리뷰는 **상시 배너 금지, 아픈 순간 원샷**(슬롯 수동 이동, 종이 결과지 촬영 직후) + 쿨다운 월 1회 + 센터 탓 금지 톤. [센터에 소개장 보내기] = 치료사가 먼저 물었을 때 받아주는 장치(마이 쪽, 저자세) |
| 센터 찾기 (② 프레임) | **탭 이름은 "센터 찾기"로 전상황 고정**(07-09 판정 4 — "다른 영역 알아보기" 개명 폐지). 내용은 병행 니즈 프레임(언어+감통+놀이가 발달 표준) — 환승 조장 인상 제거는 이름이 아니라 결과 구성이 담당 |

## 5. 상황 ③ — 연동 ("손으로 하던 것이 자동으로, 내 것은 계속 내 것")

홈 골격 불변 — 센터는 **세 번째 공급원으로 합류**할 뿐, 홈이 "센터 우편함"이 되지 않는다. ①②의 습관은 연동 후에도 그대로.

| 영역 | 확정 내용 |
|---|---|
| 자동으로 오는 것 | 예약 D-1·휴강/변경 · 온라인 검사 · 사전 설문 · 결과지 · 바우처 잔여(**이제 진짜 숫자**). 전부 센터가 이미 만드는 운영 데이터 — **상담사 신규 노동 제로** 원칙 |
| 세션 마디 | 센터 데이터로 자동 생성(수동 "다녀왔어요" 은퇴). 말씀 담기 트리거: 연동 직후 신규 유저만 세션 종료 시각 푸시(리추얼 형성기 한정·중립 문구·조기 소멸) → 이후 홈 프롬프트만 |
| 연결 경로 | **4경로** — ①문자 편승 ②데스크 QR ③가족 초대 ④역방향 연결 요청(유저 요청 → 센터 web "연결 요청 N건" → 직원 명부 확인 후 승인). **전화번호 자동 연결 금지**(오연결=개인정보 사고). **기존 계정 합류** — 새 계정이 아니라 쓰던 계정에 CenterLink 부착, 아이 프로필 확인 단계(형제 오연결 방지, 자동 매칭 없음). ② 유저의 센터가 연동되면 앱이 감지해 제안. 부수효과: "연결 대기 N명" = 영업 자산. **07-09 감사 개정(역방향 승인 보강)**: 승인 화면에 대조 근거 자동 표시(전화번호 일치 등 — 판단을 확인으로 격하) · N일 미처리 시 유저에게 대안 경로(데스크 QR) 안내 · 센터 이용계약에 승인 책임 조항(법무) · 관리자 화면에 "연결 보호자 수" 지표(센터의 자산 프레임) |
| 공유 모델 | **"보내기"가 아니라 "보여주기 허용"** — 항목별 토글 → 상담사 SaaS 화면의 "가정 기록" 영역에 조용히 표시. **풀 원칙**: 알림 금지·읽음 표시 금지·응답 무의무 명시(상담사의 새 노동 금지). 복사본 없음 → 토글 OFF·연결 해제 = 즉시 소멸. 상담사 화면에 "보호자 동의 하에 공유됨" 표시. **07-09 감사 개정**: 기대치 문구("수업 준비 때 참고해요 — 답장 기능이 아니에요")를 **토글 켜는 그 자리에 크게**. 열람 존재 표시(긍정 존재형)는 상담사 측 고지 필요성 때문에 치료사 감수와 함께 보류 |
| 바우처 노출 3층 | L1 할 일 카드(임박만) · L2 마이 상시 · L3 상세. **회기 수만, 금액 비노출** |
| 다자녀·다중 센터 | 계정→아이 프로필(N)→센터 연결(N). 홈 하나 + 사람 칩, 기록 타임라인은 아이별. 센터 간 격리(각 센터는 자기 데이터 + 자기에게 허용된 가정 기록만) |
| 가족 공유 2등급 | **관리자**(주 보호자 — 초대·내보내기·공유 토글·프로필 관리) / **가족 구성원**(열람+작성 전부). 3등급 없음. 분쟁 가정의 문지기 = 관리자 |
| 디렉터리 (연동 유저) | 탭 "센터 찾기" 고정(07-09 판정 4) — ① 첫 결과 = **지금 다니는 센터의 다른 프로그램**(센터엔 업셀 채널) ② 능동 검색에만 열림(홈 배너·추천·알림으로 타 센터 노출 금지) ③ 같은 영역 검색도 차단 안 함(막으면 가짜 어포던스). **탭 내용은 선택된 아이 칩을 계승**(첫째=③ 프레임, 둘째=① 프레임, 가족 전체=가장 이른 상황 아이 기준) — 다자녀 혼합 모순 해소. 영업 자료에 이 구조 명문화 |
| 다음 단계 (보류) | 상담사가 주는 것(브리핑·퀘스트·서류 발급) — 상담사 신규 노동 발생 기능이라 ⏸ |
| 노출 게이트 (자매 문서) | 센터 데이터의 노출/숨김 판정은 [노출요소 인벤토리](2026-07-08-내담자앱-노출요소-인벤토리.md)의 **3대 게이트**를 따름 — G1 임상 원문·AI 분석·상담사 사견 비노출 / G2 자기 데이터만(센터 내부 운영값 숨김) / G3 기존 가시성 플래그 존중(`is_report_visible_to_guardian` 등). 도메인별 매트릭스·판정 요약표 포함 |

## 6. 공통 시스템 — 계정 · 동의 · 데이터

### 6-1. 계정 모델 (07-09 전수 감사 R1 개정: 3층 → 4층)
**Account → Family → Profile(아이 N 또는 본인) → CenterLink(N).** Profile은 계정 소유가 아니라 **가족 단위 공유 엔티티** — 가족 2등급(관리자/구성원)은 Family 멤버십의 속성. 게스트 → 첫 저장에서 소셜 가입 → 전화번호 인증은 센터 연결 때만.

구현 전제(백엔드 — 기존 전문가·관리자 계정 영향 없음 확인, 07-09):
- 기존 `accounts`(글로벌 인증, 소셜 필드 기존재) **재사용** — 앱 유저 = Member 없는 Account. 단 **토큰 권한 분리**(앱 전용 계정의 SaaS API 접근 차단)
- 신설 갈래: `family_members → families → profiles → center_links` — SaaS 테넌트(center_id 격리) 밖 첫 글로벌 도메인
- CenterLink = 앱 Profile ↔ 센터 `client_id` 매핑 + 승인 이력. 오매핑 = 최악의 개인정보 사고 — 자동 매핑 금지 원칙의 데이터 층 근거
- 센터 데이터는 앱 DB로 복사하지 않고 조회 시점 파생("복사본 없음"과 일치)
- **기존 자산 정합 판정 완료(07-14 — §18)**: ClientLinkRequest는 §14의 선행 구현체가 **아님**(보호자↔보호자 Client 연동 — role='client' 연동 금지, Profile↔아이 client 매핑과 층위 상이). 판정=대체, 기존 행 동결. 엔티티별 확정 매트릭스·신설 목록·선행 과제는 §18

### 6-2. 동의 설계 (07-09 확정)
- **가입 시점 일괄 동의** — 사용 순간엔 동의창 없이 안내만. 일괄 ≠ 포괄(항목 분리 체크)
- 스택 = **필수 3**(이용약관 · 개인정보 · 민감정보=아이 발달 기록, 글·사진·영상·녹음) + 선택(마케팅). **전체 동의 원탭** 병존. 법정 명칭은 고지 본문에, 리드는 "아이의 기록을 안전하게 보관하기 위해" 톤. 각 항목 4요소(목적·항목·기간·거부권)
- **보호자 확인 2단**: 프로필 생성 시 자기신고 한 줄 + 연동 시 기존 절차(명부·본인인증)의 법정대리인 확인 공식화. "내 이야기예요" 갈림길로 성인 본인 성립. 가족 구성원도 자기 가입 시 동일 스택(법정대리인 동의는 관리자 1개로 성립)
- **공유 토글 = 제3자 제공 동의** — "한 줄 + 펼침"(제공받는 자·목적·항목), OFF = 즉시 중단
- **녹음(선생님 목소리)은 발화 소속 센터에만 공유 가능** — 타 센터엔 토글 자체가 없음. 내용의 타 센터 전달은 메모 경로. 양해 프레임은 법적 동의와 별개 층으로 녹음 화면에 유지
- **출구 4개**: 철회·탈퇴 = 내보내기 제안 → 30일 복구 유예 → 완전 파기 / 연결 해제 = 제공 중단(파생 카드 소멸, **원장 마디는 보존**) / 가족 내보내기 = 접근권 회수(작성 기록은 아이 타임라인에 보존, "구성원 작성 기록은 아이 기록의 일부" 약관 명시)
- **투명성 계단**(가드레일 ④ 구현): 목록 아이콘만 → 상세 한 줄("해맑음센터 김○○ 선생님이 볼 수 있어요") → 탭 펼침. 입력 화면엔 한 줄 상시. 허브 = **마이 > "내 기록과 동의"**(동의 현황·역방향 공유 목록·내보내기·철회·탈퇴)

### 6-3. 데이터 저장 (07-08 대전환)
서버 무저장 원칙 폐기 → **동의 기반 전체 서버 저장 + 가드레일 4**: ①암호화 ②접근=본인+항목별 허용 담당자만 ③2차 활용(AI 학습 등) 금지 ④투명성 한 줄.

| 데이터 | 저장 | 비고 |
|---|---|---|
| 글 기록·말씀 메모·전화 이력·알림·일정 | 서버(계정 귀속) | 폰 변경 생존 |
| 영상·사진·녹음 | 서버(암호화·동의 기반) | 가져오기=복사 후 업로드, 압축+30초 가이드. **쿼터(07-09 판정 2): 월 10개·개당 1분(가안), 전상황 동일.** 누적 총량 무제한·자동 삭제 없음·소급 잠금 없음. 미터·진행바 비노출, 도달 시만 한 줄("이번 달 영상은 여기까지 담겨요"). "연동하면 무제한" 류 문구 금지(센터 탓 금지) |
| 센터 데이터(③) | 서버(읽기 전용 파생) | 원본=센터 SaaS. **내용 복사본 없음 — 단 사건 스냅샷(날짜·센터명·유형)은 원장 소유**(07-09 감사 정정): 마디는 센터 해지·연결 해제에도 생존 |
| 대기 정보 익명 통계 | 서버(수집만·비공개) | 선택지 입력만, 자유 텍스트 금지 |

**데이터 계약 (07-09 전수 감사 합의):**
- 클라이언트 캐시 허용 — read-facade가 ETag 발급, 차등 TTL(예약·바우처 잔여 5분 SWR / 결과지 메타 24h), content-free silent push로 무효화, 포그라운드 복귀 시 재검증. 웹소켓·폴링 v1 배제
- **소멸 SLA 3계층**: 서버 grant 차단=즉시 / 클라 캐시=push 수신 시 purge / 최악(push 유실)=TTL 24h — 처리방침 "즉시 열람 중단" 문구 옆에 이 경계 명기(법무 정합)
- 능동 행위(공유 토글·내보내기·PDF)는 캐시 불신, 항상 서버 재검증. 열람 중 원본 소멸은 다음 재검증 때 조용한 회수 화면(센터 탓 금지 톤)
- 공유 grant = 내용 데이터만, **CenterLink 단위 + 담당 배정 상담사** + 접근 로그. 표시 계층은 개인 이름("김○○ 선생님", 담당 변경 시 자동 갱신·복수는 "외 1명")
- 업로드: presigned 직행 + 서버 트랜스코딩(upload 모듈 media 갈래 신설). 유저 작성 데이터만 낙관적 로컬 커밋 + 백그라운드 큐 — 센터 파생 데이터에 낙관 캐시 금지

## 7. 전 화면 공통 규칙

뿌리는 하나 — **"이 앱은 사용자를 채근하지 않는다."** (지친 30~40대 부모, 대기실에서 한 손)

1. **죄책감 장치 금지** — 빨간 배지·미완료 개수·**스트릭** 금지. 할 일은 때가 지나면 조용히 소멸. 집계는 긍정문만
   - 07-28 개정: **달력 빈칸 금지는 해제**(기록 탭 주간 스트립·달력 뷰 채택 — §15-4). 푼 것은 "빈칸이 보이는 것"뿐이고, **스트릭·미완료 개수 금지는 그대로다** — 날짜 축 UI에 "이번 주 N회"·연속 일수·누적 도트 카운터를 얹지 않는다. 폐기 계보 `features/F10`의 `● ● ● ○ ○ 이번 주 3회 기록`이 정확히 금지 대상이며, 이 경계가 개정의 조건이다
2. **판정 금지** — "괜찮아 보여요"류 일체 금지(거짓 안심이 최악). 정리와 안내만, 해석은 사람의 몫
3. **글 최소** — 공감 문구 화면당 1문장(19px+ 크게), 본문 14px+, 카드 2줄 상한, 명사·숫자 우선
4. **알림은 남이 봐도 무해하게** — 잠금화면 중립 문구, 남발 금지
5. **해당 없으면 표면 자체를 제거** — 빈 상태 안내가 아니라 비노출. 센터 유형 중립의 기반
6. **빈 홈은 실패가 아니다** — "다 챙기셨어요"의 평온. 채우기 콘텐츠 금지

시각 시스템 규칙 (07-09 전수 감사 추가):

7. **색 = 콘텐츠 종류로만** — 기록/일정/바우처 등 종류별 고정(시맨틱 색 5~6개 상한, 초과는 중립 폴백). 상황 ①②③을 색으로 구분하지 않음(자동 승격 시 홈 색 급변 방지). 히어로 = 해당 종류 색의 진한 변형. 상태 칩(업로드 등)은 ink 중립 계열
8. **타이포 바닥** — 최소 13px. 법적·신뢰 문구(동의 각주·풀 원칙·투명성)는 14px+ · ink2 이상 대비 의무. "카드 2줄"의 정의 = 제목+설명 텍스트 행(라벨·버튼 제외), 다이나믹 타입 1단계 확대에서도 유지되는지로 검수
9. **투명성 배지 = 정식 컴포넌트** — 이모지 금지, 전용 아이콘 에셋 + 색 토큰 + 44pt 터치 영역 + 접근성 라벨. 1단 배지는 🔒(기본)/👥(공유 중) **2상태 고정** — 열람·업로드 상태를 얹지 않는다
10. **업로드 상태는 위치 문법** — 성공/실패가 아니라 "기록이 어디 있나": 저장 즉시 타임라인 카드 생성 → "보관 중…" 칩 → 완료 시 칩 소멸. 실패도 같은 중립 칩("아직 이 폰에만 있어요 · 다시 보내기") — 빨강·경고 아이콘 금지

### 13-3. 정렬·표시 규칙

1. **정렬 4키**: tier(rank 1~4) → anchor_at asc(행동 마감 시각, 무앵커는 뒤) → type_rank(무시각 카드의 종류 고정 순서 — **#12 다녀왔어요 > #13 말씀 담기 > 대본 > 기록 > 공공** 명시) → 아이 칩 순(결정적 타이브레이크)
2. **시간 카드는 인터리브 금지** — 순수 시간순(아이 A 14시 → B 15시 → A 16시가 정답). "가족 전체" 칩에서 무시각 카드만 아이 라운드로빈, 같은 아이 연속 2장 금지 — **단 무시각 카드 보유 아이가 1명뿐이면 예외(제한 미적용)**
3. **히어로 1장**: 정렬 최상위가 eligible이면 히어로, 아니면 히어로 없음(=평온). eligible = today 전부 / deadline은 `hero_eligible=window`(anchor ≤ 24h)만 / `never`는 escalate로도 불가침(결과지 등 — 미열람이 커지면 "표정 불변" 위반)
4. **화면 상한**: 히어로 1 + 카드 4. 초과분은 oneshot→ambient→deadline 순 **완전 비노출**(접힘 줄·더보기·개수 금지, §7-1) — today 비노출 금지
5. **미열람 불변**: 위치·문구·색 첫날과 동일. 경과일 표시·색 변화·재알림 금지 — "안 읽은 게 아니라 읽을 힘을 모으는 중"
6. **조용한 소멸**: 만료 판정은 재평가 시점에만, 화면에서 실시간 제거·퇴장 애니메이션·흔적 없음. 원장 마디와 카드 소멸은 절대 결합하지 않음

- 상태 5: `requested`(승인 대기) / `active` / `suspended`(client 삭제·센터 해지·탈퇴 유예 — 복귀 가능) / `rejected` / `revoked`. 터미널에서 재연결 = 기존 행 부활 금지, 새 행(승인 이력 불변)
- **"지난 연결"은 DB 상태가 아니라 표면 명칭** — suspended(센터 사유)·revoked(유저 해제)의 유저 대면 표현. 센터 재가입 90일(가안) 내 → "다시 연결할까요?" 원탭 복원 제안(무통보 자동 재연결 금지)
- 유일성 불변식(partial unique): 살아있는 링크 = `(profile_id, center_id)` 1개 · `(family_id, client_id)` 1개(가족 내 같은 아이 프로필 1개). **가족 간은 N 허용** — 분쟁 가정에서 양쪽 다 법정대리인일 수 있어 모델이 차단하지 않고, 게이트는 승인 화면의 "기존 활성 연결 N건" 배지. 상대 가족 연결의 존재 자체 앱 비노출(안전)
- 감사: `center_link_audits` append-only + **승인 시점 증거 스냅샷 동결**(전화번호 일치·명부 대조·프로필 확인 응답). 전이와 audit insert 동일 트랜잭션. 오매핑 정정 = in-place 수정 금지 → revoke(reason=mismap)+신규

### 14-2. 엣지 판정 (14건 요지)

| 케이스 | 판정 |
|---|---|
| 초대+역방향 동시 | 같은 프로필=자동 수렴(후발 superseded 정리, 유저 비노출) / 다른 프로필=직원 확인 |
| 두 가족이 같은 아이에 요청 | 사람 개입 — "기존 연결 N건" 배지, **기존 보호자에게 알림 금지**(가정폭력 케이스의 역정보) |

| client soft delete 후 | 토큰 무효·요청은 승인 화면에 표시(복구 선행). 기존 링크 suspended |

### 14-3. 운영 정책 (원칙 3 + 확정 정책)

**원칙**: ① 앱은 가정사를 판단하지 않는다(센터는 "명부 일치"만 확인, 서류 기반 예외는 전부 고객센터 수동) ② 거절·종료·박탈의 사유는 유저에게 비노출(항상 다음 행동 안내형) ③ 센터의 퇴장을 앱이 대신 발표하지 않는다.

- **분쟁 가정**: 명부 일치→승인 / 불일치→승인도 거절도 아닌 **"내원 확인" 보류**. 데스크의 친권 서류 심사 금지(심사하는 순간 센터가 분쟁 당사자). 내보내진 구성원의 재시도는 차단하지 않고 같은 절차로 수렴, 본인 작성분 사본 열람권 보장
- **센터 해지**: 전 링크 "지난 연결" 전환, **푸시 금지** — 진입 시 한 줄만("새 소식은 오지 않아요. 기록은 그대로예요"). SaaS 해지 플로우에 "연결 보호자 N명" 고지(해지 억지력). 전원(센터 옮김)은 별도 기능 없음 — 다중 연결 구조가 흡수, 녹음의 발화 센터 한정은 전원 후에도 불변
- **승인 SLA**: **3영업일** 미처리 → 폴백 카드(데스크 QR — "보여주기만 하면 돼요", 재촉을 유저 입에 맡기지 않음). 요청 자동 만료 없음, 30일 경과 시 센터 web에 "오래된 요청" 표시
- **거절**: 기능 필요 — 고정 선택지 2(정보 불일치/내원 확인 필요) + 내부 메모(유저 절대 비노출). 유저 문구는 사유 무관 단일: "센터에서 연결 정보를 확인하지 못했어요. 방문하실 때 데스크에서 도와드릴 수 있어요"
- **가족**: 관리자 이양 v1 포함(지정→수락). 관리자 탈퇴 = 이양 or 전체 정리 갈림길 강제(구성원 30일 유예·각자 내보내기). 사망·연락두절 승계 = 앱 자동화 금지, 고객센터 서류 SOP. 프로필 삭제 = 구성원 존재 시 30일 유예+무해 통지
- **성인 프로필**: 본인인증만으로 연결 성립. **기본 Family 비공유** — 명시 초대 시에만, 관리자=본인 고정(§6-1에 예외 명시). 위기 시 가족 접근 = 앱은 우회로가 되지 않음, 법정대리 서류 SOP만
- **기타**: 유저 번호 변경 = 기존 링크 무영향. 가족 초대 토큰 72h·1회용·합류 통지+즉시 내보내기. 아이 사망 = 프로필 **"보관"**(숨김+보존+알림 영구 중단 — 삭제를 강요하지 않는 제3의 길, 문구 치료사 감수). 오매핑 사후 = 접근 로그 보존 + 사고 대응 SOP

### 14-4. 연결 UX 원칙 (보호자 검증)

1. **막힌 경로는 그 자리에서 다음 경로로**: 인증 실패 화면 = "흔한 일이에요(다른 가족 번호로 등록된 경우가 많아요)" + 역방향 요청 갈아타기 버튼. **명부 번호 힌트 노출 절대 금지**(마스킹조차 — 분쟁 가정 사고)
2. **대기는 세지 않는다**: "N일째" 금지, 폴백은 QR(절차의 얼굴, 부탁의 얼굴 아님)
3. **후회 유예**: 연결 완료 화면에 "잘못 연결하셨나요? 여기서 바로" — **10분(가안) 내 해제는 센터 표면 무노출 자동 정리**(내부 감사만). 문구는 "아이를 다시 선택할까요?"(정정의 얼굴 — "해제"·"삭제" 금지)
4. **초대 랜딩(설치 전 웹)**: "지금 안 하셔도 돼요 — 이 링크는 사라지지 않아요" + [가족에게 보내기] 원탭. 유령 계정 생성 금지
5. **해제 = "마무리"**: 끊기 전에 보존을 숫자로("다녀온 84번의 날들은 그대로 남아요"), 새 센터 연결 흐름 안에서 자연 제안, 센터엔 이벤트 알림 없이 명단 상태만. 해제 사유 묻지 않음
6. **총원칙**: 모든 연결 화면에 "이건 센터에 이렇게 보여요/안 보여요" 한 줄 — "내가 누르면 센터에 어떻게 보이는지 모른다"가 연결 전체의 공포

### 14-5. 대표 판정 3건 (07-09 확정)

1. **해지 예고 = 침묵, 확정 후 30일 사후 유예** — 예고 기간엔 안내 없음(센터 관계·번복 보호), 해지 확정 시점부터 30일간 파생 데이터 접근 유지 + "저장해 두세요" 조용한 안내 카드. 센터 이용계약에 30일 유예 명시(법무)
2. **구성원 작성 기록 = 기본 보존 + 이탈·탈퇴 시 본인 작성분 파기 선택권** — 약관 문안의 출발점, 법무 검토로 확정

### 15-1. `ledger_entries` — 타입 5종 (늘리지 않는다)

| 타입 | 내용 | 미디어 |
|---|---|---|
| `observation` | 관찰 기록(한 줄±사진·영상 — 카톡 문법, 타입 분리 없음) | 0..N |
| `teacher_note` | 말씀 담기(녹음 기본·메모 폴백 — 같은 슬롯. 홈워크는 payload 파생 속성) | 0..1 audio |
| `milestone` | 마디 = 내용 없는 사건 스냅샷. kind: visit_manual/visit_auto/first_visit/result_doc | ✗ |
| `paper_doc` | 종이 문서 촬영 | 1..N image |
| `call_log` | 전화 이력(구조화 선택지 = 익명 집계 소스) | ✗ |

- 핵심 필드: `profile_id`(귀속=아이) · `author_account_id`(구성원 구분, 센터 파생은 null+center_link_id) · `occurred_at`(**사건 시각 = 정렬 축** — 원장은 여정의 시간축, 입력 로그 아님) · `center_name_snapshot`(문자열 동결 — "다녀온 84번의 날들"의 물리 실체) · `external_ref`(내용은 링크 active일 때만 파생 — 복사본 없음) · `situation_tags`(서버 통제 vocabulary만) · `mood`(07-28 신설 — 아래) · `client_key`(멱등, 전체 unique)
- **원장에 못 들어오는 것**: 홈워크 카드·리마인더·예약·검사·설문·알림 — §13 카드의 세계. **카드는 소멸하고 원장은 축적된다** — 소멸하는 것은 원장에 못 들어온다
- `ledger_media` 별도 테이블(1:N): status(pending→uploaded→processing→ready/failed) · renditions · checksum · `quota_month`(발급 시점 동결 — 월 경계 분쟁 차단)

**`mood` — 감정 축 (07-28 신설, 시안 채택)**

`observation`의 속성 필드. 값 6종(`excited`·`calm`·`neutral`·`sad`·`angry`·`anxious` — 표면 라벨 신나요·편안해요·그저그래요·슬퍼요·화나요·불안해요), `situation_tags`와 같이 **서버 통제 vocabulary**.

- ⚠️ **타입 축이 아니다.** 표 제목의 "타입 5종 — 늘리지 않는다"는 여전히 유효하다. `mood`는 6번째 타입이 아니라 `observation` 한 타입의 속성이며, **이 조항은 타입 신설의 선례가 되지 않는다**
- **입력 시점 = 선행·필수** — §3의 "사후 선택 칩"은 `situation_tags`(장소 축)에만 적용된다. 감정은 작성 1단계이고 이후 인라인 수정 가능
- 🔴 **집계·추이·비교 표시 전면 금지** — "이번 달 화나요 12번" 류 카운트, 감정 그래프·차트, 기간 간 비교, 감정 기반 정렬·필터 일체. §7-2 판정 금지의 직접 적용이다
- §15-4-6의 선("앱은 두 시점을 나란히 놓기까지 — 화살표는 절대 긋지 않음")이 **감정에 그대로 걸린다**. 감정 시계열은 이 선이 가장 쉽게 무너지는 데이터다
- 상담사 화면(§16-4) 노출 시에도 **해당 기록의 원본 값만** — 집계·추이는 SaaS 쪽에서도 금지

### 15-2. 미디어 파이프라인

- presigned 직행 업로드(서버 채번 경로·S3 SSE-KMS·presigned GET만 — 기존 image 모듈의 공개 URL 방식 **재사용 금지**) → complete 검증 → 트랜스코딩(1분 상한 검증·포스터·압축) → ready
- **쿼터 이중 집행**: 발급 시 예약 + 완료 시 확정. pending 24h GC(행은 재시도 포인터로 잔존). 삭제분은 쿼터 반환
- **쿼터 범위 정정(모순 해소)**: 판정 2의 월 10개·1분은 **video 한정**. audio(말씀 녹음)는 회당 15분 상한 + 구조 자연 상한(엔트리당 1개) — 월 쿼터 미적용. ②의 심장을 쿼터로 조이지 않는다
- 멱등 계약: 엔트리 재전송=기존 행 200 / upload-url 재요청=같은 경로 재발급 / ready 후 다른 checksum=거부
- 모듈 배치: `modules/ledger/` — family/profile과 같은 글로벌 도메인

### 15-3. 클라이언트 상태 머신

- **작성**: draft → local_committed(타임라인 즉시 등장) → queued → uploading → synced / retry_wait / stalled. **gave_up 없음** — 포기는 업로드의 포기이지 기록의 포기가 아님. stalled = 무기한 로컬 보존 + "아직 이 폰에만 있어요 · 다시 보내기"(중립 칩). 칩은 2초 grace 후 등장(플래시 방지)
- **녹음**: 포그라운드 한정 — `UIBackgroundModes` 미등록·마이크 포그라운드 서비스 미요청(**은밀 녹음 금지를 권한 선언 수준에서 보장**, 스토어 라벨 정합). 인터럽트(잠금·전화·오디오 탈취·15분·앱 킬) 전부 auto_save_stop — 재개 없음, "여기까지 담아뒀어요". 앱 킬 대비 60초 청크 로테이션(필드노트 패턴 재사용, 손실 ≤ 60초). inactive 3초 grace(알림 배너 오탐 방지)
- **오프라인 큐**: expo-sqlite(트랜잭션) + documentDirectory(캐시 금지). 백오프 즉시→10s→1m→5m→30m. 24h 경과/영구 4xx → stalled. synced 후 원본 72h 정리. Wi-Fi 전용 옵션 v1 없음(쿼터 구조상 월 ~50MB). 재설치 유실 고지 = 칩 자체가 상시 고지

### 15-4. 타임라인 규칙

1. 정렬 = `occurred_at desc` keyset 커서(OFFSET 금지), 아이 프로필 스코프, FlashList
2. 로컬 미전송분은 클라가 위치 삽입, synced 시 client_key dedupe
3. **월 헤더 조건부 허용** — 기록 있는 달만·개수 미표기(빈 달 헤더 = 빈칸 문법)
3-1. **날짜 축 탐색 병존**(07-28 신설) — 기록 탭은 주간 스트립(주 이동·날짜별 기록 점)과 달력 뷰를 함께 갖는다. 시간축 목록(1번)이 사라지는 게 아니라 **뷰 토글로 병존**한다. 날짜 점은 유무만 — **개수·연속·"이번 주 N회" 표기 금지**(§7-1 개정 조건)
4. pending/synced 썸네일 시각 동일(차이는 칩뿐) — blurhash, 스피너 금지
5. 배지 1단 2상태 고정 — 업로드 상태를 배지에 얹지 않음(§7-9)
6. **"1년 전 오늘" 되돌아보기 = v1 포함, 단 서랍** — 기록 탭 안에서 내가 여는 것. 홈 상단 금지(가장 힘들었던 날이 아침에 튀어나오는 역효과). 앱은 두 시점을 나란히 놓기까지 — 화살표("늘었어요")는 절대 긋지 않음(판정 금지의 선)

### 15-5. 기록의 사후 생활 (보호자 검증 정책)

| 행위 | 정책 |
|---|---|
| 수정 | body·태그·occurred_at 허용, **무흔적**(v1 이력 없음, "수정됨" 딱지·이력 노출 금지). 공유 중이면 상담사 화면도 조용히 최신만(알림 금지). 미디어 교체는 불허(삭제+신규) |
| 개별 삭제 | **내용 즉시 파기 + 무내용 tombstone** — 본문 null·미디어 실파일(원본+렌디션) 즉시 삭제, 행은 멱등·감사 메타만. 타임라인 묘비·빈칸 없음. 죄책감 팝업 금지. 공유 중이었으면 상담사 화면 즉시 소멸. **grant 이력 없는 미디어 삭제 시 "아무도 보지 못했고, 완전히 삭제됐어요" 사실 확인 한 줄**(판정 아닌 사실) |
| 마디 삭제 | 유저 삭제 허용 — "마디 보존"은 시스템이 안 지운다는 뜻 |
| 프로필 간 이동 | v1 포함 — 원탭 "서준이 기록으로 옮기기", **날짜는 쓴 날 보존**, 공유는 자동 승계 아닌 **대상 프로필 설정을 새로 따름**(원 프로필 공유 화면에서 즉시 소멸) |
| 태그 | 무태그 = 완전한 1등 시민("태그 없음" 표시 금지, 첫 방문 한 장은 시간순이라 무관). 사후 추가는 개별 기록에서 언제든 — **전용 "무태그 목록"은 만들지 않음**(그 자체가 미완료 목록) |
| 탈퇴·철회 파기 | T0 grant 차단 → T+30 S3 실파일 먼저·DB 나중(역순이면 고아 파일 영구 잔존) → 파기 대장(건수·시각 메타만) |

### 15-6. 사용 주체 · 프로필 귀속 · 가족 스코프 (07-28 구체화)

> 07-22 결정 로그가 미결로 남긴 *"부부가 각자 쓴 메모를 가족끼리 서로 보게 할지"* 를 여기서 해소한다.

#### (1) 사용 주체 = FamilyMember 전원

- 작성·열람 모두 Family 구성원 전원(owner·member). `author_account_id`(§15-1)가 구성원을 가른다
- **센터 연결과 무관하게 작동한다.** 기록은 전역 평면(`modules/ledger`)이라 `center_links`가 없어도 쓰고 읽는다 — §3 상황①(센터가 처음)에서 관찰 기록이 핵심 표면이므로 연결을 전제하면 그 상황이 통째로 죽는다. 연결이 필요한 건 §16 센터 공유(grant)뿐
- 성인 본인 프로필(`Profile.relation='self'`)은 아래 (3) 예외

#### (2) 프로필 선택 — 다자녀

기록은 `profile_id`에 필수 귀속되고(§15-1), 타임라인은 아이별이다(§5).

- **프로필 1개 → 선택 단계 없음**(자동 귀속). §7-5 "해당 없으면 표면 자체를 제거"
- **2개 이상 → 진입 컨텍스트를 승계해 단계를 늘리지 않는다**
  - 기록 탭에서 특정 아이 칩이 선택된 상태 → 그 아이로 확정, 선택 화면 스킵
  - "전체" 상태이거나 홈 등 다른 진입점 → 선택 시트 1장 후 진행
- 시안의 "오늘 **은서**의 기분이 어땠나요?"가 이미 이름을 박고 있다 — 프로필이 확정된 **뒤에** 나오는 화면이다. 선택은 그 앞에 온다
- 잘못 골라도 §15-5 프로필 간 이동으로 되돌릴 수 있으므로 **선택에 확인 단계·경고를 붙이지 않는다**
- 작성 중 프로필 전환은 없다(전환 = 새 기록)

#### (3) 가시성 3층 — 기본 = 가족 스코프

| 층 | 보는 사람 | 대상 |
|---|---|---|
| **가족** | profile이 속한 Family 구성원 전원 | 본문 · 미디어 · `mood` · `situation_tags` · `occurred_at` |
| **나만** | `author_account_id` 본인만 | `private_memo` |
| **센터** | grant 살아있는 CenterLink | §16 — 가족 층 위에 다시 걸리는 게이트 |

- 기본이 가족인 근거는 새로 만든 게 아니라 **이미 확정돼 있다** — §6-4 출구 4개: *"가족에서 제외 = 접근권 회수(작성 기록은 아이 타임라인에 보존, **구성원 작성 기록은 아이 기록의 일부** 약관 명시)"*. 기록의 소유는 작성자 개인이 아니라 **아이(=가족)**다. 앱의 다른 데이터도 전부 family 스코프이고 예외는 알림(account 스코프)뿐
- **`private_memo`만 계정 스코프.** 다른 구성원 조회 시 **필드 자체를 응답에서 제거**한다(null로 내리지 않는다 — 존재 여부도 숨김). 가족 스코프 응답에 개인 필드가 섞이는 구조라 노출 사고의 1순위 지점이다
- 표면 문구: "나만 확인할 수 있는 메모" → **"나만 볼 수 있어요 — 가족에게도 보이지 않아요"**. 가족이 볼 수 있다면 "나만"은 거짓말이 된다
- **예외 — 성인 본인 프로필(`relation='self'`)의 기록은 가족 스코프가 아니다.** 작성자 본인만. §14-4 *"성인 프로필: 기본 Family 비공유 — 명시 초대 시에만, 관리자=본인 고정"*의 직접 연장이다. 성인 상담 기록이 배우자에게 열리는 건 사고다

#### (4) 권한 계단

| 행위 | 누가 |
|---|---|
| 작성 | FamilyMember 전원 |
| 열람 | 가족 전원 (`self` 프로필 제외) |
| **수정 · 삭제 · 프로필 이동** | **작성자 본인 + Family 관리자** |
| 센터 공유 토글 | **Family 관리자만** (§16-1 기존) |

- §15-5의 *"고치고 지우고 옮기는 데 앱의 허락도 흔적도 잔소리도 없다"* 는 **내 기록**에 대한 보장이다. 남의 기록까지 아무나 지우면 분쟁 가정에서 사고가 된다
- 관리자 폴백을 두는 이유는 §16-1 공유 토글과 같다 — "분쟁 가정 문지기". 이탈 구성원 기록 정리(§14-5 파기 선택권)도 관리자가 집행한다
- ⚠️ 함의: 관리자는 배우자가 쓴 기록을 지우고 센터에 공유할 수 있다. §16-1이 이미 준 권한과 일관되지만, **관리자 이양 미구현**(07-22 — sole owner 고정)과 겹치면 실사용 마찰이 날 수 있다. 관찰 대상
- **연결·공유 상태는 수정·삭제 권한에 영향을 주지 않는다**(07-28 확인). `center_link`가 active여도, grant가 켜져 있어도 작성자·관리자는 그대로 고치고 지운다. 상담사 화면은 read-time 파생이라 §16-2대로 수정=조용히 최신만·삭제=즉시 소멸로 따라온다. 기각된 대안과 근거는 아래 참조

> **기각 — "연결된 아이의 기록은 수정·삭제 불가"** (07-28 검토)
>
> 제안 취지: 보호자의 사후 변경이 센터가 보는 자료를 흔든다. 앱은 readonly 성격이어야 한다.
> 기각 근거 4:
> 1. **readonly 원칙의 대상이 아니다.** 앱이 readonly인 건 **센터 데이터**에 대해서다(§5 "앱→센터로 아이 기록 복사 없음", 테넌트 write는 회기 취소·일정 변경 요청 2개뿐). 기록은 방향이 반대인 보호자 자산이다
> 2. **임상 원문이 아니다.** §16-4가 상담사 화면에 *"확인 의무 없는 참고 자료"* 를 상시 표기하게 해 기대치를 이미 낮춰뒀다. 무결성을 걸 대상이 아니다
> 3. **범위 과잉 — 연결 ≠ 공유.** 연결된 아이의 기록이라도 grant가 없으면 센터는 아예 못 본다. 센터가 볼 수도 없는 기록까지 잠긴다
> 4. **약속 위반.** §15-5 총원칙과 §11-8 연결 완료 문구(*"그리고 변하지 않는 것 — 기록 34개는 그대로 내 것"*)의 정반대다. 성공지표 1번(연동 전환율)에도 역행한다 — "연결하면 기록이 잠긴다"가 연결을 막는 이유가 된다
>
> 삭제까지 막았다면 개인정보 **정정·삭제 요구권** 제한이라 법무가 들어왔을 지점이나, 막지 않기로 해 해당 없음.
> 우려의 실재하는 알맹이(증거 보전)는 §16-5 위험 신호 경로에서 **좁게** 처리한다 — 전면 잠금이 아니라 "치료사가 센터 내부 보고를 누른 기록만 스냅샷 보존".

## 16. 부록 — 공유·투명성 스펙 (심화 4주제)

> 07-09 심화 패스 4주제. 백엔드(grant 라이프사이클) + 치료사(상담사 화면 임상 요구 — 이번 라운드 신규 패널) + 보호자(공유 결정 5장면) 병합.
> 핵심 원리(도윤): **grant = 동의 사실(불변 행), 접근 가능 = `grant 생존 ∧ link active ∧ entry 생존 ∧ 담당`의 실시간 합성** — 복귀 가능한 상태 변화(suspended)는 동의를 건드리지 않는다.

### 16-1. `record_grants`

- **단위 = 엔트리** + **`include_body` 플래그**(병합 조정 — 보호자의 실존 조건: "영상은 주되 내 메모는 나만". 토글 시트에 "영상 2개 + 내 메모" 구성 표시, 메모만 해제 가능). 미디어 개별 토글은 미지원 — "이 사진으로 새 기록" 어포던스가 대안
- append-only: ON=행 insert, OFF=`revoked_at` 스탬프, 재토글=새 행 — grant는 제3자 제공 동의의 법적 증적(consent_text_version 보관). 살아있는 grant unique `(entry, center_link) WHERE revoked_at IS NULL`
- 대상 = **CenterLink 단위**(상담사 개인 참조 없음 — 담당은 읽기 시점 파생). 녹음은 `spoken_center_link_id` 불일치 시 서버 400(UI 미표시 + 이중 방어) — **토글이 없는 자리에 이유 한 줄 표기**("이 녹음은 해솔센터에서만 들을 수 있어요" — 버그 오인 방지)
- 토글 권한 = **켜기·끄기 모두 Family 관리자만**(분쟁 가정 문지기 — 홧김 일괄 OFF도 사고) + 구성원의 **"공유 제안"** 경로(관리자에게 요청 표시). 기본값 항상 OFF, "앞으로 자동 공유" 류 기능 금지, 일괄 = 다중 선택만("전체 켜기" 버튼 금지)
- 첫 공유 화면: 범위를 숫자·이름으로 — "이 기록 1개만, 해솔센터 김○○ 선생님에게". 다센터는 센터별 이름 박힌 줄 토글(단일 스위치로 전 센터 전송 = 즉시 이탈 요인)

### 17-2. 촬영 가이드 — 12상황 상한

목록이 길면 체크리스트 = 자가검사가 된다 — **전체 12개 상한, 영역명은 숨기고 상황만 노출**. 상황(이름 불렀을 때·원하는 게 있을 때·그림책·몸놀이·또래·새 장난감·혼자 놀이 30초·밥·새 음식·계단·같은 움직임 반복·전환 순간) × 임상 근거는 콘텐츠 팩에 수록(하윤 초안 = 감수 1차본).
- 보호자 검증 통과 조건: **예시는 일상·중립 장면만** — "이름을 불렀을 때"(중립) O / "불러도 안 볼 때"(결핍) X. 결핍 프레임 하나가 카메라를 채증 도구로 되돌린다. "상동행동" 등 임상 용어 노출 절대 금지
- **안전 지침 5**(촬영 진입 1회 + 가이드 하단 상시): 목욕·탈의 장면 금지 / 타인·다른 아이 나오는 기관 내 금지 / **우는 장면을 만들어 찍지 않기** / 위험 순간엔 카메라보다 손 / 소리 끄지 않기(영상의 절반은 소리)
- 성인 팩: 촬영이 아니라 "이럴 때 한 줄/음성 메모"로 교체 — 영상 1급 지위 자체가 팩 속성

### 17-3. 전화 도우미 스크립트 — 4문 상한

① "지금 대기하면 언제쯤 시작할 수 있나요?"(이 답이 전부를 좌우) ② "처음 가면 어떻게 진행되고 비용은요?"(초기상담·평가 분리 여부) ③ "**바우처로 시작할 자리가 지금 있나요?**"(등재 여부는 앱이 이미 앎 — 진짜 질문은 T.O.) ④ (선택) "○○ 영역 선생님 계신가요?" — 보호자가 이미 영역을 아는 경우만(앱이 영역을 먼저 채우면 치료 권유).
**금지**: "우리 아이 치료가 필요할까요?" 유도 — 전화 한 통에 판정을 외주 주는 것. 4문 상한(긴장 상태에서 그 이상 못 읽음). 스크립트의 본질 = **행정 문의 프레임**("내 아이 얘기"가 아니라서 걸 수 있다 — 전화 공포의 해체).

### 17-5. 콘텐츠 팩 체계

- **구조는 앱 내장, 텍스트는 콘텐츠 팩**(서버 배포 + 번들 폴백 — 게스트 첫 실행이 서버 없이 성립). 서버는 새 카드를 만들 수 없음(REGISTRY 정합). 일반 팩(대본·스크립트·촬영 가이드)과 **제도 팩**(3갈래·바우처 — 제도 변경이 앱 심사를 기다리면 오정보 방치) 분리
- 팩 메타 필수: `reviewer(치료사 실명)·reviewed_at·version·source(고시 링크)·review_due` — **미감수·기한 경과 팩은 배포 파이프라인이 차단**, §11-11 금지 문구 자동 린트. 제도 팩은 분기 정기 + 고시 변경 수시 재감수, 화면에 "기준일" 한 줄
- **지역성**: v1 전국 공통층만 — 지자체 차이는 콘텐츠가 아니라 **대본이 흡수**("주민센터에 이걸 물어보세요" — 지역 오정보 리스크의 구조적 제거). 위치 권한과 무관(팩 스키마에 region_scope만 예약)
- **성인 중립 보강 3**: 촬영 가이드 카드 enable 플래그화 / 3갈래를 분기 트리 데이터로(갈래 수·질문이 팩) / `profile.relation`이 팩 선택 키 → 성인 진입 = 팩 교체만으로 성립

### 17-6. 측정

유저 단위 대본 완료율 금지("2개 남았어요"로 역류하는 씨앗). 허용 = 콘텐츠 단위 익명 집계 2종(대본별 CTA 수행률·교체까지 노출 일수 — 풀 개선용, 비노출·무목표치) + 신설 1개 **"① 진입 → 첫 저장 행위 전환율"**(연동 전환율의 상류 깔때기). 세션 체류·스크롤 계측 안 함.

### 17-7. 이월

제도 사실 "확인 필요" 항목(17-1 표 — 릴리스 전 재확인 체크리스트) · 콘텐츠 팩 스키마 확정(구현) · 성인 팩 제작(성인 명단 편입 로드맵 종속) · 촬영 가이드 12상황·안전 5의 치료사 정식 감수(하윤 초안 = 1차본)
