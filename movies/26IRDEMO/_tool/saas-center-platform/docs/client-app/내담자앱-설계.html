내담자 앱 — 무엇을 만드는가

상담·발달 센터에 다니는 중이거나, 다니려고 알아보는 중인 보호자·내담자를 위한 모바일 앱입니다.
한 문장으로: "아이(또는 나)의 센터 여정에서 지금 해야 할 일과 그동안의 기록을 한곳에 모아주는 앱."
우리 회사의 본업은 센터용 운영 프로그램(SaaS)이고, 이 앱은 그 센터의 고객(보호자)에게 주는 앱입니다. 최종 목표는 상황 ③(센터와 연동된 상태)이 가장 중요하지만, 연동 전 상태(①·②)도 앱이 혼자 설 수 있게 설계했습니다.

구조는 딱 하나만 기억하면 됩니다: 사용자의 상황 3가지

같은 앱인데, 사용자가 어떤 상황이냐에 따라 홈에 보이는 것이 달라집니다. 첫 실행 때 "지금 어느 쪽에 가까우세요?"라고 물어서 시작점을 정합니다.
상황 ①
센터가 처음이에요
아이 발달이 걱정되기 시작했거나, 상담을 알아보기 시작한 사람. 아직 다니는 센터가 없다.

홈에 보이는 것: 아이 관찰 기록(글+영상), 무료 발달검사 안내, 치료비 지원(바우처) 정보, 센터 찾기, 센터에 전화할 때 물어볼 것 안내, "5월에 다시 전화하기" 알림.
✅ 설계 확정
상황 ②
센터는 다니는데, 그 센터가 우리 프로그램을 안 써요
주 1~2회 센터에 다니는 중. 센터에서 데이터가 안 내려오므로 사용자가 직접 남기는 것으로 산다.

홈에 보이는 것: "다녀왔어요" 체크 → 선생님 말씀 담기(녹음/메모), 이번 주 숙제 카드, 관찰 기록, 종이 결과지 사진 보관.
✅ 설계 확정
상황 ③
다니는 센터가 우리 프로그램을 써요 (연동)
센터의 운영 데이터가 앱으로 자동으로 내려온다. 회사 입장에서 가장 중요한 상황.

홈에 보이는 것: ②의 전부 + 예약 알림·휴강 변경, 온라인 검사·설문, 결과지, 바우처 잔여 횟수(진짜 숫자).
✅ 설계 확정
흐름: ① → (센터 등록) → ② 또는 ③ · ②의 센터가 우리 프로그램을 도입하면 ③으로 올라감 · 사용자의 기록은 상황이 바뀌어도 전부 이어짐. 상황은 다시 묻지 않고 사용자의 행동(센터 찜, 등록, 연동)에 따라 자동으로 넘어갑니다.

한 사람의 이야기로 전체 흐름 읽기

기획 논의에서 기준으로 삼은 가상 사용자: 38세 워킹맘, 5세 아이가 어린이집에서 "언어가 좀 느린 것 같다"는 말을 들은 상태.
걱정 시작
밤마다 검색과 맘카페. 아직 아무 데도 전화 못 함. 앱 설치 → "아직 지켜보고 있어요" 선택. 앱이 주는 것: "지금은 이것만 하면 돼요" — 관찰 기록 시작(글 한 줄·30초 영상, 뭘 찍으면 좋은지 가이드 제공), 무료 발달검사 안내, 치료비 지원 정보.상황 ①
알아보기
센터를 찾기 시작. 앱이 주는 것: 바우처 되는 센터 지도, "전화하면 이걸 물어보세요" 안내, 전화한 뒤 "6개월 대기래요, 5월에 다시 전화" 알림 등록.상황 ①
대기 · 첫 방문
기다리는 몇 주 동안 기록이 쌓임. 첫 방문(초진)이 잡히면 그동안의 기록을 시간순 한 장으로 정리해서 선생님에게 보여줄 수 있음.상황 ①
등록 후 매주
주 1회 언어치료 시작(이 센터는 우리 프로그램 미사용). 수업 40분은 대기실에서 대기 — 이때가 앱 쓰는 시간. 끝나면 "다녀왔어요" 누르고 선생님이 해주는 5분 설명을 녹음(양해 구하고)하거나 몇 줄 메모. 숙제는 일주일간 홈에 떠 있음.상황 ②
연동 후
센터가 우리 프로그램 도입. 예약·휴강 알림, 검사와 설문, 결과지, 바우처 잔여 횟수가 자동으로 들어옴. 매주 하던 기록 습관은 그대로, 손으로 하던 것만 자동으로 바뀜.상황 ③

상황별 기능 목록

각 줄이 화면 또는 기능 하나입니다. 상태가 ✅인 것은 그대로 만들면 됩니다.
상황 ① — 센터가 처음
기능내용상태
시작 질문첫 실행에서 "지금 어느 쪽에 가까우세요?" — 아직 지켜보고 있어요 / 센터를 알아보고 있어요 / 다니는 센터가 있어요. 진단 느낌의 단어는 쓰지 않는다.✅
가입 시점둘러보기(센터 찾기·지원 정보)는 가입 없이 가능. 무언가를 처음 저장하는 순간(기록 작성·센터 찜·알림 등록)에 소셜 로그인. 전화번호 인증은 여기선 없음(센터 연동 때만).✅
관찰 기록글 한 줄 + 사진/영상. 날짜 자동, 매일 쓰라고 요구하지 않음. 쓰고 나면 "어디서 있었던 일이에요?" 선택 태그(집/어린이집 등, 선택사항). 영상이 중요: "이럴 때 30초만 찍어두면 좋아요" 촬영 가이드 제공(문구는 치료사 감수 예정).✅
무료 검사 안내공공 무료 발달검사로 안내. 사용자 상황에 따라 3갈래: 아직 검진 안 받음 / 받았는데 추가검사 권고 나옴 / 결과는 괜찮은데 걱정됨. 문구는 치료사 감수 예정.✅
치료비 지원 정보바우처(정부 지원) 제도 설명 + 신청 기간 알림. 걱정 단계 홈에도 입구를 둔다 — 겁주는 톤이 아니라 "지원받을 수 있어요" 안심 톤.✅
센터 찾기 (리스트 + 지도 토글)기본 데이터 = 정부가 공개하는 바우처 제공기관 명단 — 전국 2,843곳이라 첫날부터 채워짐(07-09 확인). 형식은 검색바 + 카드 리스트가 기본, 지도는 토글(07-09 확정 — 시골은 빈 지도 대신 "가까운 순, 옆 지역까지"로). 리뷰·후기는 어떤 형태로도 넣지 않는다(운영 리스크). 사용자가 남긴 대기 정보의 익명 통계는 모으기만 하고 보여주지 않음(공개 시점은 나중에 별도 결정).✅
전화 도우미"전화하면 이걸 물어보세요" 질문 목록 → 전화 후 "언제 다시 확인하기로 했어요?" 한 줄 입력 → 그 날짜에 알림. 대기 순번 관리 같은 복잡한 기능은 만들지 않음(센터가 순번을 안 알려주는 게 현실이라).✅
첫 방문 준비첫 방문 날짜를 넣으면 디데이 표시 + 그동안의 기록을 시간순 한 장으로 정리한 화면(선생님에게 보여주는 용도). 앱이 기록을 해석하거나 평가하는 문구는 절대 넣지 않음.✅
상황 ② — 센터는 다니는데 미연동
기능내용상태
센터 등록 분기"다니는 센터가 있어요" → 센터 검색 → (a) 우리 프로그램 쓰는 센터면 상황 ③ 연결 절차로 (b) 아니면 상황 ② 모드 (c) 검색에 없으면 직접 입력 후 ② 모드.✅
수업 일정"매주 화 4시" 반복 일정 하나만 등록. 휴강·보강 관리 기능은 일부러 안 만듦 — 센터 데이터 없이 만들면 어차피 틀리고, 연동(③)되면 자동으로 해결되는 영역.✅
다녀왔어요 체크수업 끝나고 한 번 탭 → 기록 타임라인에 "이번 세션" 항목 생성. 다녀온 횟수는 보여주되 "남은 횟수" 계산은 절대 안 함 — 남은 횟수는 센터 장부의 영역이라 앱이 계산하면 숫자가 어긋나 신뢰가 깨진다.✅
선생님 말씀 담기수업 후 선생님의 5분 설명을 붙잡는 기능. 녹음이 기본, 직접 적기가 대안(같은 자리에 저장). 녹음 시작 화면에 "선생님께 '잊어버릴까 봐 담아둘게요'라고 말씀드려 보세요" — 양해 구하는 프레임 내장. 몰래 녹음 모드는 절대 제공 금지. 음성을 글로 자동 정리하는 것(AI)은 나중(회사 AI 배포 승인 이후).✅
숙제 카드"집에서 이렇게 해보세요"를 적어두면 일주일간 홈에 상주. 안 했다고 표시·경고하지 않음.✅
종이 문서 보관센터에서 종이로 주는 평가 보고서 등을 사진으로 찍어 기록에 붙임.✅
연동 안내"연동된 센터에서는 이게 자동으로 돼요" 안내는 상시 배너 금지. 아쉬운 순간(일정을 수동으로 옮길 때, 종이 결과지를 찍을 때)에만 한 번씩, 월 1회 이하, 센터를 탓하는 톤 금지. + 치료사가 앱에 관심 보이면 [센터에 소개장 보내기] 버튼(사용자가 조르는 구조가 아니라 관심을 받아주는 구조).✅
센터 찾기 (② 프레임)탭 이름은 "센터 찾기"로 모든 상황에서 동일(07-09 확정 — 상황별 개명 폐지). ②에서는 내용이 병행 니즈(언어+감각통합+놀이) 중심으로 구성되고, 내용은 선택된 아이를 따라간다.✅
상황 ③ — 연동 (설계 진행 중)
기능내용상태
홈 구조①②와 같은 구조(급한 것이 위로 오는 카드 목록) 유지. 센터 데이터가 세 번째 공급원으로 합류할 뿐, 사용자의 기록·타임라인은 계속 사용자 것.✅
센터에서 자동으로 오는 것예약 D-1 확인·휴강/변경 알림 · 온라인 검사 실시 · 사전 설문 · 검사 결과지 · 바우처 잔여 횟수(이제 센터의 진짜 숫자). 전부 센터가 이미 운영 중에 만드는 데이터라 상담사가 앱 때문에 추가로 일하지 않아도 돌아감.✅
세션 기록 자동화"다녀왔어요" 수동 체크가 필요 없어짐 — 센터 데이터로 자동 생성. "선생님 말씀 담기"는 그대로 유지: 연동 직후 신규 사용자에게만 수업 종료 시각 알림(습관 형성기 한정, 쓰기 시작하면 조기 종료) → 이후엔 홈 상단 안내만.✅
센터 연결(초대) 절차기본: 센터가 보내는 문자(예약 안내 등)에 연결 링크 → 전화번호 본인인증 후 연결. 추가: 사용자가 앱에서 먼저 "연결 요청"하는 역방향 경로 — 센터 직원이 명부 확인 후 승인(전화번호만으로 자동 연결은 금지, 오연결은 개인정보 사고). 기존 사용자는 새 계정이 아니라 쓰던 계정에 연결(아이 프로필 확인 단계 포함).✅
부모 → 상담사 공유"보내기"가 아니라 "보여주기 허용": 기록·영상마다 공유 스위치를 켜면 상담사의 센터 프로그램 화면(그 아이의 "가정 기록" 영역)에 조용히 나타남. 상담사에게 알림·읽음 표시 없음, 세션 준비 때 본인 리듬으로 확인, 응답 의무 없음을 부모 화면에 명시(상담사의 새 업무가 되지 않게).✅
여러 아이 · 여러 센터홈은 하나(아이 구분은 이름 칩), 기록 화면은 아이별. 한 가족 안에 상황 ①②③이 섞여 있어도 됨(첫째는 연동 센터+미연동 센터 병행, 둘째는 아직 무소속 등). 센터끼리는 서로의 데이터가 절대 안 보임.✅
가족 공유권한 2등급 — 관리자(계정을 만든 주 보호자: 가족 초대·내보내기, 공유 설정, 아이 프로필 관리) / 가족 구성원(보기+쓰기 전부 가능: 기록 작성, 다녀왔어요, 말씀 담기). 등급을 더 쪼개지 않음. 가정 분쟁 상황에서 문지기는 관리자.✅
센터 찾기 (연동 사용자)유지하되 — 첫 번째 결과는 항상 지금 다니는 센터의 다른 프로그램("다니시는 센터에도 감각통합이 있어요" — 센터에게는 추가 등록 채널). 사용자가 직접 검색할 때만 열리고, 홈 배너·추천·알림으로 다른 센터를 먼저 보여주는 일은 없음.✅
상담사가 보내주는 것상담사가 쓰는 세션 요약(브리핑), 과제 발행 등 — 상담사에게 새 일이 생기는 기능이라 다음 단계로.⏸

주로 디자이너용. 이 앱의 사용자는 지친 30~40대 부모이고, 대기실에서 한 손으로 봅니다. 규칙의 공통 뿌리는 하나 — "이 앱은 사용자를 채근하지 않는다."
죄책감을 만드는 장치 금지
금지: 빨간 배지, 미완료 개수, 연속 기록(스트릭), 달력에 빈칸 보여주기.
대신: 할 일은 때가 지나면 조용히 사라지고, 흔적을 남기지 않는다. 집계는 긍정문만("이번 주 3개를 챙기셨어요").
앱은 아이를 평가하지 않는다
금지: 기록을 보고 "괜찮아 보여요" / "걱정되네요" 같은 판정 뉘앙스의 문구 일체. 근거: 거짓 안심이 가장 위험(치료 시기를 놓치게 함).
대신: 정리와 안내만. 해석은 전문가(사람)의 몫.
글은 최소, 숫자와 명사로
공감 문구는 화면당 1문장까지(크게, 19px+). 본문 14px 이상, 카드당 텍스트 2줄까지. 형용사보다 명사·숫자("잔여 2회", "0.8km"). 설명문·훈계·응원 강요 금지.
알림은 남이 봐도 무해하게
잠금화면에 뜨는 문구는 중립적으로 — 어깨너머로 보여도 아이 정보가 드러나지 않게. 알림 남발 금지(주 단위 반복 알림은 곧 무음 처리당한다).
해당 없으면 아예 안 보이게
바우처가 없는 사용자에게 바우처 영역 자체가 안 뜬다. 빈 상태를 "여기 아직 없어요"로 보여주지 않고, 표면 자체를 없앤다. 아동 발달은 첫 시장일 뿐 — 구조는 성인 상담 센터에도 그대로 성립해야 한다.
빈 홈은 실패가 아니다
할 일이 없는 날은 "다 챙기셨어요"의 평온한 상태. 채우기용 콘텐츠(읽을거리 등)로 메우지 않는다.

개발 메모 — 데이터는 어디에 저장되나

프론트 개발자용 핵심 요약. 저장 위치가 기능별로 다르고, 이게 이 앱 설계의 중요한 축입니다.
데이터저장 위치이유
글 기록 · 선생님 말씀 메모 · 전화 이력 · 알림 · 일정서버 (계정 귀속)폰을 바꿔도 살아야 함. 계정은 소셜 로그인 — 첫 저장 시점에 가입.
영상 · 사진 · 녹음 파일서버 (암호화, 동의 기반)폰을 바꿔도 기록이 살아야 하고, 사용자 기대도 클라우드(07-08 확정). 갤러리 "참조"가 아니라 가져올 때 복사 후 업로드(OS 권한·원본 삭제 문제 때문), 앱 내 촬영·녹음이 기본 경로. 압축과 "30초 촬영 가이드"로 용량 관리. 지켜야 할 4가지: 암호화 저장 · 열람은 본인 + 본인이 항목별로 허용한 센터 담당자만 · 다른 목적 사용(AI 학습 등) 금지 · 어디 저장되고 누가 볼 수 있는지 항상 표시.
센터 데이터 (상황 ③)서버 (읽기 전용)예약·검사·설문·바우처의 원본은 센터 SaaS. 앱은 파생 화면만 — 원본이 바뀌면 카드가 자동으로 사라지는 구조라 정합이 깨질 수 없음.
대기 정보 익명 통계서버 (수집만, 비공개)선택지 입력만 받고 자유 텍스트 없음. 공개는 별도 결정 전까지 금지.
가입 흐름 요약: 게스트 둘러보기 가능 → 첫 저장 행위에서 소셜 로그인 → 전화번호 인증은 센터 연동(상황 ③ 연결) 때만. · 음성→글 변환, AI 요약 종류는 전부 "나중"(회사 AI 프로덕션 승인 전에는 탑재 불가).

동의와 데이터 권한 — 07-09 확정

영상·녹음까지 서버에 저장하기로 하면서(07-08) 필요해진 설계. "누구의 동의로 저장하고, 누가 볼 수 있고, 어떻게 지우나"의 전체 답입니다.
항목내용상태
동의 받는 시점가입(첫 저장 행위) 화면에서 한 번에. 이후 기능을 쓸 때마다 동의창이 다시 뜨지 않음 — 사용 순간에는 안내 표시만. 동의 항목: 필수 3(이용약관 · 개인정보 · 민감정보=아이의 발달 기록) + 선택(마케팅). "전체 동의" 한 번에 가능. 무서운 법률 용어는 본문에, 안내 문구는 "아이의 기록을 안전하게 보관하기 위해" 톤으로.✅
민감정보 동의는 필수이 앱의 본질이 아이 기록이므로, 기록 동의 없이 가입만 하는 어정쩡한 상태를 만들지 않음. 가입 = 전체 동의.✅
보호자 확인아이 프로필 만들 때 "저는 이 아이의 보호자입니다" 확인 한 줄. 센터 연동 때는 기존 절차(센터의 명부 확인 + 전화번호 인증)가 법적인 보호자 확인을 겸함 — 새 절차 추가 없음.✅
녹음 파일의 공유 범위선생님 목소리가 담긴 녹음은 그 선생님이 소속된 센터에만 공유 가능(다른 센터에는 공유 스위치 자체가 없음). 다른 센터에 내용을 전하고 싶으면 메모로 옮겨서. 이유: 목소리 주인(선생님)이 동의한 적 없는 제3자 공개는 치료사들의 신뢰를 깨뜨림.✅
탈퇴·동의 철회먼저 "기록 내보내기"(파일로 저장) 제안 → 30일 안에 다시 로그인하면 복구 → 이후 완전 삭제. 센터 연결을 끊으면 상담사 화면에서 가정 기록이 즉시 사라짐(삭제 아님, 보여주기 중단). 가족을 내보내면 그 사람 접근만 끊기고 작성했던 기록은 아이 타임라인에 남음.✅
"누가 볼 수 있나" 표시기록 목록에는 자물쇠 아이콘만 → 상세 화면에 "해맑음센터 김○○ 선생님이 볼 수 있어요" 한 줄 → 누르면 자세히. 녹음·촬영 시작 화면에는 항상 한 줄 표시. 마이에 "내 기록과 동의" 화면 — 동의 현황, 어떤 기록이 어느 센터에 열려 있는지, 내보내기·철회·탈퇴가 전부 여기에.✅
개발·운영 이월: 동의 이력 로그(언제·어떤 버전에 동의했는지 서버 기록) · 개인정보처리방침과 앱스토어 프라이버시 라벨 작성 · 백업 사본 파기 주기 · 14세 이상 자녀의 본인 동의 절차(나중).

시작 질문 온보딩 · 게스트
진단 언어 없음, "가까우세요"로 선언의 무게를 낮춤. 가입 요구 없음 — 첫 저장 때 소셜 로그인.
상황 ① — 지켜보는 중 상황 ①
공급원 = 사용자 + 공공 정보. 기록이 첫 카드, 검사·지원은 안심 톤.
규칙: 공감 1문장(22px 강조), 카드 2줄, 지시형("검사 받으세요") 대신 질문·초대형 문구.
상황 ① — 알아보는 중 상황 ①
급한 것이 위로: 오늘의 전화(히어로) → 첫 방문 디데이 → 촬영 가이드. 히어로 카드는 화면당 1개.
규칙: "대기 12주째" 같은 부정 집계 없음 — 다음 행동만. 히어로=Primary 1곳 원칙.
상황 ② — 수업 끝난 직후 상황 ②
대기실 프라임타임. 종료 시각이 지나면 히어로가 "다녀왔어요"로 바뀜. 숙제는 일주일 상주.
규칙: 잔여 회기 계산 안 함(센터 장부 존중) — 정직한 한 줄로 대체. 탭 명칭 "센터 찾기" 전상황 고정(07-09 판정).
말씀 담기 시트 상황 ②·③ 공용
"다녀왔어요" 직후 자동 등장. 녹음 기본 + 직접 적기 폴백. 양해 대사를 화면이 쥐여줌.
규칙: 몰래 녹음 방지 프레임 내장 · 저장 위치/열람 범위 한 줄(투명성) · "안 담아도 괜찮아요"(죄책감 금지).
상황 ② — 연동 안내 (원샷) 상황 ②
상시 배너 금지 — 종이 결과지를 찍은 직후에만 한 장. 월 1회 이하 쿨다운.
규칙: "여긴 안 돼요"(센터 탓) 대신 "이런 방법도 있어요". [괜찮아요]로 조용히 닫힘.
상황 ③ — 연동 + 다자녀 상황 ③
센터 데이터가 세 번째 공급원으로 합류. 홈은 하나, 아이는 칩. 첫째(연동)와 둘째(지켜보는 중)가 한 스택에.
규칙: 바우처 잔여 = 센터의 진짜 숫자, 임박은 주황 바만(빨간색·독촉 없음).
상황 ③ — 할 일 없는 날 상황 ③
빈 홈 = 평온. 소프트 3D 오브 + 긍정 집계 한 줄. 채우기용 콘텐츠 없음.
규칙: 미완료·놓침의 흔적 없음. 빈 상태가 실패처럼 보이지 않게.
기록 공유 설정 상황 ③
"보여주기 허용" 모델 — 항목별 스위치, 열람 범위 상시 표기, 즉시 철회.
규칙: 투명성 가드레일 + 풀 원칙("알림이 가지 않아요") 문구가 UI에 상주.
가입 게이트 공통 · 첫 저장
둘러보기는 끝까지 게스트. 첫 저장 행위(기록·찜·리마인더)에서만 이 시트가 올라옴 — 방금 쓴 기록이 뒤에 비쳐 "이걸 지키려고 가입한다"가 보이게.
규칙: 가입 이유를 앱 사정("회원이 되어주세요")이 아니라 사용자 이익("기록이 이어져요")으로. 전화번호 인증 없음 — 그건 센터 연결 때만.
동의 스택 — 한 장 R1 · R2
가입 플로우 안의 단 한 장. 전체 동의 원탭 + 항목별 체크 병존. 민감정보 항목은 법정 명칭 대신 "아이 기록 보관"으로 리드하고, 펼침(›)에 정식 고지 4요소.
규칙: 일괄 ≠ 포괄 — 항목은 법적으로 분리. 필수 3 + 선택. 가드레일(암호화·가족만·2차 활용 금지·철회처)이 quiet 문구로 이 화면에 이미 등장.
아이 프로필 + 보호자 확인 R3
법정대리인 확인은 별도 화면이 아니라 체크 한 줄. "내 이야기예요" 갈림길로 성인 본인 사용(센터 유형 중립)이 같은 화면에서 성립.
규칙: 필수 입력은 이름 하나(생년도 선택) — 진단명·발달 상태 등 프로파일링 질문 없음. CTA가 "가입 완료"가 아니라 "기록 이어가기" — 하던 일로 복귀.
센터 검색 — 세 갈래의 입구 ②R3 확정
"바로 연결" 배지 = 연동 센터(a) → 03 연결 절차로. 배지 없음(b) = 등록만 하고 상황 ② 모드. 검색 결과 없음(c) = 직접 입력 후 ② 모드.
규칙: 연동 센터를 "좋은 센터"처럼 표현하지 않음 — 배지는 기능 사실("바로 연결")만. 미연동 센터 폄하 문구 금지.
초대 링크 진입 경로 1 · 문자 편승
센터가 보내는 예약 안내 문자의 링크로 진입. 기존 유저는 "쓰던 계정으로" — 새 계정이 아니라 쓰던 계정에 센터가 부착(기존 계정 합류).
규칙: 데스크 QR·가족 초대 경로도 같은 랜딩으로 수렴. "지금까지의 기록에 센터가 더해져요" — 원장의 주인이 안 바뀜을 첫 화면부터.
전화번호 본인인증 ③R2 · 동의 R3
인증은 연결 때만(가입 때는 없음). 07-09 확정 — 이 절차가 법정대리인 확인을 겸한다는 것을 화면에 한 줄로 명시.
규칙: 전화번호가 맞아도 자동 연결 아님 — 센터 초대(또는 승인)가 선행돼 있어야 함. 오연결 = 개인정보 사고.
아이 프로필 확인 ③R2 · 기존 계정 합류
센터 명부의 이름과 앱 프로필을 사람이 확인하고 잇는 단계 — 형제가 있는 집의 오연결 방지가 목적.
규칙: 센터 쪽 실명("김지우")과 앱 쪽 애칭("지우")이 달라도 성립. 자동 매칭 없음 — 항상 사용자가 지목.
연결 완료 상황 ③ 시작
받는 것(자동 4종)과 변하지 않는 것(기록 소유·공유 기본 OFF)을 같은 화면에서. ③ 정체성 "손으로 하던 것이 자동으로, 내 것은 계속 내 것" 그대로.
규칙: 공유는 기본 꺼짐 — 연결이 열람 허용이 아님을 완료 화면에서 못박음(투명성 가드레일).
역방향 연결 요청 경로 4 · ③R2 신규
초대를 못 받은 기존 유저가 먼저 요청 → 센터 web에 "연결 요청 N건" → 직원이 명부 확인 후 승인. 위(요청 전)와 아래(대기 중) 두 상태를 한 화면에 병기.
규칙: 대기 중에도 앱은 ② 모드로 온전히 동작 — 요청이 막힘이 되지 않게. 데스크 언급 = 활성화의 영업 부수효과.
가족 관리 — 2등급 ③R4 · 경로 3
관리자(주 보호자) / 가족(보기+쓰기 전부) 딱 두 등급. 문지기 권한(초대·내보내기·공유 설정)만 관리자에게.
규칙: 등급을 더 쪼개지 않음(열람 전용 없음). 초대받은 가족도 가입 시 동일한 동의 스택을 밟음(동의 설계 R3) — 아이에 대한 보호자 확인은 관리자 것 하나로 성립.
센터 찾기 — A안 확정 반영 상황 ① · 07-09 확정
검색바 최상단 크게(맘카페 이름 검색 동선) + 세 줄 카드(이름·거리·바우처 — 공공 명단 팩트만) + 지도는 토글. "바로 연결" 배지는 연동 센터의 기능 사실만.
규칙: 후기·평점 어떤 형태로도 없음. 지방은 가까운 순 + 옆 지역 확장(빈 화면 금지). 출처 표기로 신뢰 확보.
바우처 상세 (L3) 상황 ③ · 07-07 승계
3층 노출의 마지막 층. 연동 후라 잔여가 센터의 진짜 숫자(②의 "세 번째 숫자" 문제 해소). 회기 수만 — 금액은 비노출(본인부담금은 센터 안내로 위임).
규칙: L1(홈)은 임박할 때만, L2(마이)는 상시, L3는 상세. 임박은 주황 온도만 — 빨강·경고 없음.
기록 타임라인 — 아이별 전 상황 공용
글·영상·세션 마디(자동)·말씀·결과지가 한 줄기로. 홈은 하나지만 타임라인은 아이별(사람 칩). 투명성은 R6 계단 1단 — 목록엔 아이콘만(🔒 가족만 / 👥 공유 중).
규칙: 달력 뷰 없음(구멍을 보여주는 장치) — 흐르는 목록만. 빈 날짜 개념 자체가 없음. 마디는 은은한 배경으로 구분(자동 생성 표시).
첫 방문 정리 한 장 상황 ① · 초진
첫 방문(초진) 확정 시 그동안의 기록을 시간순 한 장으로. 치료사에게 보여주는 용도 — ②의 노이즈 마케팅 접점 ①이기도. 탈퇴 시 내보내기와 같은 엔진.
규칙: 요약·해석·경향 분석 없음 — 순수 시간순 나열(판정 무음). "준비했어요"로 부모의 노력을 인정하는 톤.
내 기록과 동의 — 허브 공통 · 동의 R6
동의 현황(항목별) · 역방향 공유 목록(어떤 기록이 어느 센터에 열려 있나) · 내보내기 · 철회·탈퇴가 한곳에. 출구 4개(R5)가 전부 여기서 시작.
규칙: 철회·탈퇴를 숨기지 않음(신뢰 문구) — 단 첫 화면은 현황, 출구는 목록 마지막. 하단 한 줄 = 가드레일 ④ 상시 문구.
