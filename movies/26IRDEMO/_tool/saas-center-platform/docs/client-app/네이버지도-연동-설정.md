# 네이버 지도 연동 — 환경설정 가이드 (내담자앱 "센터 찾기")

> 2026-08-03 작성. 지도 스택: `@mj-studio/react-native-naver-map` 2.9.0 (네이버 Mobile Dynamic Map SDK 3.23.2) + `expo-location`.
> 코드는 전부 구현 완료 — **남은 것은 NCP Client ID 발급·반영뿐이다.**

## 1. NCP에서 발급받아야 하는 것 (사람이 해야 하는 유일한 작업)

### 1-1. 상품 신청 — 반드시 "신규 Maps 상품"으로

- [ncloud.com](https://www.ncloud.com) 가입 + 결제수단 등록 (Dynamic Map은 무료 쿼터가 크지만 계정에 결제수단 필수)
- 콘솔 → **Application Services → Maps** 이용 신청 → Application 등록
- ⚠️ **구 상품 경로 "AI·NAVER API ▶ 지도"는 2025-05-22부터 신규 신청이 차단**됐다([공지 #1930](https://www.ncloud.com/support/notice/all/1930)). 반드시 신규 Maps 상품으로 신청할 것. 우리가 쓰는 라이브러리는 신규 키 체계(`NCP_KEY_ID`)를 이미 지원한다.
- Application에서 **Mobile Dynamic Map** 활성화.

### 1-2. 앱 식별자 등록 — 4종 전부

| 플랫폼 | 식별자 | 용도 |
|--------|--------|------|
| Android 패키지 | `kr.mindscope.client` | 기본(로컬 dev 빌드 포함) |
| Android 패키지 | `kr.mindscope.client.dev` | Dev 변형(`APP_VARIANT=development`) |
| iOS Bundle ID | `kr.mindscope.client` | 기본 |
| iOS Bundle ID | `kr.mindscope.client.dev` | Dev 변형 |

⚠️ Dev 변형을 빼먹으면 dev 빌드에서만 지도가 인증 실패로 빈 화면이 된다 — 원인 찾기 어려운 함정.

### 1-3. 요금 확인

- Mobile Dynamic Map 과금 단위 = **지도 뷰 생성 1회(onCreate) = 1건**. 2023 개편 공지 기준 **월 1억 건 무료**([공지](https://www.ncloud-forums.com/topic/99/)) — 앱 규모에선 사실상 무제한.
- 신청 화면 요금표에서 현재 무료 쿼터를 한 번 확인할 것. 조건이 크게 나빠졌다면 카카오맵 SDK로 선회 가능 — 화면 코드는 어댑터(`src/shared/components/map/`) 뒤에 있어 교체 비용이 격리돼 있다.
- **Geocoding은 불필요** — 센터 좌표는 디렉토리 데이터(CSV)에 전건 포함, 서버에 저장됨.

## 2. 발급받은 Client ID를 반영하는 곳 (한 곳뿐)

`apps/mobile-client/app.config.ts`:

```ts
const NAVER_MAP_CLIENT_ID = '';   // ← 여기에 발급받은 Client ID
```

- 패키지명에 바인딩되는 **공개 키라 커밋해도 된다** (시크릿 아님).
- config plugin이 이 값을 Android `AndroidManifest.xml`(`com.naver.maps.map.CLIENT_ID` + `NCP_KEY_ID` meta-data)과 iOS `Info.plist`(`NMFClientId` + `NMFNcpKeyId`)에 주입한다 — 네이티브 파일을 손으로 만질 필요 없음.

## 3. 반영 절차 (ID 입력 후)

```bash
cd apps/mobile-client
npx expo prebuild -p android     # 커밋된 android/ 트리에 meta-data 값 주입
npx expo run:android             # 실기기 재빌드·설치 (JS 리로드로는 절대 반영 안 됨)
```

- `android/`는 git 커밋 대상 — prebuild 후 생기는 diff를 **함께 커밋**한다.
- `ios/`는 gitignore(로컬 생성물) — `npx expo run:ios`가 알아서 생성한다.

## 4. 현재 app.config.ts에 배선된 지도 관련 설정 (참고)

| 플러그인 | 설정 | 역할 |
|----------|------|------|
| `@mj-studio/react-native-naver-map` | `client_id: NAVER_MAP_CLIENT_ID` | 네이버 인증 키 주입 (And/iOS) |
| `expo-location` | `locationWhenInUsePermission: '주변 상담·검사 센터를 찾기 위해 위치를 사용해요.'` | 위치 권한 + iOS 권한 문구. WhenInUse만(백그라운드 위치 안 씀) |
| `expo-build-properties` | `android.extraMavenRepos: ['https://repository.map.naver.com/archive/maven']` | **네이버 SDK는 Maven Central에 없다** — 전용 저장소. 없으면 gradle이 `Could not resolve com.naver.maps:map-sdk`로 실패 |

## 5. 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `TurboModuleRegistry ... 'RNCNaverMapUtil' could not be found` | 네이티브 모듈이 없는 구 바이너리에서 JS만 리로드 | `expo run:android` 재빌드 |
| 빌드 실패 `Could not resolve com.naver.maps:map-sdk` | 네이버 maven 저장소 누락 | §4의 `extraMavenRepos` 확인 후 prebuild 재실행 |
| 지도가 빈 배경(타일 없음), 앱은 정상 | Client ID 미입력 / NCP에 해당 패키지명 미등록 | §1-2 식별자 4종 확인, §2 반영 확인 |
| dev 빌드만 지도 빈 화면 | `.dev` 패키지 NCP 미등록 | §1-2 |
| Expo Go에서 지도 안 뜸 | 네이티브 모듈이라 Expo Go 미지원 | dev client 빌드로만 확인 가능 |

## 6. 서버 쪽 설정

**없음.** 근방 조회 API(`GET /api/v1/app/directory-centers`)는 자체 DB(`directory_centers`)만 읽고 네이버 API를 호출하지 않는다. 좌표 데이터 갱신은 CSV 재임포트:

```bash
cd apps/api
uv run python -m scripts.import_directory_centers --csv <경로>   # source_id 기준 멱등 upsert
```
