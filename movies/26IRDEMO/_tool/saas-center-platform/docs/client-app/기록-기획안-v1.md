## 1. 사용자 · 권한 · 가시성

근거: §15-6

### 사용 주체

- 작성·열람 = **FamilyMember 전원**(owner·member)
- **센터 연결 없이도 작동한다.** 기록은 전역 평면이라 `center_links`가 없어도 쓰고 읽는다. 연결이 필요한 건 센터 공유(§5)뿐

### 가시성 3층

| 층 | 보는 사람 | 대상 필드 |
|---|---|---|
| **가족** | profile이 속한 Family 구성원 전원 | `body` · 미디어 · `mood` · `occurred_at` · `bookmarked_at` |
| **나만** | `author_account_id` 본인만 | `private_memo` |
| **센터** | grant 살아있는 CenterLink | §6 |

- `private_memo`는 타 구성원 조회 시 **응답 스키마에서 필드 자체를 제거**한다. `null`로 내리지 않는다 — 존재 여부도 숨긴다
- **예외**: `Profile.relation='self'`(성인 본인) 프로필의 기록은 가족 스코프가 아니다. 작성자 본인만(§14-4)

### 권한

| 행위 | 누가 |
|---|---|
| 작성 | FamilyMember 전원 |
| 열람 | 가족 전원 (`self` 프로필 제외) |
| 수정 · 삭제 · 프로필 이동 · 북마크 | 작성자 본인 + Family 관리자 |
| 센터 공유 토글 | Family 관리자만 |

**연결·공유 상태는 수정·삭제 권한에 영향을 주지 않는다.** `center_link` active여도, grant 켜져 있어도 그대로 고치고 지운다. 상담사 화면은 read-time 파생이라 수정=조용히 최신만·삭제=즉시 소멸로 따라온다(§16-2). 기각 이력은 §15-6-4 참조.

## 3. 작성 흐름

```
[작성하기]
   ↓
(프로필 2명 이상일 때만) 프로필 선택 시트
   ↓
1. 기분 선택        — 6종, 필수, [다음]
   ↓
2. 내용 작성        — 날짜·본문·개인메모·첨부 / [이전] [등록하기]
   ↓ (첨부 최초 1회)
   촬영 가이드 모달  — [확인했어요]
   ↓
등록 → 타임라인 복귀
```

### 3-1. 프로필 선택

- **1명 → 표면 없음**(자동 귀속)
- **2명 이상 → 진입 컨텍스트 승계**
  - 기록 탭에서 아이 칩이 선택된 상태 → 그 아이로 확정, 시트 스킵
  - "전체" 상태이거나 타 진입점 → 선택 시트 1장
- 확인 단계·경고 없음(§15-5 프로필 이동으로 복구 가능)
- 작성 중 전환 없음(전환 = 새 기록)

### 3-2. 기분 선택

- 6종 2×3 그리드, 단일 선택, 필수
- 헤드라인에 아이 이름 — "오늘 **은서**의 기분이 어땠나요?"
- 🔴 **집계·추이·비교 표시 전면 금지**(§15-1) — 감정 그래프, "이번 달 화나요 12번", 기간 비교, 감정 정렬·필터 일체. 상담사 화면 포함

### 3-3. 내용 작성

- `occurred_at` 표시 + **수정 가능**(§15-5). 표기는 "2026년 7월 16일 목요일 오후 2:00" (시안의 "오후 14:00"은 오류)
- "이렇게 적으면 상담에 도움이 돼요" 아코디언 — 접힌 상태 기본
- **본문** — 자유 서술. 한 줄도 1등 시민임이 보이게(§3 "카톡 나에게 보내기 문법"). 길이 강제·최소 글자 수 없음
- **개인 메모** — 라벨 "🔒 나만 볼 수 있어요 — **가족에게도 보이지 않아요**"
- **파일 첨부** — 촬영이 주경로, 갤러리가 보조(§3). 진입 시 촬영 가이드 모달
- 투명성 한 줄 상시(§6) — 공유 상태를 문장으로

### 3-4. 촬영 가이드 모달

§17-2 준수. 상세는 [기록-시안-정합-요청.md](기록-시안-정합-요청.md) §1.

- 예시 = **12상황 중립 목록**(이름 불렀을 때·원하는 게 있을 때·그림책·몸놀이·또래·새 장난감·혼자 놀이 30초·밥·새 음식·계단·같은 움직임 반복·전환 순간)
- 🔴 **결핍 프레임 금지** — "찢어진 책·상처·떼쓰기·다툼" 류. *"결핍 프레임 하나가 카메라를 채증 도구로 되돌린다"*
- **안전 지침 5 상시 노출** — 목욕·탈의 금지 / 타인 아이 나오는 기관 내 금지 / **우는 장면을 만들어 찍지 않기** / 위험 순간엔 카메라보다 손 / 소리 끄지 않기
- "다시 표시 안할게요"는 **상황 예시에만**. 안전 지침은 영구 숨김 대상 아님

### 3-5. 미디어

| 항목 | 규칙 |
|---|---|
| 영상 길이 | **60초 하드 상한** — 서버가 거부(§15-2). 시안의 02:30은 불가 |
| 영상 쿼터 | 월 10개. 발급 시 예약 + 완료 시 확정. **미터 비노출**, 도달 시에만 문구(§11-4) |
| 사진 | 하드 제한 없음. 가이드에 "3장 이내 권장"만 |
| 업로드 | presigned 직행 PUT → complete 검증 → 트랜스코딩 → ready |
| 삭제 | 실파일 + 렌디션 즉시 삭제, 쿼터 반환 |

⚠️ **presigned PUT은 신규 인프라다.** 현 `StorageClient`(`app/infrastructure/storage/common/base.py`)는 presigned **GET**만 있고, `field_note` 오디오도 서버 경유 multipart 업로드라 선례가 없다. §15-2가 *"기존 image 모듈의 공개 URL 방식 재사용 금지"* 를 명시하므로 우회 불가.

### 3-6. 저장 실패 처리 (v1 축소)

§15-3 전체 오프라인 큐(expo-sqlite + 백오프 5단계 + stalled 칩)는 v1 이월. 대신 **작성 내용은 절대 소멸하지 않는다**:

- 등록 실패 → 화면 유지 + 중립 문구 + [다시 시도]. 입력 내용 보존
- 앱 이탈 시 로컬 draft 보존, 재진입 시 복원
- 미디어 업로드 실패는 엔트리와 분리 — 엔트리는 저장되고 미디어만 재시도
- 🔴 폐기 계보 `F10`의 *"작성 중 앱을 닫으면 작성 내용 소멸(임시 저장 없음)"* 은 금지

## 4. 기록 탭

### 공통 크롬

프로필 필터 칩 → 주 이동 헤더(월 라벨·좌우 화살표 + 뷰 토글) → 주간 스트립 → 뷰 콘텐츠

- **주간 스트립 점** — 그날 기록 유무만. 최대 3개(4px, `#31A4F7`) + 초과분 `+N` 캡션
- 🔴 **"이번 주 N회"·연속 일수·누적 도트 카운터 금지**(§7-1 개정 조건)

### 3뷰

| 뷰 | 내용 |
|---|---|
| **목록** | `occurred_at desc` keyset 커서(OFFSET 금지). 월 헤더는 기록 있는 달만·개수 미표기 |
| **달력** | 월 격자 + 날짜별 점. 날짜 탭 → 그날 기록 |
| **북마크** | `bookmarked_at desc` |

### 카드

- 날짜 · **작성자 관계 라벨**(엄마/아빠/조부모) · 기분 · 본문 발췌 · 썸네일 · 투명성 배지
- ⚠️ 작성자는 **배지가 아니라 메타 행**에 — §7-9 투명성 배지는 🔒/👥 **2상태 고정**
- 이탈 구성원 작성분은 **"이전 구성원"** 폴백(이름 노출 금지)

### 빈 상태

현행 구현 유지 — 일러스트 + "오늘의 작은 변화도 놓치지 마세요" + [작성하기]

## 5. 상세 화면

- 날짜 · 작성자 · 기분 · 미디어 · 본문 · (본인일 때만) 개인 메모
- **북마크** 토글
- **투명성 배지** — 🔒(나와 가족만) / 👥(공유 중) 2상태. 탭 시 "해맑음센터 김○○ 선생님이 볼 수 있어요"
- 액션: **[수정하기]** · **[공유 켜기]** · **삭제** · **프로필 간 이동**

§15-5 준수:

| 행위 | 규칙 |
|---|---|
| 수정 | **무흔적** — "수정됨" 딱지·이력 노출 금지. 미디어 교체 불허(삭제+신규) |
| 삭제 | 즉시 파기 + 무내용 tombstone. **죄책감 팝업 금지.** grant 이력 없는 미디어 삭제 시 "아무도 보지 못했고, 완전히 삭제됐어요" 사실 한 줄 |
| 프로필 이동 | 원탭. 날짜는 쓴 날 보존. 공유는 대상 프로필 설정을 새로 따름(원 프로필에서 즉시 소멸) |

⚠️ `child` ↔ `self` 프로필 간 이동은 가시성 스코프가 바뀐다 — **차단하거나 명시 경고**(§15-7 이월).

## 6. 센터 공유 (조건부)

§16 전체 적용. 앱 쪽 요구:

- **기본값 항상 OFF**
- 범위를 숫자·이름으로 — "이 기록 1개만, 해솔센터 김○○ 선생님에게"
- 법무 감수 3문을 **토글 자리에 크게**(§11-8, 임의 개작 금지):
  > 선생님에게 알림이 가지 않아요 / 수업 준비하실 때 직접 열어보시는 방식이에요 / 끄면 선생님 화면에서 바로 사라져요
- 용어 = **켜다/끄다**(07-13 용어 정리). "공유하기"·"전달" 금지

### 6-0. 표면 위치 — 상세 한 곳

**작성 화면에서는 공유를 다루지 않는다.** 등록 후 상세에서만 켠다.

- §16-1 "기본값 항상 OFF"와 자연스럽게 맞는다 — 작성 시점엔 공유 결정 자체가 없다
- 작성 마찰이 준다 — 쓰는 순간에 "이걸 선생님이 봐도 되나"를 판단시키지 않는다
- 공유 결정이 시트 한 곳으로 일원화된다(시안은 작성 인라인 토글 + 상세 시트 이중 표면이었다)

시트 구성은 §16-1 그대로 — 센터별 이름 박힌 줄 토글, 담당 선생님 이름, 안내 문구 상시.

🔴 **"선생님께 한마디" 류 입력란은 두지 않는다.** 보호자→상담사 메시지 채널이 생기는 순간 §16-4가 "죽는 조건"으로 명시한 답장/리액션이 되고, §16의 "상담사의 새 노동 금지"를 깬다. 맥락을 전하려는 욕구는 **기록 본문**이 흡수한다(§0-3 "선생님에게 건널 재료").

### 6-1. 노출 조건 — 축 3개

⚠️ **판정 기준은 계정·가족이 아니라 그 기록이 귀속된 `profile_id`다.** `center_links`가 `profile_id ↔ client_id` 매핑이라, 아이가 둘인데 첫째만 연결됐으면 **둘째 기록에는 토글이 없다**. 계정 단위로 판단하면 갈 곳 없는 토글이 뜬다.

**축 1 — 연결 수** (`profile_id` 기준 `status='active'`인 링크)

| 개수 | 표면 |
|---|---|
| 0 | **토글 없음**(§7-5 "해당 없으면 표면 자체를 제거 — 빈 상태 안내가 아니라 비노출") |
| 1 | 단일 토글, **센터 이름을 박아서** |
| 2+ | **센터별 이름 박힌 줄 토글** — 단일 스위치 금지(§16-1 "전 센터 전송 = 즉시 이탈 요인") |

**축 2 — 링크 상태**

| 상태 | 표면 |
|---|---|
| `active` | 노출 |
| `requested`(연결 대기) | 노출 안 함 — 아직 대상이 없다 |
| `suspended` | **미결** — §10 참조 |

**축 3 — 권한** (§16-1)

| 역할 | 표면 |
|---|---|
| Family 관리자(owner) | 토글 조작 가능 |
| 구성원(member) | **토글 대신 이유 한 줄** — "공유는 관리자(○○님)만 바꿀 수 있어요" |

구성원 처리는 §16-1의 기존 선례를 따른다 — 녹음 센터 잠금에서 *"토글이 없는 자리에 이유 한 줄 표기(버그 오인 방지)"* 로 이미 쓰인 패턴이다. 상태 자체는 투명성 배지(🔒/👥)로 어차피 보이므로, 필요한 건 "왜 내가 못 바꾸는가" 한 줄뿐이다.

§16-1의 구성원 **"공유 제안"**(관리자에게 요청 표시) 경로는 알림 생산자 추가가 필요해 **v1 이월**한다.

### 6-2. 토글이 없어도 투명성 배지는 남는다

§6이 *"입력 화면엔 한 줄 상시"* 를 요구하고 §11-8 배지 기본 상태가 **"🔒 나와 가족만"** 이라, 연결이 0이어도 "이 기록은 나와 가족만 봐요"는 계속 보인다. 사라지는 건 토글뿐이다.

> **기각 — 연결 0일 때 "연결하면 공유할 수 있어요 → 연결하기" 유도**
> 연동 전환율이 성공지표 1번이라 매력적이지만, §7-5가 "빈 상태 안내가 아니라 **비노출**"로 못박고 뿌리가 *"사용자를 채근하지 않는다"* 이다. 기록을 쓰는 자리에서 연결 결핍을 상기시키지 않는다 — 연결 유도는 홈 카드(§13)의 역할이다.

### ⚠️ 릴리스 판단 필요

**앱 토글과 상담사 web 화면(§16-4)은 한 세트다.** web이 없으면 켜도 아무도 못 보는 토글이 된다. web은 §16-6에서 SaaS 측 과제로 이월된 상태다.

- **함께 낼 수 있으면** → v1 포함
- **못 내면** → 토글 표면 자체를 v1에서 제거(§7-5). 스키마는 만들어 두되 UI 비노출

## 8. API 표면

`/api/v1/app/records/*` — `authenticate_app()`(JWT `aud=client_app`). 모든 요청은 `person_id → family → profile` 소유 검증(G2).

| 메서드 | 경로 | 비고 |
|---|---|---|
| POST | `/app/records` | `client_key` 멱등 |
| GET | `/app/records` | `profile_id`·`cursor`·`limit`·`view(list\|bookmark)`. keyset |
| GET | `/app/records/dates` | `profile_id`·`from`·`to` → 날짜별 건수(주간 스트립·달력 점) |
| GET | `/app/records/{id}` | |
| PATCH | `/app/records/{id}` | `body`·`private_memo`·`mood`·`occurred_at` |
| DELETE | `/app/records/{id}` | tombstone |
| PATCH | `/app/records/{id}/profile` | 프로필 이동 |
| PATCH | `/app/records/{id}/bookmark` | |
| POST | `/app/records/{id}/media/upload-url` | presigned PUT 발급 + 쿼터 예약 |
| POST | `/app/records/{id}/media/{mid}/complete` | 검증 → 트랜스코딩 |
| DELETE | `/app/records/{id}/media/{mid}` | 실파일 삭제 + 쿼터 반환 |
| PUT | `/app/records/{id}/grants` | 센터별 on/off (§6 포함 시) |

`/app/records/dates`가 건수를 주지만 **UI는 유무와 최대 3점까지만 쓴다** — 카운터 표시는 §7-1 위반.
