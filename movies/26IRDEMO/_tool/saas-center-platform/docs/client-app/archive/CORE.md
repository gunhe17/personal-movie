# 내담자 앱 — 핵심 정의 (SSOT)

> **이 문서가 내담자 앱 기획의 최상위 진실원(Single Source of Truth)이다.**
> 정체성·범위가 충돌하면 이 문서가 이긴다. README/features/auto-design/SUMMARY는 모두 이 문서의 하위 상세다.
> 확정일: 2026-06-23 · 방식: 백지 재정의 (기존 산출물은 재료로만 사용)

---

## 0. 정체성 선언

> **"연동된 상담의 동반자" — 동반자 코어는 양보 불가, 획득은 센터에 위협 안 되는 선까지만.**

마음건강 슈퍼앱이 **아니다**. B2B 고객(상담센터)과 이해충돌하는 모든 것을 배제한다.
정체성 노선 = **절충** (동반자 코어 + 선택적 획득). auto-design의 "동반자 영구고정"을 이 문서가 갱신한다 — 획득 레이어를 일부 되살리되 경계를 명시한다.

---

## 1. 왜 존재하는가 (Why)

> **상담은 비싸고, 느리고, 중간이 안 보인다. 이 앱은 그 불투명함을 메워 '진전 감각'을 만든다.**

내담자·보호자의 근본 문제는 **불확실성**이다. 다음에 뭘 하는지, 지금 어디쯤인지, 나아지고 있는지가 안 보인다.
앱의 존재 이유 = **불확실성 해소 → 진전 감각 → 상담 지속(센터의 리텐션)**.

---

## 2. 타겟과 근본 욕구

| 주체 | 근본 질문 | 앱이 답하는 방식 |
|---|---|---|
| 성인 내담자 | "다음에 뭘 하지? 나아지고 있나?" | 다음 일정 + 회차 진행 + 검사결과 |
| 아동 보호자 | "우리 애 어디까지 했고, 좋아지고 있나?" | 자녀별 진행 + 결과 + 내가 도울 거리 |

- 두 경험은 **동일 화면, 데이터만 다름**. 역할 선택/분기 없음.
- 아동이 직접 쓰는 케이스 없음 (보호자가 사용).

---

## 3. 정체성 경계 (무엇을 하고 / 안 하는가)

```
[ 코어: 양보 불가 ]  연동된 상담의 동반자
   다음 행동·진행·결과를 투명하게 비춘다 (읽기 투영)
   → 절대 안 흔듦. 모든 화면의 중력 중심.

[ 획득 레이어: 선택적, "센터에 위협 안 되는 선"까지만 ]
   ✅ 무료 셀프체크 (결과 비저장) — 즉시 가치 + 연동 동기
   ✅ 큐레이션 매거진 (정적 seed) — 빈 화면 이탈 방어
   ✅ 셀프체크 → "더 받으려면 센터 연결" 깔때기
   ✅ 정부 바우처 "정보성 안내"만 — 자격판정/매칭 엔진 없이 정적 정보 + 외부 링크
   ❌ 주변 센터 노출 — 제외 (B2B 고객 간 경쟁 노출 = 이해충돌)

[ 비목표: 영구 제외 ]
   ❌ 마음건강 슈퍼앱 정체성
   ❌ 주변 센터 찾기 / 디렉터리 / 마켓플레이스 (B2B 이해충돌)
   ❌ 정부 바우처 자격판정·매칭 엔진 (오안내 법적 리스크)
   ❌ 검사결과 AI 재가공 (임상 책임 경계 붕괴)
   ❌ 미발행 노트·내부메모 노출 (신뢰 차단막)
   ❌ 전역 프로파일/센터 전환 스위처 (가짜 어포던스)
```

### 확정된 정책 결정 (2026-06-23)

**정체성·범위 (1차 라운드)**

| # | 쟁점 | 결정 | 이유 |
|---|---|---|---|
| D1 | 제품 정체성 노선 | **절충** (동반자 코어 + 선택적 획득) | 동반자 안전성 + 획득 깔때기 둘 다 취함 |
| D2 | 정부 바우처 | **정보성 안내만 허용** | 자격판정 엔진은 오안내 법적 리스크. 정적 정보+외부링크는 안전 |
| D3 | 주변 센터 노출 | **제외 유지** | B2B 고객(센터) 간 경쟁 노출 = SaaS 이해충돌 |
| D4 | 작업 방식 | **백지 재정의** | auto-design 결론을 당연시 않고 제1원칙에서 재도출 |

**세부 정책 (미결 7건 확정)**

| # | 쟁점 | 결정 | 이유 |
|---|---|---|---|
| D5 | 바우처 신선도 표시 | **`updated_at` 정직 라벨링**("최종 업데이트") | 잔여 조회는 Phase 2. `last_synced_at` 신규 컬럼은 MVP 백엔드 0 위반·오버엔지니어링 |
| D6 | 멀티센터 푸시 토큰 스코프 | **account-wide 단일 토큰** (Person 기준) | 로그인 주체=Person, 디바이스 1개. 센터별 분리 불필요. 알림 본문에 센터 라벨로 구분 |
| D7 | 오브 이름 / 좌표 저장 | **MVP 이름 없음**(P2) / **좌표 미저장, 주소 딥링크** | 이름은 브랜드 결정(P2). 길찾기는 주소 문자열로 지도앱 딥링크, 좌표 컬럼 신설 불필요 |
| D8 | F05 셀프체크 척도 목록 | **임상팀 별도 확정** (트랙 분리) | 라이선스·임상 타당성 판단 영역. MVP는 척도 무관 구조로 선제작 |
| D9 | 바우처 안내 콘텐츠 | **운영팀 별도 확정** (트랙 분리) | 제도 선정·문구는 운영 영역. MVP는 안내 영역·레이아웃·외부링크 슬롯만 선제작 |
| D10 | 연동 거절 사유 | **사유 비노출 + 재신청 허용** | 사유 노출은 분쟁·CS 부담. 거절 대부분은 번호 재입력으로 해소. "센터 문의" 일반 안내 |
| D11 | 매거진 콘텐츠 운영 주체 | **본사 공통 큐레이션** | 브랜드 일관성 + 센터 운영 부담 0 + MVP 백엔드 0(번들 임베드/정적 JSON) |

## 4. 핵심 가치 흐름 (단일 여정)

```
비연동  → 셀프체크로 "내 상태" 즉시 확인 → 매거진 → "더 받으려면 연결" → 연동신청
대기    → 신뢰 유지 (가짜 미완료감 방지)
연동 후 → [다음 일정] → [회차 진행] → [검사 결과] → (보호자) [자녀 현황]
```

## 5. 기능 골격 (정체성에서 재도출한 MVP)

- **프레임**: 2탭(홈/마이) 고정 — 정보는 하나의 흐름, 분리 안 함
- **코어 MVP**: 인증·연동(F01) / 홈·상태별(F02) / 일정·타임라인(F03) / 검사결과(F04) / 마이(F08) / 오브 경량(F09)
- **획득 레이어 MVP**: 셀프체크(F05) / 매거진(F06 정적) / 알림(F07) / 바우처 정보성 안내
- **읽기 전용 원칙**: 내담자의 write는 ①연동신청 ②OTP/푸시토큰 등록뿐. 일정·검사·예약은 전부 읽기.

### 신규 백엔드 도메인 경로 (MVP)
1. **연동(link)**: `POST /me/link-requests` (JWT person_id 강제), 전화 OTP, 1Person-1Client 중복 가드, 센터코드→센터명 lookup
2. **임상 조회(counseling)**: 클라이언트 셀프 JWT 회차/일정 조회 EP + client-facing 화이트리스트 스키마
3. **검사결과(assessment)**: `GET /me/assessment-results` (발행분만, N-call 머지) + JWT presigned PDF
4. **알림(notification)**: client JWT 푸시 토큰 등록 + `client_id→Person.account_id` 해석 헬퍼 + 일정 리마인더 SMS→푸시 승격

> 상세 기능 명세는 `features/F01~F12*.md`, 토론 근거는 `auto-design/SUMMARY.md` 참조.

## 6. Phase 로드맵 (요약)

- **MVP**: §5 — 읽기 투영 + 4개 백엔드 경로 + 획득 레이어
- **Phase 2**: write 개방(인앱 셀프응답·셀프예약·변경취소), 바우처 잔여 조회, 검사 시각화, 오브 풀캐릭터, 콘텐츠 CMS
- **Phase 3**: AI (production 미배포, 별도 승인 필수) — 점수 비교 차트, F12 AI 성장가이드
