# F01. 인증 & 온보딩

> 앱 설치부터 센터 연결까지의 전체 플로우

**Phase**: MVP

---

## 유저 스토리

- 사용자로서, 카카오/네이버/애플 계정으로 간편하게 가입하고 싶다
- 사용자로서, 센터에서 받은 코드를 입력해 센터와 연결하고 싶다
- 센터(상담사)로서, 승인 요청을 확인하고 내담자/보호자 역할을 지정해서 승인하고 싶다

---

## 1. 온보딩 슬라이드

### 정상 흐름

1. 앱을 처음 설치하고 연다
2. 온보딩 슬라이드 3장이 표시된다
3. 좌우 스와이프로 넘긴다
4. 3번째 슬라이드에서 "센터 코드 입력하기" 또는 "나중에 할게요" 중 선택한다

```
[1/3]  나를 위한 작은 변화의 시작 / 일정, 진행현황을 한눈에 확인하세요
[2/3]  센터와 연결하면 / 상담 일정 알림, 검사 결과까지
[3/3]  센터 코드가 있으신가요? / [센터 코드 입력하기] [나중에 할게요 →]
```

### 예외

- **이미 본 사용자가 다시 접속하면?** → 슬라이드 미표시, 바로 로그인 화면
- **앱을 재설치하면?** → 슬라이드 다시 표시 (로컬 저장소 초기화되므로)
- **중간에 앱을 닫으면?** → 다음 진입 시 슬라이드 처음부터

### 규칙

- 최초 1회만 표시. 완료 여부는 로컬에 저장
- 하단에 페이지 인디케이터 (● ● ○)

## 2. 소셜 로그인

### 정상 흐름

1. 로그인 화면에서 카카오/네이버/애플 중 선택한다
2. 해당 제공자의 동의 화면이 뜬다
3. 동의하면 앱으로 돌아온다
4. 처음 가입이면 → 계정이 자동 생성되고 미소속 홈으로 이동
5. 이미 가입한 사람이면 → 기존 계정으로 로그인되고 이전 상태의 홈으로 이동

### 예외

| 상황 | 동작 |
|---|---|
| 제공자 화면에서 취소 | 로그인 화면으로 복귀, 아무 안내 없음 |
| 제공자 인증은 됐는데 서버 오류 | "로그인에 실패했어요. 다시 시도해주세요" |
| 네트워크 끊김 | 오브: "연결이 불안정해요" + [다시 시도] |
| 같은 이메일로 다른 제공자 가입 시도 | 별도 계정으로 생성 (이메일이 아닌 provider + provider_id로 구분) |

### 규칙

- 제공자: 카카오, 네이버, 애플 (애플은 iOS 필수)
- 기존 Account/Person 구조 그대로 사용 (모델 변경 없음)
- 애플 로그인은 이메일 숨기기(Private Relay) 가능 → 이메일이 아닌 provider_id 기반으로 계정 매칭
- 애플은 최초 로그인 시에만 이름을 제공하므로 첫 응답에서 반드시 저장
- 토큰은 기기 보안 저장소에 보관. 만료 시 자동 갱신, 갱신 실패 시 재로그인

## 3. 센터 연결

### 정상 흐름

1. 센터 코드를 입력한다 (6자리 영숫자)
2. 센터 이름이 표시된다 ("○○심리상담센터에 연결할까요?")
3. 확인을 누른다
4. 전화번호를 입력한다 (최초 1회만)
5. SMS 인증번호(6자리)가 발송된다
6. 인증번호를 입력한다
7. "승인 요청을 보냈어요. 센터에서 확인하면 알려드릴게요" 메시지 표시
8. 승인 대기 홈으로 전환

### 예외

| 상황 | 동작 |
|---|---|
| 잘못된 센터 코드 | 입력 필드 하단에 "유효하지 않은 코드예요" |
| 이미 소속된 센터의 코드 | "이미 연결된 센터예요" |
| 이미 승인 대기 중인 센터 | "이미 승인 요청 중이에요" |
| 인증번호 틀림 | "인증번호가 맞지 않아요" (재입력 가능) |
| 인증번호 3분 초과 | "인증번호가 만료됐어요. 다시 받아주세요" |
| 5회 연속 실패 | 10분간 잠금. "잠시 후 다시 시도해주세요" |
| SMS 발송 실패 | "인증번호 발송에 실패했어요" |
| 센터에서 거절 | 푸시: "○○센터에서 요청을 확인할 수 없었어요" → 미소속으로 복귀. 동일 센터 재요청 가능 |

### 규칙

- 센터 코드: 6자리 영숫자, 입력 시 대문자 자동 변환, 센터별 고정 (만료 없음)
- 전화번호: 최초 센터 연결 시 1회만 입력. 추가 센터 연결 시 기존 번호 자동 사용
- 전화번호 변경: 마이페이지 > 개인정보 관리에서 재인증
- SMS 인증번호: 6자리 숫자, 유효 3분, 재발송 시 이전 번호 즉시 무효
- 일일 발송 제한: 동일 번호 10회/일

## 4. 센터 승인 (센터 측 동작)

내담자/보호자 구분은 앱에서 하지 않는다. **센터에서 승인 시 역할과 대상을 지정**한다.

### 정상 흐름 (센터 웹)

1. 승인 요청 목록에서 요청을 확인한다
2. 요청자 정보(이름, 전화번호)를 본다
3. 연결 대상(어떤 내담자)을 선택한다
4. 역할(내담자/보호자)을 선택한다
5. [승인] 또는 [거절]을 누른다
6. 승인하면 → 앱에 푸시 알림 → 앱이 소속 홈으로 전환

### 예외

| 상황 | 동작 |
|---|---|
| 해당 전화번호와 일치하는 내담자가 없을 때 | 센터가 수동으로 대상 지정 (전화번호 자동 매칭은 보조 수단) |
| 승인 후 앱이 포그라운드 상태 | 푸시 수신 → 자동으로 소속 홈 전환 |
| 승인 후 앱이 백그라운드/종료 상태 | 푸시 알림 표시 → 앱 진입 시 소속 홈 |

## 5. 사용자 상태 정의

| 상태 | 조건 | 홈 화면 |
|---|---|---|
| 미인증 | 로그인 전 | 로그인 화면 |
| 미소속 | 로그인 완료, 소속 센터 0개, 대기 0개 | 미소속 홈 |
| 승인 대기 | 대기 중인 요청 1개 이상 | 승인 대기 홈 |
| 소속 | 승인된 센터 1개 이상 | 소속 홈 |

앱 진입 시 서버에서 현재 상태를 받아 판별한다.

## 6. 앱 업데이트

### 정상 흐름

1. 앱을 실행한다
2. 서버에 현재 버전을 보낸다
3. 최소 지원 버전보다 낮으면 → 강제 업데이트 화면 (닫기 불가)
4. 최신 버전이 아니지만 최소 이상이면 → 하단에 "새 버전이 있어요" 배너 (닫기 가능)
5. 최신이면 → 아무 동작 없음

### 화면

**강제 업데이트**:
```
(오브) "새로운 버전이 나왔어요.
       업데이트 후 이용해주세요"
[업데이트 하기] → 스토어로 이동
```

닫기 버튼 없음. 업데이트하지 않으면 앱 사용 불가.
