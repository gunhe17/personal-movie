## 1. 판정

**A안 — 리스트 우선 + 지도 토글.** (07-06 배민 형식 시안 승계)

- 검색바 상단 + 카드 리스트(이름 · 거리 · 바우처 여부 세 줄) + [지도로 보기] 토글
- 지방(밀도 희박 지역)은 **가까운 순 + 옆 지역 확장**으로 빈 화면 방지 — 빈 지도가 "여기엔 없네요"를 시각화하는 것을 피함
- 검색 퍼스트 강화형(지민맘 동선)은 기각이 아니라 **A안 내 검색바 비중 문제**로 흡수 — 시안 단계에서 검색바를 최상단 크게

## 3. 판정 논거 (패널)

| 관점 | 논거 |
|---|---|
| 데이터 밀도 (사실) | 시군구당 십여 개 — 배민식 수백 개 정렬도, 지도식 빽빽한 핀 밭도 아닌 밀도. 리스트 한 화면 분량 |
| 팩트 두께 (서연) | 공공 명단의 팩트 = 기관명·주소·전화·사업구분뿐(운영시간·주차 없음). 얇은 팩트로 성립하는 형식 = 세 줄 카드. 지도는 얇음이 빈 공간으로 노출 |
| 과업 빈도 (준호) | 케이스 ① 골격 = 행동 대본("두 군데 전화 — 물어볼 것") → **비교·선택 과업**이 다수 = 리스트 홈그라운드. 공간 질문("동네에 뭐 있지")은 첫 진입 한두 번 → 토글 뒤 |
| 실사용 동선 (지민맘) | 맘카페에서 이름 듣고 **검색부터** — 검색바가 형식보다 상위 |
| 지방 현실 (하윤) | 군 단위 0~2개 — 빈 지도는 막막함의 시각화(죄책감 금지의 사각지대). 리스트는 옆 지역 확장으로 조용히 대응 |
| 운영 리스크 (민재) | 명단 갱신 연간 → 폐업 센터가 반년 노출될 수 있음("낡은 숫자" 리스크 동류). 지도 핀은 이 리스크를 더 크게 보이게 함 |

## 4. 구현 노트

- 데이터 파이프라인: 표준데이터(좌표 있음) + 복지부 현황(전수) 병합 → 누락분 지오코딩 배치 → 연간 갱신 시 재실행
- 지도 토글 화면은 같은 데이터의 뷰 전환일 뿐 — 별도 데이터·별도 화면 설계 아님
- 07-06 배민 시안 카드의 "주차 가능·평일 야간" 등은 공공 명단에 없는 항목 — **v1 카드는 세 줄(이름·거리·바우처)로 얇게**, 부가 팩트는 데이터 확보 시(아맘때 제휴 또는 성장층 수집) 추가
