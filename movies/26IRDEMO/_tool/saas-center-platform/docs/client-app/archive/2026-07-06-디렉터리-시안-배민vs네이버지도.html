관점A · 배민 형식B · 네이버지도 형식
선택 기준 정합치료영역·바우처·대기 = 카드에서 즉시 비교거리 중심 — 발달센터 선택은 거리가 1순위가 아님
아맘때 커버리지 리스크밀도가 얇아도 리스트는 티가 안 남핀 2~3개짜리 빈 지도 = 죽은 서비스 인상 (가짜 어포던스 금지 위반 소지)
공감 톤(요구 ②) 표면헤더·카드 사이에 자연스럽게 삽입시트 안으로 밀려남 — 지도 위엔 얹을 곳이 없음
공간 감각지도 토글 한 겹 뒤즉시 — 병행 센터 간 동선 감각에 유리
디스크리트중립적 리스트 화면내 위치 + 발달센터 핀 = 어깨너머 노출 시 민감
구현 비용 (P1)리스트 + 필터 — 지도 SDK 없이 시작 가능지도 SDK·좌표 정제·클러스터링 선행 필요

권고는 A(배민 형식)를 기본, B의 지도는 A의 [지도로 보기] 토글로 흡수 — 배민도 실제로 이 구조입니다. 단, 아맘때 데이터의 지역 커버리지가 충분히 두껍다면 B의 매력(즉각적 공간 파악)이 살아나므로, 데이터 밀도 확인 후 최종 확정 권장.
