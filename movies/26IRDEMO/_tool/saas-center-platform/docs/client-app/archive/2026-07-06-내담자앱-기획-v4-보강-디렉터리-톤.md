## 1. 센터 디렉터리 (요구 ①) — 유일한 미결정

### Phase 재배치 (선언)

v4에서 "무소속·마켓 = P2"였으나, 이 요구는 **조회 전용(read-only) 디렉터리**라 마켓(예약·전환 퍼널)보다 훨씬 가볍다. → **미연동 모드의 진입점으로 P1 편입.** 미연동 홈의 [우리 센터에 알리기] 옆에 "센터 찾기" 탭으로 자연스럽게 붙는다. 데이터 출처 = 아맘때 수집 센터 (출처 표기).

### 배민 형식 vs 네이버지도 형식 — 비교 요약

시안: [`2026-07-06-디렉터리-시안-배민vs네이버지도.html`](2026-07-06-디렉터리-시안-배민vs네이버지도.html)

| 관점 | A · 배민 (리스트 우선 + 지도 토글) | B · 네이버지도 (지도 우선 + 바텀시트) |
|---|---|---|
| 선택 기준 정합 | ✅ 치료영역·바우처·대기 = 카드에서 즉시 비교 | ❌ 거리 중심 — 발달센터 선택은 거리가 1순위 아님 |
| 아맘때 커버리지 리스크 | ✅ 밀도 얇아도 티 안 남 | ❌ 핀 2~3개 빈 지도 = 죽은 서비스 인상 (가짜 어포던스 금지 위반 소지) |
| 공감 톤 표면 | ✅ 헤더·카드 사이 삽입 가능 | ❌ 시트 안으로 밀림 |
| 공간 감각 | ❌ 토글 한 겹 뒤 | ✅ 즉시 — 병행 센터 동선 감각 유리 |
| 디스크리트 | ✅ 중립적 리스트 | ❌ 내 위치+발달센터 핀 = 어깨너머 노출 민감 |
| 구현 비용 (P1) | ✅ 지도 SDK 없이 시작 가능 | ❌ 지도 SDK·좌표 정제 선행 |

**권고: A 기본 + B의 지도는 [지도로 보기] 토글로 흡수** (배민의 실제 구조). 단, 아맘때 데이터의 지역별 밀도가 충분히 두꺼우면 B의 즉각적 공간 파악이 살아나므로 **데이터 밀도 확인 후 최종 확정**.

## 2. 신규 디자인 원칙: "따뜻하되 글은 최소" (요구 ② 흡수)

### 근거

- 타깃 30~40대: 스마트폰 네이티브라 연령 자체는 문제 아님. 단 **노안이 40대 초중반 시작** — 12px 이하에서 실불편.
- 연령보다 **상태**: 대기실에서 아이 잡고 한 손으로, 지친 채 훑는 사용 맥락. 지친 사용자는 읽지 않고 **훑는다** — 글이 많으면 앱을 닫는다.
- 공감 톤 요구의 최대 리스크 = "친절한 장문". 07-06 사용자 지적: 설명형 2문장 공감 문구("서두르지 않아도 괜찮아요. 비교하고…")는 작은 글씨 + 많은 글로 역효과.

### 규칙

| 항목 | 규칙 |
|---|---|
| 공감 톤 문구 | **1문장 상한**, 헤드라인급(19px+) 크게. 서브 설명문 금지. 훈계·응원 강요 금지. **센터 유형 중립 문구** (발달 부모 직접 지칭 금지 — 비치헤드 원칙) |
| 타이포 바닥 | 본문 14px+ / 핵심 정보(할 일 제목·센터명) 16~17px / 화면당 큰 제목 하나 19px+ / 부가정보(시간·출처)만 11.5px 허용 |
| 밀도 | 카드당 텍스트 2줄 상한. 형용사보다 **명사·숫자**("0.8km", "바우처")가 훑기에 강함 |
| 위계 | 크기를 키우는 방법 = 글을 빼서 공간을 버는 것. 전부 키우면 위계가 죽는다 — "이 화면에서 읽을 것 하나"만 크게 |

죄책감 금지·디스크리트와 한 몸인 원칙. 메모리 저장됨(`feedback_warm_but_minimal_copy`) — 이후 모든 시안·카피에 기본 적용.

## 3. 요구 ③·④ 적용 방침 (선언)

- **③ 마이크로 인터랙션 + 3D** — 토스 레퍼런스와 합치. 버튼 프레스 스케일·햅틱 / **할 일 카드 완료 → "기록으로 변환" 전환 애니메이션** (v4 B3 보상 규칙의 시각화) / 빈 홈·온보딩·아이콘에 소프트 3D 그라디언트. 디렉터리 시안에 1차 적용됨.
- **④ "뭘 할 수 있나" 직관성** — v4 할 일 스택이 답 그 자체. 보강 지점은 **할 일이 아직 없는 첫 사용자**: 연결 직후 첫 홈에 "이 앱에서 할 수 있는 것" 가이드 카드 / 미연동 홈에 가능한 액션(관찰기록·질문 메모·센터 찾기)을 명시적 진입점으로 노출.
