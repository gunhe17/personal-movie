## 1. 한 줄 정의

**"센터가 문자로 흩어 보내던 할 일들이 모이는 곳."**
내담자·보호자가 상담/발달 여정에서 해야 할 일을 하나씩 해치우게 해주는 컴패니언 앱. 기록(원장)은 할 일을 해낸 결과로 쌓인다. 서비스명(가칭): 마인드스코프.

### 방향의 진화 (요약)

| 시점 | 방향 | 상태 |
|---|---|---|
| 06-30 | 사용자 획득 우선 + 센터 디렉터리 (C+R1) | 폐기 |
| 07-01 | **컴패니언 피벗** — 센터를 통한 톱다운 배포, Account→Profile→CenterLink 3층 모델 | 유지 |
| 07-02 (v3) | 북극성=여정 원장, 킬러=세션 브리핑(상담사 발행) | 개정됨 |
| 07-03 (v4) | **액션 퍼스트** — 홈=할 일 스택, 상담사 신규 노동 제로, 토큰 초대 3경로 | **현행** |

**v3→v4 개정의 핵심 진단:** v3는 유저가 앱을 열 이유가 전부 상담사 노동(브리핑 발행)에 걸려 있었다. v4는 센터가 **이미 생산 중인 운영 데이터**(예약·검사·설문·바우처·결제)만으로 홈이 굴러가게 바꿨다 — 지금도 문자 링크로 흩어져 날아가는 것들이다.

## 2. 핵심 구조

### 홈 = 할 일 스택 (토스 레퍼런스)

여정 = 해야 할 일들의 연속. 세션 전(예약 확인·설문·검사), 세션 사이(관찰기록·질문 메모), 세션 후(결과지·결제), 여정 레벨(서류·바우처). 홈은 이것들을 긴급도 순으로 쌓는다. 다자녀는 Account 통합 스택 하나에 사람 칩(지우/서준)으로 구분.

### 할 일 카드 인벤토리

| # | 카드 | 공급원 | Phase |
|---|---|---|---|
| 1 | 예약 D-1 확인 / 임박 안내 | 센터 자동 (Schedule) | P1 |
| 2 | 예약 변경·휴강 대응 | 센터 자동 (백엔드 보강 필요) | P1 |
| 3 | 검사 온라인 실시 | 센터 발행 (기존 링크의 앱 수신) | P1 |
| 4 | 검사 결과지 확인 | 센터 발행 (기존) | P1 |
| 5 | 사전 설문 작성 | 센터 발행 (기존) | P1 |
| 6 | 바우처 잔여 임박 | 센터 자동 (기존, §6) | P1 |
| 7 | 관찰기록 남기기 | 유저 자립 (신규, 경량) | P1 |
| 8 | 다음 세션 질문 메모 | 유저 자립 (신규, 경량) | P1 |
| 9 | 브리핑 확인 | 상담사 발행 (신규 노동) | P1.5 |
| 10 | 과제(퀘스트) 수행 | 상담사 발행 (신규 모델) | P1.5 |
| 11 | 서류 발급 | 유저 요청형 (로직 신규) | P1.5 |

1~6은 데이터가 이미 실존 — **상담사 신규 노동 제로로 홈이 산다.** 7·8은 센터가 아무것도 안 해줘도 홈이 죽지 않는 바닥(미연동 모드의 주인공).

### 데이터 원칙

- **할 일 = 파생 뷰.** 원본(Schedule, AssessmentSendLink, FormSend, ClientVoucher…)의 상태에서 파생 — 원본이 바뀌면 카드가 자동 소멸, 정합이 깨질 수 없다. 앱 측 저장은 열람·완료 view-state뿐.
- **귀속:** 할 일은 Profile(여정 주체) 귀속, 공급원 표시는 CenterLink 경유. 자립형 할 일은 CenterLink 없이 성립.
- 신규 엔티티는 퀘스트·브리핑(P1.5)과 관찰기록·메모(유저 소유)뿐.

### 온보딩 — 토큰 초대 3경로 (자동 매칭 폐기)

전화번호 자동 매칭은 오매칭 리스크로 폐기. 매칭을 "검색"이 아니라 **"토큰 확인"** 문제로 전환 (AssessmentSendLink의 토큰 발송 패턴 확장).

1. **주경로 — 문자 편승 초대:** 이미 나가는 문자(예약 확정·리마인더 등)에 토큰 링크 자동 탑재 → 탭 → 전화번호 본인인증(토큰 수신 번호와 대조) → 생년월일 교차확인 1개 → 연결. 센터 직원 노동 제로, 오연결 없음.
2. **현장 — 데스크 QR:** 센터 스코프 안에서만 번호 대조, 실패해도 눈앞의 직원이 즉석 해결.
3. **fallback — 가족 초대:** 이미 연결된 주보호자가 앱에서 초대 (아빠·조부모).

목표: **설치 후 1분 안에 첫 할 일이 보이는 홈 도착** (연결 직후 최소 1개 할 일 보장).

## 3. 디자인 원칙

### 6원칙 (유지) + 죄책감 금지 구체 규칙

- 원본 미러링 금지 (필드노트 원문·AI 분석 앱 비노출) / 디스크리트 (중립 푸시, 어깨너머 노출 고려) / 가짜 어포던스 금지 / 소유자 노출 통제 / 부재의 비대칭 / **죄책감 금지**:
  - 모든 카드는 **자연 만료** — 만료 = 조용한 소멸, 원장에 "놓침" 흔적 없음.
  - 빨간 배지·미완료 카운트·스트릭 없음. 집계는 긍정문만 ("이번 주 3개를 챙기셨어요").
  - 완료된 카드는 기록으로 변환되어 원장에 쌓임 — 전환 자체가 보상.
  - 퀘스트 미수행은 상담사에게 안 보임 (완료만 전송).
  - 빈 홈 = 실패가 아니라 평온. 채우기용 콘텐츠 금지.

### "따뜻하되 글은 최소" (07-06 추가)

타깃 30~40대 지친 부모 — 대기실에서 한 손으로 훑는 사용 맥락. 글이 많으면 닫는다.

- 공감 톤 문구 **1문장 상한**, 헤드라인급(19px+)으로 크게. 서브 설명문·훈계·응원 강요 금지. 센터 유형 중립 문구.
- 타이포 바닥: 본문 14px+ / 핵심 정보 16~17px / 화면당 큰 제목 하나 19px+ / 부가정보만 11.5px.
- 카드당 텍스트 2줄 상한. 형용사보다 **명사·숫자** ("0.8km", "잔여 2회").
- 마이크로 인터랙션: 버튼 프레스·햅틱, 할 일 완료 → "기록으로 변환" 애니메이션, 소프트 3D는 빈 홈·온보딩·아이콘에.

### 센터 유형 중립 (비치헤드 원칙)

아동 발달은 비치헤드일 뿐 — 코어 **구조**는 항상 센터 유형 중립. 할 일 구조(예약·검사·설문·기록)는 성인 상담에 그대로 성립. 발달 특화 요소(바우처 등)는 콘텐츠 레벨로만, 해당 없으면 표면 자체가 안 뜨게(부재의 비대칭).

## 4. 미연동 모드 & 센터 디렉터리

- **미연동 홈:** 자립형 할 일(관찰기록·질문 메모) + 연결 시 프리뷰(블러) + [우리 센터에 알리기] + 센터 찾기 진입점.
- **센터 디렉터리 (07-06에 P1 편입):** 조회 전용(read-only)이라 마켓(P2)보다 훨씬 가벼움. 데이터 = 아맘때 수집 센터(출처 표기).
  - 형식: **A안(배민 — 리스트 우선 + 지도 토글) 권고.** 선택 기준 정합(치료영역·바우처·대기 즉시 비교), 데이터 밀도 얇아도 티 안 남, 지도 SDK 없이 시작 가능. 🔴 아맘때 데이터 밀도 확인 후 최종 확정.
- **바우처 제도 정보(07-07):** 미연동에서 유일하게 보여줄 수 있는 "진짜 데이터" — §6 참조.

## 6. 바우처 (07-07 확정 — 최초 문서화)

### 배경

백엔드에 3층 구조가 이미 있다: `Voucher`(정부 카탈로그 — 사업명·지원금·신청기간·문의처) → `CenterVoucher`(센터 단가·기본 회기) → `ClientVoucher`(내담자 발급분 — **총/잔여 회기·유효기간**). 세션 청구 시 `BillableItem`으로 차감 이력도 남는다. 필요한 데이터 전부가 기존 SaaS 생산분 — 신규 엔티티 없음.

### 결정: 3층 노출

| 층 | 위치 | 내용 | 조건 |
|---|---|---|---|
| **L1** 할 일 카드 | 홈 | "발달재활 바우처 · 잔여 2회 · 8/31까지" | 잔여 ≤2회 또는 만료 30일 전에만 등장, 해제 시 조용히 소멸 |
| **L2** 상시 현황 | 마이 | 바우처별 카드: 프로그램명 + 사람 칩 + 잔여 N회/총 M회 + 바 | 상주. "몇 회 남았지?"의 상설 답 — 지금은 센터에 전화해야 아는 정보 |
| **L3** 상세 | L1·L2에서 탭 | 위: 잔여 회기 큰 숫자 + 사용 내역(세션 연결) / 아래: 제도 정보(주관·정부 고시 지원금·문의처) | 출처 표기: "센터 등록 기준 · 정부 잔액은 사회서비스 포털" |

- **금액 비노출 (P1):** `remaining_amount`는 음수 허용되는 센터 내부 운영값 — 정부 포털 잔액과 어긋나 분쟁 소지. **회기 수만 노출.** 제도 정보의 "정부 지원 월 18~25만원"은 공개 고시라 무해.
- **죄책감 금지 적용:** "결제하세요" 압박 문구·빨간색 없음. 임박은 바 색 온도(주황)로만.
- **정합 리스크:** 잔여 회기는 센터 직원이 차감 관리하는 값 — web 노출 토글에 바우처 포함, 출처 문장으로 선 긋기.
- **미연동에서 제도 정보만 노출:** L3 하단(제도 정보) 재사용 + [이 바우처 취급 센터 찾기] → 디렉터리 연결. 진입점은 센터 찾기 안(할 일 스택 오염 금지, 앱 레벨 탭 금지 — 구조는 중립 유지). 여정 초입 보호자의 "받을 수 있는 지원이 뭐지?" 페인을 치면서 디렉터리 퍼널을 완성. 단, 카탈로그 신선도 관리(기준일 표기 + 공식 출처 링크) 필수.
- **확장 (P1.5+):** 재신청 카드 — 카탈로그 신청기간에서 파생. "2027년 바우처 신청이 시작됐어요" — 매년 재신청 시기를 놓치는 실제 페인 + 센터가 문자로 하던 안내 노동 대체.
