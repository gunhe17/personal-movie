# Round 06 — 센터 컨텍스트 홈 — 진입 후 임상 데이터 영역

## 주제/긴장
연동 후 소속홈(센터 컨텍스트)의 임상 데이터 영역을 어떻게 채울지. R5까지 확정된 단일 조건부 트리·통합 무전환·빈 영역 미노출·행동 우선 위계 골격 위에서, 다음 일정 카드의 정보 밀도 경계(R4/R5에서 placeholder로 연기)와 멀티센터 통합 데이터 소스(R6 위임)와 임상 데이터 노출 정책(T10)을 확정한다.

관련 긴장: 센터별 스코프, 모듈 멀티테넌시. CounselingSession이 (center_id, counseling_case_id, schedule_id) 종속이고 크로스센터 통합 쿼리가 코드상 부재한 현실(T6/T8)과, 임상 신뢰가 핵심 자산이라 한 번의 오노출이 연동 관계를 깨는 신뢰 리스크(T10)가 핵심 축.

## A · 옹호 주장 (근거 포함)
임상 데이터 영역의 전부의 목적은 첫 뷰포트에서 두 질문에 답하는 것이다 — 성인 "다음에 뭘 하면 되지", 보호자 "우리 애 어디까지 했지".

1. **다음 일정 카드 정보밀도 LOCK** (날짜·D-day / 대상+센터 라벨 / 회차 한 줄 / 길찾기): R4/R5에서 placeholder로 연기한 경계를 닫는다. 0.5초 응답을 위해 한 눈에 파싱돼야 하므로 준비물·온라인 링크·전체 이력은 첫 뷰포트에서 제외하고 타임라인(F03)/바텀시트로 드릴다운. F02 명세의 카드 구성이 이미 이 경계이며 R3 행동 우선 위계의 직접 귀결. (px)
2. **회차 진행 표시 첫 뷰포트 유지**: 보호자에겐 1급, 성인에겐 보조이되 동일 컴포넌트 같은 위치 사용, 데이터 없으면 미노출. F02 진행 규칙(총 회기수 있으면 진행바, 없으면 텍스트)이 두 역할을 한 컴포넌트로 커버, 저비용 고가치. (px)
3. **멀티센터 통합 데이터 소스 = client-side N-call 시간순 머지**: Session이 center+case+schedule 종속이라 합산이 본질, 멀티는 소수(센터당 1 Client)라 N≈1~2. 신규 집계 엔드포인트는 크로스센터 인가/정렬/페이징 신규 설계 비용으로 정당화 불가. R2/R3 연기를 머지로 종결. (code/roi)
4. **필터칩·집계 헤더 계속 Phase 2 연기**: 칩을 박으면 머지 결과를 센터별로 재분할해 무전환과 충돌. 카드 내 센터 라벨로 식별 충분. 필요성은 멀티센터 사용비율 데이터로 입증돼야 함. (roi)
5. **임상 데이터 노출 화이트리스트 LOCK**: 일정/회차번호·진행/센터명/담당 상담사명(바텀시트)/길찾기 주소·좌표만. 미발행 노트·내부 메모·취소 회차·미방문 사유는 노출 금지. F03이 이미 cancelled 제외·no_show 사유 미표시로 선을 그음. 명시 화이트리스트로 향후 정보 추가 시 오노출 구조 차단. (px)
6. **부분 실패 폴백 + 다음일정 없음 오브 흡수**: R3 빈영역 미노출·영역 독립 로딩 골격의 구현. 일부 센터 실패 시 성공분만 표시 + 하단 배너(F03 #10), 다음 일정 없으면 오브 멘트로 흡수하고 영역 자체 미노출. 추가 IA 0. (code)

## B · 검증 반박 (근거 포함)
A의 입장은 코드 현실·기존 명세에 잘 정렬돼 있어 대부분 인정. 확인 결과 CounselingSession은 (center_id, counseling_case_id, schedule_id) 종속이고, `find_case_ids_by_participant_ids`조차 center_id를 필수 인자로 강제 — 크로스센터 통합 쿼리는 코드상 부재. 따라서 N-call 머지 확정과 집계 엔드포인트 제외는 정당. 다만 A가 '명세 일치 = 추가비 0'으로 슬쩍 넘긴 두 신규 백엔드 비용을 명시 LOCK해야 한다.

1. **카드 정보밀도 LOCK은 인정하나 '추가비 0'은 오류**: 클라이언트 계정이 자기 회차/일정을 조회할 셀프(JWT) 엔드포인트가 신규로 필요. counseling 전 핸들러/라우터가 센터 admin/write 스코프(add_participant, update_attendance 등)라 내담자 본인 조회 경로가 코드상 0. 카드 정보밀도 결정 자체는 IA 0이 맞지만, 그 카드를 채울 데이터 조회는 R4 link 셀프 신청과 동급의 신규 백엔드(participant_id=JWT client 강제 + 센터 스코프 N회). (code)
2. **진행 표시 첫 뷰포트는 보호자 한정 1급**: 성인에겐 회차 텍스트만, 진행바는 격하. total_sessions가 nullable이라 다수 케이스는 진행바 아닌 텍스트(F03 '총 회기수 없음(일반적)'). 성인 1차 질문은 '언제'지 '몇 회 남았나'가 아니라 진행 표시 1급 격상의 px 근거 약함. 빈 영역 미노출과 결합해 '데이터 있으면 한 줄, 없으면 생략, 보호자만 강조'로 위계 격차 명시. (px)
3. **N-call 머지·집계 엔드포인트 제외 동의**: find_case_ids_by_participant_ids center_id 필수로 크로스센터 쿼리 부재, 합산이 본질. (code)
4. **화이트리스트는 UX 권고가 아니라 구조적 필수**: CounselingNote는 content(dict)/summary/author_id만 있고 client 가시성 플래그 없음, Session엔 cancel_reason이 컬럼으로 존재. DB에 '미발행 노트' 개념이 없으므로 client-facing 응답 스키마를 명시 화이트리스트로 못박지 않으면 Note 전체나 cancel_reason이 join 한 번에 샌다. Pydantic 스키마 레벨 화이트리스트가 유일한 구조적 차단막. (code/px)
5. **부분 실패 폴백·오브 흡수 인정**: N-call 머지 확정의 필연적 시나리오, F02 #5/F03 #10 명세 그대로. (code)
6. **필터칩·집계 헤더 연기, 센터 분할 뷰 제외 동의**: 칩은 머지 결과 재분할이라 무전환 충돌, 카드 라벨로 식별 충분. (roi)

## 결정 요약
센터 컨텍스트 홈 임상 데이터 영역은 **다음 일정 카드(날짜·D-day / 대상+센터 라벨 / 회차 한 줄 / 길찾기)를 첫 뷰포트 정보밀도로 LOCK**하고, R4/R5에서 placeholder로 연기했던 경계를 이번 라운드에서 닫았다. 회차 진행 표시는 첫 뷰포트에 유지하되 **보호자에게만 1급, 성인에게는 데이터 있으면 텍스트 한 줄·없으면 생략으로 위계를 격하**(B안)했다.

핵심은 **두 가지 신규 백엔드 비용을 명시 LOCK**한 것: (1) 카드 데이터를 채울 **클라이언트 셀프(JWT) 회차/일정 조회 엔드포인트**(counseling 전 핸들러가 센터 admin 스코프라 내담자 본인 조회 경로가 0, R4 link 셀프신청과 동급) — A가 '명세 일치=추가비 0'으로 넘긴 비용. (2) **client-facing 응답 스키마 레벨 화이트리스트**(Note에 가시성 플래그 없고 Session에 cancel_reason 존재, DB에 '미발행' 개념 부재라 스키마 화이트리스트가 유일 구조적 차단막).

멀티센터 통합은 **client-side N-call 시간순 머지로 확정**(크로스센터 쿼리 코드상 부재, 멀티 소수), 신규 집계 엔드포인트와 센터 분할 뷰는 제외, 필터칩·집계 헤더는 계속 Phase 2 연기. 부분 실패 폴백과 다음일정 없음 오브 흡수는 머지의 필연적 귀결로 채택.

## 남은 질문
- (R7/F03) 다음 일정 카드에서 회차 바텀시트로의 드릴다운 정보 구성: 준비물·담당 상담사명·전체 회차 이력을 어디까지 바텀시트에 노출할지, 화이트리스트 경계 재확인.
- (백엔드) 클라이언트 셀프 회차/일정 조회 엔드포인트의 정확한 형태: participant_id=JWT client 강제 주입 방식, 센터 스코프 N회 반복을 클라이언트가 호출 vs 서버가 N회 fan-out 후 합산(후자면 집계 엔드포인트 제외 결정과 경계 재확인 필요).
- (R8) 셀프체크 결과 화면 동선/톤(R3·R5 연기분)과 임상 안전 카피 T10 검증.
- (R9) 보호자 자녀 섹션 relation 기반 인가 범위·프라이버시, role both 시 본인/자녀 섹션 상하 위계, 셀프 조회 엔드포인트의 보호자→자녀 데이터 접근 인가.
- (Phase 2 입증) 멀티센터 필터칩·집계 헤더 필요성을 입증할 멀티센터 사용비율·실제 혼란 데이터 측정 방법.

임상 데이터 영역은 다음 일정 카드 정보밀도 LOCK(날짜/D-day·대상+센터라벨·회차 한 줄·길찾기)과 회차 진행의 역할별 위계 격차(보호자 1급, 성인 텍스트만·없으면 생략)로 확정됐고, 두 신규 백엔드 비용(클라이언트 셀프 JWT 조회 엔드포인트 + client-facing 응답 스키마 화이트리스트)을 명시 LOCK했다. 멀티센터는 client-side N-call 시간순 머지로 종결하고 집계 엔드포인트·분할 뷰는 제외, 필터칩·집계 헤더는 Phase 2 유지. 후속 라운드는 이 카드/화이트리스트 경계를 건드리지 말고, F03 회차 바텀시트 드릴다운 구성(R7)과 셀프체크 결과 동선(R8)과 relation 인가(R9)를 채우며, 셀프 조회 엔드포인트의 fan-out 구현 형태가 집계 엔드포인트 제외 결정과 모순되지 않는지만 확인한다.
