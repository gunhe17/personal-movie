# Round 14 — 오브 캐릭터 & 콘텐츠/매거진/셀프체크 ROI

## 주제/긴장
- T4(오브 정당성): placeholder로 묶어둔 오브 비주얼을 어디까지 MVP로 켤 것인가. 멘트 영역은 R3/R5/R10에서 5회 MVP LOCK된 순수 로컬 로직(서버 0)이라 재론 대상이 아니고, 이번 라운드의 실질 쟁점은 비주얼 요소의 경량/풀 경계를 닫는 것이다.
- T9(콘텐츠 ROI): F06 §1 '매거진 100 + 카드뉴스 100건 자체 제작 기확보'라는 새 사실 위에서, sunk cost가 콘텐츠 노출을 정당화하는가. 노출에 드는 forward cost(net-new 백엔드/CMS/태그분류)와 R1 캡(미소속 10개 정적)의 관계를 확정한다.

## A · 옹호 주장 (근거 포함)
- 오브 멘트 영역은 F09 §3 '서버 호출 없이 로컬 결정'·R3/R5/R10 5회 LOCK이라 번복이 아닌 재확인. 이 라운드는 placeholder로 묶은 비주얼 경계만 닫는 라운드다 (code).
- 경량 비주얼(CSS 그라데이션 원 + 시간대 4색 + 단순 맥동/페이드)을 placeholder에서 MVP로 승격해야 한다. R3 소속홈 최상단 1순위가 '오브멘트'로 고정됐는데 텍스트만 뜨면 동반자 정체성(R1)의 시각 닻이 빈다. F09 §2 시간대 색(빛/추상형)은 브랜드 톤의 '파스텔 캐릭터 금지'와 충돌하지 않는 유일 형식 (px).
- 경량 비주얼은 expo-linear-gradient + Animated만으로 구현 가능해 추가 백엔드 0, Skia 강제 안 함 (code).
- Skia 풀 캐릭터 애니메이션·일러스트·이름 부여(ISSUE-003)는 셰이더+디자인 리소스 크고 획득/리텐션 기여 미입증이라 Phase 2 (roi).
- 매거진/카드뉴스 200건은 자체 제작 기확보(F06 §1)된 sunk cost라 안 쓰면 순손실. R1이 매거진을 신뢰 신호로 이미 MVP 확정 (roi).
- 단 콘텐츠 노출은 R1 캡(미소속 10개 정적 seed)을 지키는 한에서만 MVP. content/magazine 모듈 0건(grep), F06 §7 선행작업 전부 미완이라 풀 라이브러리는 net-new (code).
- 태그 개인화 추천은 케이스 매칭 파이프라인 필요·R1 '추천엔진 신규 금지·개인화 연동 후'로 Phase 2 (roi).
- 콘텐츠 넛지 푸시는 R13 LOCK대로 exclude 유지, 셀프체크 F05는 R1/R8 LOCK 재확인 (px/roi).

## B · 검증 반박 (근거 포함)
- 멘트 영역 include 재확인은 F09 §3/§7 코드 확인으로 이견 없음 (code).
- A의 '경량 비주얼=Skia 없이 비용 작음'은 F09 §7이 '빛 효과/그라데이션/맥동: @shopify/react-native-skia'를 명시한다는 코드 사실과 충돌. 더 결정적으로 apps/mobile-client 디렉터리 부재(apps/mobile=상담사 전용)라 RN 클라 앱이 0부터다. '비용 작음'은 백엔드 0에만 해당, 프론트/디자인 0이 아니다. include는 하되 '서버 0'만 LOCK하고 구현형식 경계를 닫아야 한다 (code).
- 경량 비주얼은 시간대 4색+로딩 맥동+에러 흐릿 3상태(멘트 우선순위 로직에 이미 종속)로 한정하고, F09 §2 상황별 7종 모션은 Skia 셰이더+모션 종속이라 풀 캐릭터와 묶어 defer (px).
- '경량과 풀의 경계'가 §7 Skia 의존성에서 둘 다 같은 라이브러리를 쓸 수 있어 흐리다. 'CSS/expo 그라데이션+시간대 색전환만 MVP, Skia 도입 일체 Phase 2'로 코드 명시 LOCK해야 다음 구현자의 비용 누출을 막는다 (roi).
- 200건 sunk는 새 사실이나 'sunk라 안 쓰면 순손실' 논리는 결함. ROI는 forward cost로 판정한다. A의 결론(캡 안에서 켜기)엔 동의하나 근거를 '순손실 회피'→'정적 10개의 forward cost < 신뢰신호 가치'로 정정해야 한다. T9 긴장은 sunk로 해소되지 않는다 (roi).
- content/magazine/article/card-news 모듈 0건(grep), notice 모듈은 center_id 강제+태그/공개 미인증 읽기 부재로 B2C 미소속 재사용 불가. include 조건을 '미소속 10개 정적 JSON/DB seed, 신규 백엔드 최소, 홈 하단 가로스크롤 IA 0'로 LOCK. 캡 미준수 시 exclude 전환 (code).
- 상세 뷰어는 정적 렌더로만 한정(본문도 정적 seed), 무한스크롤 전체목록은 분리 defer (px).
- 태그 개인화 defer·넛지 푸시 exclude·셀프체크 F05 include는 A와 일치 (code/px/roi).

## 결정 요약
오브는 멘트(서버 0, 5회 LOCK 재확인)와 경량 비주얼만 MVP로 켜되, B의 코드 정정을 채택해 경량의 정의를 'CSS/expo 그라데이션 원 + 시간대 4색 전환 + 멘트 종속 3상태(로딩 맥동/에러 흐릿)'로 못박고 'Skia 도입 일체 Phase 2'를 경계로 LOCK한다 — apps/mobile-client 부재·F09 §7 Skia 명세로 경량의 forward cost는 백엔드 0이지 프론트/디자인 0이 아니다. F09 §2 상황별 7종 모션은 Skia 종속이라 풀 캐릭터·일러스트·이름 부여와 함께 defer해 fait-accompli를 막는다. 콘텐츠는 200건 sunk가 켜는 결정을 정당화하지 않으며(B 정정 채택, ROI는 forward cost로 판정), R1 캡(미소속 10개 정적 seed)을 지키는 정적 노출+정적 뷰어만 MVP, 백엔드 모듈/CMS/태그 개인화/무한스크롤은 net-new로 Phase 2다. 셀프체크 F05는 재확인, 넛지 푸시는 R13대로 exclude. 신규 비용 LOCK은 (1) RN 경량 오브 프론트 구현(서버 0), (2) 미소속 10개 콘텐츠 정적 seed + 정적 뷰어(신규 백엔드 최소) 둘뿐이다.

## 남은 질문
- 경량 오브 비주얼 구현형식 LOCK의 실측 경계: 'CSS/expo 그라데이션 + 시간대 색전환 + 3상태'가 RN에서 Skia 없이 실제로 충분한지 mobile-client 부트스트랩 시 검증, Skia가 끌려들어오면 7종 모션으로 번지는 비용 누출 방어선 재확인.
- 콘텐츠 정적 seed 진실원: 번들 임베드 vs 단순 DB row(공개 미인증 읽기 엔드포인트 필요) 중 어느 쪽이 신규 백엔드 최소인지, 10개 큐레이션 교체 운영 동선(센터 공통 vs 본사) 확정.
- ISSUE-010(F05 척도 라이선스): 미소속 공개 셀프체크 적격 척도 목록·라이선스 별도 트랙 확정(PHQ-9/GAD-7 외).
- ISSUE-003(오브 이름 부여): 브랜드 정책 결정이라 사용자 확인 사항 — Phase 2 진입 전 방향/데이터 확정.
- Phase 2 입증 지표: 경량 오브→풀 캐릭터 승격, 10개→전체 라이브러리 승격을 정당화할 리텐션/획득 데이터 측정 방법.

## 다음 라운드로 이어받기
오브 경량 비주얼은 '서버 0'만 LOCK하고 구현형식을 CSS/expo 그라데이션+시간대 4색+멘트 종속 3상태로 한정, Skia 도입 일체와 F09 §2 7종 모션·풀 캐릭터·이름 부여는 Phase 2로 잘라냈다(forward cost는 백엔드 0이지 프론트/디자인 0 아님). 콘텐츠는 sunk가 아닌 forward cost로 판정해 R1 캡(미소속 10개 정적 seed)+정적 뷰어만 MVP, 백엔드 모듈/CMS/태그 개인화/무한스크롤은 net-new Phase 2, 넛지 푸시 exclude·셀프체크 F05 재확인이다. 후속 라운드는 이 경량 오브 구현형식 경계와 콘텐츠 정적 캡 LOCK을 건드리지 말고, mobile-client 부트스트랩 시 Skia 누출 방어와 콘텐츠 정적 seed 진실원·운영 동선만 채운다.
