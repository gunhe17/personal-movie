# Round 10 — [종합] 센터 컨텍스트 + 프로파일 + 시안 v2

## 주제/긴장

R06~R09에서 코드근거로 LOCK된 결정들(센터 컨텍스트 임상 데이터 영역 + 보호자 relation 인가 + 자녀 멀티프로파일)을 v1 골격 위에 **시각적으로 충전**해 v2로 버전화하는 종합 라운드. 새 IA를 여는 라운드가 아니다.

- **관련 긴장**: R6~9 통합 (T1 통합 무전환 / T5 셀프응답 적격 / T7 보호자 프라이버시 / T10 데이터 노출 정책)
- **v2 입증 기준**: "예쁜가"가 아니라 **(1) v1 대비 임상 데이터로 충전된 3상태×2역할 연속체가 보이는가 + (2) 보호자 자녀 그룹핑이 제품 기능으로 읽히는가 + (3) 상태 토글이 데모 장치임이 주석으로 방어되는가**.
- **계승 원칙**: v1의 render-vs-lock 분리 — 미정 백엔드(집계 엔드포인트/필터칩/셀프 응답 엔진/오브 비주얼/셀프 예약/바우처)는 v2에서 자리(placeholder div)조차 그리지 않는다.

## A · 옹호 주장 (근거 포함)

A는 R10을 "절제의 보상이 처음 보이는 라운드"로 프레이밍한다. 발견·콘텐츠 확장을 계속 잘라낸 대가로 얻은 차별 가치 — **보호자가 한 화면에서 내 아이 둘의 다음 일정·회차 진행·도착한 검사 결과를 0.5초에 파악하는 경험** — 이 v2에서 처음 렌더된다.

- **자녀 섹션 1차 그룹핑이 v2의 단 하나의 결정적 신규 가치** (px): R02/R03/R09에서 보호자 멘탈모델='내 아이 단위 한눈에'로 일관 확정, 멀티프로파일=홈 자녀섹션 누적(스위처/▾ 제외)로 LOCK. v1은 더미+주석으로만 표시했으나 R09 relation 1-hop 인가 헬퍼 MVP 확정으로 자녀 일정/회차/결과 3건이 노출 0·visibility 0으로 청산됐으므로 v2는 충전된 모습을 그릴 자격이 생겼다. changelog 1번 헤드라인.
- **다음 일정 카드 정보밀도 LOCK 그대로 + 회차 진행 역할별 위계 시각 분기** (code): R06 LOCK(날짜/D-day+대상·센터라벨+회차 한 줄+길찾기). total_sessions nullable이라 성인 progress bar는 가짜 UI, 보호자만 진행 1급/성인 텍스트 한 줄·없으면 생략. 준비물·온라인 링크는 바텀시트 진입점만.
- **검사 결과 = send_result 2상태 게이트로만 렌더** (code): R07 발행분만 화이트리스트 반환+JWT 신원 PDF 인앱 열람(4자리 코드 대체). 미공유 신호·시각화·3단 공개수준은 그리지 않음.
- **멀티센터 통합 머지 타임라인 + 부분 실패 폴백 배너** (roi/px): R06 N-call 머지 종결, 카드 라벨 식별. 폴백 배너는 동반자의 솔직한 신뢰 신호.
- **relation 인가·자녀 데이터는 인가 통과 가정+더미+주석으로만, 토글은 데모 장치 주석 방어** (code): R09 인가 헬퍼 LOCK. 인가 게이트 UI/프라이버시 토글 미렌더.
- **오브는 멘트 영역만 확정 렌더, 비주얼은 placeholder 유지** (roi): R14 fait-accompli 방지.

## B · 검증 반박 (근거 포함)

B는 검증자 기본입장(포함 반대)에도 불구하고 **A가 인용한 핵심 코드 사실 4개를 직접 검증해 모두 정직함을 확인**하고, A의 11개 include 대부분을 정당하다고 인정했다. 그 위에 세 곳을 조였다.

- **A의 코드 근거 4개 직접 검증, 트집 잡을 지점 없음** (code): `counseling_case/models.py:72` total_sessions: Mapped[int|None] nullable 확정(성인 progress bar=가짜 UI 정확), `send_result/models.py:54,60` expired_at/revoked_at 실존(2상태 게이트 visibility 0 성립), relation_category=guardian Literal(R09 1-hop 헬퍼 정확), v1 mockup.html 실존. A가 명세일치=비용0으로 호도한 흔적 없음.
- **[조임 1] 자녀 그룹핑 더미는 화이트리스트를 한 픽셀도 못 넘게 v2 주석 LOCK** (code): A는 노출 필드 범위를 명시 안 함. 더미라도 화이트리스트 밖 필드(상담 메모·취소 사유)를 자녀 카드에 그리면 다음 구현자가 스펙으로 오독해 T10 위반을 코딩한다. 자녀 섹션 더미는 화이트리스트 필드만, 주석으로 '이 필드 집합이 client-facing 노출 경계'임을 명시.
- **[조임 2] 부분 실패 폴백 배너 카피는 R08 톤 선점 금지** (px): 신뢰 신호 px 가치는 인정하나 폴백 카피도 톤의 일부. 중립 사실 문구('일부 센터 정보를 불러오지 못했어요. 다시 시도')+재시도 어포던스로만, 감정/영업 톤은 R08 보존.
- **[조임 3] 검사 결과 미공유는 placeholder로조차 안 그림** (code): 발행분 0건이면 검사결과 영역 자체를 미노출. 회색 placeholder도 R03 빈영역미노출+R07 차집합 defer 동시 위반.
- **회차 진행 역할별 분기는 안 그리면 LOCK을 시각으로 배신** (code): include를 넘어 '반드시 분기해야 LOCK이 증명된다'로 강화.
- **미정 라운드 자리(placeholder div)조차 만들지 말 것** (roi): 빈 자리도 다음 라운드에 시각적 압력을 만드는 fait-accompli.

## 결정 요약

이 라운드는 **이례적 합의 라운드**다. B(검증자)가 A의 핵심 코드 근거 4개(total_sessions nullable / expired_at·revoked_at 실존 / relation_category=guardian / v1 mockup 실존)를 직접 검증해 전부 정직함을 확인했고, 모든 verdict에서 A와 일치했다. 따라서 신규 비용 추가나 결정 번복은 없으며, 본 라운드의 실질 산출은 **B가 추가한 세 개의 시각 가드레일을 결정에 흡수**한 것이다.

- **include(MVP, 10건)**: 자녀 섹션 1차 그룹핑 충전 / 다음 일정 카드 정보밀도 / 회차 진행 역할별 분기 / 검사 결과 2상태 게이트+PDF 열람 / 멀티센터 머지 타임라인 / 부분 실패 폴백 / 3상태×2역할 연속체+토글 주석 / 오브 멘트 영역 / 대기홈 갱신 / 마이 자녀 정보 카드. 모두 R06~R09 LOCK의 시각 구현으로 **추가 백엔드·IA 비용 0**(R06/R07/R09에서 이미 LOCK된 신규 비용 외 net-new 없음).
- **B 가드레일 3종 (결정에 LOCK 흡수)**:
  1. **화이트리스트 더미 LOCK** — 자녀 섹션 더미는 일정/회차/진행/센터명/상담사명/주소좌표 + send_result PDF 필드만. 미발행노트/내부메모/취소회차/미방문사유는 더미로도 금지. v2 주석에 '이 필드 집합이 client-facing 노출 경계'를 명시한다.
  2. **폴백 배너 중립 카피 LOCK** — '일부 센터 정보를 불러오지 못했어요. 다시 시도' + 재시도 어포던스만. 감정/영업 톤은 R08 보존.
  3. **미정 라운드 무자리 LOCK** — 필터칩/집계헤더/오브 비주얼/셀프예약/바우처/셀프응답은 v2 HTML에 placeholder div조차 만들지 않는다. 빈 자리도 fait-accompli이기 때문.
- **defer/exclude(13건)**: 전원 미정 라운드(R11/R12/R14) 또는 net-new 백엔드·정규화 신설을 우회 선점하는 항목으로, A/B 분류 일치. v2 합격선은 **임상 데이터로 충전된 3상태×2역할 연속체 + 자녀 그룹핑이 제품 기능으로 읽힘 + 토글 데모 장치 주석 방어**로 확정.

## 남은 질문

- (mockup-v2 검수) v2가 실제로 v1 대비 임상 데이터 충전을 보여주는가 + 자녀 그룹핑이 제품 기능으로 읽히는가 + 화이트리스트 더미 주석/토글 데모 주석/폴백 중립 카피 3종 가드레일이 HTML에 반영됐는가.
- (R11/T6) 셀프 예약 & 가용 슬롯 정책 — schedule 전부 센터 write 권한이라 셀프 예약은 신규+센터 on/off 토글. v2가 자리조차 안 비웠으니 R11이 IA 압력 없이 백지에서 판정.
- (R12/T8) 바우처 발견(B2C 별개 개념) vs 잔여((center_id,client_id) 종속 소속홈 기능). 잔여는 R01 defer를 R12에서 소속홈 기능으로 재론.
- (R14/T4·T9) 오브 비주얼(placeholder→그라데이션원→캐릭터) 정당화 + 콘텐츠/매거진 획득 ROI. v2 placeholder 자리가 R14 판정을 선점하지 않게 중립 최소화 유지됨.
- (R08 톤 연동) 대기홈 멘트·폴백 배너·고위험 셀프체크 결과 카피의 통일 톤 — R08에서 중립 문구들을 일괄 확정.
- (백엔드 fan-out 경계 재확인) R06 셀프 회차 조회 + R07 결과 목록의 client N-call vs 서버 fan-out 형태가 R06 집계 엔드포인트 제외와 모순 없는지(결과 목록은 case 단위 단순 머지=집계 아님으로 정리하되 명시).

## 다음 라운드로 이어받기

R10은 새 비용·번복 없는 합의 버전화 라운드로, R06~R09에서 코드근거로 LOCK된 결정(다음 일정 카드 정보밀도/회차 진행 역할별 분기/검사 결과 2상태 게이트/멀티센터 머지+폴백/relation 1-hop 인가 자녀 충전)을 v1 골격 위에 시각 충전해 v2로 버전화했고, B가 A의 핵심 코드 4사실을 검증해 전원 verdict 일치, 본 라운드 실질 산출은 **세 가드레일 LOCK 흡수**(화이트리스트 더미 필드 경계 주석 / 폴백 배너 중립 카피·톤 R08 보존 / 미정 라운드 placeholder div 무자리)다. v2 합격선은 임상 데이터로 충전된 3상태×2역할 연속체 + 자녀 그룹핑이 제품 기능으로 읽힘 + 토글 데모 장치 주석 방어다. 후속 R11(셀프 예약)·R12(바우처)·R14(오브/콘텐츠)는 v2가 자리조차 비워둔 백지 위에서 IA 시각 압력 없이 판정하되, 이미 LOCK된 카드/화이트리스트/머지 경계와 단일 조건부 트리 IA는 건드리지 않는다.
