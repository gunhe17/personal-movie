# Round 02 — 네비게이션/탭 구조 & 2축 컨텍스트(프로파일×센터)

## 주제/긴장

내담자 앱의 하단 탭 구조와 2축 컨텍스트([프로파일: 본인/자녀] × [센터: A/B…])를 어떻게 IA로 표현할지 결정한다.

- **T1. 통합 무전환 vs 센터 전환 칩** — 멀티센터를 통합 타임라인으로 보여줄지, 센터 전환/필터 UI를 둘지. 단일센터가 현실 다수(seed C: link는 센터당 1Client, 멀티는 소수 케이스).
- **T3. 2탭 유지 가능성** — 발견 콘텐츠(매거진/주변센터)를 넣어도 2탭(홈/마이)이 유지되는가, 아니면 B2C 목업의 4탭(홈/콘텐츠/내센터/마이)으로 가야 하는가.

전제(R1 확정): 정체성은 "연동된 상담의 동반자". 미소속홈은 activation 깔때기(센터 연결 CTA 1순위 + F05 셀프체크 + 소수 고정 매거진). 발견 기능은 1급 탭으로 승격하지 않는 보조 표면.

---

## A · 옹호 주장 (근거 포함)

큰 명제: R1에서 정체성을 "동반자"로 고정한 이상 발견 콘텐츠를 위해 탭을 늘릴 이유가 없다. 2탭(홈/마이)을 유지하되, 멀티센터 현실(T1)을 위해 홈 상단에 **선택적 센터 필터 칩**을 도입한다. 2축은 둘 다 전역 모드 스위처로 만들면 인지부하·상태비용이 폭증하므로, 프로파일축은 데이터에 내장(자녀 섹션 분기), 센터축만 필터(default=전체)로 노출한다.

- **하단 2탭(홈/마이) 유지, 4탭 거부 (px)**: 앱이 0.5초에 답할 질문은 "다음에 뭐 하지"(성인)와 "우리 애 어디까지"(보호자) 둘뿐이고 둘 다 홈에서 종결. 4탭은 매 진입마다 "콘텐츠 탭인가 내센터 탭인가" 판단을 강요. F02/S01이 일관되게 2탭.
- **콘텐츠 전용 탭 거부 (roi)**: R1에서 매거진은 수동 큐레이션 10개 이하·추천엔진/CMS 금지로 캡. 전용 탭은 빈약해져 "운영 안 하는 앱" 인상. 홈 가로 스크롤 + F06 전체목록 드릴다운이면 추가 IA 0.
- **'내 센터' 전용 탭 거부 (code)**: 비연동 시 0개라 빈 탭. 연동 데이터는 (center_id, client_id) 종속이라 마이페이지 센터 카드(S01 #5)에서 검사결과 N건·진행현황·내담자가 자연 드릴다운. 별도 탭은 중복 진입점.
- **프로파일축 데이터 내장 (px/code)**: 보호자의 "자녀 모두 한눈에" 욕구를 전역 스위처(한 번에 한 명)는 깬다. F02 역할별 분기(순수내담자=섹션없음/보호자=자녀 섹션/both=내 일정+자녀 섹션)가 같은 컴포넌트 조건부 렌더로 기설계. 프로파일은 "스위치"가 아니라 "섹션 헤더".
- **센터 필터 칩, default=전체, 센터수≥2일 때만 노출 (roi/px)**: T1 절충. 데이터 평면은 통합 유지, 단일센터 다수는 칩 미노출(인지부하 0), 멀티센터 헤비유저만 필터 획득. "전환"(모드 진입/이탈)이 아닌 "필터"(같은 화면 좁히기)라 SSR·상태비용이 작다.
- **프로파일 ▾는 전환 스위처에서 프로필 진입 장식으로 격하 (code)**: 센터칩+프로파일 모드를 동시에 굴리면 [본인/자녀]×[센터A/B/전체] 2D 격자 → 빈상태·동기화·회귀 비용 비선형. relation 인가 미구현 현실에서 과투자. ▾는 R9로 이관.
- **상태 무관 고정 2탭 (px)**: S01 미소속/대기/소속이 모두 홈/마이 2탭. 연동 승인 전환(F02 #3 자동 전환) 시 레이아웃이 흔들리지 않아 activation 깔때기 경험이 매끄럽다.

## B · 검증 반박 (근거 포함)

A의 골격(2탭 유지 + 콘텐츠/내센터 탭 제외 + 프로파일 데이터내장 + 상태무관 고정탭)은 코드현실·기존명세·R1 정체성과 정합적이라 입증책임을 충족했다고 인정. 단 두 곳에서 A가 비용을 과소평가했거나 너무 일찍 확정했다.

- **2탭 유지 인정 (code)**: S01 #1~5 전부 [홈][마이], F02 "세 케이스 모두 같은 컴포넌트 조건부 렌더". 탭 확장은 명세 전면 재작업 회귀비용. 추가 IA 0 검증됨.
- **콘텐츠/내센터 전용 탭 제외 인정 (roi/code)**: 매거진 캡 10개로 빈약, 내센터는 S01 #5 마이 센터 카드 드릴다운으로 흡수. 중복 진입점.
- **프로파일 데이터 내장 인정 (px)**: F02 조건부 렌더 기설계, 보호자 욕구 정합. 단 이건 "탭 결정"이 아니라 "홈 위계"라 R3에서 구체화. relation 인가는 신규(seed C)이며 R9 소관 — 탭 라운드에서 인가 구현 약속 안 함.
- **[반박] 센터 필터 칩 include 확정은 시기상조 → defer (roi)**: seed C상 MVP 다수는 단일센터(칩 미노출). 칩 UI+상태를 MVP에 넣는 건 소수 헤비유저만을 위한 투자. 더 결정적으로, A 자신이 "전체=시간순 합산" 데이터 소스(백엔드 집계 vs client 머지)를 defer로 미뤘는데 칩 UI만 먼저 확정하면 칩 동작을 client-side N-call 머지로 떠받쳐야 하는 압력이 생긴다 — UI 약속이 백엔드 미결정을 강제하는 역전.
- **[대안] MVP 멀티센터는 'F02 통합 시간순 + 카드 내 센터 라벨'만 (px)**: F02 "다중 센터 통합"이 이미 시간순 합산·센터명 라벨·"이번주 뭐있지" 멘탈모델 명시. principles 전환없음 일치. 자녀 섹션 분기가 사실상 1차 그룹핑. 필터 필요성은 멀티센터 비율·실제 혼란 데이터로 정당화될 때 R6에서 추가.
- **[반박 강화] 프로파일 ▾는 장식으로도 두지 말고 제거 (px)**: 셰브론은 관습상 "펼침/전환"을 강하게 암시. 기능 없이 두면 가짜 어포던스(인지부하 0이 아니라 음수). 마이페이지 진입은 [마이] 탭이 담당하므로 헤더엔 이름만(셰브론 없이). 멀티프로파일 전환은 R9.
- **상태 무관 고정 2탭 인정 (px)**: S01 세 상태 동일 프레임, F02 #3 자동 전환 시각 연속성.

## 결정 요약

1. **하단 탭은 2탭(홈/마이)로 고정**하고 비연동/대기/소속 모든 상태에서 동일 프레임을 유지한다(MVP). 콘텐츠·내센터 전용 탭은 둘 다 제외 — 콘텐츠는 홈 하단 섹션+F06 드릴다운, 내센터는 마이페이지 센터 카드(S01 #5)로 흡수.
2. **2축 컨텍스트는 비대칭으로 처리한다.** 프로파일축(본인/자녀)은 전역 스위처가 아니라 **데이터 내장(자녀 섹션 분기, F02 조건부 렌더)**으로 표현(MVP). 프로파일 ▾(셰브론)는 가짜 어포던스라 **완전 제거** — 프로필 진입은 [마이] 탭이 담당.
3. **멀티센터는 MVP에서 'F02 통합 시간순 + 카드 내 센터 라벨'만 확정**(필터 없음). 센터 필터 칩과 '전체 합산' 데이터 소스(백엔드 집계 vs client 머지)는 **함께 Phase 2(R6)로 연기** — UI가 미정 백엔드를 강제하는 역전을 막기 위함.
4. 결과적으로 T1은 "통합 무전환(필터 없음)을 MVP로, 전환/필터 UI는 데이터 정당화 시 Phase 2"로, T3은 "2탭 유지 가능 — 발견 콘텐츠는 탭이 아닌 홈 섹션으로 흡수"로 판정.

신규 비용 메모: 프로파일축 데이터 내장이 동작하려면 relation 기반 인가가 신규로 필요하나(seed C) 이는 R9 소관으로 분리했고, 이번 라운드의 탭/IA 결정 자체는 기존 F02/S01 명세로 추가 백엔드 0. 멀티센터 '전체 합산'은 Phase 2에서 백엔드 집계 엔드포인트 또는 client 머지 중 택일(R6).

## 남은 질문

- (R3) 홈 위계: 미소속홈 3블록(센터 연결 CTA/셀프체크/매거진)의 시각적 위계·스크롤 순서, 그리고 소속홈에서 자녀 섹션 분기와 통합 타임라인의 위계 배치.
- (R6) 멀티센터 '전체 합산' 데이터 소스 확정(백엔드 멀티센터 집계 엔드포인트 신규 vs client-side N-call 머지)과, 그 위에서 센터 필터 칩 Phase 2 재론.
- (R6) 필터칩 필요성 입증 기준: 멀티센터 사용자 비율·실제 혼란 데이터 수집 방법.
- (R9) 프로파일 멀티프로파일 전환 UI(▾ 부활 여부)와 relation 기반 인가 구현 범위/프라이버시.
- (R3/R9) 마이페이지 센터 카드(S01 #5)가 검사결과·진행현황·바우처 드릴다운의 단일 진입점으로 부하가 과한지(여러 센터일 때 카드 N개의 스크롤·정보밀도).

## 다음 라운드로 이어받기

탭은 2탭(홈/마이) 고정·상태무관 프레임으로 확정됐고, 2축은 비대칭(프로파일=데이터 내장 자녀 섹션, 센터=MVP 통합 무전환·필터칩은 Phase2)으로 판정됐다. R3(홈 위계)는 이 2탭/무전환/자녀섹션 골격 위에서 미소속·단일·멀티 각 상태의 홈 정보 위계와 스크롤 순서를 확정하되, 센터 필터·집계 데이터 소스는 건드리지 말고 R6로 넘긴다(UI가 미정 백엔드를 강제하지 않도록).
