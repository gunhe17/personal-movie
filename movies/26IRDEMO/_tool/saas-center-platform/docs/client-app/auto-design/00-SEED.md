# 내담자 앱 자율 설계 — 시드 컨텍스트 (Round 0)

> 이 문서는 2-에이전트 토론 워크플로우의 출발점이다. 모든 라운드는 이 시드 + 누적 결정 로그를 기반으로 진행한다.
> 목표: **15+ 라운드 적대적 토론으로 내담자 앱 설계의 각 기능에 대한 "정당성(justification)"을 확보하고, 5라운드마다 시안을 버전화한다.**

---

## 1. 제품 한 줄 정의

상담센터 내담자/보호자를 위한 모바일 앱 (가칭 **마인드엔서**).
"다음에 뭘 하면 되지?"(성인 내담자) + "우리 애 어디까지 했지?"(보호자)에 답하는 앱.

## 2. 세 갈래의 입력 (토론이 종합해야 할 소스)

### (A) 기존 기획 "마인드엔서" — 코드베이스에 이미 존재
- 위치: `docs/client-app/README.md`, `principles.md`, `features/F01~F12*.md`, `S01-screen-map.md`, `viewer.html`
- 참고 뷰어: `/Users/janghojun/Downloads/viewer.html` (소속홈/미소속홈/타임라인/마이/온보딩 + F01~F12 명세)
- 핵심 주장:
  - **2탭(홈+마이)**, 정보는 하나의 흐름이라 분리 안 함
  - **다중 센터/자녀 통합 표시, 전환 없음** ("사용자는 센터 단위로 생각 안 한다")
  - **미소속(비연동) 화면은 최소한** ("핵심 가치는 센터 연결 후")
  - **오브(Orb) 캐릭터** 중심 감성 UX, 다크모드 MVP
  - 브랜드 톤: "심리센터 앱처럼 보이지 않게", 파스텔 보라/핑크 금지
  - 기능: F01 인증·온보딩 / F02 홈 / F03 일정·타임라인 / F04 검사결과 / F05 자가진단 / F06 콘텐츠 / F07 알림 / F08 마이 / F09 오브 / F10 미션·기록(P2) / F11 전문가노트(P2) / F12 AI 성장가이드(P3)
  - 기술: React Native Expo, `apps/mobile-client/`, FCM, Account/Person 재사용

### (B) 신규 논의 방향 (이번 세션) — B2C 강화
- **포털 우선 + 발견 깔때기**: 비연동 사용자도 쓰는 획득 콘텐츠(매거진/카드뉴스, 무료 셀프체크, **주변 센터 찾기**, **정부 바우처 발견**)를 깔아 자연 유입
- **2축 컨텍스트**: `[프로파일: 본인/자녀] × [센터: A/B...]`
- **하이브리드 진입 + 센터 전환 칩**: 멀티센터에서 "전체 통합" + 센터별 전환
- 산출물: `docs/client-app/b2c-home-mockup.html`, `b2c-home-states.html` (비연동/멀티센터 상태)

### (C) 코드베이스 현실 (구현 정당성의 바닥)
- **Client = 센터 소유 연락처 DB**, 로그인 주체 아님. 로그인은 `Person`(=`Account`).
- **`client/link`: "1 Person = 1 Client (센터당)"** → 한 계정이 **여러 센터에 각각 연동 가능**(멀티센터 성립). 연동은 센터코드+전화 → 센터 관리자 승인.
- **보호자 자녀 접근**: `link`가 아니라 `client/relation`(guardian, 양방향) 기반 → **relation 기반 인가는 현재 없음(신규 필요)**.
- **검사 결과 공유**: `assessment/send_result` + 공개 `verify-result`(링크+4자리 인증). 계정 기반 "내 결과 목록"은 신규.
- **검사 응답**: `assessment-flow`(별도 쿠키 인증, 현장/이름·생년월일 식별). 로르샤흐 등 임상가 시행 검사는 셀프 불가 → **검사별 셀프응답 적격성 플래그 필요**.
- **예약**: `schedule` 전부 센터 write 권한. 셀프 예약 = 신규 + 센터 정책(가용슬롯 공개/승인) → **센터별 on/off 토글 권장**.
- **바우처**: `ClientVoucher` = (center_id, client_id) 단위. 잔여 조회는 센터 종속. "정부 바우처 발견"은 별개의 B2C 개념.
- **구독**: 센터 단위 SaaS 요금 (내담자 무관).
- **모바일 앱**: `apps/mobile` = 상담사 전용.
- **AI/구독 기능은 production 미배포(별도 승인 필요)**.

## 3. 토론이 반드시 해소해야 할 핵심 긴장(TENSIONS)

토론 에이전트는 라운드마다 아래 긴장 중 관련된 것을 **근거(코드/사용자심리/ROI)로 판정**해야 한다. "좋아 보여서"는 금지. 각 기능은 **포함/제외/연기(Phase) + 이유**로 결론낸다.

- **T1. 통합 무전환(A) vs 센터 전환 칩(B)** — 멀티센터를 어떻게 보여줄 것인가. principles는 "전환 없음", 신규안은 "전환 칩". 단일 센터가 다수일 현실 고려.
- **T2. 미소속 최소화(A) vs 획득 깔때기 강화(B)** — 비연동 화면을 최소로 둘 것인가, 주변센터·매거진·셀프체크로 적극 획득할 것인가. 앱 정체성(포털 vs 슈퍼앱)이 걸림.
- **T3. 2탭(A) vs 더 많은 탭/발견 영역** — 발견 콘텐츠를 넣으면 2탭이 유지되는가.
- **T4. 오브 캐릭터** — 임상 맥락에서 정당한가, 구현비 대비 가치는. 다크모드 시너지 vs 산만함.
- **T5. 검사 셀프응답 범위** — 적격 검사(자기보고식)만 vs 전체. 임상 타당도 리스크.
- **T6. 셀프 예약** — MVP 포함 vs 연기. 센터 운영정책 충돌, 백엔드 최대 부하.
- **T7. 보호자 멀티프로파일 권한/프라이버시** — 자녀 결과 노출 범위(전체 PDF vs 요약, 성인 자녀 제외), relation 기반 인가 신설.
- **T8. 바우처 두 의미** — 발견(정부지원 안내) vs 잔여(센터 종속). 둘 다 MVP인가.
- **T9. 콘텐츠/매거진/셀프체크의 ROI** — 리텐션·획득 기여 vs 운영(콘텐츠 제작) 비용.
- **T10. 데이터 노출 정책** — 미발행 노트/내부메모 비노출, 검사결과는 상담사 공개범위 설정 따름.

## 6. 토론 규칙 (정당성 확보)

1. 모든 주장은 (A) 사용자 심리/가치, (B) 코드베이스 구현 현실, (C) 비용/리스크/ROI 중 최소 하나의 근거를 댄다.
2. 검증자(B)는 기본 입장이 "포함 반대" — 옹호자(A)가 정당성을 입증해야 채택된다 (입증 책임 = 옹호자).
3. 결정은 반드시 **포함(MVP) / 연기(Phase 2·3) / 제외** 중 하나 + 한 줄 이유.
4. 이전 라운드 결정은 번복 가능하나, 번복 시 명시적으로 사유를 적는다.
5. 코드베이스 사실과 충돌하는 기능은 "신규 백엔드 필요" 비용을 명시한다.
