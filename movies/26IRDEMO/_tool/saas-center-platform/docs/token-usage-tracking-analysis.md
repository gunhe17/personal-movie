## 1. 페르소나 정의

### P1. 플랫폼 운영자 (Super Admin)
- **이름**: 김도현 (28세, 플랫폼 운영팀장)
- **역할**: SaaS 플랫폼 전체를 관리. 모든 센터의 구독, 크레딧, AI 비용을 모니터링
- **핵심 관심사**: 전체 비용 관리, 센터별 사용량 편차, 이상 탐지, 수익성
- **접근 경로**: apps/admin
- **기술 수준**: 높음 (API 스펙 이해, 데이터 분석 가능)

### P2. 센터 관리자 (Manager / 실장)
- **이름**: 박지영 (42세, 상담센터 실장)
- **역할**: 센터 운영 총괄. 구독 플랜 관리, 예산 내 AI 사용량 통제
- **핵심 관심사**: 월 예산 대비 AI 비용, 상담사별 사용량, 플랜 적합도
- **접근 경로**: apps/web → /settings/subscription, /settings/ai-usage
- **기술 수준**: 중간 (수치는 읽으나 토큰 개념은 낯설 수 있음)

### P3. 상담사 (Counselor / 전문가)
- **이름**: 이수진 (35세, 놀이치료 상담사)
- **역할**: 현장 상담 수행. 필드노트, AI 가이드 등 AI 기능 직접 사용
- **핵심 관심사**: 내가 쓸 수 있는 AI 기능이 남아있는지, 기능 사용 시 비용 영향
- **접근 경로**: apps/web → 필드노트, 상담 가이드 사용 중 크레딧 확인
- **기술 수준**: 낮음 (토큰/크레딧 개념 친숙하지 않음)

## 2. 이터레이션 1: 핵심 질문 도출 및 코드 기반 답변

### P1. 플랫폼 운영자 관점

#### Q1-1. "전체 플랫폼에서 이번 달 AI 비용이 얼마나 발생했는지 한눈에 볼 수 있는가?"

**코드 확인:**
- `apps/admin/src/routes/(protected)/ai-usage/+page.svelte` — KPI 카드 영역
- `apps/api/app/modules/platform_admin/ai_usage/router.py` → `GET /admin/ai-usage/summary`
- 응답: `total_tokens`, `total_cost`, `total_calls`, `active_models`, `audio_minutes` + 전월 대비 변화율

**답변:** **O (구현됨)** — AI Usage 대시보드에 총 호출수, 월 비용, STT 사용량, 토큰/크레딧 비율이 KPI 카드로 표시. 전월 대비 변화율(%)도 포함.

#### Q1-2. "어떤 센터가 비정상적으로 많이 쓰고 있는지 파악할 수 있는가?"

**코드 확인:**
- `GET /admin/ai-usage/by-center` → 센터별 사용량 순위 (토큰, 비용, 호출수)
- `apps/admin` AI Usage 페이지 → Top 5 센터 표시
- `GET /admin/subscriptions/usage-overview` → `top_credit_users` 필드

**답변:** **O (구현됨)** — 센터별 랭킹 테이블 존재. 하지만 "비정상" 판단 기준(표준편차, 급증 알림)은 **없음**. 운영자가 직접 눈으로 비교해야 함.

**Gap:** 이상 탐지(anomaly detection) 알림 시스템 부재

#### Q1-3. "AI 기능별로 비용이 어떻게 분배되는지 볼 수 있는가?"

**코드 확인:**
- `GET /admin/ai-usage/by-feature` → purpose별 토큰, 비용, 호출수, 지연시간
- AI Usage 페이지 Feature Usage 테이블: 기능, 모델/프로바이더, 상태, 응답시간, STT 분, 호출당 비용, 비용 점유율(%)

**답변:** **O (잘 구현됨)** — 다차원 분석 가능. 모델별, 프로바이더별, 기능별 분류와 비용 점유율까지 표시.

#### Q1-4. "토큰→크레딧 환산율을 변경하면 기존 기록에 영향이 있는가?"

**코드 확인:**
- `LlmCall` 모델에 `tokens_per_credit` 스냅샷 저장
- `CreditRateConfig` → `effective_from/to`로 버전 관리
- `ChangeRateService` → 기존 rate 닫고 새 rate 생성

**답변:** **O (잘 설계됨)** — 각 LlmCall에 호출 시점의 환산율이 스냅샷으로 기록되어 소급 적용 없음. 이력도 조회 가능.

#### Q1-5. "쿼터 초과한 센터를 즉시 파악하고 조치할 수 있는가?"

**코드 확인:**
- `GET /admin/subscriptions/stats` → `quota_exceeded_count`
- `GET /admin/subscriptions?quota_exceeded=true` → 필터링
- Subscription Dashboard → KPI 카드에 쿼터 초과 수 + 경고 배지
- Action Items Banner → 쿼터 초과, 승인 대기, 결제 실패 빠른 링크

**답변:** **O (구현됨)** — 대시보드에서 즉시 확인 가능하고 상세 페이지에서 크레딧 추가/리셋 조치 가능.

#### Q1-6. "특정 센터의 크레딧을 수동으로 조정할 수 있는가?"

**코드 확인:**
- `POST /admin/subscriptions/{centerId}/adjust-credit` → add/reset
- 관리 페이지 CreditAdjustModal → 추가 금액 또는 플랜 기준으로 리셋

**답변:** **O (구현됨)** — 추가(add)와 리셋(reset) 모두 가능.

#### Q1-7. "월별 AI 비용 추세를 6개월 이상 조회할 수 있는가?"

**코드 확인:**
- `GET /admin/ai-usage/monthly?months=6` → 월별 토큰, 비용, 호출수
- AI Usage 페이지 Monthly Trends 테이블 + 전월비 변화율

**답변:** **O (구현됨)** — 6개월 이상 조회 가능. 현재 월 하이라이트.

#### Q1-8. "LLM 호출 로그를 모델, 에러 여부로 필터링해서 디버깅할 수 있는가?"

**코드 확인:**
- `GET /admin/ai-usage/calls?model=...&center_id=...&has_error=...`
- `LlmCallRepository.list_calls_paginated()` → 필터 + 페이지네이션

**답변:** **O (API 존재)** — 백엔드 API는 완비. 하지만 admin UI에서 이 호출 로그 페이지가 별도로 렌더되는지 확인 필요. AI Usage 페이지에 통합되어 있을 가능성.

### P2. 센터 관리자 관점

#### Q2-1. "이번 달 AI 크레딧을 얼마나 썼고 얼마나 남았는지 직관적으로 알 수 있는가?"

**코드 확인:**
- `apps/web` → `/settings/ai-usage` 개요 탭
- CreditUsageResponse: `credit_used`, `credit_limit`, `credit_remaining`
- 프로그레스바 (green/amber/red), 잔여일수 카운트다운

**답변:** **O (잘 구현됨)** — 사용량/한도/잔여를 프로그레스바 + 숫자 + 색상 코딩으로 직관 표시. 리셋까지 남은 일수도 표시.

#### Q2-2. "어떤 AI 기능이 크레딧을 가장 많이 소모하는지 알 수 있는가?"

**코드 확인:**
- AI Usage 개요 탭 → Purpose Breakdown 파이차트 + 테이블
- 기능별: 호출수, 크레딧, 점유율(%)

**답변:** **O (잘 구현됨)** — 파이차트 + 테이블로 시각화. 기능명도 한글 라벨로 표시.

#### Q2-3. "어떤 상담사가 AI를 가장 많이 사용하는지 파악할 수 있는가?"

**코드 확인:**
- AI Usage 개요 탭 → Member Usage List
- `CreditFacade.get_usage_with_response()` → `active_members`
- `CreditHistoryResponse` → 멤버별 사용 이력 (member_name, purpose, credits)
- `mapToMemberUsage()` → 멤버별 크레딧 합계 + 바차트

**답변:** **O (구현됨)** — 멤버별 크레딧 사용량 바차트와 목록 제공.

#### Q2-4. "현재 플랜이 우리 센터에 적합한지 판단할 수 있는 정보가 있는가?"

**코드 확인:**
- `/settings/subscription` → 플랜 비교 카드
- `calcPlanFitInsight()` → 일평균 사용량, 고갈일수, 여유율(%) 계산
- 적합도 라벨: 부족/빠듯/여유/충분

**답변:** **O (잘 구현됨)** — 현재 사용 패턴 기반으로 각 플랜의 적합도를 자동 계산하여 표시. 업그레이드/다운그레이드 의사결정 지원.

#### Q2-5. "크레딧이 곧 소진될 때 사전 경고를 받을 수 있는가?"

**코드 확인:**
- AI Usage 페이지 → 80% 이상 amber 경고, 95% 이상 red 위험 알림
- `SubscriptionAlertBanner` 컴포넌트 → 레이아웃에 통합
- 고갈 예상일(depletion days) 계산 표시

**답변:** **부분 구현** — 페이지 진입 시 알림은 있으나, **푸시 알림이나 이메일 사전 경고는 없음**. 사용자가 직접 페이지에 들어가야 확인 가능.

**Gap:** 프로액티브 알림(이메일/푸시) 시스템 부재

#### Q2-6. "일별/주별 AI 사용 추세를 차트로 볼 수 있는가?"

**코드 확인:**
- AI Usage → 크레딧 추세 탭: 일별 크레딧 소비 + 누적 사용 라인/에리어 차트
- AI Usage → API 호출 빈도 탭: 일별 호출수 + 누적 차트
- 기능별 멀티라인 추세 차트

**답변:** **O (잘 구현됨)** — 3개 탭으로 개요/크레딧 추세/호출 빈도 분리. 일별 데이터 + 기능별 브레이크다운.

#### Q2-7. "플랜 변경(업그레이드/다운그레이드) 프로세스가 매끄러운가?"

**코드 확인:**
- 업그레이드: Toss Payments 연동 → `initiateUpgrade()` → `confirmUpgrade()`
- 다운그레이드: 예약 방식 → `reserveDowngrade()` (기간 종료 시 적용)
- 다운그레이드 취소: `cancelDowngrade()`
- 플랜 변경 요청: `requestPlanChange()` → 관리자 승인 대기

**답변:** **O (잘 설계됨)** — 업그레이드는 즉시(결제 연동), 다운그레이드는 예약, 취소 가능. 상태 머신 기반 전환 검증.

### P3. 상담사 관점

#### Q3-1. "AI 기능을 사용할 때 크레딧이 차감되는지 인지할 수 있는가?"

**코드 확인:**
- `CreditGauge.svelte` → 에이전트 채팅 헤더에 잔여 크레딧 표시
- 필드노트 녹음 시 → 크레딧 표시 여부 확인 필요

**답변:** **부분 구현** — AI 에이전트 채팅에서는 크레딧 게이지 표시. 하지만 **필드노트 녹음/분석 과정에서는 크레딧 소비 안내가 없음**. 상담사는 자신의 행동이 크레딧에 어떤 영향을 미치는지 모를 수 있음.

**Gap:** 기능 사용 시점의 크레딧 소비 예고/확인 UX 부재

#### Q3-2. "크레딧이 부족하면 어떤 메시지를 받는가?"

**코드 확인:**
- `CheckQuotaService` → 쿼터 초과 시 `QuotaExceededException` 발생
- 에러 메시지: "이번 달 AI 크레딧이 부족합니다..."
- 프론트엔드에서 스낵바/토스트로 표시

**답변:** **O (구현됨)** — 기능 실행 시점에 사전 체크하여 크레딧 부족 시 한글 에러 메시지. 다만 "부족합니다" 이후 **어떻게 해야 하는지 안내(관리자에게 연락, 플랜 업그레이드)가 부족**할 수 있음.

**Gap:** 크레딧 부족 시 해결 경로(CTA) 안내

#### Q3-3. "내가 AI를 얼마나 사용했는지 개인별 사용 현황을 볼 수 있는가?"

**코드 확인:**
- `/settings/ai-usage` 멤버 사용 목록에서 상담사별 크레딧 확인 가능
- 하지만 이 페이지는 **센터 관리자용** (전체 멤버 보기)
- 상담사 본인만의 개인 대시보드는 **존재하지 않음**

**답변:** **X (미구현)** — 상담사가 자신의 AI 사용량만 별도로 볼 수 있는 개인 뷰가 없음. 관리자 페이지에서 전체 멤버 중 하나로만 확인 가능.

**Gap:** 상담사 개인용 AI 사용 현황 페이지 부재

#### Q3-4. "무료 기능과 유료 기능의 구분을 알 수 있는가?"

**코드 확인:**
- `AIPurpose` enum에 `FREE_PURPOSES` 정의 (STT chunk, diarize, streaming, refine, recommendation)
- 하지만 이 구분이 **프론트엔드 UI에 표시되는 코드는 없음**
- 플랜 비교 카드에서 기능 가용 여부는 표시하지만, 개별 기능의 무료/유료 구분은 없음

**답변:** **X (미구현)** — 백엔드에서는 무료/유료를 정확히 구분하지만, **사용자에게 "이 기능은 무료입니다" / "이 기능은 N크레딧이 소모됩니다" 같은 안내가 없음**.

**Gap:** 기능별 크레딧 소비 정보 노출 (무료 표시, 예상 크레딧 표시)

#### Q3-5. "필드노트 AI 분석이 얼마나 크레딧을 소모하는지 사전에 알 수 있는가?"

**코드 확인:**
- `AIPurpose` → 각 목적별 `estimated_credits` 존재 (summarize: 7, generate_note: 8, case_analysis: 11)
- `CreditBalanceResponse` → `estimated_credits` 딕셔너리로 반환
- 하지만 **필드노트 녹음 종료 → 분석 시작 시점에 예상 크레딧을 표시하는 UI는 없음**

**답변:** **X (미구현)** — API에는 예상 크레딧 데이터가 있지만 사용자에게 노출되지 않음.

**Gap:** AI 기능 실행 전 예상 크레딧 안내 UX

> **이후 변화 (2026-09-03)** — 이 보고서는 2026-06-04 시점의 스냅샷이라 본문은 그대로 둡니다.
> · 이 Gap은 **해소**됐습니다 — 경과 분석 실행 모달이 `예상 사용량`을 실행 전에 보여줍니다.
> · `case_analysis` 예상값은 **11 → 14**로 올랐습니다(서버 `PURPOSE_ESTIMATED_CREDITS`).
> · 실행 가능 여부는 API가 내려주는 `estimated_credits`로 판정하고, 웹 상수는 **표시 전용**입니다.

## 3. 이터레이션 2: 교차 관점 질문 (역할 간 인터페이스)

### Q-Cross-1. "관리자가 특정 상담사의 AI 사용을 제한할 수 있는가?"

**코드 확인:**
- 크레딧은 **센터 단위**로 관리 (개인별 할당 없음)
- 쿼터 체크도 센터 단위: `CheckQuotaService.execute(center_id, purpose)`
- 멤버별 제한 메커니즘 없음

**답변:** **X (미구현)** — 센터 전체 크레딧만 관리 가능. 특정 상담사의 과다 사용을 제한하려면 구두로 요청해야 함.

**Gap:** 멤버별 크레딧 할당/제한 기능

### Q-Cross-2. "운영자가 크레딧 환산율을 변경하면 센터 관리자가 인지하는가?"

**코드 확인:**
- `ChangeRateService` → 환산율 변경은 admin에서만 가능
- 센터 관리자 UI → `CreditBalanceResponse`에 `tokens_per_credit` 포함
- 하지만 **변경 알림 시스템은 없음**

**답변:** **X (미구현)** — 환산율 변경 시 센터 관리자에게 자동 알림 없음. 크레딧 잔여가 갑자기 변할 수 있는데 원인을 모를 수 있음.

**Gap:** 환산율 변경 시 센터 관리자 알림

### Q-Cross-3. "free 플랜 센터가 유료 AI 기능을 시도하면 어떤 경험을 하는가?"

**코드 확인:**
- Free 플랜: `credit_limit = 0`
- `CheckQuotaService`: 잔여 크레딧 < 예상 소비 → `QuotaExceededException`
- 에러 메시지: "이번 달 AI 크레딧이 부족합니다. 플랜을 업그레이드해주세요."
- 하지만 **Free 플랜에서는 크레딧 레코드 자체가 없을 수 있음** (`clear_credit` 호출)

**답변:** **부분 구현** — 에러는 발생하지만, Free 플랜 사용자에게는 "크레딧이 부족합니다"보다 **"이 기능은 유료 플랜에서 사용 가능합니다"**가 더 적절. Free 플랜은 크레딧이 "부족"한 게 아니라 "없는" 것이므로.

**Gap:** Free 플랜 전용 업그레이드 유도 메시지/CTA

## 6. 이터레이션 3: 심화 분석 — 데이터 흐름 검증

### AI 호출 → 크레딧 차감 → 기록 경로 추적

```
1. 기능 트리거 (예: 필드노트 요약 생성)
   └→ AIGateway.generate_text(ctx={center_id, purpose="field_note_summarize", member_id})

2. 사전 쿼터 체크
   └→ CreditOps.check(center_id, purpose)
       └→ CheckQuotaService.execute()
           ├→ FREE_PURPOSES 확인 → 무료면 통과
           └→ CreditBalance 조회 (lazy reset 포함)
               └→ remaining >= estimated_credits[purpose] ? 통과 : QuotaExceededException

3. LLM 실행
   └→ LLMClient.generate() → {input_tokens, output_tokens, latency_ms}

4. 사후 기록 + 차감
   └→ AddLlmCallService.execute()
       ├→ CreditRateConfig.get_active() → tokens_per_credit
       ├→ FREE_PURPOSES 체크 → 무료면 credits_charged=0
       ├→ DeductCreditService.execute(center_id, total_tokens)
       │   └→ CreditBalance.credit_used += credits (ceiling division)
       └→ LlmCall 레코드 생성 (tokens, credits, rate 스냅샷)

5. 센터 관리자 조회
   └→ GET /centers/{id}/credit/usage
       └→ CreditFacade.get_usage_with_response()
           ├→ CreditBalance (잔여)
           ├→ LlmCallRepository.get_center_usage_summary() (집계)
           └→ daily gap fill (차트용 연속 데이터)
```

**검증 결과:** 데이터 흐름이 끊김 없이 일관적. 특히 `tokens_per_credit` 스냅샷이 LlmCall과 CreditBalance 양쪽에 기록되어 reconciliation 가능.

### 잠재적 데이터 정합성 이슈

1. **Overflow 처리**: `credit_used > credit_limit`일 때 warning만 로그하고 차감은 계속됨 → **의도적 설계** (서비스 중단보다 초과 허용 후 사후 관리)
2. **Lazy Reset 타이밍**: 기간 만료 후 첫 조회/체크 시 리셋 → 기간 경계에서 짧은 시간 동안 "만료됨" 상태 노출 가능 → **실사용 영향 미미**
3. **동시성**: `get_active_for_update()`로 row lock → PostgreSQL 기준 안전. 하지만 **CreditOps가 별도 세션 사용** (`AsyncSessionLocal()`) → UoW 밖에서 독립 커밋 → 메인 트랜잭션 롤백 시 크레딧은 이미 차감됨 → **보상 로직 없음**

**리스크:** LLM 호출 성공 → 크레딧 차감 → 결과 저장 실패 시 크레딧만 날아감. 실제 빈도는 극히 낮을 것으로 예상되나, 고빈도 사용 시 누적될 수 있음.
