# Payment 도메인 Summary

> 핵심 개념 및 정책 요약 (1-2페이지)

---

## 🎯 핵심 개념

### B2C 회계 관리
센터 → 내담자 수납/청구 시스템 (B2B Subscription과 분리)

### Phase 1 목표
1. **서비스 완료 → 자동 청구 생성** (핵심 워크플로우)
2. 미수금 추적 (핵심 pain point)
3. **단가표 기반 가격 관리** (오타/불일치 방지)
4. 바우처 자동 계산 (한국 특화)
5. **일괄 청구** (월말 청구 지원)
6. 기본 매출 리포트

---

## 📦 핵심 엔티티 (6개)

### 1. Billable (청구서)
- 여러 서비스를 묶어서 청구
- **자동 생성**: 서비스 완료 시 draft 자동 생성
- 상태: `draft → issued → paid/overdue`
- 과납부 허용 (`paid_amount > total_amount`)

### 2. BillableItem (청구 항목)
- 개별 서비스/제품 상세
- **음수 금액 허용** (환불/차액)
- 수정 불가, 삭제 후 재생성만

### 3. Payment (수납 기록)
- 부분 납부 지원
- **영수증 번호**: nullable (Phase 1), 자동 생성 선택 (Phase 2)
- draft 청구서 수납 시 자동 발행

### 4. PriceList (단가표)
- **센터별 단가 관리** (가격 표준화)
- 서비스 유형별 단가 설정
- 청구 시 자동 참조

### 5. VoucherPolicy (바우처 정책)
- **센터 관리** (각 센터가 자체 관리)
- 정부 지원금 정책 (80% 지원 등)
- 월별 사용 한도

### 6. ClientVoucher (내담자 바우처)
- 내담자별 바우처 사용 내역
- 잔여 횟수 자동 계산
- 사용 시 자동 차감

---

## 🔑 핵심 정책 (반드시 숙지)

### 1. 청구서 상태 관리
- ✅ draft: 항목 추가/삭제 가능 (수정 불가)
- ❌ issued: 모든 변경 불가
- ⚠️ cancelled 없음 → 음수 청구서로 상계

### 2. 수납 처리
- ✅ 과납부 허용 (경고 로그)
- ✅ draft 수납 시 자동 발행
- ✅ 부분 납부 가능
- ✅ 영수증 자동 생성

### 3. 음수 금액 (환불)
- ✅ `unit_price < 0` 허용
- ❌ refund 타입 없음
- ⚠️ notes 권장 (사유 기록)

### 4. 바우처 검증 (엄격)
- ❌ 잔여 횟수 < 1 → 에러
- ❌ 월별 한도 초과 → 에러
- ❌ 유효기간 만료 → 에러
- ✅ 금액 자동 계산

## 🚀 주요 API

### Billable
```
POST   /billables                 # 청구서 생성
POST   /billables/batch           # 일괄 청구 (월말)
GET    /billables/unpaid          # 미수금 목록
POST   /billables/{id}/items      # 항목 추가 (draft만)
DELETE /billables/{id}/items/{id} # 항목 삭제 (draft만)
```

### Payment
```
POST /payments                    # 수납 처리
GET  /billables/{id}/payments     # 청구서별 수납 내역
```

### PriceList
```
GET  /price-lists                 # 단가표 목록
POST /price-lists                 # 단가 생성
PUT  /price-lists/{id}            # 단가 수정
```

### Voucher
```
GET  /vouchers/policies           # 바우처 정책 목록
POST /vouchers/policies           # 바우처 정책 생성 (센터)
GET  /vouchers/clients/{id}       # 내담자 바우처
POST /vouchers/clients            # 바우처 등록
```

## ⚡ 주요 비즈니스 로직

### 자동 청구 생성 흐름 (NEW)
```
1. 서비스 완료 (CounselingSession/Assessment)
2. 이벤트 발생 → Payment 모듈 핸들러
3. PriceList에서 단가 자동 조회
4. Billable (draft) + BillableItem 자동 생성
5. 센터 알림 (검토 후 발행)
```

### 일괄 청구 흐름 (NEW)
```
1. 기간 + 내담자 범위 지정
2. 완료된 서비스 조회
3. 내담자별 Billable 생성
4. PriceList 자동 참조
5. 바우처 자동 계산
6. draft 상태로 생성 (검토 필요)
```

### 수납 처리 흐름
```
1. Payment 생성
2. draft → issued 자동 전환
3. Billable.paid_amount += amount
4. paid_amount >= total_amount → paid
5. 영수증 번호 (nullable)
```

### 바우처 청구 흐름
```
1. 잔여 횟수 체크
2. 월별 한도 체크
3. 금액 자동 계산 (80% 지원 등)
4. used_sessions += 1 자동 차감
5. 청구서 생성
```

## 🔴 정책 결정 필요 사항

### 1. 과납부 처리 ⚠️
**현재 결정**: 허용 + 경고 로그 (유연)

**검토 필요**:
- 과납부 금액 상계 방법? (다음 청구에서 자동 차감?)
- 환불 요청 시 프로세스?

---

### 2. 영수증 번호 형식 ⚠️
**현재 결정**: `{center_code}-{YYYYMM}-{seq:05d}`

**검토 필요**:
- center_code 형식? (`C001` vs `CENTER001` vs 센터명 약자)
- 월별 리셋 vs 연간 리셋?

---

### 3. 바우처 정책 업데이트 프로세스 ⚠️
**현재 결정**: 센터별 자체 관리

**검토 필요**:
- 정부 정책 변경 시 센터 공지 방법?
- SaaS 팀 제공 템플릿 필요성?
- 기존 ClientVoucher에 영향은?

---

### 4. 연체 처리 정책 ⚠️
**현재**: 배치로 자동 overdue 전환

**검토 필요**:
- 연체 후 조치? (알림만? 서비스 제한?)
- 연체 이자/수수료 부과?

---

### 5. 미수금 독촉 정책 ⚠️
**현재**: 시스템에 없음

**검토 필요**:
- 자동 독촉 알림?
- 독촉 주기 (3일, 7일, 14일)?
- 센터별 설정 가능?

---

### 6. 환불 프로세스 ⚠️
**현재**: 음수 청구서 생성

**검토 필요**:
- 환불 승인 프로세스?
- 환불 내역 별도 추적?
- Phase 2 Refund 엔티티 필요성?

---

### 7. 청구서 삭제 정책 ⚠️
**현재**: draft만 삭제 가능, issued는 불가

**검토 필요**:
- 실수로 발행한 경우 대응 방안?
- 관리자 권한으로 삭제 가능?

---

### 8. 바우처 중복 사용 방지 ⚠️
**현재**: 동시성 제어 (비관적 잠금)

**검토 필요**:
- 성능 이슈 가능성?
- 낙관적 잠금으로 변경?
