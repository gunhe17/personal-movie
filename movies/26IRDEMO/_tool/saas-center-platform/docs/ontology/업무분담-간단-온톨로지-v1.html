업무 분담 — 온톨로지 v1 도입

전원 버티컬 개발 가능. 그래서 배분 기준은 파트가 아니라 "각자의 전문 분야에서 온톨로지 도입에 무엇을 책임지고, 무엇을 산출물로 내놓는가" 하나다.

① 스키마신설 6테이블 + center_type
② 용어 팩기관별 어휘·탭·뷰 프리셋
③ 화면 4종명렬표·승격시트·대시보드·개인관리 정리
④ graph explorer온톨로지를 눈으로 확인

BE-A (나)

온톨로지의 뼈대 — 신원·식별 규칙 "한 사람이 시스템에서 어떻게 유일한가"를 스키마와 API로 확정하는 사람. 패널 합의의 스키마 정본 소유.

다루는 것

  • 신설 스키마 전체 정의 (rounds·roster·org_units·enrollments·identifiers·referrals)
  • 신원 규칙: Person 비승격 · Client 병합 · 외부 식별자(학번·군번) 수명
  • 스크리닝 반입·파기의 트랜잭션 (FE-A와 페어)

산출물

  • alembic 마이그레이션 1벌6테이블 + center_type + partial unique 2본 — P0에 초안
  • client merge API관계·케이스 승계 + merged_into 마커
  • 통합 검색 API이름 부분일치 + 식별자 정확일치 + 기간 스코프
  • 스키마 계약 문서 1장전원이 참조하는 테이블·제약·금지사항(주민번호 등)

BE-B

온톨로지의 축 — 조직·시간·집계 "3학년 2반", "2중대"라는 축을 만들고, 그 축으로 세는 사람. 대량 데이터(800명 반입·집계)의 성능 책임.

다루는 것

  • 조직 위계(org_units 수명 행)와 배정 이력(enrollments)
  • 명부 엑셀 반입 파이프라인 + 회차 파기(purge)
  • 집계: org_unit·round 차원 group_by, n<5 서버 마스킹

산출물

  • org_units·enrollments API+ clients.org_unit_id 캐시 동기화, agent query dim 편입
  • 명부 반입 API검증·미리보기·오류 리포트 포함
  • 회차 파기 잡round 단위 hard purge
  • 집계 대시보드 API내부 모드 먼저 — 방출은 대표 판정 후

FE-A

온톨로지가 처음 만나는 화면 — 스크리닝 루프 신규 화면의 절반을 만드는 사람. "명단 업로드 → 명렬표 → 절단선 → 개별 관리 시작"이라는 새 코어 루프 전체.

다루는 것

  • 명렬표 화면(대량 뷰 — 발송·회수·판정 컬럼)
  • 승격 시트("개별 관리 시작" = roster→Client 탄생의 단일 관문)
  • 조직 트리 관리 + 집계 대시보드 화면 (BE-B API 소비)

산출물

  • 명렬표 화면roster_entries 계약, 전역 검색과 격리
  • 승격 시트roster 프리필 Client 생성 + 중복 경고 배너 재사용 + 역링크
  • 조직 편성 화면unit 트리 CRUD + 학년도 롤오버
  • 집계 대시보드 화면내부 모드 (방출 모드는 판정 후)

FE-B

온톨로지의 번역층 — 용어 팩 + graph explorer "같은 구조를 기관마다 다른 말로 보여주는" 장치를 만드는 사람. 기존 화면의 하드코딩을 걷어내고, 온톨로지를 눈으로 보이게 한다.

다루는 것

  • 용어 팩 시스템(로더·소비 규약) — DE의 사전을 코드로
  • 기존 화면 정리: "아동" 하드코딩 제거, role 표시=관계 파생, 보호자 탭
  • graph explorer (엣지 4종 시각화, BE-A와 API 페어)

산출물

  • 팩 로더 + 소비 규약center_type→레이블·탭·기본 뷰, 세션 1회 로드
  • 하드코딩 제거 PRROLE_TABS→카탈로그 키, 폴백=무표시
  • 병합/재사용 제안 UI중복 경고 배너 승격 (BE-A merge API 소비)
  • graph explorer 화면기존 관계도-캔버스 팬·줌 재사용, Person·Account 노드 금지

DE

온톨로지의 언어와 경계 — 어휘 사전 · 화면 설계 · 민감정보 노출 규칙 "이 기관에서 이걸 뭐라고 부르고, 누구에게 어디까지 보여주나"를 정의하는 사람. 모든 화면 산출물의 입력이자 최종 검문.

다루는 것

  • 기관별 어휘 사전(팩의 내용물) — FE-B가 이걸 코드로 얹음
  • 신규 화면 4종의 와이어→시안 (항상 개발보다 한 발 앞서)
  • 민감정보 노출 규칙 — Person 명사 금지, 마스킹, 노출 '순간' 3곳

산출물

  • 용어 팩 사전 4종센터·학교·병원·군 — 레이블·탭 구성·기본 뷰까지
  • 명렬표·승격 시트 와이어P0 — FE-A 착수 조건
  • 대시보드(내부/방출)·explorer 와이어P1 중 선행 제작
  • 노출 가이드 1장온톨로지 노출 순간 3곳 + n<5 마스킹 표시 규칙 — 전 PR 리뷰 기준

산출물이 합쳐지는 순서

DE 사전·와이어＋ BE-A 스키마 계약→ BE-A·BE-B API→ FE-A 신규 화면 · FE-B 팩·기존 정리→ graph explorer로 최종 확인

P0(3일): 왼쪽 두 개(사전·와이어 + 스키마 계약)를 동결 → P1(1~2주): 나머지 전부 병행 — 서로 다른 테이블·화면이라 충돌 없음. 각자 산출물이 다음 사람의 입력이므로, 막히면 기다리지 말고 목(mock)으로 선진행.

대표 판정 대기로 착수 금지인 것 (전원 공통): 방출 모드(익명 집계 반출) · 승격 소급 링크 · 절단선 노출 수준. 이 셋만 피하면 5명 전원이 첫날부터 병렬 시작 가능.
