업무 분담 제안 — 온톨로지 v1

5인 전원 버티컬(프론트·백 구분 없이 슬라이스 전체) 개발을 전제로, 오너십은 버티컬로 · 전문성은 앵커(리뷰 게이트)로 쓰는 배분안. 작업 단위는 패널 합의안(패널논쟁-사람-내담자-멤버-기관.html)에서 도출. 이름은 자리표시자 — 회의에서 매핑.

0

팀 — 자리표시자와 앵커 역할

전원이 어느 슬라이스든 잡을 수 있지만, 각 분야의 최종 리뷰 게이트(앵커)는 전문가가 소유한다. 앵커는 "그 분야 산출물이 머지되기 전 반드시 거치는 눈"이며, 본인 슬라이스 개발과 병행한다.

BE-A (나)백엔드 · 온톨로지 논쟁 컨텍스트 최다 보유앵커스키마·마이그레이션·agent query 계약
BE-B백엔드앵커집계·성능(대량 반입·group_by)
FE-A프론트앵커화면 아키타입 컴포넌트 계약
FE-B프론트앵커용어 팩 소비 규약·하드코딩 감시
DE디자이너앵커팩 어휘 사전 + 아키타입 디자인 시스템 + 민감정보 노출 UX
1

배분 원칙 3개

① 슬라이스 = DB→API→화면 통째 오너십

"백엔드 끝나면 프론트 시작"의 핸드오프 대기를 없앤다. 한 슬라이스는 한 명이 마이그레이션부터 화면까지 끝까지 책임. 리뷰는 앵커가.

② 전문성은 리드 배치가 아니라 게이트 배치

스키마 변경 머지 = BE 앵커 승인 / 아키타입 컴포넌트 신설 = FE 앵커 승인 / 어휘·노출 수준 = DE 승인. 전문가 병목이 아니라 전문가 검문소.

③ 경계 넘는 첫 작업은 30분 페어로 시작

프론트가 첫 alembic 마이그레이션을 짤 때 BE와 30분 페어, 백엔드가 첫 Svelte 아키타입을 만들 때 FE와 30분 페어. 이후는 혼자 + PR 리뷰.

2

슬라이스 6개 — 배분안

크기: S(수일) M(1주±) L(2주±). 각 슬라이스는 패널 합의 스키마·원칙을 그대로 구현 단위로 자른 것.

S1. 신원·식별 코어

MP1
  • client_identifiers (temporal stable|periodic, partial unique 2본, issuer 참조) + centers.center_type
  • Client 수동 merge(관계·케이스 승계 + merged_into 마커)
  • 통합 검색: 입력 패턴 감지 → 정확 일치 섹션 + 기간 칩 (API+화면 둘 다)
오너BE-A 페어·리뷰FE-B검색 UI 게이트DE중복 경고→병합 제안 UX
신원 스파인·병합은 실수 시 개인정보 사고로 직결 — 논쟁 컨텍스트를 가장 많이 보유한 사람이 잡는 게 맞다. 검색 UI에서 버티컬 경계를 한 번 넘는다.

S2. 조직·시간성

MP1
  • org_units(수명 행 valid_from/to, unit_code 결정 반영) + enrollments(append-only) + clients.org_unit_id 캐시
  • agent query 편입: org_unit 필터·group_by dim + 감사 스크립트 갭 0
  • 조직 편성 관리 화면(unit 트리 CRUD + 학년도 롤오버)
오너BE-B 페어·리뷰FE-A트리 UI 게이트BE-A스키마·dim 계약
group_by dim·집계 성능과 직결되는 슬라이스 — 집계 앵커가 소유하면 이후 S4(집계·방출)로 자연스럽게 이어진다.

S3. 스크리닝 깔때기

LP1
  • screening_rounds + roster_entries + 회차 파기(purge) 실행
  • 명부 엑셀 반입 파이프라인(검증·미리보기·오류 리포트)
  • 명렬표 화면(아키타입 ①) + 승격 시트(아키타입 ④ — roster 프리필 Client 생성 + 중복 경고 재사용 + 역링크)
오너FE-A 페어BE-A반입 검증·파기 tx 게이트DE명렬표·승격 시트 와이어 선행
가장 큰 신규 슬라이스이자 화면 신설 2개 — 아키타입 컴포넌트 앵커가 오너를 잡고, 반입·파기의 트랜잭션 설계에서 백엔드 페어. "화면 멘탈 모델이 API를 견인한다"(패널 C 원칙)를 그대로 실행하는 구조.

S4. 집계·방출

MP2대표 판정 대기 — 익명 집계 반출 v1·절단선
  • 집계 대시보드(아키타입 ③) 내부 모드 — round·org_unit 차원, threshold 기록 필드
  • 방출 모드(판정 통과 시): n<5 서버 마스킹(플랫폼 고정) + 게이트 위저드 + 방출 이력
오너BE-B 페어FE-A대시보드 뷰 게이트DE마스킹 표시("보이는 것=나가는 것")
n<5 마스킹은 화면 재량이 아니라 서버 강제(패널 합의) — 집계 앵커 소유. S2와 같은 오너라 dim 설계가 끊기지 않는다. 판정 전에는 내부 모드까지만 착수 가능.

S5. 용어 팩 + UI 통일성

MP0→P1
  • 팩 스키마 정의(레이블·탭 구성·기본 뷰·식별자 패턴·명렬표 컬럼) + center_type 프리셋 4종 + 세션 로드
  • "아동" 하드코딩 제거(ROLE_TABS→카탈로그 키), role 표시=관계 파생·폴백 무표시, 보호자 탭 정리
  • 중복 경고 배너 → 병합/재사용 제안 승격(S1의 merge API 소비)
오너FE-B 공동 오너DE어휘 사전 내용은 DE 소유 게이트BE-A팩 API 계약
팩은 모든 화면 슬라이스의 공통 의존 — 가장 먼저 계약을 동결해야 한다(P0). 사전의 "무엇이라 부르나"는 디자이너 소유, "어떻게 소비하나"는 프론트 소유로 가른다.

S6. 온톨로지 graph explorer

MP2
  • 엣지 정본 4종 API(Client—Case—Session / Client—enrollment—OrgUnit / roster⇢Client / Client—referral) + referrals v1 행 기록
  • 그래프 시각화 화면(기존 API-관계도-캔버스.html 팬·줌 패턴 재사용) — Person·Account 노드 없음
오너FE-B 페어BE-A투영·봉투 계약 게이트DE노출 수준(민감 엣지)
S1·S2 스키마가 깔려야 그릴 그래프가 생긴다(P2). 팩 소비 규약 앵커(FE-B)가 오너면 explorer 라벨이 자동으로 팩을 따른다.

순서 — 계약 먼저, 화면은 뒤

P0회의 직후 ~3일

계약 동결 스프린트. ① 스키마 마이그레이션 초안 전체(BE-A·BE-B 합작 — unit_code 1줄 결정 포함) ② 팩 스키마+프리셋 계약(FE-B+DE) ③ 명렬표·승격 시트 와이어프레임(DE+FE-A) ④ 대표 판정 6건 수령(회의에서). 산출물 = 마이그레이션 PR + 팩 JSON 스키마 + 와이어 — 이후 병렬 작업의 공통 지반.

P11~2주

S1 + S2 + S3 + S5 병행. 4개 슬라이스가 서로 다른 테이블·화면을 만지므로 충돌 최소. 유일한 교차점은 S5 팩을 S3 명렬표가 소비하는 것 — P0에서 계약을 동결했으므로 목(mock) 팩으로 선진행 가능.

P23주~

S4 + S6 착수, S3 마무리. S4는 대표 판정(방출 v1) 결과에 따라 내부 모드까지 or 방출까지. S6은 S1·S2 스키마 위에서. 통일성 개선(S5)은 신규 화면이 생길 때마다 팩 준수 리뷰로 상시 확산.

5

협업 규칙 (버티컬 팀 운영)

계약 우선

슬라이스 간 인터페이스(팩 스키마, merge API, roster→Client 승격 API)는 P0에 문서로 동결. 이후 변경은 앵커 승인 + 소비자 통보.

앵커 게이트는 24h SLA

게이트 리뷰가 병목이 되면 버티컬의 의미가 없다. 앵커는 24시간 내 리뷰, 불가 시 사전 위임.

DE는 병렬 선행

디자이너는 항상 한 페이즈 앞 화면(P1 중엔 S4·S6 와이어)을 깎는다. 개발자가 와이어 없이 화면을 시작하는 일이 없게.

민감정보 3원칙은 전 슬라이스 공통 게이트

Person·Account 명사 노출 금지 / Member↔Client 엣지 비노출 / n<5 서버 마스킹 — 위반은 DE+BE-A 이중 게이트가 잡는다.

주 2회 15분 경계 싱크

슬라이스 간 교차점(팩↔명렬표, merge↔승격 시트)만 논의. 전체 스탠드업 대체 아님.

판정 대기 항목은 착수 금지

방출 모드·소급 링크·절단선 노출 수준은 대표 판정 전 구현 금지 — 내부 모드·기록 필드까지만.

이번 회의에서 정하고 나올 것

① 자리표시자 → 실명 매핑 (특히 S3 오너 — 가장 큰 슬라이스, 본인 의사 확인) ② 대표 판정 6건(패널 문서 §6 — 익명 집계 반출 v1이 S4 범위를 가름) ③ unit_code 축 1줄 결정(S2 착수 조건) ④ P0 마감일과 P1 목표(파일럿 기준: 교육청 vs 사단 — 반입·보고 화면의 첫 폴리시 결정) ⑤ 앵커 SLA 합의
이 배분의 검증 포인트: 누구도 "남의 파트 대기"로 멈추지 않는가(버티컬) / 스키마·어휘·민감정보가 전문가 게이트를 반드시 통과하는가(앵커) / 판정 대기가 임계 경로를 막지 않는가(S4만 영향, 나머지 5개 슬라이스는 무관).
