## 도메인 개요

### 핵심 개념

**Careboard(게시물)**은 내담자 관점의 “무슨 일이 있었는가”를 기록하는 타임라인 아이템입니다.
- 시스템 이벤트 중심(등록/접수/취소 등)
- Append-only (수정 불가)
- 역추적 링크(`relation_item_type/id`)를 통해 원천 도메인으로 이동
- 타임라인 정렬은 `occurred_at`(발생 시각) 기준

**CareboardComment(댓글/답글)**은 담당자들이 타임라인 아이템에 남기는 협업 커뮤니케이션입니다.
- 2-depth 고정(댓글 + 답글)
- 삭제는 소프트 삭제(`is_deleted`)이며, content는 유지

**Mention(언급)**은 댓글/답글에서 특정 사용자를 언급하기 위한 기능입니다.
- content에 `<mention id="UUID">@닉네임</mention>` 형태로 저장
- 작성 시 파싱하여 `careboard_comment_mentions`에 정규화 저장

### 설계 원칙

- **독립 도메인**: FieldNote(세션/녹음 중심)와 목적이 다르므로 Careboard는 별도 Bounded Context로 운영
- **시스템 이벤트 중심**: Phase 1에서 게시물은 시스템만 생성, 사용자는 댓글/답글만 생성
- **확장 가능한 이벤트 코드**: `event_code`는 문자열로 저장, UI 매핑은 별도 테이블/매핑 레이어로 관리
- **멀티테넌시 명시**: `center_id`를 Careboard에 포함하여 격리와 인덱스를 단순화

### 책임 (Responsibility)

- 내담자별 타임라인 아이템 저장/조회
- 타임라인 아이템에 대한 댓글/답글 저장/조회
- 언급 파싱 및 “나를 언급한 댓글” 같은 조회를 위한 메타데이터 제공

### 의존성

- **Depends on**: Center(멀티테넌시), Client(내담자), User/Account(댓글 작성자)
- **Depended by**: Client/Counseling/Assessment 등(시스템 이벤트 생성 시 Careboard에 기록)

## 스키마 정의

> 표기: `occurred_at`(이벤트 발생 시각) vs `created_at`(기록 생성 시각) 분리 운영

### 1. Careboard (게시물)

```python
from datetime import datetime
import uuid
from sqlalchemy import String, Text, DateTime, ForeignKey, Index
from sqlalchemy.dialects.postgresql import UUID
from sqlalchemy.orm import Mapped, mapped_column


class Careboard(Base):
    """
    내담자 타임라인 아이템 (시스템 이벤트 중심, Append-only)
    """
    __tablename__ = "careboards"

    id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        primary_key=True,
        default=uuid.uuid4,
    )

    # 멀티테넌시 격리 (RLS/인덱스)
    center_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        ForeignKey("centers.id", ondelete="RESTRICT"),
        nullable=False,
        index=True,
    )

    # 내담자
    client_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        ForeignKey("clients.id", ondelete="RESTRICT"),
        nullable=False,
        index=True,
    )

    # 이벤트 코드 (확장 가능: 문자열)
    event_code: Mapped[str] = mapped_column(
        String(50),
        nullable=False,
        index=True,
    )  # e.g. "CLIENT_REG", "COUNSEL_REC", "ASMT_REC", "ASMT_CANCEL"

    # 컨텐츠 (렌더링 가능한 텍스트, 멘션 태그 포함 가능)
    content: Mapped[str] = mapped_column(Text, nullable=False)

    # 원천 도메인 역추적용 링크 (polymorphic 1:1)
    relation_item_type: Mapped[str | None] = mapped_column(String(50), nullable=True)
    relation_item_id: Mapped[uuid.UUID | None] = mapped_column(UUID(as_uuid=True), nullable=True)

    # 이벤트 발생 시각 vs 기록 생성 시각
    occurred_at: Mapped[datetime] = mapped_column(DateTime, nullable=False, index=True)
    created_at: Mapped[datetime] = mapped_column(DateTime, nullable=False, index=True, default=datetime.utcnow)

    __table_args__ = (
        Index("ix_careboards_center_client_occurred", "center_id", "client_id", "occurred_at"),
        Index("ix_careboards_center_relation", "center_id", "relation_item_type", "relation_item_id"),
        # 권장(멱등성): 동일 원천 리소스에 대해 동일 이벤트가 중복 기록되지 않도록 제약
        # (DB/제품 정책에 따라 unique로 승격 가능)
        Index("ix_careboards_center_event_relation", "center_id", "event_code", "relation_item_type", "relation_item_id"),
    )
```

**필드 설명**:

| 필드 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `id` | UUID | PK | 게시물 ID |
| `center_id` | UUID | FK, NOT NULL | 센터 격리(RLS) |
| `client_id` | UUID | FK, NOT NULL | 내담자 |
| `event_code` | String | NOT NULL | 확장 가능한 이벤트 코드 |
| `content` | Text | NOT NULL | 표시용 본문(멘션 태그 가능) |
| `relation_item_type` | String | NULL | 원천 도메인 타입(역추적) |
| `relation_item_id` | UUID | NULL | 원천 도메인 PK(역추적) |
| `occurred_at` | DateTime | NOT NULL | 이벤트 발생 시각(타임라인 정렬 기준) |
| `created_at` | DateTime | NOT NULL | 기록 생성 시각(지연처리/재처리 추적) |

> Phase 1 정책: 게시물은 시스템 생성으로 고정되므로 `created_by`를 두지 않습니다. (추후 수동 작성 기능이 생기면 추가 고려)

### 2. CareboardComment (댓글/답글)

```python
from sqlalchemy import BigInteger, Boolean


class CareboardComment(Base):
    """
    Careboard 댓글/답글 (2-depth 고정)
    - comment_id NULL: 댓글
    - comment_id NOT NULL: 답글 (comment는 항상 '댓글'이어야 함)
    """
    __tablename__ = "careboard_comments"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)

    # RLS 단순화를 위한 중복 보관(권장)
    center_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        ForeignKey("centers.id", ondelete="RESTRICT"),
        nullable=False,
        index=True,
    )

    careboard_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        ForeignKey("careboards.id", ondelete="CASCADE"),
        nullable=False,
        index=True,
    )

    user_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        ForeignKey("users.id", ondelete="RESTRICT"),
        nullable=False,
        index=True,
    )

    comment_id: Mapped[int | None] = mapped_column(
        BigInteger,
        ForeignKey("careboard_comments.id", ondelete="SET NULL"),
        nullable=True,
        index=True,
    )

    content: Mapped[str] = mapped_column(Text, nullable=False)
    is_deleted: Mapped[bool] = mapped_column(Boolean, nullable=False, default=False, index=True)

    created_at: Mapped[datetime] = mapped_column(DateTime, nullable=False, index=True, default=datetime.utcnow)

    __table_args__ = (
        Index("ix_careboard_comments_careboard_created", "careboard_id", "created_at"),
        Index("ix_careboard_comments_careboard_comment_created", "careboard_id", "comment_id", "created_at"),
    )
```

### 3. CareboardCommentMention (댓글 언급)

```python
from sqlalchemy import UniqueConstraint

class CareboardCommentMention(Base):
    """
    댓글/답글의 멘션 메타데이터 (작성 시 파싱하여 정규화 저장)
    """
    __tablename__ = "careboard_comment_mentions"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)

    center_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        ForeignKey("centers.id", ondelete="RESTRICT"),
        nullable=False,
        index=True,
    )

    comment_id: Mapped[int] = mapped_column(
        BigInteger,
        ForeignKey("careboard_comments.id", ondelete="CASCADE"),
        nullable=False,
        index=True,
    )

    target_user_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        ForeignKey("users.id", ondelete="RESTRICT"),
        nullable=False,
        index=True,
    )

    created_at: Mapped[datetime] = mapped_column(DateTime, nullable=False, default=datetime.utcnow, index=True)

    __table_args__ = (
        Index("ix_careboard_comment_mentions_target", "center_id", "target_user_id", "created_at"),
        UniqueConstraint("comment_id", "target_user_id", name="ux_careboard_comment_mentions_unique"),
    )
```

## 연동 패턴

### 1. 시스템 이벤트 → Careboard 기록 생성

Careboard 게시물은 “원천 도메인”에서 이벤트가 발생할 때 생성됩니다.

**예시 이벤트(초기)**:
- `CLIENT_REG`: 내담자 등록
- `COUNSEL_REC`: 상담 접수
- `ASMT_REC`: 검사 접수
- `ASMT_CANCEL`: 검사 취소

**권장 입력(표준화)**:
- `center_id`, `client_id`
- `event_code`
- `content` (템플릿 기반)
- `relation_item_type`, `relation_item_id` (역추적 링크)
- `occurred_at` (원천 이벤트 발생 시각)

> 중복 기록 방지(멱등성): 원천 도메인 핸들러가 재시도될 수 있으므로 `(center_id, event_code, relation_item_type, relation_item_id)` 기준으로 중복 생성을 방지하는 로직/제약을 권장합니다.

---

### 2. 댓글 작성 시 멘션 파싱

댓글/답글 생성 시:
1. `content`에서 `<mention id="UUID">...</mention>` 패턴을 파싱
2. `careboard_comment_mentions`에 `(comment_id, target_user_id)` 저장

이 구조로 다음 쿼리가 단순해집니다:
- “나를 언급한 댓글” 알림 목록
- 특정 사용자가 언급된 댓글 필터링

## 비즈니스 규칙

### 1. 게시물 생성/변경 정책

- Careboard 게시물은 **시스템만 생성** (Phase 1)
- 게시물은 **수정 불가(append-only)**  
  - 삭제는 원칙적으로 사용하지 않으며, 필요 시 “추가 이벤트”로 표현(예: 취소는 `ASMT_CANCEL` 이벤트로 추가)

### 2. 타임라인 정렬 기준

- 화면 정렬은 `occurred_at DESC, id DESC` (권장)
- 감사/동기화 확인은 `created_at`로 별도 필터링/점검 가능

### 3. 댓글/답글 구조 제약

- `comment_id IS NULL` → 댓글
- `comment_id IS NOT NULL` → 답글
- 답글의 `comment_id`는 반드시 “댓글(= comment_id가 NULL인 row)”을 가리켜야 함 (앱 레벨 검증)
- 2-depth 초과는 허용하지 않음 (Phase 1)

### 4. 삭제 정책

- 댓글/답글 삭제는 `is_deleted=true`로만 처리
- `content`는 유지(감사/추적 목적)

### 5. 권한/노출 규칙

- **Client 접근 권한이 있으면 Careboard도 동일하게 허용** (Phase 1)
- 별도 게시물 단위 ACL은 두지 않음

## API 설계

> 목표: “내담자 찾기(이름/코드) → 타임라인 보기”를 최소 왕복으로 제공

### 엔드포인트 목록

| Method | Path | 설명 |
|--------|------|------|
| GET | `/centers/{center_id}/careboard` | 내담자 검색 + 타임라인 조회(통합) |
| GET | `/centers/{center_id}/clients/{client_id}/careboards` | 내담자 타임라인(게시물) 목록 |
| GET | `/centers/{center_id}/careboards/{careboard_id}` | 게시물 상세 + 댓글/답글 조회 |
| POST | `/centers/{center_id}/careboards/{careboard_id}/comments` | 댓글 작성 |
| POST | `/centers/{center_id}/careboards/{careboard_id}/comments/{comment_id}/replies` | 답글 작성 |
| PATCH | `/centers/{center_id}/careboards/{careboard_id}/comments/{comment_id}` | 댓글 삭제(소프트 삭제) |
| GET | `/centers/{center_id}/careboard/my-mentions` | 나를 언급한 댓글 목록(옵션) |

---

### 1) 내담자 검색 + 타임라인 조회(통합)

`GET /centers/{center_id}/careboard`

**Query Params**:
- `q`: string (내담자 이름/코드 검색어)
- `client_id`: UUID (직접 지정 시 `q` 무시)
- `cursor`: string (페이지네이션 커서)
- `limit`: int (기본 30)

**Response(권장)**:
- `client`: ClientSummary (선택된 1명; `q`가 여러 명 매칭되면 `clients[]`만 반환 가능)
- `clients`: ClientSearchResult[] (검색 결과)
- `items`: CareboardItem[] (선택된 client의 타임라인)

> 정책 예시: `client_id`가 있으면 해당 client 타임라인을 반환, 없고 `q`가 있으면 “가장 우선 매칭 1명 + clients 후보 목록 + 타임라인”을 함께 반환.

---

### 2) 내담자 타임라인(게시물) 목록

`GET /centers/{center_id}/clients/{client_id}/careboards`

**Query Params**:
- `from`, `to`: datetime (옵션)
- `cursor`, `limit`: 페이지네이션

**Response Item(권장)**:
- `id`, `event_code`, `content`, `occurred_at`, `created_at`
- `relation_item_type`, `relation_item_id`
- `comment_count` (옵션)

---

### 3) 게시물 상세 + 댓글/답글

`GET /centers/{center_id}/careboards/{careboard_id}`

**Response(권장)**:
- `board`: CareboardItem
- `comments`: CommentThread[] (2-depth)
  - `comment`
  - `replies[]`

---

### 4) 댓글/답글 작성

**댓글**: `POST /centers/{center_id}/careboards/{careboard_id}/comments`  
**답글**: `POST /centers/{center_id}/careboards/{careboard_id}/comments/{comment_id}/replies`

Request:
- `content`: TEXT (멘션 태그 가능)

처리:
- 작성자 `user_id`는 인증 컨텍스트에서 결정
- 멘션 파싱 후 `careboard_comment_mentions` 저장

## 구현 우선순위

### Phase 1: 핵심 타임라인 + 협업 댓글

1. Careboard/CareboardComment/CareboardCommentMention 스키마
2. 시스템 이벤트 기록 생성 API/Service(원천 도메인에서 호출)
3. 내담자 검색 + 타임라인 조회(통합) API
4. 게시물 상세 + 댓글/답글 조회
5. 댓글/답글 작성 + 멘션 파싱/저장

### Phase 2: 운영 메모(수동 게시물) 및 고급 기능

1. 수동 게시물 작성(작성자/권한/감사 정책 포함)
2. 게시물/댓글 알림(멘션, 구독)
3. 고급 검색(키워드/기간/이벤트 필터)
