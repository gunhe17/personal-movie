# Counseling 도메인 피드백

## 케이스 및 회기 관련 요구사항

먼저 case는 상담 유형과 1:1로 매핑된다(놀이치료, 미술치료, 일반상담 등)

그리고 회기는 횟수를 지정할 수 있지만 꼭 필수적으로 몇회까지 해야한다는 아니다.
왜냐하면 보통 아이가 나아질때까지 (혹은 성인도 상담을 진행하는경우 이상 없는경우 중단) 하는 경우가 많기 때문이다.

그리고 아동 관점에서 여러 케이스(놀이치료, 미술치료)를 진행할 수 있으며 각 케이스의 회기를 관리하면 된다.

여기서 추가로 짝 치료 같은 경우는 상담사와 내담자가 한 쌍이라고 하면 2쌍, 3쌍 이상이 될 수도 있다.
여기서 케이스를 어떻게 구성하는게 좋을까? 짝 치료이긴 하지만 각 상담사는 자신의 내담자만 관리하기 때문에 케이스를 쌍 별로 생성하면 될지 아니면 하나로 관리해야할지 잘 모르겠다.

그리고 보통은 개별(e.g. 놀이치료) 치료를 진행하다가 짝 치료(사회화)가 필요한 경우 별도의 케이스를 둬서 하는게 맞을것같은데 이는 어떻게 생각하는가?

마지막으로 그룹 치료 같은 경우는 메인상담사, 보조상담사(필요에 의하면)와 다수의 내담자를 한 케이스로 보는게 맞을지 아니면 내담자별로 각 케이스를 둬서 관리하는게 맞을지 모르겠다.
왜냐하면 화면에서 보는것처럼 개별 치료에 대한 회기 관리로 되어 있기 때문이다.

깊게 생각해보고 사용하는 사람 입장에서 최적의 효율성을 따져서 좋은 설계 방향을 제시해줬으면 좋겠다.

## 확정된 설계 방향

### 권한 모델
1. **기본 정보 조회**: 같은 센터 상담사는 모든 케이스의 기본 정보(제목, 내담자명, 담당 상담사, 상태) 조회 가능
2. **상세 정보 조회**: 본인이 참여한 케이스만 상세 정보(상담 기록, 일지, 진행 현황) 조회 가능
3. **전체 조회**: 센터장/관리자는 모든 케이스의 상세 정보 조회 가능

### 편성 권한
1. **짝 치료 편성**:
   - 관련 상담사들이 협의 후 직접 편성 가능
   - 센터장도 편성 가능
   - 권한 검증: 요청자가 해당 케이스들의 참여자인가?

2. **그룹 편성**:
   - 센터장 또는 프로그램 담당자가 편성
   - 일반 상담사는 편성 권한 없음

### 케이스 구조
- **1 Case = 1 Counselor + 1 Client + 1 Billing Unit**
- 짝 치료/그룹 상담에서도 각 상담사-내담자 조합은 개별 케이스로 관리
- `PairedCaseGroup` / `GroupCaseCluster`: 케이스들을 연결하는 메타데이터
- 청구, 기록 작성, 권한은 모두 개별 케이스 기준

### API 설계
1. `GET /centers/{center_id}/counseling-cases?level=basic` - 센터 전체 케이스 기본 정보 조회
2. `GET /members/{member_id}/counseling-cases` - 본인 케이스 상세 정보 조회
3. `POST /paired-case-groups` - 짝 치료 그룹 생성 (상담사들 협의 후)
4. `POST /group-case-clusters` - 그룹 편성 (센터장/관리자만)

상세한 내용은 `domain_v2.md` 파일의 "짝 치료 및 그룹 상담 설계" 섹션 참고.
