# AI 상담 경과 분석

> 케이스 단위로 회기 일지를 묶어 읽고, 근거 회기가 달린 리포트를 만드는 기능.
> 작성일: 2026-09-03 · 상태: production 반영 (실 케이스 실행 검증 미완)

---

## 0. 한 줄

**분석 단위는 케이스다.** 개인이든 그룹이든 한 케이스의 완료 회기 일지를 한 번에 읽어,
무엇이 달라졌고 어떤 개입 기법이 통했는지를 **근거 회기와 함께** 정리한다.

---

## 1. 자리 — 우측 도크

케이스 상세(`/counseling/status/[id]`)의 **우측 도크**다. 케어보드(내담자 상세)와 같은
표면 규격을 쓰고 폭만 다르다.

| 항목 | 값 | 근거 |
|---|---|---|
| 닫힘 | 우하단 떠 있는 진입 버튼 (인셋 56/56) | §Spacing FAB |
| 열림 | 우측 고정 도크 **800** | 플로우시트 min 760 · 개입 표 min 720이 400에선 둘 다 가로 스크롤 |
| 본문 밀림 | `pr-[760px]` (= 800 − 40) | §Spacing 열린 도크 40 |
| 밀림 조건 | 뷰포트 **≥ 1600**에서만 | 그 아래에서 밀면 남는 본문이 400 아래로 눌려 회기 카드가 깨진다 |
| 기본 상태 | **항상 접힘** | 이 화면의 주 콘텐츠는 좌측 상담 정보 + 우측 회기다 |
| 닫기 | 가장자리 토글 · **본문 클릭** | 판정은 "도크 밖"이 아니라 **"페이지 루트 안"** — 모달·사이드패널은 포탈이라 자동 제외 |

### 왜 탭이 아닌가

리포트의 값은 **근거 회기로 되짚을 수 있다**는 데 있다. 탭이었을 땐 근거를 누르는
순간 탭이 회기 목록으로 넘어가 리포트가 사라졌다. 도크면 리포트는 열린 채 왼쪽 본문만
그 회기로 바뀌어, 리포트와 원본 일지를 나란히 놓고 대조할 수 있다.

> 계보: 좌측 `ProgramInfoPanel` 안 → 페이지 헤더 세그먼트(폐기) → 우측 컨테이너 탭(폐기) → 도크.

### 헤더의 `상담 정보` 버튼

**화면이 좁을 때만** 뜬다. 도크 때문에 좌측 패널이 접힌 경우까지 띄우면 같은 정보로
가는 문이 둘이 된다 — 왼쪽에 붙어 있던 패널이 도크를 열자 헤더 버튼을 눌러야 나오는
오버레이로 형태를 바꿔 다시 나타난다. 도크를 닫으면 패널이 제자리로 돌아오는 게 그 문이다.

## 2. 리포트 구성 — 요지 → 분석 → 근거 → 계획

상담·의료 기록의 관례(SOAP의 S/O → A → P)를 따른다.

```
[배너]     상담 · 내담자 · 주호소        │  정서 흐름 · 진행 · 참석률
[스트립]   AI 요약 · 지켜볼 점 · 강점        지금 무슨 상황인가   (요지)
 1. 개입 기법과 반응                        뭐가 통했나        ┐ 전 회기를
 2. 주제 흐름                               뭐가 계속 나오나    ┘ 가로지른 분석
 3. 회기별 기록                             정말 그런가        (근거)
 4. 앞으로                                  그래서 다음에       (계획)
[읽은 기록] 무엇을 읽었나 · 언제 분석했나
```

- **`앞으로`는 맨 뒤다.** 한때 맨 앞이었는데 "요약을 먼저"와 "계획을 먼저"를 뒤섞은
  판단이었다. 결론 먼저의 몫은 상단 AI 요약이 이미 지고, **계획은 근거를 읽고 난 뒤라야
  평가할 수 있다.** 읽고 나서 들고 나가는 것도 '다음에 뭘 할까'라 마지막이 맞다.
- **지켜볼 점과 강점은 나란히.** 같은 질문의 반대 부호다. 위험이 맨 위 · 강점이 맨 아래면
  걱정거리의 무게를 재줄 정보를 보려고 끝까지 스크롤해야 하고, 판단이 한쪽으로 기운다.
- **레일 ↔ 스트립.** 판단 블록은 컨테이너 폭 `@[1080px]` 이상이면 우측 레일, 아니면
  배너 아래 가로 스트립으로 눕는다. **숨기지 않는다** — 화면이 좁다는 이유로 요지와
  위험이 사라지면 안 된다. 도크 800에서는 늘 스트립이다.

### 한 값은 한 자리에서만

같은 사실이 두 군데 그려지던 곳을 전부 한쪽으로 몰았다.

| 값 | 옛 중복 | 남긴 자리 |
|---|---|---|
| 현재 상태 | 배너 `현재` + AI 요약 | **AI 요약** (프롬프트상 headline 뒷절이 곧 current_state) |
| 지켜볼 점 건수 | 배너 지표 + 목록 | **목록** (보이는 걸 세지 않는다) |
| 국면 | 표 위 스트립 + 표 안 밴드 행 | **밴드 행** (시간축을 두 번 안 그린다) |
| 회기 수·참석률 | 지표 값 + 그 밑 설명문 | **값** (없을 때만 이유를 댄다) |
| 섹션 부제 | 제목 밑 부제 + 자식 라벨 | **자식 라벨** |
| 상담 코드 | 도크 헤더 + 배너 | **배너** |
| 기간 | 배너 이름 줄 | **읽은 기록** (신원이 아니라 "무엇을 읽었나") |

**프롬프트도 중복을 만든다.** 화면이 표·지표로 그리는 값(회기 수·진행률·참석률·`sessions`·
`count`·날짜/출결)을 문장에 다시 쓰지 않도록 프롬프트에 금지 표를 뒀다.

## 3. 🔴 데이터 출처 — 손 작성 일지는 3필드뿐

| 일지 출처 | 있는 필드 |
|---|---|
| **직접 작성** | `main_topic` · `progress` · `next_goal` (+ 분석 제외 `private_notes`) |
| **녹음 기반** | 위 + `mood` · `intervention` · `homework` · 서식별 필드 |

정서·개입 기법·과제는 **입력 수단 자체가 없다** — 녹음(필드노트)→AI 일지 경로에서만 생긴다.
그래서:

- 리포트는 조건부 렌더링이 필수다(빈 칸이 늘어선 표 = 분석 부실로 읽힌다).
- `_merge_server_facts`가 손 작성 회기의 `mood`·`intervention`·`homework`를 **서버에서
  `None`으로 덮는다.** LLM이 "비어 있음"을 "기록 안 함"으로 해석해 지어내는 걸 막는다.
- 프롬프트가 일지 출처를 블록마다 알린다.

## 4. 서버 파이프라인

`app/runtime/case_analysis/executor.py` — reaction이 batch 큐로 던지고 executor가
로드 → 프롬프트 조립 → LLM → `mark_completed/failed`.

### 예산

| 상수 | 값 | 뜻 |
|---|---|---|
| `TOTAL_INPUT_CHARS` | 36,000 | 회기 수로 나눠 배분 |
| `MIN/MAX_PER_SESSION_CHARS` | 600 / 4,000 | 회기당 하한·상한 |
| `BASE_OUTPUT_TOKENS` | 2,000 (+회기당 250, 최대 8,000) | `generate_json(max_tokens=…)` |

- 🔴 **`generate_json`에 `max_tokens`를 안 주면 `SUMMARY_MAX_TOKENS=2048`이 먹는다.**
  큰 JSON을 뱉는 기능은 반드시 명시해야 한다(안 그러면 출력이 잘려 `json.loads` 실패 → 크레딧만 나감).
- 🔴 **입력은 회기별로 자른다.** 옛 `prompt_text[:12000]`은 회기 블록이 오래된 순이라
  **최신 회기가 잘려나갔다.** 지금은 회기별 예산 + 필드별 균등 절단이고, 잘린 사실을
  `coverage.truncated_notes`로 화면에 고지한다.
- ⚠️ **그룹은 회기당 읽는 양이 1/N이다.** 예산을 회기 수로만 나누므로 5명 그룹의 12회기면
  회기당 3,000자를 5명이 나눠 쓴다. 고지는 되지만 비용 정책 결정이 필요한 미해결 항목.

### 진행 표시

**서버에는 단계가 없다.** DB 조회 6번 + 프롬프트 조립 + 저장은 전부 합쳐 1초 안쪽이고,
나머지 95%가 `generate_json` 호출 하나다. 화면은 실제 구조대로 **2단계**(모으기 → AI가
읽는 중)만 두고, 단계로 낼 수 없는 진행감은 **경과 시간**이 진다.

- 경과 시간은 **이 화면에서 실행을 눌렀을 때만** 표시한다. `created_at`으로 역산하면
  서버가 timezone 없는 UTC를 내려주는 탓에 KST에서 9시간이 어긋난다.
- 진짜 진척률은 LLM 스트리밍으로만 가능하다 — `generate_json`은 지금 `client.quick()`으로
  한 번에 받으므로 게이트웨이 계약 변경이 필요하다(별도 과제).

### 상태·복구

- `/latest`는 `processing`·`failed`도 반환한다(진행 표시용). 예전엔 `completed`만 내려와
  "눌러도 아무 일 없는" 화면이 됐다.
- 워커가 죽어 남은 `processing`은 **15분 뒤 직전 완료본으로 폴백**한다.
- 화면은 5초 폴링(상한 60회 = 5분).

## 5. 그룹 케이스

**집단 단위로만 분석한다.** 성원별 개인 리포트가 아니다.

### 판정

**실제 명단 인원수**(`len(client_ids) > 1`)로 가른다. 프로그램 유형(GROUP/INDIVIDUAL)은
보조 신호일 뿐이다 — 그룹 프로그램에 한 명만 남은 케이스는 개인처럼 다뤄야 한다.

> 화면의 라벨은 `coverage.is_group`(분석이 실제로 쓴 값)을 따르고, 케이스 표시명의
> `- 그룹`만 케이스 유형을 따른다(breadcrumb·좌측 패널과 같은 표기). **둘은 갈릴 수 있고,
> 갈리는 게 사실이다.**

### 🔴 두 개의 함정

**① 녹음 일지는 성원 전원에게 복사된다** (`field_note/counseling_note/service.py`).
5명이면 글자까지 똑같은 일지가 5벌 저장돼 있다. 그대로 프롬프트에 실으면 입력 예산을
5배로 먹고 LLM이 "다섯 명이 다 그랬다"는 강한 신호로 오독한다.
→ `_group_notes_by_content`가 내용이 같은 일지를 접어 **`[전원 공통]`으로 한 번만** 싣는다.

**② 참석률의 분모가 다르다.** `_reduce_attendance`가 "한 명이라도 오면 참석"으로 접기
때문에, 그룹에 회기 단위를 쓰면 5명 중 1명만 와도 100%가 된다.
→ 개인은 **회기 단위**, 그룹은 **성원 단위(회기 × 인원)**. 회기표의 출결 칸도 그룹에서는
상태가 아니라 **참석 인원(`3/5`)** 을 보여준다(전원이 아니면 빨강).

### 프롬프트 규칙

- `mood_trend`는 **집단 전반의 분위기**. 내담자마다 갈리면 **`mixed`**(↕ 갈림)를 쓴다 —
  `flat`(유지)에 담지 않는다. 상담사는 `→ 유지`를 "안 변했다"로 읽지 "사람마다 다르다"로
  읽지 않는다.
- **`[전원 공통]` 일지는 개인차의 근거가 될 수 없다.** 개인별 차이는 이름 붙은 일지와
  출결에서만 읽는다.
- `risks`·`strengths`는 **내담자 이름으로 시작**하고, 근거가 `[전원 공통]`뿐이면 항목을 만들지 않는다.
- `interventions`·`themes`·`direction`은 원래 집단 단위라 그대로 쓴다.

### 시크릿 모드

프롬프트가 `risks`·`strengths`에 이름을 넣게 하므로, **AI가 쓴 문장 안의 이름**을
VM 한 곳(`maskNamesDeep`)에서 가린다. 컴포넌트마다 걸면 반드시 빠뜨리는 곳이 생긴다
(이름은 요약·주제 메모·개입 반응 어디에든 들어간다).

### 미해결

- **성원별 개인 리포트** — 위 함정 ①(복사) 때문에 화자분리 + 화자↔사람 매핑이 선행돼야
  한다. 현재 `speaker_roles.py`는 "내담자 1·2·3"까지만 내고 신원은 사람이
  `update_speaker_map`으로 지정한다. 손 작성 일지는 이미 사람별이라 매핑 없이도 가능하지만
  3필드 한계 + 저장에 `client_id` 추가가 필요하다.
- **성원별 주호소** — `counseling_cases.chief_complaint` 하나뿐이라 담을 자리가 없다.

## 6. 어휘 규약

**현장 전문어는 쓰고, 번역투 조어는 쓰지 않는다.**

| | |
|---|---|
| 쓴다 | 개입 기법 · 정서 · 호전/유지/악화 · 강점 · 주제 · 주호소 · 회기 · 과제 · 슈퍼비전 · 라포 |
| 안 쓴다 | 치료적 동맹 · 정서 추세 · 치료적 관계 · 개입의 효과성 · **내적 자원** |

한때 전자까지 풀어 썼다(개입→'써본 방법', 호전→'나아짐', 강점→'잘 되고 있는 것').
과교정이었다 — 전문가용 도구가 전문어를 풀면 정확도를 잃는다('방법'은 개입보다 넓고 흐릿하다).

**이 리포트가 정하지 않는 어휘가 둘 있다 — 앱 정본을 따른다.**

- **출결** = `참석 / 취소 / 노쇼` (회기 상세 출결 토글·확인 모달·스낵바)
- **일지 필드 라벨** = `AiDraftHistory`의 `FIELD_LABELS` —
  `mood=정서 상태` · `main_topic=주요 주제` · **`intervention=개입 기법`** · `homework=과제`
  → 표 헤더·섹션 제목처럼 **필드를 이름 부르는 자리**는 전체 이름을, 문장 속에서는 줄여 쓴다.

또 하나: **`해소`가 아니라 `사라짐`.** 일지에서 안 나온다는 사실만 말한다 — 회피해서 안
꺼내는 것과 풀려서 안 나오는 것이 기록상 똑같이 보이는데, `해소`라고 쓰면 둘 중 하나로 단정한다.

## 7. 함정 모음 (재작업 시 먼저 볼 것)

- `generate_json`에 `max_tokens` 미지정 → 2048에서 잘림
- 입력 절단이 **오래된 순**이면 최신 회기가 날아감
- 그룹 녹음 일지는 복사본 → 접지 않으면 예산 5배 + 거짓 신호
- 그룹 참석률에 회기 단위 → 1명만 와도 100%
- `created_at`은 tz 없는 UTC → JS `new Date()`가 로컬로 읽어 9시간 어긋남
- 모달 폭은 `BaseModal.size`가 아니라 **`modalStore` 호출부의 `options.size`** 가 정한다
- `BaseModal.bodyClass` 기본값은 빈 문자열 → 모달이 `p-5 pb-7`을 직접 넘겨야 한다
- 웹 `PURPOSE_ESTIMATED_CREDITS`는 **표시 전용**이고 게이트는 API `estimated_credits`를 쓴다
  → 서버 값을 바꾸면 웹 상수도 같이 고쳐야 숫자가 맞다(실제로 11→14 드리프트가 있었다)
- 랩(`/lab/case-analysis-report`)은 **프로덕션 컴포넌트를 import**한다. 복제하면 갈라진다
