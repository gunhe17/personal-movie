## 1. 배경과 목적

### 1.1 시장 상황

한국 심리상담 시장의 수요는 정부 주도 바우처 사업으로 빠르게 확장되고 있다.

- **전국민 마음투자 지원사업** (2024~): 보건복지부, 전 국민 대상, 연 8회 상담 지원
- **청년마음건강지원사업**: 만 19~34세, 10회 상담 지원
- **아동·청소년 심리지원**: 지역별 상이, 회기 한도 있음
- **근로자지원프로그램(EAP)**: 기업·공공기관 계약
- **지자체 자체 바우처**: 시·도·구 단위 별도 사업 다수

바우처는 단순 할인이 아니라 **정부/기관 지원금 + 본인부담금의 이중 결제 구조**를 가지며, 제공기관 등록·상담사 자격·일지 양식·청구 절차 등 **일반 결제와 완전히 다른 운영 규칙**을 따른다.

### 1.2 현재의 문제

상담센터 현장에서 바우처 관리는 **수기·엑셀·사람의 기억**에 의존한다.

- **잔여 회기 파악 실패** → 이미 소진된 바우처로 상담 진행 → 센터 손실
- **중복 사용 감지 불가** → 같은 세션에 두 번 차감되거나, 서로 다른 상담사가 동시에 차감
- **청구 누락** → 월말 마감 시 기록 유실 → 수익 누락
- **바우처 양식 재작성의 반복 노동** → 상담사가 센터 내부 일지를 바우처 제출용 양식으로 매번 수기 재작성
- **자격 판별의 속인성** → 접수 담당자의 경험에 의존, 신규 직원은 놓치기 쉬움
- **감사 대응의 어려움** → 5년치 증빙 서류 분산 보관

### 1.3 도입의 기대 효과

| 가치 영역 | 기대 효과 |
|---|---|
| **센터 수익 보호** | 회기 차감·청구 누락 방지, 본인부담금 수금 정확성 |
| **상담사 업무 경감** | 바우처 양식 자동 변환으로 일지 재작성 시간 대폭 감소 |
| **접수 품질 향상** | 내담자 상담 시작 전 적합 바우처 자동 추천 |
| **감사·보고 대응력** | 증빙 자료 통합 관리, 월별 청구 자동 집계 |
| **스케일 확보** | 바우처 사업별 수동 관리 노동 감소 → 센터 규모 확장 가능 |

### 1.4 한 줄 요약

> 바우처의 **중앙화(P1 수동 관리)** → **자동화(P2 AI·판별)** → **정산(P3 사용 측정·청구)** 순으로 단계적으로 제공해, 상담센터가 바우처를 "관리할 수 있는 대상"으로 다루게 한다.

## 2. 도메인 이해

### 2.1 바우처의 본질

**바우처는 결제 수단이면서, 회기 한도 관리 대상이면서, 증빙 제출 의무 대상이다.** 이 세 얼굴이 동시에 존재한다는 점이 일반 결제와 다르다.

| 측면 | 설명 |
|---|---|
| **결제** | 지원금(정부·기관)과 본인부담금(내담자)의 분리 결제 |
| **한도** | 유효기간·회기 수·주기(월별·주별) 제한 |
| **증빙** | 상담일지·동의서·시간 기록 등 감사 대응 서류 |

### 2.2 이해관계자

```
[정부·사업주체] ── 바우처 발행, 자격 판정, 정산 ──→ [제공기관(센터)]
      │                                                    │
      │ 자격 확인, 본인부담금 결제                         │ 상담 제공, 청구
      ↓                                                    ↓
  [내담자] ←────── 상담·검사 서비스 ────────────── [상담사]
```

### 2.3 초기 타겟: 전국민 마음투자 지원사업

**선정 이유**
- 2024년 시작된 최신 사업으로 수요가 급증 중
- 전 연령 대상으로 센터별 적용 범위가 넓음
- 단가·회기·서식이 비교적 명료하게 표준화되어 있음
- 1종을 제대로 구현하면 타 바우처로 구조 확장 가능

**개요**
- 대상: 정신건강 위험군으로 판정된 전 국민
- 회기: 기본 8회, 연 1회 갱신 가능
- 본인부담률: 소득분위별 차등 (0~30%)
- 필수 절차: 자가진단(PHQ-9, GAD-7 등) → 공공 판정 → 제공기관 매칭 → 상담 제공 → 청구

## 3. 사용자 페르소나

| 페르소나 | 주요 관심사 | 바우처 기능에서 얻는 것 |
|---|---|---|
| **센터 관리자** | 센터 수익, 바우처 사업 참여 결정 | 우리 센터가 취급할 바우처 결정·관리, 월별 사용·청구 현황 |
| **접수 담당자** | 신규 내담자 온보딩 속도·정확성 | (P1) 내담자별 바우처 수동 등록·관리, (P2) 적용 가능 바우처 자동 추천 |
| **상담사** | 상담 품질, 일지 작성 부담 | 내담자 보유 바우처·잔여 회기 조회, 센터 일지 → 바우처 양식 자동 변환 |
| **회계·정산 담당** | 청구 누락 방지, 정산 정확성 | 월별 사용 회기·청구 대상 자동 집계, 증빙 통합 |
| **super_admin(플랫폼 운영자)** | 바우처 카탈로그의 정확성·최신성 | 신규 사업 공고 반영, 센터 전체 배포 |
| **(미래) 내담자** | 남은 회기, 만료일 가시성 | 별도 앱에서 자신의 바우처 상태 확인 |

> 본 기획 범위에서 **내담자는 직접 사용자가 아니다.** 내담자 접근은 별도 앱 프로젝트로 분리되며, 이 기획에서는 **센터 측 기록이 훗날 내담자 앱에서 재사용될 수 있도록** 데이터 경계만 깨끗하게 유지한다.

## 4. 범위 (Scope)

### 4.1 포함

**P1 (중앙화·수동 관리)**
- **바우처 카탈로그 관리** (super_admin이 신규 사업 등록·수정)
- **센터의 취급 바우처 결정** (센터 관리자가 카탈로그에서 선택)
- **내담자에게 바우처 수동 발급·등록·조회** (담당자 판단으로 등록, 잔여 회기·만료일 확인)

**P2 (AI·자동화)**
- **상담일지의 바우처 양식 자동 변환** (AI 활용)
- **내담자별 바우처 자격 판별·추천** (접수·상담사 지원)

**P3 (정산·감사)**
- **실제 상담·검사 진행 시 회기 차감·중복 방지**
- **월별 사용 현황·청구 대상 집계** (회계용)

### 4.2 제외 (Out of Scope)

- **공공 API·크롤링 자동 수집** (단일 공공 API 없음 → 운영자 큐레이션)
- **국민행복카드 PG 연동 실시간 결제** (초기엔 수기 기록, 추후 별도)
- **복지로·사회서비스전자바우처 EDI 자동 청구** (초기엔 수동 청구서 작성 지원만)
- **내담자 전용 앱·로그인** (별도 프로젝트로 분리)
- **타 기관·타 플랫폼 중복 수급 감지** (플랫폼 외부 데이터 접근 불가)
- **부정 수급 이상 탐지** (장기 과제)

### 4.3 바우처 미사용 센터와의 공존 (Opt-in 원칙)

모든 센터가 바우처 사업에 참여하지 않는다. 바우처 기능은 **센터별 opt-in**으로 동작한다.

- 센터 설정에서 "바우처 기능 사용"을 켜야 관련 UI·메뉴·위젯이 노출된다.
- 기본 상태는 **꺼짐**. 기존 워크플로를 쓰던 센터가 갑자기 새로운 UI로 혼란을 겪지 않도록 한다.
- 구독 플랜(subscription 모듈)과의 연동 여부는 별도 결정 (Open Question).

### 4.4 플랫폼 간 역할 매트릭스

본 기능은 **3개 플랫폼**에 걸쳐 동작할 수 있다. 각 플랫폼에서 **무엇을 할 수 있고 없는지**를 먼저 합의해야, 설계·권한·동기화 설계가 명확해진다.

| 기능 | SaaS 웹 (센터 스태프) | 전문가 앱 (상담사 모바일) | 내담자 앱 (미래) |
|---|---|---|---|
| 카탈로그 조회 | ✅ 전체 | ✅ 내 내담자 관련만 | ❌ |
| 센터 취급 바우처 설정 | ✅ 관리자 | ❌ | ❌ |
| 내담자 바우처 등록 (P1 수동) | ✅ 접수 담당자 | △ 간이 등록 (현장용) | ❌ |
| 잔여 회기 조회 | ✅ | ✅ (내 담당) | ✅ (본인 것만) |
| 회기 수동 차감 (P1) | ✅ | ✅ | ❌ |
| AI 일지 변환 (P2A) | ✅ 전체 | ✅ 트리거·결과 검토 | ❌ |
| 자격 판별 결과 조회 (P2B) | ✅ | ✅ (간이 뷰) | ✅ (본인 적용 가능 바우처) |
| 자동 차감·청구 (P3) | ✅ | ✅ 세션 완료 시 | ❌ |
| 동의서 전자 서명 | △ 종이 스캔 업로드 | △ 태블릿 서명 | ✅ 직접 서명 |
| 증빙 업로드 (고지서 등) | ✅ 담당자 대리 업로드 | ✅ | ✅ 본인 업로드 |
| 자가진단 입력 (P2B 입력값) | ✅ 담당자 대리 입력 | ✅ | ✅ 직접 입력 |
| 만료 임박 알림 수신 | ✅ 인앱 배너·이메일 | ✅ 푸시 | ✅ 푸시 |

> 💡 **중요**: 내담자 앱이 도입되면, **전자 서명·증빙 업로드·자가진단 직접 입력**이 내담자 쪽에서 발생하게 되어 센터의 "수동 입력" 부담이 대폭 감소한다. 따라서 P1 데이터 모델은 **"어느 주체가 입력했는가(staff_entered / client_submitted)"** 를 구분할 수 있게 설계해 둘 필요가 있다.

### 4.5 기존 모듈과의 연동점 (Interface Map)

바우처 기능이 건드리게 되는 기존 모듈·연동 시점·Phase 속성.

| 기존 모듈 | 연동 내용 | 발생 Phase |
|---|---|---|
| `client` | 내담자 FK, 바우처 소유자 | P1 |
| `counseling` | 상담 세션 완료 시 회기 차감 | P3 (P1에서는 수동) |
| `assessment` | 검사 케이스 완료 시 회기 차감 (상세 정책은 7.6) | P3 |
| `billing/payment` | 지원금·본인부담금 분리 결제 레코드 | P3 |
| `billing/billable` | 월별 청구서 생성 | P3 |
| `subscription` | 바우처 기능 유료 플랜 gating 여부 | P1 설계 시 결정 |
| `schedule` | 예약 취소·no-show 정책 → 회기 처리 연결 | P3 |
| `field_note` | 녹음·요약을 AI 일지 변환 입력으로 활용 | P2A |
| `auth` | 상담사 자격증 만료 추적 (향후 role 확장) | P2 이후 |

> 이 맵은 **설계 단계에서 각 모듈의 Facade를 어떻게 호출할지 결정하는 기준**이 된다. 바우처 모듈은 다른 모듈의 Repository·Model에 직접 접근하지 않고 Facade만 호출한다 (CLAUDE.md 아키텍처 원칙).

## 5. Phase별 로드맵

> **Phase 분리 원칙**: 리스크가 낮은 순서로 가치 제공. 각 Phase는 이전 Phase 데이터 위에 쌓이며, 독립적으로 사용자에게 가치를 준다.

**테마 요약**

| Phase | 테마 | 한 줄 약속 |
|---|---|---|
| **P1** | 중앙화·수동 관리 (엑셀 탈출) | "바우처가 시스템 안에서 관리된다" |
| **P2** | AI·자동화 (업무 경감) | "담당자가 직접 판별·재작성하지 않아도 된다" |
| **P3** | 정산·감사 (돈 영역) | "모든 사용이 정확히 기록·청구·감사 대응된다" |

### Phase 1 — 조회와 수동 등록 (MVP)

> **"센터가 취급하는 바우처와 내담자가 보유한 바우처를, 엑셀 대신 플랫폼 안에서 관리한다."**

**범위를 좁힌 이유**
자격 판별·추천은 민감정보(소득분위·자가진단 점수) 수집 체계와 동의서 개정이 선결되어야 하며, 판별 룰 구조화도 은근히 복잡하다. P1에서는 이를 배제하고 **"중앙화된 기록·관리"** 만 제공해도 현장의 엑셀·수기 부담은 이미 크게 줄어든다.

**핵심 사용자 가치**
- super_admin: 신규 바우처 사업을 플랫폼 전체에 일괄 배포
- 센터 관리자: 우리 센터가 취급하는 바우처 목록을 명시적으로 관리 (담당자 교체 시 인수인계 용이)
- 접수 담당자: 내담자에게 발급된 바우처를 플랫폼에 **수동 등록**하고, 언제든 조회
- 상담사: 내담자 상세 페이지에서 보유 바우처·잔여 회기·만료일 확인

**주요 시나리오**
1. super_admin이 전국민 마음투자 카탈로그를 플랫폼에 등록 (단가·회기·양식 스펙 포함)
2. 센터 관리자가 카탈로그에서 해당 바우처를 선택 → "우리 센터 취급" 등록 (제공기관 번호 입력)
3. 접수 담당자가 내담자의 바우처 수급 상태를 **외부 경로(국민행복카드 앱·복지로·지자체 확인서 등)로 확인**한 뒤, 플랫폼에서 카탈로그 선택 + **초기 잔여 회기·만료일 수동 입력**하여 등록
4. 상담사가 내담자 상세에서 보유 바우처·잔여 회기·만료일 확인
5. 센터 관리자가 "우리 센터 바우처 현황 대시보드"에서 발급된 바우처 목록·소진율 조회

**Phase 1의 중요 포인트**
- **자동 판별·추천은 이 Phase에 포함하지 않는다.** 담당자가 본인의 경험·외부 확인 결과를 근거로 등록한다.
- **잔여 회기·만료일은 플랫폼 내부 기록값**이다. 공공 시스템(복지로·사회서비스전자바우처)과 실시간 동기화되지 않으며, 담당자가 외부에서 확인한 값을 직접 입력·갱신한다.
- **회기 차감은 아직 자동화되지 않는다.** 상담사가 필요 시 수동으로 "회기 사용" 버튼을 누르거나, 잔여 회기를 수동 조정. (본격 자동 차감은 P3)
- 내담자 민감정보 수집은 **최소한**으로 제한 (바우처 종류·잔여 회기·만료일 정도).
- 데이터 구조는 P2 자격 판별·P3 자동 차감 확장을 염두에 두고 설계 (예: 바우처별 규칙 필드는 비워두되 스키마는 준비).

**Phase 1 성공 기준**
- 센터 관리자가 취급 바우처 목록을 5분 안에 설정 가능
- 내담자별 바우처 현황을 담당자 2명 이상이 동일하게 확인 (가시성 일관성)
- 엑셀·수기 관리 병행 비율 80% 이상 감소 (파일럿 센터 기준)
- 담당자 교체 시 인수인계 시간 대폭 감소

### Phase 2 — AI·자동화 (업무 경감)

> **"담당자의 머리 대신 시스템이 판단한다 — 일지 양식도, 적용 가능 바우처도."**

P1의 "수동 등록" 위에 **두 개의 자동화 기능**을 얹는다. 둘 다 "사람이 반복적으로 판단·재작성하던 것을 시스템이 대신한다"는 공통 테마를 가진다.

#### Phase 2A — AI 상담일지 양식 변환

**배경**
상담사는 센터 내부용 일지(자유 서술)와 바우처 제출용 양식(호소문제·중재·진전·다음 목표 등 필수 항목)을 매번 두 번 작성한다. 바우처 사업마다 요구 양식이 조금씩 다르다. 이 반복 노동이 상담사의 일지 품질 저하·업무 부담 호소의 주원인이다.

**핵심 사용자 가치**
- 상담사: 기존 일지 작성 워크플로 그대로 유지하면서, 바우처 양식이 자동 생성됨
- 센터 관리자: 일지 품질 표준화, 감사 대응력 향상

**주요 시나리오**
1. 상담사가 상담 종료 후 센터 일지 작성 (기존 양식 그대로)
2. 상담사가 "바우처 양식 생성" 버튼 클릭
3. 시스템이 일지 내용(+ 선택적으로 필드노트 요약)을 바탕으로 바우처별 필수 항목을 채운 초안 생성
4. 상담사가 초안 검토·수정·확정
5. 확정된 양식이 바우처 증빙 자료로 저장

**중요 포인트**
- AI는 **내용을 만들어내지 않고, 재구성·포맷팅한다**. 원본에 없는 정보를 지어내는 것은 금지 (hallucination 방지).
- 상담사의 **검토·수정이 필수 단계**. AI 결과를 자동 저장하지 않는다.
- 원본 센터 일지는 **그대로 보존**한다. 바우처 양식은 별도 저장되는 "파생 문서".
- **기밀성**: 외부 LLM으로 전송 시 개인정보 마스킹 또는 내부 모델 우선 검토.

#### Phase 2B — 자격 판별·추천

**배경**
P1에서는 접수 담당자가 내담자의 자격 적합성을 경험·외부 확인으로 판단했다. 이 단계에서는 시스템이 **"이 내담자에게 적용 가능한 바우처"** 를 자동 추천한다.

**핵심 사용자 가치**
- 접수 담당자: 신규 내담자 인테이크 시 적용 가능 바우처 즉시 안내
- 상담사: 기존 내담자의 새로운 자격 발생 시 알림 (예: 만 19세 도달 → 청년마음건강 적격)

**주요 시나리오**
1. 접수 담당자가 내담자 기본 정보 입력 (생년월일, 주소, 주호소 등)
2. 시스템이 인테이크 자가진단(PHQ-9 등) 결과·소득분위 자가신고를 동의 기반으로 수집
3. 시스템이 카탈로그의 자격 요건과 매칭 → ✅/⚠️/❌ 3단계 결과 + 판별 근거 표시
4. 담당자가 결과를 참고하여 내담자에게 안내·등록

**중요 포인트**
- **판별 결과는 "안내"이지 "확정"이 아니다.** 최종 승인은 복지로·지자체 소관. UI에 이를 명시.
- 3단계 결과: ✅ 적용 가능 / ⚠️ 추가 정보 필요 / ❌ 적용 불가 — 각각 이유를 투명하게 표시.
- 민감정보(소득분위·검사 점수 등)는 **별도 동의 기반**으로 수집, 접근 권한 최소화.
- 카탈로그 스키마에 **자격 요건 표현 방식**이 추가됨 (연령·소득분위·검사 점수 등). P1의 카탈로그가 이 확장을 감당할 수 있도록 설계.

**Phase 2 전체 성공 기준**
- (2A) 상담사 체감 일지 작성 시간 30% 이상 감소
- (2A) AI 초안 그대로 승인되는 비율 60% 이상 (수정 없이 통과)
- (2A) AI 생성 결과의 hallucination 발생률 5% 미만 (검증 샘플 기준)
- (2B) 자격 판별 정확도 95% 이상 (샘플 케이스 검증)
- (2B) 신규 내담자 접수~바우처 등록 소요 시간 추가 단축

### Phase 3 — 사용 측정과 정산

> **"바우처가 실제로 언제·누구에게·얼마나 쓰였는지 정확히 기록되고, 월말에 누락 없이 청구된다."**

**핵심 사용자 가치**
- 회계 담당: 월별 청구 대상 자동 집계, 증빙 누락 감지
- 센터 관리자: 수익 가시성, 바우처별 ROI 판단
- 상담사: 상담 진행 시 회기 자동 차감으로 수기 관리 불필요

**주요 시나리오**
1. 상담사가 상담 세션 완료 처리
2. 결제 방식이 바우처로 지정된 경우 → 시스템이 잔여 회기 차감 + 지원금·본인부담금 결제 레코드 생성
3. 중복 차감·잔액 초과는 자동 차단
4. 월말에 회계 담당이 "이번 달 바우처 사용 현황" 조회 → 청구 대상 목록·금액 확인
5. 청구서 작성 지원 (사회서비스전자바우처 양식 자동 채우기)
6. 청구 반려 시 재청구 관리

**Phase 3의 중요 포인트**
- **회기 차감 타이밍을 명확히 정책화**해야 한다. (상담 시작 시 vs 종료 시 vs 관리자 승인 시)
- **중도 취소·환불 시 잔액 복구**는 원자적으로 처리 (회기 복구 + 결제 취소가 함께)
- **감사 대응**: 5년치 증빙을 언제든 조회·출력 가능해야 함
- **수정 이력**: 누가·언제·왜 차감·취소했는지 전체 로그 보존

**Phase 3 성공 기준**
- 월별 청구 누락률 1% 미만
- 중복 차감·잔액 초과 사고 0건
- 청구서 작성 시간 80% 감소
- 감사 시 요청 증빙 100% 출력 가능

## 7. 정책·규칙 (Business Rules)

### 7.1 자격·적용 규칙
- 한 내담자가 **여러 바우처를 동시 보유**할 수 있다. 상담 시 어느 바우처를 차감할지 결정 규칙이 필요하다. (예: 만료 임박 우선 / 본인부담률 낮은 것 우선 / 수동 선택)
- **자격 판별 결과는 법적 효력 없음**. 최종 승인은 사업주체(복지로 등)가 한다. UI에 이를 명시한다.
- **민감정보(소득분위·검사 점수 등)는 별도 동의 기반**으로 수집·활용한다.

### 7.2 회기 관리 정책
- **차감 타이밍**: 상담 **종료 후 상담사 완료 처리** 시점 (초안) — 조기 차감 후 노쇼 시 복원 로직 복잡도 회피
- **No-show 처리**: 바우처별 정책 상이. 카탈로그에 명시 후 그 규칙을 따름
- **취소 기한**: 상담 시작 전 취소는 차감 안함. 시작 후 취소는 차감
- **유효기간 만료 임박**: D-30, D-7 자동 알림 (상담사·접수 담당자)

### 7.3 결제·환불 정책
- 지원금과 본인부담금은 **분리된 결제 레코드**로 관리 (정산·환불 시 분리 처리 필요)
- **중도 해지**: 잔여 회기에 해당하는 지원금은 사업주체로 반납, 본인부담금은 내담자에게 환불
- **부가세**: 바우처 사업은 일반적으로 **면세** (일반 상담과 세무 처리 분리)

### 7.4 청구·정산 정책
- **월별 마감**: 매월 말 → 익월 초 청구서 발행 → 15~20일 입금 (사업별 상이)
- **청구 반려 처리**: 반려 사유별 재청구 기한 관리
- **정산 후 감사**: 5년 이내 증빙 요청 가능 → 서류·로그 보존 필수

### 7.5 자격·문서 의무
- **제공기관 등록번호**는 센터가 취급 바우처 등록 시 필수 입력
- **상담사 자격**: 바우처별 요구 자격(예: 정신건강임상심리사 1·2급)이 다름 → 자격증 보유·만료 추적 필요
- **상담일지 보존**: 5년 이상 (감사 대응)

### 7.6 상담과 검사(Assessment)에서의 바우처 차감 규칙

이 플랫폼은 **상담(counseling)** 과 **검사(assessment)** 두 축으로 운영된다. 바우처는 두 축 모두에 적용될 수 있으며, **차감 방식이 다르다**.

**상담에서의 차감**
- 기본 단위: **상담 세션 1건 = 1회기**
- 변형: 90분 집중상담을 1회기로 인정할지 2회기로 인정할지 (바우처별 정책)
- 집단상담·부모상담·치료놀이 등 부가 상담 유형은 바우처별로 포함/제외/환산율이 다름

**검사에서의 차감**
- 기본 단위: **검사 케이스 1건 = N회기** (N은 바우처별 상이, 일부는 검사 아예 제외)
- 검사는 "세션"이 아니라 **케이스** 단위로 진행되므로, 회기 환산 로직이 상담과 다름
- 검사 결과 보고서가 바우처 증빙 자료로 활용될 수 있음
- 재검사(retest) 허용 여부·환산율 별도

**설계 원칙**
- **카탈로그 스키마에 "차감 규칙" 필드 자리를 예비**한다 (P1에서는 비워두거나 기본값 "1건=1회기"로 시작)
- P3 자동 차감 시 이 규칙에 따라 분기 처리
- 규칙 데이터 구조화 방식은 **Open Question** (JSON 조건식? 또는 계산 표?)

> ⚠️ **주의**: 이 규칙을 간과하면 "상담에는 차감되는데 검사에는 못 쓰는" 혹은 "1회기인 줄 알고 썼는데 2회기 깎여 있는" 사고가 발생한다. P3 착수 전 실제 바우처 사업 지침을 정독하여 규칙을 확정해야 한다.

## 8. 핵심 사용자 시나리오

### S1a — 신규 내담자 접수 시 바우처 수동 등록 (P1)
1. 접수 담당자가 내담자 기본 정보 입력
2. 담당자가 내담자가 어느 바우처를 받았는지 본인 경험·외부 확인으로 판단
3. 플랫폼에서 "바우처 등록" → 카탈로그에서 해당 바우처 선택 → 회기·만료일 입력
4. 등록 완료, 상담사·접수 모두 조회 가능

### S1b — 신규 내담자 접수 시 바우처 자동 추천 (P2)
1. 접수 담당자가 내담자 기본 정보 입력 (생년월일, 주소, 주호소 등)
2. 시스템이 인테이크 자가진단(PHQ-9 등) 결과를 수집
3. 소득분위 항목을 자가신고로 받음 (동의 기반)
4. 적용 가능 바우처 목록이 ✅/⚠️/❌로 표시됨, 각 항목의 판별 근거 함께
5. 담당자가 안내·선택 → 센터가 바우처를 내담자에게 발급

### S2 — 상담 세션 완료 후 회기 차감
1. 상담사가 세션 완료 버튼 클릭
2. 결제 방식이 "바우처"인 경우 시스템이 내담자 보유 바우처 중 적용 가능한 것을 자동 선택 (정책 기반)
3. 잔여 회기 1 차감, 지원금·본인부담금 결제 레코드 생성
4. 잔여 회기 부족 시 경고 표시, 차감 차단

### S3 — 월말 청구 정산
1. 회계 담당자가 "월별 바우처 사용 현황" 조회
2. 사업별·제공기관별로 집계된 회기 수·금액 확인
3. 증빙 누락 내담자·세션 경고 표시
4. 청구서 양식 자동 작성 → 검토 후 사업주체로 제출
5. 반려 시 재청구 관리

### S4 — 바우처 만료 임박 관리
1. 만료 30일 전 상담사·접수 담당자에게 알림
2. 만료 임박 바우처 보유 내담자 리스트 제공
3. 센터가 내담자에게 선제적 상담 제안 가능

### S5 — 중도 해지 및 환불
1. 내담자가 중도 해지 요청
2. 센터가 해지 처리 → 잔여 회기·지원금 사업주체 반납 청구
3. 본인부담금 환불 처리
4. 모든 변동이 감사 로그로 기록

### S6 — 바우처 양식 일지 생성 (Phase 2)
1. 상담사가 센터 일지 작성 완료
2. "바우처 양식 생성" 클릭 → AI가 초안 생성
3. 상담사가 검토·수정·확정
4. 양식이 증빙 자료로 저장됨

### S7 — 전문가 앱(모바일) 현장 회기 처리
상담사가 출장·가정방문 상담을 마친 직후 모바일로 처리하는 시나리오.

1. 상담사가 전문가 앱에서 "오늘 진행한 세션" 확인
2. 내담자 상세 화면에서 **잔여 회기·만료일 뱃지** 즉시 확인 (내담자 앞에서도 가능)
3. "세션 완료 + 회기 사용" 버튼 클릭 → 1회기 차감 (P1: 수동, P3: 자동)
4. 네트워크 불안정 시 로컬에 기록 → 온라인 복귀 후 서버 동기화 (충돌 시 서버 값 우선)
5. 태블릿으로 내담자 서명 받기 → 증빙 파일로 저장
6. (P2A) "바우처 양식 초안 생성" 모바일에서 트리거 → 결과는 이후 웹에서 정밀 검토 가능

> 💡 모바일에서의 차감·서명 결과는 **웹과 실시간(또는 최대 수 분 이내) 동기화**되어야 한다. 같은 세션에 대해 웹에서 중복 처리되지 않도록 idempotency 키를 부여한다.

### S8 — 내담자 앱(미래) 증빙·서명
내담자 앱이 도입된 이후의 미래 시나리오. 현재 기획의 선행 설계 배려 대상.

1. 센터가 바우처 등록을 요청하면 내담자 앱으로 **푸시 알림** 도착
2. 내담자가 앱에서 **소득분위 증빙(건강보험료 고지서 사진)** 업로드
3. 내담자가 **자가진단(PHQ-9 등)** 앱에서 직접 응답
4. 개인정보 제3자 제공·민감정보 수집 동의에 **전자 서명**
5. 센터 담당자의 플랫폼 대기열에서 내담자 제출 항목 확인 → 바우처 등록 확정

> P1 데이터 모델은 **"입력 주체(staff_entered / client_submitted)" 구분 필드**를 미리 두어, 미래에 내담자 앱이 붙어도 데이터 이원화·재구축 없이 매끄럽게 전환되게 한다.

## 9. 놓치기 쉬운 고려사항 (Cross-cutting Concerns)

Phase별 기능과 별개로, 기획 단계에서 명시적으로 짚어야 할 횡단적 주제들. 각 항목을 Phase 1/2/3 또는 후속 과제로 **라벨링하는 작업이 P1 착수 전 필요**하다.

### 9.1 법률·규제·개인정보
- **사회서비스이용권법**: 부정수급 시 제공기관 행정 처분 리스크
- **증빙 보존 의무**: 상담일지·청구서·동의서 5년 이상
- **민감정보 처리 근거**: 소득·건보·진단 정보는 별도 동의 및 처리 근거 필요
- **제3자 제공**: 바우처 수급 내역은 사업주체 제공 대상 → 동의서에 명시
- **개인정보처리방침 업데이트**: 수집 항목·목적·보관기간 반영

### 9.2 제공기관·상담사 자격 관리
- 제공기관 등록번호는 바우처별로 다름 (한 센터도 사업마다 별도 번호)
- 상담사 자격 요건(정신건강임상심리사 등급 등) 충족자만 청구 가능
- 자격증 만료 시 해당 상담사 세션은 청구 불가 → 자격 만료 추적 필요
- 상담사·센터 자격 상실 시 진행 중 바우처의 담당 이관 프로세스

### 9.3 회기 관리 세부 규칙
- No-show 정책, 취소 기한, 차감 타이밍은 **바우처별 정책으로 카탈로그에 명시**해야 확장성 있음
- 회기 유효기간 표현 방식이 다양 ("12개월 내 8회" vs "월별 최대 2회")
- 회기당 상담 시간 규정 (50분 기본, 90분 집중 상담을 1회기로 인정하는지)
- 같은 날 동일 바우처 복수 회기 허용 여부

### 9.4 결제·환불 구조
- 본인부담금은 소득분위별 차등 (0/10/20/30%)
- 지원금·본인부담금은 **분리 결제·분리 환불**
- 국민행복카드 연동은 초기엔 수기 기록, 추후 PG 연동
- 부가세 처리가 일반 상담과 다름

### 9.5 상담일지·서식 요구사항
- 필수 기재 항목(호소문제·중재·진전·다음 목표 등)이 바우처마다 다름
- 서명(상담사 자필·전자, 내담자 확인) 요구 여부가 다름
- 상담 시간 인증(시작·종료 시각)
- 대면·비대면 인정 여부
- 회기별 일지 vs 종결 보고서 분리
- 수퍼비전 이수 증빙 요구 여부

### 9.6 청구·정산 타임라인
- 월별 마감·청구·입금 주기
- 반려 시 재청구 기한
- 청구서 양식 표준화 (사회서비스전자바우처 EDI 정합성)
- 정산 오류 조정 절차
- 회계 인식 시점 (제공·승인·입금 중 무엇 기준?)

### 9.7 운영·UX 관점
- 접수 인테이크에 "바우처 보유 여부·종류" 질문 포함 여부
- 잔여 회기 실시간 가시성 (상담사·접수 동일 숫자)
- 만료 임박 알림 설계 (D-30, D-7 등)
- 복수 바우처 동시 보유 시 우선순위 결정 규칙
- 바우처 + 자비 혼합 결제 처리
- 상담사 성과급이 바우처 사용 회기 기반인 경우의 집계 요건

### 9.8 감사·품질 관리
- 지자체 현장 점검 대응 (연 1회 이상)
- 녹음·녹화 보존 의무 (일부 바우처)
- 내담자 만족도 조사 의무
- 부정 수급 이상 탐지 (장기)

### 9.9 정책·비즈니스 변경 대응
- 바우처 사업 중단 시 진행 중 내담자 처리 방침
- 단가·본인부담률 변경 시 **시행일 전후 청구 분리** (버전 관리 필요)
- 수급 중 자격 변동 시 잔여 회기 재계산 여부
- 센터 제공기관 자격 상실 시 이관 프로세스

### 9.10 감사·이력 보존
- 발급·차감·취소·수정의 전체 이력 영구 보존 (누가·언제·왜)
- 증빙 파일(서명된 동의서·일지 PDF) 스토리지 보관·검색
- 기존 수기·엑셀 기록의 일회성 이관

### 9.11 플랫폼 간 동기화·일관성 (모바일·웹)
- 상담사가 **모바일에서 회기 차감** 시 웹과의 동기화 전략 (실시간? 풀링? 최대 지연 허용 기준?)
- 같은 세션에 대한 **중복 처리 방지**: idempotency 키, 마지막 쓰기 우선 정책
- **오프라인 처리**: 네트워크 불안정 시 로컬 기록 → 온라인 복귀 동기화 (전문가 앱)
- **권한 범위 일관성**: 모바일에서 허용된 액션이 웹에서 허용되지 않거나 그 반대의 불일치 방지

### 9.12 내담자 앱 선행 설계 배려
내담자 앱이 미래에 도입될 것을 대비하여, **지금 P1 데이터 모델·Facade 설계 시 다음을 고려**한다:
- **"입력 주체" 구분 필드**: 모든 바우처 관련 입력(증빙·동의·자가진단)이 **누가(staff / client) 입력했는가**를 기록
- **내담자에게 공개 가능한 필드 vs 내부 전용 필드 분리**: 응답 DTO를 처음부터 두 종류(`VoucherSummary` / `VoucherInternal`)로 설계
- **동의서 버전 관리**: 내담자 앱에서 동의 재확인이 필요할 때 현재 동의 버전 추적
- **이벤트 기반 구조**: 발급·차감·만료 이벤트를 알림 큐로 빼기 좋게 Facade 경계에서 발생

### 9.13 알림 채널 전략
- **만료 임박 D-30/D-7**: 웹 인앱 배너, 이메일, (전문가 앱) 푸시, (미래 내담자 앱) 푸시
- **회기 소진 알림**: 해당 내담자 담당 상담사·접수 담당자
- **청구 마감 임박**: 회계 담당에게 주·월 단위 알림
- **각 채널의 실패 폴백**: 푸시 실패 시 이메일, 이메일 반송 시 인앱 대기열

## 10. 성공 지표 (KPI)

### Phase 1 (중앙화)
- 엑셀·수기 관리 병행 비율 감소율
- 센터 관리자의 취급 바우처 설정 완료 시간
- 담당자 교체 시 인수인계 소요 시간
- 센터 전체에 걸친 바우처 현황 가시성 (2명 이상 동일 숫자 확인)

### Phase 2 (AI·자동화)
- **2A**: 상담사 체감 일지 작성 시간 감소율 / AI 초안 그대로 승인 비율 / hallucination 발생률
- **2B**: 자격 판별 정확도 / 접수~등록 소요 시간 추가 단축

### Phase 3 (정산·감사)
- 월별 청구 누락률
- 중복 차감·잔액 초과 사고 건수
- 청구서 작성 시간 감소율
- 감사 시 증빙 출력 가능률

### 공통
- 센터별 바우처 매출 비중 변화
- 센터 NPS (바우처 기능 도입 전후)

| **감사 대응 실패** | 증빙 누락 시 지원금 반납 | 모든 변동 로그 영구 보존, 증빙 파일 통합 스토리지 |
| **민감정보 유출** | 법적 책임, 플랫폼 신뢰도 손상 | 수집 최소화, 동의 기반 수집, 접근 권한 최소화, 감사 로그 |

| **단일 바우처 의존** | 전국민 마음투자 정책 변경 시 전체 리스크 | 카탈로그 구조를 바우처별 확장 가능하게 설계 |

## 12. 의사결정이 필요한 사항 (Open Questions)

착수 전 이해관계자와 확정해야 할 질문들.

### 12.1 회기 차감 타이밍
- (A) 상담 시작 시 / (B) 종료 후 상담사 완료 처리 시 / (C) 관리자 최종 승인 시
- **초안 권장**: B (노쇼 복원 복잡도 회피). 센터 측 의견 확인 필요.

### 12.2 복수 바우처 보유 시 우선순위

- **초안 권장**: A + C 혼합 (기본은 만료 임박 자동, 수동 오버라이드 가능)
