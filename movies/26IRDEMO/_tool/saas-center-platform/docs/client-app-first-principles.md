## 1. 제1원칙 적용 과정

### 기존 가정 해체

기존 기획에서 무의식적으로 가정한 것들:

| 기존 가정 | 질문 | 결론 |
|---|---|---|
| 앱이니까 하단 4탭이 필요하다 | 탭은 왜 존재하는가? | 서로 다른 맥락의 정보 분리를 위해. 우리 핵심 정보는 하나의 흐름이므로 4탭 불필요 |
| 홈/일정/기록/마이 구조가 표준이다 | 사용자가 이 구분을 원하는가? | 아니다. "언제 가지 → 뭘 하지 → 뭐 했대 → 어디쯤이지"는 하나의 흐름 |
| 미소속 유저에게도 풍부한 화면이 필요하다 | 왜? | 콘텐츠는 있지만, 핵심 가치는 센터 연결 후 발생. 미소속 화면은 최소한으로 |
| 다른 헬스케어 앱처럼 대시보드가 필요하다 | 대시보드를 왜 보는가? | 사용자가 원하는 건 대시보드가 아니라 "다음에 뭘 하면 되지?"에 대한 답 |

### 근본 질문

**"내담자가 이 앱을 여는 이유는 딱 하나, 뭔가?"**

→ 기획서에 이미 답이 있었다:

- 성인 내담자 1순위: **"다음에 뭘 하면 되지?"**
- 보호자 1순위: **"우리 애 어디까지 했지?"**

## 2. 핵심 결정 사항

### 2-1. 사용자 경험은 동일하다

성인 내담자와 보호자의 앱 경험은 **같다**.

- 별도 역할 선택, 분기된 화면 구성 없음
- 보호자가 자녀 정보를 볼 때도 같은 화면 구조
- 다중 자녀/다중 센터 모두 통합 표시 (전환 없음)

### 2-2. 정보 우선순위

앱을 열었을 때 위에서 아래로 보이는 순서:

| 순위 | 정보 | 사용자 질문 | 왜 이 순서인가 |
|---|---|---|---|
| **1** | 캐릭터 멘트 | — | 감성적 첫인상, 상황별 안내 |
| **2** | 다음 일정 (진행 바 포함) | "언제 가지? 어디쯤이지?" | 앱 여는 즉시 0.5초 안에 답을 얻어야 하는 질문. 진행현황을 일정 카드에 통합 |
| **3** | 미션/성장 가이드 (Phase 2) | "그때까지 뭘 하지?" | AI 성장 가이드 콘텐츠, 연구 기반 검증 필요 |
| **4** | 콘텐츠 | — | 매거진/카드뉴스, 태그 기반 맞춤 추천 |

### 2-3. 앱 구조: 홈 + 마이 (2탭)

**4탭이 아닌 2탭인 이유:**

일정, 미션, 진행현황은 서로 다른 맥락이 아니라 **하나의 흐름**이다. 분리할 이유가 없다.

반면 마이페이지(센터 정보, 알림 설정, 로그아웃)는 맥락이 다르다. "내 상담 현황"과 관계 없는 설정/관리 영역.

```
┌────────────────────────────────────────┐
│                                        │
│  [ 홈 ]                    [ 마이 ]    │
│                                        │
│  홈: 캐릭터 멘트 + 일정 + 콘텐츠       │
│  마이: 센터별 정보 + 설정/관리          │
│                                        │
└────────────────────────────────────────┘
```

**상세 화면은 드릴다운:**

- 홈에서 일정 영역 터치 → 타임라인 (과거 이력 + 미래 일정 + 진행현황 통합)

탭으로 분리하는 게 아니라, 필요할 때 **눌러서 들어가는** 방식.

## 3. 다중 센터 + 다중 자녀 통합 표시

### 3-1. 설계 원칙

사용자는 센터 단위로 생각하지 않는다. **"이번 주에 뭐가 있지?"**로 생각한다. 자녀도 마찬가지. 전환 방식은 불필요한 인지 부하를 준다.

### 3-2. 영역별 통합 규칙

| 영역 | 통합 방식 | 구분자 | 이유 |
|---|---|---|---|
| **일정** | 전체 시간순 합산 | 자녀 이름 + 센터명 라벨 | 사용자는 "언제 어디 가지"가 궁금 |
| **진행현황** | 자녀별 분리 | 자녀 이름 섹션 | 치료 맥락이 다르므로 섞으면 의미 없음 |
| **콘텐츠** | 통합 | 태그 기반 매칭 | 소속 여부 무관 공통 레이어 |

### 3-3. 역할별 홈 일정 표시

| 케이스 | 홈 일정 영역 |
|---|---|
| 순수 내담자 (client) | 내 일정만 표시 |
| 순수 보호자 (guardian) | 자녀 일정만 표시 |
| 둘 다 (both) | **내 일정** 섹션 + **자녀 일정** 섹션 분리 |

both일 때 일정 카드 구조:

```
── 내 일정 ──────────────────
5/21 수  14:00
개인상담 3회차 · ○○상담센터
━━━━━━━━━━░░░░░░░░░░ 3/10회

── 민준 ─────────────────────
5/21 수  16:30
상담 6회차 · 놀이치료센터 · D-2
━━━━━━━━━━░░░░░░░░░░ 5/10회

── 서연 ─────────────────────
5/23 금  10:00
언어평가 · 언어치료센터 · D-4
━━━░░░░░░░░░░░░░░░░░ 1/8회
```

데이터가 없는 섹션은 미노출 (조건부 렌더링으로 세 케이스 하나의 로직으로 처리).

### 4-4. 드릴다운: 타임라인 (일정 + 진행현황 통합)

홈에서 "전체 보기"를 터치하면 진입. 월간 캘린더가 아닌 **타임라인 형태**.

타임라인이 캘린더보다 나은 이유:
- 주 1~2회 상담에 월간 그리드는 빈 칸만 많음
- "다음에 뭘 하면 되지?"에 대한 답이 바로 보임
- D-day 카운트, 카드 애니메이션 등 재미 요소 적용 용이

```

## 5. 캐릭터 시스템 (오브)

### 5-1. 기본 정의

- **형태**: 빛/오브 (따뜻한 빛 덩어리, 추상형)
- **성격**: 차분한 안내자, 따뜻한 톤
- **역할**: MVP에서는 상황별 한 줄 멘트, Phase 2에서 AI 성장 가이드의 인격으로 확장
- **말투**: 느낌표 없이 마침표로 끝나는 차분한 톤

### 5-2. 시각 변화

| 구분 | 상태 | 오브 표현 |
|---|---|---|
| **시간대** | 아침 | 밝은 금빛 (활기) |
| | 낮 | 따뜻한 주황빛 |
| | 저녁 | 부드러운 보랏빛 (차분) |
| | 밤 | 은은한 달빛 |
| **상황** | 일정 임박 | 살짝 반짝임 |
| | 상담 완료 | 포근하게 퍼짐 |
| | 장기 미접속 | 조용히 흔들림 |
| | 로딩 중 | 숨쉬듯 맥동 (스피너 대체) |
| | 에러 | 흐릿해짐 |

### 5-3. 상황별 멘트

| 상황 | 멘트 |
|---|---|
| 아침 접속 | "좋은 아침이에요" |
| 일정 D-1 | "내일 민준이 상담이 있어요" |
| 일정 없음 | "오늘은 여유로운 하루예요" |
| 상담 완료 직후 | "오늘도 수고했어요" |
| 진행현황 50% 돌파 | "벌써 절반이나 왔어요" |
| 오랜만에 접속 | "다시 만나서 반가워요" |
| 네트워크 오류 | "연결이 불안정해요" |
| 서버 오류 | "잠깐 문제가 생겼어요" |
| 빈 데이터 | "아직 예정된 일정이 없어요" |

### 5-4. 에러/빈 상태 처리

일반적인 에러 화면 대신 **오브가 상태를 표현**한다. 에러조차 브랜드 경험이 되는 설계.

```
── 네트워크 오류 ──────────────

      (흐릿해진 오브)

  "연결이 불안정해요.
   잠시 후 다시 올게요"

      [다시 시도]

───────────────────────────────
```

## 6. 디자인 방향

### 6-1. 핵심 키워드

- **풍부한 콘텐츠** + **시각적 화려함** + **재미 요소** + **높은 직관성**
- 단순한 관리 도구가 아닌, 열 때마다 눈이 가고 손이 가는 앱

### 6-2. 적용 요소

| 요소 | 적용 범위 | 비고 |
|---|---|---|
| **캐릭터 (오브)** | 전체 | 가이드형, Phase 2에서 AI 연결 |
| **마이크로 인터랙션** | 전체 기본 적용 | 진행 바 애니메이션, 카드 전환, 숫자 카운트업 |
| **감성 비주얼** | 포인트만 적용 | 시간대별 톤 변화 (홈 상단), 계절감 |
| **게이미피케이션** | 제외 | 상담 맥락에서 배지/레벨은 부자연스러움 |

### 6-3. 다크 모드

MVP에서 포함. 오브 캐릭터가 빛 기반이라 다크 모드에서 시너지 발생.

- **라이트 모드**: 밝은 배경 + 은은한 오브 → 차분하고 깨끗한 느낌
- **다크 모드**: 어두운 배경 + 빛나는 오브 → 몰입감, 감성적

### 6-4. 접근성

| 항목 | 결정 |
|---|---|
| 폰트 크기 | 시스템 설정 따름 + 최대 상한선 (레이아웃 보호) |
| 한 손 조작 | 주요 액션 버튼 하단 배치 원칙 |
| 인지 부하 | 최소화 (우울/불안 상태 내담자 고려) |

간편 로그인 (카카오 / 네이버 / 애플)
    ↓
슬라이드 3장째에서 분기
    ↓ 센터 코드 입력           ↓ "나중에 할게요"
승인 대기                     미소속 홈
    ↓ 센터에서 승인
    (역할/대상 매칭)
    ↓ 푸시 알림
소속 홈
```

### 7-2. 온보딩 슬라이드 (최초 1회)

```

[2/3]

[3/3]
센터 코드가 있으신가요?
[센터 코드 입력하기]
[나중에 할게요 →]
```

### 7-3. 센터 연결 (센터 주도 승인)

내담자/보호자 구분은 앱에서 하지 않는다. **센터에서 승인 시 역할/대상을 지정**한다.

```
앱 사용자가 센터 코드 입력 → 승인 요청
    ↓
센터 웹 승인 화면:
┌──────────────────────────┐
│ 승인 요청                │
│ 홍길동 (010-5678-0000)   │
│ → 연결 대상: [민준 ▾]    │
│ → 역할: [보호자 ▾]       │
│ [승인] [거절]             │
└──────────────────────────┘
    ↓
앱에 반영 → 소속 홈 전환
```

### 7-4. 자가진단 (미소속 콘텐츠)

- **성격**: 가벼운 체험 콘텐츠 (일회성)
- **저장**: 하지 않음 (이력 관리 없음)
- **이유**: 단일 검사로는 의미 있는 이력이 되기 어려움. 종합 평가는 센터에서.
- **목적**: 센터 연결 유도

```
자가진단 결과 화면:
──────────────────────────

당신의 점수: 12점
중등도 우울이 의심돼요.

정확한 평가와 맞춤 상담은
전문 센터에서 받아보세요.

[센터 코드 입력하기]
[홈으로 돌아가기]
──────────────────────────
```

## 8. 알림 시스템

### 8-1. MVP 알림 정책

타이밍은 **시스템 고정**. 사용자 설정은 향후 피드백 기반으로 확장.

| 알림 | 타이밍 | 내용 예시 |
|---|---|---|
| 일정 전날 | D-1 오전 10시 | "내일 14:00 상담이 있어요" |
| 일정 당일 | 1시간 전 | "1시간 뒤 상담이에요, 준비됐나요?" |
| 센터 승인 | 즉시 | "○○센터에서 승인했어요!" |
| 일정 변경/취소 | 즉시 | "5/21 상담 일정이 변경됐어요" |

### 8-2. 다중 센터/자녀 알림 규칙

- 각 센터/자녀 일정마다 개별 발송
- 같은 날 여러 일정이 있으면 D-1 알림은 **묶어서 한 번**: "내일 일정이 2건 있어요"
- 캐릭터 톤 적용 (딱딱하지 않게)

### 8-3. 보호자 알림

보호자에게도 동일하게 발송, **자녀 이름으로 구분**.

| 케이스 | 알림 예시 |
|---|---|
| 자녀 1명 | "내일 민준이 상담이 있어요" |
| 자녀 2명 | "내일 민준이 14:00, 서연이 16:00 상담이 있어요" |
| 본인도 내담자 (both) | "내일 상담이 있어요" (본인) + "민준이 상담이 있어요" (자녀) |

## 9. 검사 결과 시스템

### 9-1. 공개 범위 (상담사 설정)

검사 결과의 공개 범위는 **상담사가 결정**한다. 임상적 판단이 필요한 영역.

| 수준 | 내담자에게 보이는 것 | 사용 예시 |
|---|---|---|
| **비공개** (기본값) | 검사 실시 이력만 (날짜 + 검사명) | 민감한 검사, 아직 설명 전 |
| **요약 공개** | 해석 요약 + 종합 소견 | 대부분의 경우 |
| **전체 공개** | 점수 + 해석 + 종합 소견 | 자가진단, 경과 비교용 |

### 9-2. 종합 보고서

풀배터리 검사는 보통 초기 평가 때 **1회 실시**. AI가 초안을 생성하고 상담사가 검수/수정 후 발행.

```
검사 실시 (초기 1회)
    ↓
AI 종합 보고서 초안 생성
    ↓
상담사 검수/수정
    ↓
공개 범위 설정 후 발행
    ↓
내담자 앱에서 열람
```

내담자 앱에서 보이는 보고서:

```
── 종합 심리검사 결과 ────────
2026.05.10 실시 · ○○상담센터
김상담 선생님

[종합 소견]
전반적인 정서 상태는...

[영역별 결과]
정서 ──────── 주의 필요
인지 ──────── 양호
사회성 ───── 양호

※ 자세한 내용은 담당 선생님과
  상담 시 확인해주세요.
```

## 10. 콘텐츠 시스템

### 10-1. 현황

## 11. 엣지케이스 처리

### 11-1. 센터 종결

- MVP: 종결 = **읽기 전용 전환** (데이터 유지)
- 삭제 정책: 법률 검토 후 별도 수립 (향후)
- 마이페이지에서 "종결" 라벨 + 기간 표시 + 기록 열람만 가능

### 11-2. 보호자 변경

- 앱에서 자동 처리하지 않음 (양육권 등 법적 판단 필요)
- **센터에서 수동 처리**: 기존 보호자 관계 해제 → 새 보호자 관계 추가
- 현재 센터 웹 기능(관계 해제 + 추가)으로 처리 가능
- 자녀 성인 전환도 동일 (센터에서 역할 변경)

### 11-3. 다중 기기 / 양쪽 부모

- 현재 데이터 모델이 지원함 (하나의 내담자에 복수 보호자 연결 가능, `is_primary`로 주 보호자 구분)
- 각자 계정으로 로그인 → 센터에서 각각 보호자로 연결 → 양쪽 다 자녀 정보 열람 가능
- 알림도 양쪽 발송

### 11-4. 에러 상태

오브 캐릭터가 에러 상태를 표현 (별도 에러 화면 없음):

| 상황 | 오브 상태 | 멘트 |
|---|---|---|
| 네트워크 끊김 | 흐릿해짐 | "연결이 불안정해요" |
| 서버 오류 | 깜빡임 | "잠깐 문제가 생겼어요" |
| 로딩 중 | 숨쉬듯 맥동 | (멘트 없이 빛 애니메이션) |
| 빈 데이터 | 조용히 떠있음 | "아직 예정된 일정이 없어요" |

## 13. 타임라인 상세 규칙

### 13-1. 회기 상태별 표시

| Session status | 표시 | 아이콘 | 스타일 |
|---|---|---|---|
| `completed` | 완료 | ✓ | 정상 톤 |
| `no_show` | 미방문 | ─ | 흐린 톤 (부정적 느낌 배제) |
| `scheduled` (다음) | 예정 | ● | 강조 + D-day |
| `scheduled` (먼 미래) | 예정 | ○ | 흐림 |
| `cancelled` | **미노출** | — | 타임라인에서 제외 |

### 13-2. 완료 회차 터치 시 (드릴다운)

MVP에서는 기본 정보만 표시, Phase 2에서 노트/미션 확장:

```
── MVP ──────────────────────
5/14 수 · 상담 5회차 · 완료

놀이치료센터
담당: 김상담 선생님
14:00 ~ 14:50

── Phase 2 확장 ─────────────
(위 정보 + 아래 추가)

[상담사 노트]              NEW
감정 어휘가 다양해짐.

[미션 기록]
감정 이름 먼저 말해주기 4/7
```

### 13-3. 케이스별 분리

같은 센터에서 여러 케이스(놀이치료 + 미술치료)는 치료 맥락이 다르므로 **케이스별 별도 타임라인**:

```
── 민준 · 놀이치료센터 ───────

  [놀이치료 - 개별]
  6회차 진행 중 · 3개월째

  ✓ 5/14  상담 5회차  완료
  ● 5/21  상담 6회차  D-2  [길찾기]
  ○ 5/28  상담 7회차  D-9

  [미술치료 - 개별]
  2회차 진행 중 · 1개월째

  ✓ 5/12  치료 1회차  완료
  ● 5/19  치료 2회차  D-0  [길찾기]
```

케이스 이름은 `Program.name`에서 가져옴.

### 13-4. 종결 케이스 표시

종결된 케이스는 **접힌 상태(collapsed)**로 표시. 터치하면 펼쳐져서 전체 이력 확인 가능:

```
  [미술치료 - 개별]              ← 활성 (펼쳐짐)
  2회차 진행 중 · 1개월째
  ...

  [놀이치료 - 개별]  종결  ▸    ← 종결 (접힘)
  12회 완료 · 6개월 · 2025.11~2026.04
```

### 13-5. 진행 표시 (total_sessions 유무)

상담은 회기수를 정해놓지 않는 경우가 일반적 (내담자 개선 상태에 따라 진행).

| 케이스 | 표시 방식 |
|---|---|
| total_sessions 있음 (소수) | `━━━━━━━━━━░░░░░░░░░░ 6/12회` (진행 바) |
| total_sessions 없음 (일반적) | `6회차 진행 중 · 3개월째` (텍스트) |

경과 기간 계산 (첫 회기 날짜 기준):

| 경과 | 표시 |
|---|---|
| 1개월 미만 | "2주째" |
| 1~11개월 | "3개월째" |
| 12개월 이상 | "1년 2개월째" |

### 14-2. 인증

기존 Account/Person 구조를 그대로 사용. 모델 변경 없음.

```
소셜 로그인 (카카오/네이버/애플)
    ↓
Account 생성 (provider: "kakao", provider_id: "xxx")
    ↓
Person 생성 (이름, 이메일)
    ↓
센터 코드 입력 시 전화번호 + SMS 인증
    ↓
센터 승인 → Client.person_id = Person.id 연결
```

- 전화번호: 최초 센터 연결 시 1회만 입력 + SMS 인증, 추가 센터 연결 시 자동 포함
- 전화번호 변경: 마이페이지 > 개인정보 관리에서 재인증

### 14-3. API

내담자 앱 전용 API 분리 (`/api/v1/client-app/`). 읽기 위주, 본인+자녀 데이터만 접근.

```
/api/v1/client-app/

── 인증 ──────────────────────
POST   /auth/social-login        # 소셜 로그인
POST   /auth/refresh              # 토큰 갱신
POST   /auth/phone-verify/send    # SMS 인증번호 발송
POST   /auth/phone-verify/confirm # SMS 인증번호 확인

── 센터 연결 ─────────────────
POST   /centers/connect           # 센터 코드로 승인 요청
GET    /centers                   # 내 소속 센터 목록

── 일정/타임라인 ─────────────
GET    /schedules/upcoming        # 다가오는 일정
GET    /cases/{case_id}/timeline  # 케이스별 타임라인

── 검사 ──────────────────────
GET    /assessments               # 검사 결과 목록
GET    /assessments/{id}/report   # 종합 보고서

── 콘텐츠 ────────────────────
GET    /contents                  # 맞춤 콘텐츠 목록
GET    /contents/{id}             # 콘텐츠 상세

── 자가진단 ──────────────────
GET    /self-tests                # 자가진단 목록
POST   /self-tests/{id}/submit    # 자가진단 제출 (저장 안 함)

── 프로필 ────────────────────
GET    /profile                   # 내 정보
PATCH  /profile                   # 프로필 수정
GET    /children                  # 자녀 정보 목록
```

홈 데이터는 통합 API 대신 **영역별 분리 호출** (체감 속도 향상):

```
앱 진입 → 캐릭터 멘트 (로컬, 즉시)
       → GET /schedules/upcoming (병렬)
       → GET /contents (병렬)
       → 각각 도착 순서대로 렌더
```

FCM 기반 (전문가 앱과 동일 인프라).

### 14-5. 분석

### 14-7. 앱 업데이트

스토어 업데이트만 사용 (OTA 미사용). 서버에서 최소 지원 버전 관리, 구버전 앱은 강제 업데이트 유도:

```
앱 실행 → 버전 체크
    ↓ 현재 < 최소 지원 버전
(오브) "새로운 버전이 나왔어요.
       업데이트 후 이용해주세요"
[업데이트 하기] → 스토어 이동
```

## 16. 기존 기획서와의 관계

이 문서는 기존 기획서(client-app-planning.md)를 **대체하지 않는다**. 기존 기획서의 기능 상세(미션 시스템, 기록 플로우, 전문가 노트, SaaS 연계 등)는 그대로 유효하며, 이 문서는 **구조와 우선순위, 디자인 방향**을 재정립한 것이다.

| 항목 | 기존 기획서 | 이 문서 |
|---|---|---|
| 기능 상세 | 유효 | 다루지 않음 |
| Phase 로드맵 | 유효 | 다루지 않음 |
| 디자인 원칙 | 유효 | 보완 (캐릭터, 다크모드, 접근성 등) |
| 화면 구조 (IA) | 4탭 → **2탭으로 변경** | 이 문서 기준 |
| 정보 우선순위 | 명시적이지 않았음 | 이 문서 기준 |
| 홈 화면 레이아웃 | 카드 스택 → **통합 흐름으로 변경** | 이 문서 기준 |
| 다중 센터/자녀 | 향후로 미룸 → **MVP 포함** | 이 문서 기준 |
| 드릴다운 상세 | 캘린더 뷰 → **타임라인으로 변경** | 이 문서 기준 |
| 진행현황 | 별도 카드 → **일정 카드에 통합** | 이 문서 기준 |
